# 停复牌来源记录身份调整

用户明确要求按通达信分别保留，不选一个覆盖另一个：既包括相同停牌时间、不同复牌时间，
也包括相同停复牌时间下来源并列返回的不同说明和原因。

## 维护方案

- 唯一键改为 `(source, market, code, suspended_at, resume_key, record_key)`。
- `resume_key` 是复牌时间的 SQL 索引表示；未知时为 `1000-01-01 00:00:00`，
  业务 `resumed_at` 仍为 NULL，不向用户或回测返回这个索引占位值。
- `record_key` 是长度前缀规范化后的来源说明和原因的 SHA-256；不向用户或回测返回。
- 不删除、不重写已有业务字段；先新增索引表示、填充值，再替换主键并加一致性约束。
  迁移前后按全部原业务列计算行数及 SHA-256，要求完全相同。
- 正常关闭 Empire，持有正式单实例锁，待归档 Stream 必须为 0。
  只失效当前命名空间的 `suspensions/tdx` 摘要，不清空共享 Redis。
- 旧逻辑曾合并来源记录，保留已有业务但重置该项目覆盖与已入队断点，
  从 2004-12-27 重新核验补回。其他项目不变。相同业务回源不写业务 DML。
- MySQL DDL 不是可回滚事务；各阶段支持重入，Redis 清理未完成时在 SQL 留维护标记，
  应用拒绝使用未完成维护状态。启动不自动迁移。

显式执行：`python scripts/migrate_suspension_identity.py`。

## 验证准备

已在测试专属表验证旧主键迁移、重复执行、前后摘要相同，以及相同停牌时间下插入两个复牌时间、
相同停复牌时间下插入两组来源说明和原因。后续执行公共入队/归档集成、重复免 SQL、
完整来源记录重放、成功清队及正式发布门禁。未知复牌与已知复牌分别保存；
同一个完整来源身份的冲突仍报告来源日期和证券身份。

本数据保留来源记录，不替用户裁定互相矛盾的交易区间；回测若需唯一约束区间，应由独立处理规则决定。

# 减少写盘与新闻翻页规则

用户明确要求 Redis 不再写硬盘、项目 MySQL 永久关闭可选日志并删除旧日志、所有业务避免无变化写入，以及新浪新闻每页 50 条、初次仅第一页、遇到上轮新闻即停止向前翻页。本次没有修改表结构，也没有删除已有业务记录。

## Redis：已生效

通过现有认证连接关闭 `appendonly`、清空 `save`，CONFIG REWRITE 保存到实际服务配置 `D:\Redis\redis-d.conf`。运行时设置 `loglevel nothing`，配置文件同步保存。配置文件设置 `logfile /dev/null`；`dbfilename volatile-no-snapshot.rdb` 指向不存在的新快照文件，防止重启误加载旧 dump。

当前 `dbfilename` 与 `logfile` 不能在线更改，下一次服务启动才采用文件中的新值；运行时已通过关闭 AOF/快照和日志级别 nothing 停止常规数据及日志写盘。本次不重启共享 Redis，不清空 key，不删除共享 AOF/RDB 备份（含既有临时快照文件）。检查时没有进行中的 BGSAVE/AOF 重写。

Redis 服务或电脑重启会丢失待归档业务、断点、计划、错误及运行记录。这是对原有持久化保障的明确变更；只重启应用、Redis 仍存活时继续恢复。新采集默认从第一页建立新基线，MySQL 已归档业务不受影响。

## MySQL：已完成

仅目标 `MySQL_Empire`（3307），`E:\mysql\empire\my.ini` 已配置：

```ini
skip-log-bin
general-log=OFF
slow-query-log=OFF
log-output=NONE
log-error=NUL
log-error-services=""
```

`mysqld --validate-config` 返回成功。电脑另一实例 MySQL84 未改动。管理员维护脚本随后执行成功，MySQL_Empire 正常停止和重启；复核显示 `log_bin=OFF`、`general_log=OFF`、`slow_query_log=OFF`、`log_output=NONE`。

`scripts/restart-mysql-low-write.ps1` 已按精确路径执行，删除 `binlog.000001`、`binlog.000002`、`binlog.000003`、`binlog.index` 及指定目录中的 3 个 migration 日志和 `mysql.err`，共约 25.8 MiB。脚本不递归删除目录，没有触碰 redo/undo、业务文件或其他 MySQL 实例。执行清单保存在 `artifacts/mysql-low-write-maintenance.json`。

InnoDB redo/undo 是数据库事务恢复所需文件，保留；不能承诺把正常运行的 MySQL 变成完全不写日志的数据库。删除旧 binlog 后无法用这些文件进行时间点恢复；实际删除清单以维护脚本结果为准。

## 业务行为与验证

新闻每页 50 条，首次/fresh 只请求第一页；后续只在未接上上轮上界时翻页。旧游标的 refresh_pages 字段被忽略，仍沿原 before_id 续跑。停止页正常比较内容、处理修订，之后更早的修订不保证发现。

新闻按页、在事务内读取已有记录，业务字段及来源修订版本相同则不发出 DML，也不刷新 last_seen_at；旧响应跳过。来源版本变化属于有效变更，即使正文相同也保留版本，以拒绝迟到旧版。last_seen_at 改为最近一次实际写入版本的观测时间。

股票整份规范化列表相同则不 DELETE/INSERT；SQL generation 和时间保留最后实际变化。最新成功核验身份放在 Redis stocks:committed:<source>，防止不写 SQL 后迟到批次倒退数据。列表有业务变更时继续采用原子整份发布。

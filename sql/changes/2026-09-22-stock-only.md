# 股票列表单表与 Redis 记录规则调整

本次操作由用户明确要求并确认；不是应用启动或版本升级时自动执行的迁移。

## 采用的规则

- MySQL 当前只保留 `stock` 业务表和一份股票列表，不按日保存完整快照。
- 成功响应只提取必要业务字段，规范化数据与断点先写入 Redis。每 60 秒检查归档，完整性通过后在一个 MySQL 事务内替换当前列表，提交后才删除对应 Redis 临时数据。
- 成功 HTTP 原文不持久保存。失败 HTTP 请求（含重试后成功的中间失败）、解析及校验失败保存 Redis 错误样本，每采集项目最近 300 条。正文上限 64 KiB，记录原始字节数、SHA-256、截断、脱敏、请求、阶段及程序版本。
- 采集记录、归档记录分别每项目最近 100 条，只留 Redis，不归档。MySQL 故障保存归档失败记录，有效数据留在待归档队列，不能按错误样本上限丢弃。
- 显式重新采集会建立新的 Redis 断点；确认已被替代且仍不完整的旧临时进度可释放。已经完整的有效待归档数据仍受提交后删除规则保护。

## 错误处理后的清理流程

规则同时写入 [AGENTS.md](../../AGENTS.md) 和桌面离线说明：

1. 处理前读取对应项目的错误记录，记下本次处理的记录 ID、发生阶段和原因。
2. 修复程序并验证导致这些错误的路径。
3. 调用 `collection.records.clear_errors(project_id, record_ids)` 或在“运行记录 → 错误记录”选择对应记录，勾选已修复并验证，再清除。
4. 在本次处理记录中写明修复、验证和删除数量。保留新出现及未处理的错误；查看页面、成功采集或成功归档均不会自动视为错误已经修复。

本次切换前旧隔离错误为 0，尚无需要沿用或清除的实际错误记录。故障注入测试产生的错误位于随机专属命名空间，验证后只清理测试拥有的记录和数据。

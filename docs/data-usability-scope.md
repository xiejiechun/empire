### 范围证明算法

显式选择证券时，在同一只读 SQL 一致快照读取现有证券单元完整内容与 collection_state 单元证明：校验现行契约、规范行、业务键、内容摘要、完整有序集合 count/digest 与带时区观测版本。证券身份由当前目录和该业务历史联合解析；跨市场不唯一或缺证明时阻断。最多100证券、每证券2000条，复用正式规范和查询边界。只有完整单元精确匹配后，才按 event_date 投影日期范围；空范围必须来自完整单元证明。逐证券报告返回业务键和内容集合的摘要，不能以相同数量替代。

不从聚合摘要反推来源成员。不匹配单元可能包含保留历史、当前来源变更或未知遗漏，仅凭日期筛选不能证明它的任何子集，继续阻断并明确需要原来源成员/内容证明。范围外的其他证券不参与本范围的完整性判断。未指定证券保留原全范围严格检查；不静默缩成有数据证券。增发未知详情不被删掉或解释成空详情。完整分红容量原已通过；本专项不改采集消息、归档、结构或容量布局。

用途沿用公共 PreparationScope 的 analysis / historical_signal。analysis 是当前修订版的事后分析；历史信号要求当时可用的版本，不能把报告期或最早预案公告日当作修订可用日。当前资本契约缺少稳定事件关联与每次修订可用日，因此历史信号明确来源受限；不新增可用时间假设。现有名义派息及区间名义现金股息率均是事后分析；持仓及到账现金收益未实现，原始事件浏览或理论复权不能代替它们。

### 预案与实施

正式浏览保留全部历史。现有理论复权排除预案/取消，拒绝同日并列实施；增加同一报告期多条实施、不同除息日的歧义拒绝，避免修订产生双计。拒绝表示无法裁定关联，不认定它们属于同一事件，也不合并、求和或选择最近一条。多个不同报告期的独立实施仍依明确除息日计算。缺失契约是来源事件稳定ID、预案到实施关联和修订真实可用时间；金额相似不能补足这些契约。

### 停复牌时效

原13:40的10-21覆盖只能证明当时已核查来源日期；15:30后不能冒充当天收盘后证据。检查正常计划、最后覆盖日回查和统一归档行为；来源日与事件生效日仍分别保留。如果无变化重查只推进统一 Redis 摘要，SQL 时间保留旧值，则沿现有只读可信摘要补充时效，绝不刷新 SQL 时间。补充仅限 SQL 已有连续覆盖，不延伸覆盖日期；摘要的范围、规范版本、内容、有效期和观测顺序均须匹配。Redis 不可用/失配回 SQL，盘前证据仍失败。没有真实新核查就不得结案为盘后通过。

### 展示与缓存

现有数据准备入口和每项证据增加来源限制原因、实际观测时间；用途/证券/日期使用原 scope。详情汇总已满足、阻断缺口、非阻断限制，区别未检查、检查失败、来源受限、通过。检查执行时间不是来源证据时间。提高受影响 preparation cache_revision，旧缓存不冒充新规则证明。不新增平行准备系统、启动迁移或兼容写入。

## 关键边界

- 正常可信摘要命中仍不查询、不写 MySQL；SQL 故障保留业务消息，恢复确认后才删除。新闻来源修订时间相对观测超前 5 分钟只取消缓存可信资格，不拒收真实业务；SQL 成功可清队，不写入错误证明，并精确失效该键旧证明。
- 当前 JSON 正文上限分别为股票 1 MiB、新闻 4 MiB、日历 512 KiB；统一缓冲预算 64 MiB。按“三倍正文上限 + 256 KiB”预留，计入 bytearray 扩容、组装副本和有界工作区；默认预算最多持有 19 个股票响应预留，不能把 64 MiB 称为进程内存上限。
- 文件默认上限 256 MiB、缓冲预留 256 KiB、目录配额 2 GiB、磁盘余量 128 MiB、并发 4。没有增加公告数据表、采集任务、PDF 解析/OCR 或自动文件保留策略。
- 文件准入/目录扫描/锁等待放在工作线程；准入和写入取消须等实际操作结束再回收临时文件。发布提交点中的取消等待真正提交完成并返回文件结果，不遗失已经成功发布的文件引用。
- 提前终止原文明确标记不完整，完整长度/摘要未知；已读量与脱敏样本摘要单独记录。原有错误记录上限和确切 ID 清理规则保持不变。
- 刷新选择只跟随当前结果内的业务身份，不隐藏跨页保留选择，也不会将已消失股票替换成同一位置的新行。
- 本轮不需要数据库结构迁移，不清空共享 Redis，不删除生产业务数据，不修改 RouterProxy 生产者目录。

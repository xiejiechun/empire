# 同花顺前十大持有人

## 入门与日常操作

已实现一个股东研究采集插件，同时取得前十大股东、前十大流通股东、十大债券持有人，来源为股票的股东研究页面，例如 https://basic.10jqka.com.cn/601139/holder.html 。采集管理配好每日北京时间18:00计划，代理优先、不可用允许直连，新任务初始停用，保存启用后开始调度。任务和网站策略保存于MySQL，下一轮生效；已保存选择优先。数据浏览目录搜索对应名称，按股票、报告期及债券名称查询已归档报告，点击报告查看当前和退出名单。

## 来源与生命周期设计

设计于实现前登记，2026-10-13。页面HTML一次包含三栏和多个报告期，每证券仅请求一次，不请求每个栏目或标签一次；独立股票使用公共有界预取。当前601139页面股票两类各五期、燃23转债三期。支持范围是当前股票池各页面实际展示的全部报告期，不承诺上市以来完整历史；未展示的日期不能推断无记录。报告期不是公告日，来源无公告日期，不能作为历史回测信号的可用日。已核实持股详情弹窗agencyHoldInfo.php为某持有人历史/其他持仓的独立研究视图，不将其当当前前十名单。

| 生命周期项 | 契约 |
| --- | --- |
| 初始化 | 固定本轮当前股票池有序集合，从首股票一次读取三个栏目全部可见报告期及退出名单；不生成季度日期，不删除以前已存的报告 |
| 完整单元 | 单股票三栏共同校验，报告标签与内容一一对应；结构、日期、必需字段或身份损坏不发布该证券。仅空名债券按报告隔离，来源缺口与可识别三栏同次入队及同事务保存；明确未提供栏目单独证明，不与缺失/损坏混用 |
| 完成 | 无缺口范围全部按序入队，最终范围证明及本轮全部消息已确认成功才完成；仅来源缺口时有效消息归档后显示“已结束（来源缺口）”，保留首缺口连续断点，不生成完整范围证明 |
| 后续 | 每日重新读取当前窗口，发现新增及窗口内修订；早于窗口的独立修订无法发现，限制公开说明 |
| 中断 | 按连续核验成功的股票索引恢复。单证券来源校验失败继续检查后续证券，有效报告照常入队；连续索引停在首个缺口，整轮不发完整证明。下一轮从缺口补采；不逐股票等待归档，SQL提交后失败保留消息由原归档器重放 |
| Redis丢失 | 从当前股票池首股票重新核验窗口；SQL历史保留，可信摘要缺失回SQL比较；不承诺恢复最后内存断点 |
| 池变化 | 范围摘要改变须重建本轮，不能以旧索引跳过新股票；旧消息保留 |
| 重新初始化 | 下载阶段重建当前窗口计划，保留历史及已入队消息；等待归档阶段先完成原轮次 |
| 版本 | 来源没有修订版本，以请求前观测时间限制迟到响应；不提供严格历史版本重放 |

一个任务统一归档三种持有人报告实体，采用`holder_report`父表与`holder_member`明细，kind区分总股东/流通股东/债券持有人；固定来源ths。没有业务JSON。证券统一unified_code；历史不外键到当前stock。债券页面未提供稳定债券代码，采用页面债券名称的SHA-256作为instrument_key并保留名称，名称变更形成另一个来源身份，不猜测合并。

正式查询：单证券报告期范围父头游标分页（最多100报告）；报告详情按report_key返回最多400成员；全市场日期截面按kind、report_date、unified_code、report_key索引游标；覆盖核查读父头及collection_state证券证明，审计再读受限明细核对规范摘要及身份。父头索引`(kind,unified_code,report_date,report_key)`及`(kind,report_date,unified_code,report_key)`；明细主键`(report_key,member_group,seq)`。查询预算：列表/详情P95≤100ms，最大响应≤1MiB；隔离放大至少10000报告。按6000股票×每年4份定期报告×3类×平均10成员估算，定期报告基准为每年72万明细、五年360万；债券仅部分发行人实际存在。变动公告不是季度报告，须另按实际新增公告数和成员数计入增长，不把该基准称为来源硬上限。五年含索引8GiB为定期报告基准预算，长名称及公告增长须按已测字节/报告和实际新增量校正。

## 迁移与验收计划

显式维护入口新增两表，停桌面、队列零、取得维护锁，核对已有表数量/结构/状态前后不变；新表为空，无历史业务转换或数据删除。DDL不具备整体事务回滚；部分建表失败可重试同一入口，启动只校验不迁移。开发须覆盖缺标签、同数异集、退出/当前分组、多债券、空栏目、单位和精度、迟到旧响应、冷热摘要、提交后重放、下一股票不等待前一归档。实采、容量、正式发布和真实桌面证据在交付时另列，设计不代表验收已完成。

开发实采验证使用 `scripts/verify_ths_holders.py --test-mysql-settings <13348测试连接JSON> --random-count 30 --seed <显式种子> --proxy-only --output build/<新报告>.json`。正常关闭桌面后执行；正式配置仅供只读股票池、站点设置及共享代理连接，写入使用与生产 server_uuid 不同的测试 MySQL 和本轮 UUID 数据库、私有 Redis 前缀。脚本不会修改生产断点、摘要或任务设置，旧 `--apply --rebuild-proofs` 入口已退役。随机至少30只不同股票，另加固定历史反例，禁止失败换样；逐证券核对来源、三栏规范内容、Redis入队、统一归档、SQL证明及正式查询，结束后队列为零并清理本轮私有资源才可能通过。来源空名债券缺口保留有效报告和缺口证明，整体结果仍为FAIL；可归档内容一致、随机30股结果、来源完整性及数据用途分别记录，不能以组织迁移或已知反例冒充完整通过。失败残留只能用 `--cleanup-only --run-state <原报告.ownership.json>` 和新的 `--output` 报告恢复清理；它不采集，也不声称采样通过。所有权记录含私有恢复凭据，只留本地build。验证完成后恢复桌面。

## 单证券来源失败与续采

结构、日期、必需字段或身份校验失败时，保留该证券的错误样本，继续采集后续证券；结构损坏的失败证券三个栏目均不入队。可识别报告的未知数量/比例和来源汇总矛盾保留原值并标记质量限制，不按结构损坏拒绝。仅空名债券按报告隔离，未识别报告不保存正文，其他可识别三栏同事务入队，债券来源缺口持久保存且不写泛化错误样本。

整轮末确认所有有效消息归档后，真实校验失败仍显示失败；仅已隔离来源缺口时显示“已结束（来源缺口）”。两者均保留首缺口连续断点、不生成完整范围证明。已检查进度包含缺口证券，已采集报告数包含缺口后的有效报告，连续进度只包含首缺口前的成功部分，不能相互替代。再次继续从第一个缺口重新核验剩余证券；新尝试重建有界入队序号，保留连续前缀证明。取消会回收预取，本机配置、下载资源、网络或归档故障仍按公共错误流程停止。

## 数据准备的证券范围核验

在数据准备选择证券、日期和用途后执行检查。三栏分别使用所选证券的现行独立归档证明，逐份核对报告身份集合、正文摘要、成员数量和来源质量；不会要求其他证券也已完成整轮采集。全市场检查以当前股票池为范围，未取得有效证明的证券显示具体代码和缺口数，已核验报告仍计数。完整有效的空栏目显示来源未提供，不能从缺少证明推断为空。

每只所选证券的确认须在3天内。SQL确认过期时，可只读核对尚未过期的统一Redis摘要；须与SQL三栏完整规范内容相同且版本不早于SQL才能补充时效，损坏、缺失或不一致回到SQL证据，不为检查刷新状态。旧的准备结果因规则版本变化自动失效。采集连续断点和整轮完成条件保持原契约，有缺口仍不发布完整范围证明。

分析用途保留来源缺值、合计矛盾、排名缺口及缺公告日期的限制；历史信号用途仍受公布日期限制。准备可用表示在声明页面窗口和用途内可用，不代表源站业务前十无遗漏或提供上市以来全历史。

持有人插件显式声明 analysis_quality_limits，统一准备汇总器只在分析用途接受该来源质量限制；正常质量项仍为通过，来源异常保留“有限制”。未声明插件、未知结果、字段损坏、身份或覆盖缺口不能借非阻断证据绕过检查；历史信号用途继续阻断来源质量异常和缺公布日期。声明默认关闭，不改变其他插件的准入规则。

缓存补充时效前还须核对当前SQL栏目摘要与本次已审计内容相同；检查期间发生修订时，不能把新内容的确认时间移给旧内容。此时保留本次SQL的原确认时间，后续重新检查核验新版本，不刷新业务或缓存来通过验收。

2026-10-17新增质量口径：未知数量与明确零不同；仅已知数量之和超出来源汇总才足以证明矛盾。未来报告期的标记按请求观察日核算，历史读取不随时钟自动清除；新一轮重采才可更新。分析用途显示可用（有限制），历史信号仍受无公告可用日限制。两个债券块即使报告期相同也不能借名合并，空名报告继续报缺口。设计见[本轮类型修复设计](evidence/ths-holders-run-errors-design-2026-10-17.md)，处理范围及验证见[运行错误处理记录](evidence/ths-holders-run-errors-2026-10-17.md)。

## 空名债券按报告隔离

消息schema5必需携带gaps数组，最多100条，字段kind、report_date、source_panel、reason仅定位来源缺口，不充当债券身份。归档在collection_state.units证券证明的source_gaps中保存缺口，债券栏目availability=source_gap；可识别报告仍按原业务键写入holder_report/holder_member。准备分别核验三栏，只有债券栏目显示缺口及报告期；股东两栏可以独立通过。不会将缺口当成来源未提供，也不会填名、合并或保存未知债券正文。

日常遇到空名报告不再写泛化“持有人标的身份无效”样本。若本轮仅有这类已隔离来源缺口，检查到末尾且有效消息全部确认归档后，运行结果显示“已结束（来源缺口）”，列出缺口证券、报告数和补采位置；与“已完成”和“失败”分开筛选。连续断点仍停在首个缺口，不发布完整范围证明。下一轮继续重查，来源恢复身份后消除相应证明缺口；历史失败运行不改写。来源页面表结构、日期或其他必需字段损坏仍按错误样本记录；混合发生真实校验失败或归档失败时仍显示失败。债券数据准备继续保留具体缺口，不因运行状态分类变化转为可用。发布前须待归档为0；本次无DDL，既有完整报告契约4不变，准备缓存revision4失效旧结果。设计见[evidence](evidence/ths-holders-identity-partial-design-2026-10-17.md)。

旧版在关闭前可能仍有schema4待归档消息；通过唯一维护入口 scripts/migrate_holder_source_rows.py --pending-only 预检，关闭程序并取得单实例锁后加 --apply，无损转成schema5并增加空gaps。保留业务正文、批次、页码和来源观察版本；原子比较原消息后追加新信封并移除旧信封，失败保留原文。启动不转换，不删除有效业务，转换后由统一归档器正常处理和清队。source_gaps_digest认证SQL中的来源缺口集合。


## 代码定位与模块边界

本业务唯一定位入口为 [股东业务包README](../src/empire/features/holders/README.md)。纯契约、来源解析、采集、归档映射、正式查询/审计和页面分别位于 `features/holders` 对应模块；跨业务共用的HTML节点实现位于 `sources/html.py`，资本运作不依赖股东私有模块。正式任务、数据集、页面、数据库和已保存策略沿用现有身份，组织迁移本身不执行生产DDL或重建证明。

组织迁移验收依 [模块化方案H1～H3](architecture-evolution-plan.md) 逐项核对：精确导入映射后的运行AST、规范输入输出、身份及顺序、恢复回归和范围明确的正式端到端。公开契约的显式类型注解须单列去注解运行AST等价证据，不能借去注解隐藏业务表达式变化。任何解析、请求、采集执行装配、恢复或消息契约变更，仍按实质修改执行随机30股代理准入。

严格工具的 `pipeline_verified` 仅说明已识别记录及来源缺口证明在本轮正式链路中一致；任一所选来源缺口都会使 `acceptance_complete` 为false并令整体FAIL。`sample_30_met` 是随机样本自身的完整代理结果，不能覆盖固定反例失败或等同全市场完成。已知300398.SZ/601515.SH空名债券须固定保留；不能换样、填零、借名或用“文件搬迁”把来源限制改成完整通过。开发测试、实际范围、性能、发布和桌面结果只有完成后才在带日期证据登记。

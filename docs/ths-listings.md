# 同花顺股票上市与发行资料

## 操作与范围

入口为“采集管理 → 任务 → 股票上市与发行资料（同花顺）”；结果在“数据浏览”搜索“上市与发行”。首次逐证券补齐当前沪深北 A 股股票池，日常补新增、缺失及契约不完整记录，每七天回查当前股票池全部证券。“重新初始化”重查当前股票池，不删除已归档记录；退出现有名单的已存记录保留。本接口不能枚举已经退市且从未采集的证券，也不能还原代码变更、重新上市或历史发行修订版本。默认每天北京时间18:00，代理优先并允许受频控约束的直连回退；已保存设置优先，用户可修改。

## 实现前存储设计卡（2026-10-06）

- 粒度：每个统一证券代码一条来源当前首次上市及发行资料；完整归档单位为一只证券。表 `stock_listing`，固定来源 ths，由登记校验；主键 `unified_code`，不依赖当前 stock 的外键，不保存逐轮业务副本。
- 接口：`/fuyao/info/company/v1/issuance/detail?code=<六位代码>&market=<同花顺市场>`，每个必要证券正常一次请求，无分页。已实证 SH=17（600000）、SZ=33（000001、300750）、BJ=151（920009）；映射为显式来源契约，不按数字代码前缀猜市场，不为每只证券常规重复请求基础接口。身份由可信股票池及请求参数绑定，响应自身不返回证券代码。
- 必需字段：证券身份、上市日期、契约版本、规范内容摘要；可选发行字段保持 NULL，零是有效值。历史沿革是当前文本，无公告可用日期，不用于严格历史信号回放。
- 正式查询：按 unified_code 点查详情（1行，正文按需读取）；按 listing_date/unified_code 游标范围浏览（最多200行，不投影正文）；按股票池 LEFT JOIN 摘要/日期/契约做覆盖与补缺规划（最多15000）；数据准备详细核验按200行分页读取正文及摘要，不用行数或最大日期替代集合完整性。
- 索引：主键 unified_code；二级 `(listing_date,unified_code)` 支持全市场日期范围及稳定分页。证券日期点查由主键定位。不为可选数值逐列加索引。
- 容量预算：当前样本正文2051～29366字节；历史正文UTF-8最多64KiB，机构文本最多2048字符，最大规范单元80KiB；当前池最多15000证券，通常一年/五年仍每证券一行（不保留快照），最坏正文约1GiB，索引/页余量后预算1.5GiB。容量实验为15000行、真实样本尺寸与最大正文反例；热列表/详情P95≤50ms、轻量覆盖≤500ms、详细审计≤5秒；实测报告绑定DDL与正式代码。
- 一致性：规范数字采用十进制字符串，SQL DECIMAL 精确往返；同内容零业务DML；新修订更新单证券，collection_state 同事务。来源无版本，以请求开始的绝对观测时间排序，只防迟到请求覆盖，不声称识别源站返回的语义旧版本。摘要可信命中免SQL，成功消息由统一归档器删除。
- 迁移：新表显式维护入口添加；先关闭Empire、取得单实例及SQL维护锁、核实待归档Stream为0，前后核对既有表数量/结构及collection_state摘要；仅新增表，无历史业务转换、删除或配置覆盖。空库 init-db；运行时只检查结构，不建表。

## 字段字典

| 字段 / 来源路径 data.* | SQL类型 | 含义与规则 |
| --- | --- | --- |
| unified_code / 请求身份 | VARCHAR(9) ASCII | 六位代码.SH/SZ/BJ，主键 |
| listing_date | DATE NOT NULL | 来源首次上市日，1900起至观察日，不用成立日替代 |
| establish_date | DATE NULL | 来源成立日；可能晚于上市日，保留并提示冲突，不据此推算上市日 |
| issuance_num | DECIMAL(24,4) NULL | 股，非负；保留来源精度，不换成万股存储 |
| issuance_price / first_day_open_price | DECIMAL(24,4) NULL | 元，非负 |
| estimated_raised / actual_raised | DECIMAL(24,4) NULL | 元，非负；不要求预计募资等于实际募资 |
| issuance_pe | DECIMAL(20,4) NULL | 倍，负值保留来源亏损语义 |
| winning_rate | DECIMAL(20,10) NULL | 百分数原值，0～100，不除100入库 |
| lead_underwriter / sponsor | VARCHAR(2048) NULL | 机构字符串，保留并列机构，不猜拆分身份 |
| history | MEDIUMTEXT NULL | 历史沿革，UTF-8 ≤65536字节，无历史可用时间 |
| content_hash | CHAR(64) ASCII NOT NULL | 以上业务规范内容SHA-256，不含请求页、批次、观测时间 |
| contract_version | SMALLINT UNSIGNED NOT NULL | 字段与完整性契约版本2；旧1需完整重查建立新证明 |
| version_observed_at | DATETIME(6) NOT NULL | 当前存储修订观察时间，北京时间；内容相同不刷新此业务列 |

所有十二个发行字段必须在响应中出现；可选值为NULL、空字符串或`--`表示来源未知，缺字段、未知字段、异常类型、超精度/上限、无效日期或接口失败均报错，不填零、不截断、不推进断点。上市日期必需，明确无详情响应也不能伪装成功记录。

## 生命周期与恢复

| 问题 | 契约 |
| --- | --- |
| 初始化起止 | 固定本轮当前股票池键集合；按统一代码顺序从未完成证券开始至集合终点 |
| 完整性 | 每只证券十二字段完整校验；池集合去重前验证，不接受同数异集；恢复池变化报错，明确重新初始化 |
| 完成 | 本轮所有必要证券成功入队，最终范围消息入队，全部消息归档/确认且无本轮残留 |
| 后续 | SQL轻量完整性检查补缺；七天全池复核，发现独立发行资料及正文修订；非全池轮次不承诺发现旧记录修订 |
| 中断 | 已入队断点原子推进；失败证券留在原位置。下一证券立即下载，整轮结束才等归档；SQL后确认失败原消息重放 |
| Redis丢失 | 从SQL已归档行、契约和完整性重新规划缺口及七天回查；可能重查，不保证内存断点精确恢复 |
| 配置与fresh | 网络下轮生效，已保存计划不覆盖；fresh不丢弃已入队消息，先复用正式归档流程 |
| 日期用途 | 上市日用于交易开始日；当期发行资料与正文无历史公布日，不作严格历史信号版本 |
| 已采范围 | 动态进度放在有日期的验收证据，支持范围不等于已采完成 |

## 验证与交付

专项测试覆盖来源→规范化→Redis→统一归档→正式查询、旧记录补齐、相同内容零业务DML、冷热摘要、迟到旧消息、提交后重放、事务失败留队、同数异集、逐证券不等待归档、断点与Redis丢失补缺、单响应及字段边界。分页来源/尾页、历史版本号和文件签名不适用：接口一次完整详情且无上述契约。容量与真实小样本分别记证据，完整股票池及退市历史未经核验不得标完成。

真实反例000032来源上市日1993-10-28、成立日1993-12-04。两个字段独立保留；成立日属于附加资料，该冲突显示为质量警告，不阻止必需上市日用于交易起点。已有契约1表通过 `scripts/create_listing_schema.py --upgrade-date-contract --apply` 显式调整日期与版本约束，要求正常关闭程序、待归档清零，核对原内容不变；失效上市摘要并重置该项目断点，新契约全池复核，不删除旧记录。启动不自动维护。

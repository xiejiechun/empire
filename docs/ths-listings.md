# 同花顺股票上市与发行资料

## 操作与范围

发行数字包括零值和很小的中签率，正式SQL解码保持十进制定点精度；数据库驱动的0E-10等表示形式不代表来源无效，不修改已存值。相同资料回源确认仍不写业务表，处理成功清理对应待归档消息。

入口为“采集管理 → 任务 → 股票上市与发行资料（同花顺）”；结果在“数据浏览”搜索“上市与发行”。首次逐证券补齐当前沪深北 A 股股票池，日常补新增、缺失及契约不完整记录，每七天回查当前股票池全部证券。“重新初始化”重查当前股票池，不删除已归档记录；退出现有名单的已存记录保留。本接口不能枚举已经退市且从未采集的证券，也不能还原代码变更、重新上市或历史发行修订版本。默认每天北京时间18:00，代理优先并允许受频控约束的直连回退；已保存设置优先，用户可修改。

## 实现前存储设计卡（2026-10-06）

- 粒度：每个统一证券代码一条来源当前首次上市及发行资料；完整归档单位为一只证券。表 `stock_listing`，固定来源 ths，由登记校验；主键 `unified_code`，不依赖当前 stock 的外键，不保存逐轮业务副本。
- 接口：`/fuyao/info/company/v1/issuance/detail?code=<六位代码>&market=<同花顺市场>`，每个必要证券正常一次请求，无分页。已实证 SH=17（600000）、SZ=33（000001、300750）、BJ=151（920009）；映射为显式来源契约，不按数字代码前缀猜市场，不为每只证券常规重复请求基础接口。身份由可信股票池及请求参数绑定，响应自身不返回证券代码。
- 必需字段：证券身份、上市日期、契约版本、规范内容摘要；可选发行字段保持 NULL，零是有效值。历史沿革是当前文本，无公告可用日期，不用于严格历史信号回放。
- 正式查询：按 unified_code 点查详情（1行，正文按需读取）；按 listing_date/unified_code 游标范围浏览（最多200行，不投影正文）；按股票池 LEFT JOIN 摘要/日期/契约做覆盖与补缺规划（最多15000）；数据准备详细核验按200行分页读取正文及摘要，不用行数或最大日期替代集合完整性。
- 索引：主键 unified_code；二级 `(listing_date,unified_code)` 支持全市场日期范围及稳定分页。证券日期点查由主键定位。不为可选数值逐列加索引。
- 容量预算（以长正文修复后的现行协议为准）：历史正文UTF-8最多256KiB，机构文本最多2048字符；当前池最多15000证券，通常一年/五年仍每证券一行（不保留快照）。容量实验固定15000行：普通正文2049字节、5%为105078字节并保留单条262144字节边界；全部满额约3.75GiB仅为理论上界，不冒充实采分布。正式列表/详情/范围P95≤100ms（读取统一状态呈现来源缺值，原50ms取舍见容量证据）、轻量覆盖≤500ms、详细审计≤5秒、导入≤60秒、该分布表索引≤1.5GiB、15000状态单元≤8MiB；报告绑定DDL与正式代码。
- 一致性：规范数字采用十进制字符串，SQL DECIMAL 精确往返；同内容零业务DML；新修订更新单证券，collection_state 同事务。来源无版本，以请求开始的绝对观测时间排序，只防迟到请求覆盖，不声称识别源站返回的语义旧版本。摘要可信命中免SQL，成功消息由统一归档器删除。
- 迁移：新表显式维护入口添加；先关闭Empire、取得单实例及SQL维护锁、核实待归档Stream为0，前后核对既有表数量/结构及collection_state摘要；仅新增表，无历史业务转换、删除或配置覆盖。空库 init-db；运行时只检查结构，不建表。

## 生命周期与恢复

### 成功响应缺上市日期的处理设计（2026-10-08）

001381发行详情返回status_code=0、完整十二字段，但listing_date为NULL。它证明来源当前缺必需字段，不能证明未上市、无发行或退市。先校验全部字段、数字精度、可选日期及正文边界；只有上市日明确为空（NULL、空字符串、--），其余结构和值合法时，发布独立incomplete状态，不新增缺上市日期的stock_listing行，不填造日期，不删除旧行。

粒度及正式路径仍为每证券当前资料；collection_state原units元数据增加availability=incomplete、source_status_code=0、missing_fields=[listing_date]，availability_contract仍为1。这仅是有界缺字段证明，不能把原始响应或发行核心值整份放入状态JSON。最多15000单元，每单元仅一个缺字段名称，容量增加不足1MiB；原主键、日期索引、点查/游标列表和轻量补缺查询不变，不需要DDL或历史业务转换。完整记录和明确10001暂无证明仍符合现行契约，已成立的摘要无需全局失效；缺日证券通过新状态提交重建其覆盖证明，源版本防覆盖不变。

正式查询分别呈现“来源暂无”和“来源缺上市日期”，旧行仅作历史参考；缺日证券日常每轮补查，来源补齐后通过同一入队/归档路径恢复完整资料，清除缺字段状态。采集可继续其他证券，整轮完成仅表示有效资料或明确来源状态都已归档；数据准备仍拒绝缺必需日期的证券。未知协议、缺字段、非法数值、未来/无效日期、超限正文继续失败且不推进断点。验收须覆盖来源到查询、无空业务行、保留旧行、冷热摘要、迟到响应、失败留队/重放、来源恢复和下一证券续采。实际范围及清理记录见[本次处理](evidence/ths-listings-date-repair-2026-10-08.md)。

### 明确暂无详情的处理设计（2026-10-06）

已核实301139（元道退）返回 `status_code=10001 / status_msg="result empty" / data={}`，网页亦无发行资料。仅精确匹配该响应可作为“来源暂无资料”证明，不能推断退市，也不把网络失败、未知状态码或残缺成功响应归为暂无。

粒度仍为每证券首次上市资料：无资料不新增 `stock_listing` 空行、不填零、不删除已有资料。暂无证明作为现有 `collection_state.payload.units` 中该证券的覆盖元数据保存，字段为 `availability=unavailable`、`source_status_code=10001`、`availability_contract=1`，沿用已有观察版本、摘要和契约；上限仍15000证券，每单元只保存当前状态，不保留响应正文或历史状态。核心上市字段仍仅在正式业务表中存储；状态是来源查询结果证明，不是另一份上市业务记录。

来源状态消息与断点原子入队，经统一归档后继续下一证券；整轮完成表示每证券已取得有效资料或精确暂无证明，不能冒充数据准备完整。暂无每天复查；已有正常资料每七天回查。已有资料遇暂无时保留为历史参考，正式详情与浏览提示当前来源暂无；恢复正常后清除暂无标记，旧响应不覆盖新状态。正式查询一次读取该项目有界状态，不扫描历史正文；主键、业务列、索引和SQL表结构不变，无DDL迁移。摘要使用新的 `ths_listings_v3` 命名空间重建；不影响已有有效资料，断点从失败证券继续。容量预算沿用15000行及现有15000单元状态上限，重新测量正式查询路径。

验收覆盖精确空响应、未知协议仍失败、来源→Redis→SQL状态→正式查询、继续下一证券、重复无业务DML、保留旧资料、空与有效响应的迟到防覆盖、来源恢复、SQL失败留队及成功清队。错误28a1bf510d3e4beda160a930c4b8fd23仅在修复、回归和真实验证通过后按ID清理，其他错误保留。

容量命令 `scripts/measure_listings.py --test-mysql-settings <13348设置JSON> --output <build内新报告>` 保留上述合成协议，复用同一归属、取消及清理保护。仅额外精确允许四条固定查询的EXPLAIN和本表ANALYZE，仍先核实际连接身份。两工具正常关闭连接、核实并清理自己拥有的SQL/Redis/锁后才落盘最终结果；失败保留报告及归属记录，恢复使用各自 `--cleanup-only --run-state <原ownership.json> --test-mysql-settings ... --output <新报告>`，不猜测删除未知资源，不修改日常任务设置。报告和归属文件在本地build，后者含秘密不得提交。

## 长历史沿革修复设计（2026-10-06）

项目ths-listings，错误91fb02cc8a96400eb4a5cf5a20090402：603107有效history为105078个UTF-8字节，旧64KiB限制过小。业务粒度、字段、唯一键与正式读写路径不变；MEDIUMTEXT及解析上限同步扩至256KiB，不截断、不填空、不把长正文标为暂无。共享HTTP正文预算仍执行，列表和补缺不读取history，详情1行、详细审计200行。当前样本加256KiB边界容量实验验证查询预算；15000行极端全部满额约3.75GiB仅为理论上界，容量实验按5%实测长正文与单条上限正文放大，不能冒充全市场正文分布。

显式维护入口scripts/create_listing_schema.py --upgrade-history-limit --apply：正常关闭程序、共享待归档队列归零、取得数据库维护锁，仅调整ck_listing_history；对既有完整行数量和内容摘要逐项等价核对。DDL隐式提交，失败后重新检查约束，不声称事务回滚。来源语义与业务合同2不变：原已通过的短正文仍有效，失败长正文从保留断点重试；不改既有业务值，不为扩容刷新SQL行或全池证明，不重置断点。摘要业务内容不变，不把缓存视为新增长正文的成功证明。反例覆盖UTF-8恰好上限、超过1字节、类型错误、NUL、长正文源到正式查询与重复/旧响应/确认后清队。开发验收、603107及后续证券实采、发布及精确错误清理分别记录。

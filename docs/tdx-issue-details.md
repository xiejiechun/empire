# 增发详情采集

现行契约为 additional_issues.unit@3，正常、暂无、未采/真正异常的区分及唯一维护入口见[增发暂无详情规则](tdx-issue-availability.md)。下方有日期的旧错误/发布证据仅为历史记录；此前 -1005 失败冷却规则已退役。

增发任务同时采集列表与每个方案的详细资料；数据浏览选择增发记录即可查看发行对象、定价方式、募资额、中签、承销及上市首日信息。缺失详情显示“尚未补齐”，详情接口明确返回的空字段显示“来源未提供”。详情属于增发项目，不另建采集任务或业务表。

## 生命周期与来源契约

| 项目 | 实现约定 |
| --- | --- |
| 用途与范围 | 通达信增发列表返回的全部历史方案及证券别名，用于估值与日频分析。详情不提供完整预案／取消历史，中签公告日不是增发预案公告日，不用作公告前选股信号。 |
| 初始化边界 | 本轮一次读取完整列表（容量 10000，达到上限即拒绝截断），按证券顺序请求其中每个方案编号的详情，校验后入队。 |
| 完整性单位 | 单证券全部方案，详情一条有效资料或明确暂无状态；正常明细须证券关联及共有字段一致。有效空列表无详情请求；未采、损坏或真正异常不能作为暂无。 |
| 初始化完成 | 所有证券单元的列表及详情校验、入队，并经统一归档确认；最终摘要必须与真实 SQL 内容匹配。 |
| 后续起止、补缺与修订 | 普通增量每轮只读一次列表；新增、列表业务字段变化、详情缺失或损坏请求详情，另对日期在启动日向前 90 天内的方案按北京时间每天首次完整轮次回查。有效且未变化的其余详情复用 SQL；相同内容免业务写入。未知日期或窗口外的详情独立修订通过“从头重新采集”回查。 |
| 请求次数 | 列表正常一次；补采及当日近期回查的来源编号请求一次详情，成功响应跨证券别名本轮复用。同日后续完整无变化轮次详情零请求。共享有界网络重试不变，业务校验失败不重复请求碰运气。 |
| 中断恢复 | 连续成功单元原子推进断点；失败处保留，后续有效证券独立入队但不推进连续范围。连续五个网络或结构异常停止；明确 -1005 不计入停止阈值。有缺口不发布最终证明。恢复时完整列表有变化，自动建立新批次重建范围证明，旧数据及队列保留，未变化详情仍可复用 SQL；强制回查模式保留，近期范围重新计算。首个有效单元与新断点原子发布。不逐批等待归档。 |
| 状态丢失 | Redis 丢失后重读列表，从 SQL 已归档业务重建增量判断，完整未变详情不重新下载；未归档详情需补采。不承诺恢复内存位置。 |
| 旧响应 | 整轮列表请求开始 UTC 作为观察顺序，防止旧轮结果覆盖新轮；不是源端修订版本，不承诺识别源端历史回退。 |
| 操作与配置 | 继续采集沿用已入队断点；同一强制轮次中已核实且未变的详情，须当前 SQL 内容与可信归档摘要一致、版本不早于该轮核实起点才复用。明确“从头重新采集”建立新轮次，重新强制核实并绕过本方案诊断冷却一次，不绕过网站频控。强制标记/核实起点随断点保存，任务间隔及代理策略保持原设置。 |
| 进度与证据 | 下载列表不表示完成；按已发布证券和已归档记录报告，缺详情的旧 SQL 记录不得通过完整性验收。开发测试与实采范围分开记录。 |

## 接口和字段

现行规则保留列表方案并将明确空详情/-1005 保存为“来源暂无可用详情”状态，保留接口返回码；不当成无增发方案。六小时失败冷却已退役，新的正常轮次重新核实暂无方案，同编号别名本轮复用。旧有效明细保留为历史参考，真正错误仍不推进断点。详见[现行暂无规则](tdx-issue-availability.md)。

强制轮次继续采集的一次有界 SQL 查询后，只读核对已有统一指纹。摘要缺失、损坏、过期、版本早于本轮核实起点或内容不匹配时，不能据 SQL 已有详情跳过强制核实。新轮次核实起点取第一次列表请求开始时刻，避免原 started_at 晚于请求导致已核实内容反复下载。旧游标没有该可选字段时使用原启动时刻作保守下界。无业务 schema、身份或证明结构变更，不需要迁移；Redis 丢失不保证恢复原强制轮次或冷却位置。

来源列表正常新增导致自动换批次时，延续原强制轮次的核实起点，未变化方案可继续复用已核实详情；新增或业务字段变化的方案仍需下载。新的显式全量回查才重置起点，不能把普通范围更新变成重复全历史详情请求。

页面 `tdxsj_xgzx_zfmx.html` 使用 `CWServ.tdxsj_xgzx_zfmx`，POST `Params=[rec_id]`。增量判断使用一次有界 SQL 查询，不按方案逐条访问数据库，不新增详情永久缓存或运行状态表。全部网络请求沿用共享下载器、网站频控、资源预算、代理和重试。详情按方案编号关联，代码别名取自已核验列表，禁止用当前股票池过滤旧代码。

既有列表字段保存增发代码、股票代码／简称、发行方式、价格、发行／上市／登记日期及发行前后股本和总发行数量。新增 `payload.detail` 保存增发简称、网上配售日期、网上／网下数量、实际募资额、中签公告日期及中签率、发行后 EPS／每股净资产、主承销商、承销方式、发行对象、定价方式、上市首日开收盘价格及涨幅。来源万股／万元乘 10000；百分数保持百分数。详情 `ClosePrice` 是上市首日收盘价，不同于列表的实时最新价，必须保存。来源中签日期的空字符串转未知、零点时间转日期，不伪造公告时间。

## 显式升级

关闭 Empire，确认待归档队列为空，运行 `python scripts/migrate_issue_availability.py`。维护不修改既有业务行或做DDL；升级状态至schema3，重建受影响证明及断点，保留SQL观察水位和规范内容未变的证券摘要。启动只校验，不自动迁移。未知缺字段不直接转暂无，须实际采集确认。

相关说明：[增发送配](tdx-capital-actions.md)、[开发指南](collector-development-guide.md)。

# P2-09 HTTP 与采集管理正式路径验收

日期：2026-09-27。

## HTTP 唯一路径

所有本机直连、代理、代理失败回退、重试和重定向请求都通过 `routed_request`。`HttpService` 不再在“没有代理池”时切换到另一套 Semaphore 和旧 Redis 许可脚本；单元测试只替换 HTTP transport 与 Redis 执行结果，仍运行生产的路由、并发、出口和频控算法。

未启用代理时，routing 使用本机出口并保证同一站点最多一个本机请求在途。任务要求代理但代理池暂未提供时，允许回退的任务才使用本机出口并计入回退次数；禁止回退的任务明确失败，不会偷跑直连。生产插件依赖仍要求 `proxy.pool`，因此正常运行不会依靠缺失依赖维持服务。

每次尝试和每次重定向重新取得站点、全站与出口许可。429 继续写入站点组共同冷却；直连、所有代理及后续重试共享该冷却。此次收敛不改变自动/固定扩展、每出口间隔、全站保护、下载窗口或字节预算。

## 采集管理唯一查询和保存契约

采集控制器只提供有界 `workspace` 读取任务、站点、历史和概览，不再保留一次复制全部任务、全部历史和站点的 `snapshot`。桌面和集成测试都按相同分页契约读取；任务精确导航也属于该查询契约。

网站设置只接受完整策略字典并调用 `configure_site`。旧整数参数和 `configure_interval` 已删除，调用方必须明确提交本机间隔、代理间隔、全站间隔、并发安全阀、扩展方式及每秒保护；后端会与当前策略合并并统一校验。历史配置转换仍只属于显式维护入口，不重新引入运行时双格式。

## 自动验收

回归覆盖：

1. 直连多请求共享相同站点许可与并发限制。
2. 直连和代理使用同一 routing 函数，重定向重新申请许可。
3. 429 同时阻断其他直连及代理出口，等待取消后资源归零。
4. 仅代理且代理池不可用时明确失败，不发送本机请求。
5. 代理优先回退仍串行使用本机出口并记录回退次数。
6. 连接失败换代理、跨来源凭据清理、响应字节限制、并行预取和全局窗口继续通过同一路径。
7. 旧 `snapshot`、`configure_interval` 与标量网站保存入口均不可调用。

真实 Redis 集成测试使用随机测试命名空间，HTTP 响应使用 MockTransport；不会请求公开源站、使用 RouterProxy 生产出口或修改业务数据。

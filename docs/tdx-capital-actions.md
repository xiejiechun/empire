# 通达信增发送配

## 日常操作与范围

采集管理中分别运行“分红送转（通达信）”“增发（通达信）”“配股（通达信）”。三个独立插件共享通达信频控、下载资源、代理、入队、归档与错误记录；默认手动执行。数据浏览目录提供三个独立入口，数据准备分别验收。

分红送转以本轮开始时 SQL 当前股票目录的沪深北证券作为声明股票池，按报告期批量取列表并组装每证券完整历史；不把 688110 写成固定对象，不承诺已退市且不在目录中的全部股票。增发和配股按来源全部栏目记录取完整集合，包括返回的历史代码。来源支持范围以实际日期统计为准，增发来源存在未提供发行日期/发行价的老记录，配股存在缺少上市日/缴款结束日的老记录，均保留空值、明示限制，不能据此编造可交易日期。两个栏目没有公告时间和取消历史，不作为公告前选股信号，也不冒充完整预案/取消方案库。

分红送转每十股派息、送股、转增除以 10；派息按已确认含税口径，除权除息日为项目记账日，不保证实际现金到账。保留来源每股收益、净资产、公积金和未分配利润。最新股价是行情数据，不混入增发/配股事件摘要。没有独立版本号，以本次请求开始的绝对时间排序，迟到旧请求不覆盖较新观测；不能识别来源随后发布的无版本历史倒退。

增发同一 rec_id 可返回新旧证券代码：保留各代码关联，以 rec_id 与市场代码共同标识，不任选一条丢弃。配股相同证券同登记日可能有多种认购代码或缴款期，按市场、代码、登记日、认购代码和缴款起日组成键分别保存；无来源 ID 时，这些身份字段变化无法断言为同一方案修订。

分红现行 dividends.unit@3 按市场、代码、报告期、预案公告日以及每股派息、送股、转增标识。来源会并列返回同日期的不同派息方案（如中国国贸每十股 8 元和 5 元），分别保留，不擅自求和或选择其一。相同金额方案内的进度、登记/除息日期、财务辅助字段修订更新原记录；身份字段含金额改变时，因来源没有稳定方案 ID，无法判断是修订还是另一方案，保留两条，若旧条已从来源移除则集合验收失败，不能宣称已裁定唯一现金流。

旧 @1/@2 数据须关闭 Empire、确认队列为空后执行 scripts/migrate_dividend_identity.py。维护只重算业务键与摘要，保留所有业务字段和观测时间，保留 SQL 旧版防覆盖水位；失效分红摘要、整轮证明及断点，从股票池首项重新核验。运行时不转换旧键，也不接受旧 schema 消息。具体证据见[重复业务键修复记录](tdx-dividends-fix-2026-09-30.md)。

正常响应只请求一次：分红每个计划报告期一次，单期容量10000；缺少历史发现证明的证券另读一次完整历史目录；增发、配股列表每栏目一次，增发补采新增、变化、缺失或损坏的 rec_id 及当日近期回查范围，其余未变详情复用 SQL。从头重新采集强制全读，列表请求容量为 10000，返回达到容量即拒绝截断。排除实时股价，保留业务内容和证券关联；重复业务键仍拒绝，不用去重凑齐。报告期下载失败或历史目录键未覆盖时，任何组装中的证券都不入队，断点不推进；取消回收预取及缓冲。源端别名只解释总数口径，入库不丢弃关联。完整响应超出共享正文上限或安全记录数即失败，不退回不稳定的偏移分页。每证券单元超出入队上限失败，不截断。

网络异常沿用共享下载器的有界重试；来源完整列表校验失败立即停止，不能使用部分列表。增发详情失败时保留诊断，继续处理其他有效证券；连续五个网络或结构异常停止本轮。HTTP 200 内明确的源站 -1005（数据库执行失败）不计入此阈值，不能据几个损坏旧方案判断全站不可用。失败证券不入队，连续断点停在最早失败处，后续有效单元由统一归档器处理；有缺口不发布最终证明、不显示完成。继续采集从失败处补缺，为重建顺序证明会重新核验其后证券，增发可复用已归档详情。取消、入队、隔离及数据库规划错误仍立即停止。同一增发编号的代码别名本轮复用明确业务失败，不重复请求；下一轮重新尝试，失败不冒充空详情。来源详情的完整性限于该股票接口返回集合，不能证明网站本身无遗漏。

### 近期详情回查与三个采集器差异

增发除新增、变化、缺失或损坏详情外，发行日、公开/定向发行日、上市日或登记日在本轮北京时间启动日向前 90 天内的方案，每个成功完成的北京时间日首次轮次回查一次详情。同日随后完整轮次复用；回查日期与模式随原有有界断点保存，中断续跑保留本轮规则。仍有缺口的轮次不会把尚未核验范围当成已完成，恢复可能重查失败位置后的近期方案。Redis 丢失允许重新回查一次近期范围。未知日期或早于窗口的独立详情修订仍由“重新采集”发现；来源列表不提供预案完成状态，不能凭缺上市日推断所有老方案仍活跃。

分红每轮按报告期完整列表核验已知历史修订。来源只支持单个报告期，未发现多日期或范围参数；目录仅最近20季度，不能代替历史范围。以1980年起季度、SQL已有日期及历史发现日期建立计划（最多1000期），并查询目录最新季度后的每日日期至北京时间当天。SQL中保留每证券history_discovered_at；没有有效证明的新证券先发现历史日期和方案键，明确重新采集会全池重新发现。普通轮次不能保证发现新引入的更早未知非季度日期，遇到这种范围修订须重新采集。首次无任何历史证明的全新库仍需逐股发现，不能承诺首次就省掉这些请求。配股每轮一次完整列表，无独立详情下载，当前不存在详情缓存失效问题；列表失败必须整批停止，不能拆解损坏响应继续。三者沿用共享下载、入队、归档及每项目一行状态，不新增业务表或永久下载缓存。增发与配股本次请求参数及业务契约保持；分红升级到@3，须显式无损维护。金额键分量统一NULL/零身份，payload保留实际来源值；原完整历史证明核对匹配时保留日期发现标记，不复用旧整轮完成证明。

2026-09-30 的取消默认双读改动仅减少冗余请求，不改变业务身份、规范字段、来源范围、SQL 集合摘要和断点格式；既有有效证明与断点仍适用，无须迁移或从头重采。恢复增发/配股时仍会读取一次当前完整集合，与已入队范围摘要比较，变化则拒绝混用。此前双读是开发实现过度推断，非公共准入要求，见[开发指南澄清](collector-development-guide.md#请求次数与完整性证据2026-09-30-澄清)。

现行增发为 additional_issues.unit@3，暂无可用详情属于来源状态，未采或真正异常不能冒充暂无。显式升级入口 scripts/migrate_issue_availability.py，旧维护入口退役。详细字段及现行生命周期见[暂无详情规则](tdx-issue-availability.md)，有日期的@2报告仅作历史证据。

本次单次读取的开发测试、实采请求次数、发布及文档追溯见[单次读取验收](capital-single-read-review.md)。

每个数据集在 MySQL 独立业务表保存规范字段，来源业务内容以 JSON 保存，不保存成功原文；统一 collection_state 每项目一行。摘要按证券完整单元及最终范围证明维护，复用统一过期与容量限制；相同业务零 DML，成功含摘要命中和旧响应确认均由统一归档器清队。来源消失的历史记录保留，若因此与最新声明集合不一致，数据准备明确失败，不能自动删历史来通过验收。

## 结构维护与验证

2026-10-01 续采规划修订：来源完整集合摘要或分红股票池变化是正常业务更新，不再要求用户手动初始化。通过来源完整性校验后建立新 batch_id，重置本轮位置、计数和有序集合摘要；新范围断点与首个有效业务单元同次 Redis 提交，scope_changed 标记说明旧范围证明不能代表正在建立的新范围。查询准备检查只读该标记作为否定证据，不授权删除队列；完成新范围并确认归档后才解除。Redis 不可用时仍能读取 SQL，但不能承诺恢复丢失的内存规划。未验证响应或新范围失败不能提前改断点，不清旧消息、摘要或 SQL 历史；旧消息使用原有版本保护正常归档。增发未变化的详情继续 SQL 复用，既有强制全量回查保持；新范围近期回查重新计算。无业务结构变化，不需要维护脚本。awaiting_archive 轮次只确认原批次，下一轮再核验新来源。

dividend_plan、additional_issue、rights_issue 为三张独立业务表。旧版完整业务库通过 scripts/migrate_business_schema.py 显式升级，必须关闭 Empire、待归档队列为零，核实全部业务键及内容摘要后原子切换；原表保留为恢复副本。新空库使用 init-db，正式定义以 sql/schema.sql 为准，启动不迁移。

开发测试与实际采集证据分别记录。部分实采不等于全部股票历史已完成；测试使用独立 namespace/source，不清空共享 Redis。归档成功才可查询，最终范围证明缺失时数据准备不通过。

数据准备先读取正式 SQL 全集合，再只读核对未过期的统一 Redis 摘要。只有内容匹配且版本不早于 SQL 的摘要可补充最近三日时效；缓存不可用回退 SQL，缓存不能掩盖缺行或字段损坏。

## 数据浏览

分红送转、增发与配股以逐方案卡展示关键生效日、状态、字段和来源限制，可按证券、日期范围、状态筛选并展开精确明细。事件定位使用记录键，平行方案分别呈现，不自行裁定唯一方案。来源每股/每10股口径明确，未知不作零；复权事件可带证券及记录键回到相应方案。

分红目录的T002为可选报告期，maxrq为网页默认选中期，可能落后于最新可选季度。校验目录唯一、默认期一致且属于目录，保留所有可选期及已有历史；每日补查从默认期之后开始，避免目录提前列出新季度而遗漏期间非季末方案。正常目录只请求一次。

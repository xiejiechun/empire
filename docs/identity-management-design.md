# 平台身份管理实施设计

2026-10-24，范围为身份配置、只读管理与运行诊断，不新增行情采集或市场业务表。

## 操作与生命周期

采集管理 → 身份管理，平台选择器只列已接入平台，首个平台为同花顺远航版。按平台隔离节点档案和运行记录；设备 code 为固定绑定键，离线保留。页面可查看状态、最近已结束的申请/登录轮次、时间、阶段、错误码及参数详情，并通过现有插件命令启停自动身份服务。读取页面不注册、不登录、不启动采集。

一轮是一次实际节点申请或登录；空闲的目录检查不产生成功记录，不覆盖上轮错误。正在执行与上一已结束轮次分别显示；历史每平台最近100条，仅存Redis。进程意外退出可能只有running，不能判作成功；界面结合当前服务活动标记为中断/未确认。Redis或电脑重启会丢失运行历史，显示无记录；SQL中的申请状态及参数仍保留。无自动重试拒绝/未知申请，无批量重置或身份轮换。

## 配置粒度与字典

2026-11-09修订：申请异常仅按节点隔离，其他在线健康的unrequested继续串行申请。异常后重读SQL并确认已有持久意图或成功绑定，才继续其他节点；配置/解密不可读或申请前置诊断记录失败时停止本轮。health.blocked_nodes保留节点列表，status=degraded不代表全局申请停止；automatic_application_paused只表示全局故障。页面明确提示待核查数量和其他节点继续申请，未知结果不自动重置。设计与验证见[本次记录](evidence/yuanhang-node-application-isolation-2026-11-09.md)。

沿用app_setting主键(namespace, kind=yuanhang, setting_key=guest-profiles)。一行有界身份配置整体事务读写，最多1000节点、4MiB；不用于行情查询。schema2每节点保留profile_id、registration、protected、rejection_code，增加creation快照。正式读取仅schema2，schema1必须显式维护迁移。

creation含recipe_version（已支持配方编号）、provenance（recorded或legacy-reconstructed）、recorded_at（快照记录UTC时刻）、requested_at（首次申请意图时刻，旧档案未知为null）、client_version（建档时协议版本）、device_mac（逻辑标识）、imei、endpoint、method、params（仅imei/qsid/reqtype三字段）。快照在网络申请前存储；首次requested_at仅设置一次。MAC/IMEI固定延用，旧快照不可由新默认参数覆盖；目前登录使用固定逻辑标识和当前已支持协议。密码/账号继续DPAPI保护，会话、公钥和令牌不持久化；管理查询不输出凭据或密文。

登录协议版本与创建参数分开。旧请求endpoint/params仅作为原始配方证据，不允许任意配置URL变成网络入口。未经适配支持的配方显式拒绝。升级先适配、测试，明确哪些身份字段继续使用；不通过新建身份规避协议不兼容。

## 查询、容量与完整性

查询平台清单；选定平台读取一份有界配置，页面按code排序并分页50条，详情按code投影。按现有主键定位一行，不新增索引、DDL或市场数据JSON。账号不进入DTO；详情仅显示白名单参数。运行记录复用RecordsPlugin的有界原子追加和按ID替换，独立identity-runs列表/修订键，最近100条上限；读失败明确提示，不把不可读取当没有失败。

相同ensure/bind不写SQL。原profile_id、code集合、DPAPI密文、申请状态和逻辑标识必须迁移前后严格相等。旧档案按旧实现可推导MAC/IMEI及已知常量，明确legacy-reconstructed，不能声称保存了原始报文或真实申请时间。迁移只更新配置行，事务失败回滚；再次执行无变化。先正常停止Empire，持应用锁执行；不启动源请求或改业务表，不清理共享Redis。

## 验收

专项覆盖平台隔离、运行中保留上轮、空闲不覆盖错误、取消/异常无成功、凭据不泄露、固定参数不随新默认变化、迁移集合及密文保留/幂等、UI按需创建/取消/选择保留。隔离SQL与Redis核对配置持久化及有界记录。生产迁移核对原身份保持，使用现有账号正常登录验证，无需创建新账号；非股票粒度，30股采集门槛不适用本次身份管理。正式发布完整门禁、配置保留及真实桌面另验，不能当作全市场初始化完成。

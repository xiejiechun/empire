# 构建与发布门禁

2026-11-02：本文描述当前源码的检查入口和本机启动器构建。原 Qt 打包、目录切换、搬移验收及恢复命令保留在[历史存档](history/qt-release-gate-before-2026-11-02.md)，不作为当前可执行要求。客户端退役边界见[退役记录](legacy-client-retirement.md)，使用及限制见[当前桌面](../desktop/README.md)。

## 当前产物与完成边界

现行客户端为 React + Ant Design + Electron，入口产物是 `dist/EmpireDesktop/Empire.exe`，依赖仓库、Python 环境和 desktop/node_modules，不能独立搬移。门禁成功报告使用 kind=local-development-launcher、portable=false；actual_desktop 明确标为未由门禁验证。

本机构建、真实桌面、来源实采及独立分发是不同证据。功能交付继续完成适用静态检查、专项/集成/公共安全回归、配置保留及真实桌面检查；不能因旧步骤退役而跳过现行检查，也不能把本机启动器通过宣称为独立分发、安装器、代码签名或恢复包验收。纯开发文档修改只运行文档契约及相关回归，不需要停机或构建。

## 入口与测试范围

先完成实现和说明、检查共享环境冲突，正常关闭 Empire 并等待采集、归档与连接退出。该正常关闭已获项目授权；不得强杀服务、删除锁或绕过单实例保护。

根目录 `verify-release.ps1` 与 `build.ps1` 都进入 `scripts/release.py`。范围可界定的变更按[开发流程](development-workflow.md)选择完整测试文件，使用现有入口：

```powershell
.\verify-release.ps1 -TestPlan build/<本次测试清单>.json
```

清单按路径排序，采用 `scripts/release_test_plan.py` 支持的 JSON 格式；保留受影响调用链及适用公共安全回归。门禁记录总量、选中量及未测范围，不能称为全量通过。只有影响无法界定或广泛改变公共契约时安排一次全量；不传 TestPlan 的当前程序行为仍是执行完整测试，因此定向验证必须显式传入清单。

2026-10-28 的“约 5% 总测试”只属于当次授权，不是未来任务通用标准。采集开发的“约 5% 实采”是最小完整业务单元的源数据抽样，与测试代码范围无关。当前规则不新增每次选择测试清单的用户审批。

## 当前检查与构建顺序

执行顺序以 `scripts/release.py`、`scripts/release_steps.py` 和 `scripts/build_desktop_launcher.py` 为准：

1. 取得全过程独占锁并确认应用已正常停止；冻结源输入、Git 身份及本轮输出证据，任何失配都拒绝形成成功证据。
2. 验证运行及依赖环境，执行 `release_test_preflight.py`，核对独立 13348 测试实例的端口、身份、建库/读写/清理权限、Redis 连通及日期夹具。不要使用生产账号尝试全套建库。
3. 执行依赖审计、文档聚合只读检查、文档/数据库设计/架构/装配契约、Ruff、Mypy、pip check 与差异检查。
4. 运行选定测试文件（未传计划则全量），采用私有测试数据库、Redis 命名空间和本轮 pytest 目录；记录 JUnit 及 preparation 证据。失败、跳过或源码过期不得伪装成通过。
5. 执行隔离容量验证、Electron 前端构建及传输测试；调用本机启动器构建，继续使用同一锁、核对该构建的输入并保留程序目录 config.toml。
6. 保存 `build/releases/<标识>/report.json` 及对应 evidence；失败写入 failure.json。报告成功限于本轮实际完成的当前门禁。

仅需重建本机启动器时，`python scripts/build_desktop_launcher.py` 是现有构建入口，默认保留 dist/EmpireDesktop/config.toml；首次复制才显式指定 --config-source，不同配置拒绝覆盖。它有自身的前端构建、传输测试和输入校验，**不等同于完整 verify-release 门禁**，不能替代功能交付所需检查。

## 等待与失败处理

阶段日志保存在本轮 steps/step-NNN.log；对应 JSON 记录输出完整性和退出码。优先可靠完成通知或可恢复会话，避免高频轮询及无变化播报；仍须读取最终结果、处理失败并完成后续验证。环境确实不能继续等待或恢复时，报告运行标识、日志和剩余项，不称完成，也不承诺自动返回。

任一阶段失败停止该次门禁，保留失败证据；这不要求助手放弃整个已授权任务。先诊断并修复，重验失败及受影响范围，再按正式入口要求重走必要阶段。当前没有通用跨轮证据合并，不手改摘要、成功标志或 JUnit 让失败报告变绿，不自动重跑无关全项目测试。

旧 `verify-release.ps1 -Recover` 已明确拒绝，不能用于当前客户端。当前构建没有旧 Qt 的原子目录切换与恢复包保障，不承诺失败自动回滚；恢复须依据当前产物、配置及实际故障制定明确维护动作，涉及数据丢弃或范围外操作仍另行授权。

## 配置与真实桌面

构建前后保留真实 config.toml，不输出凭据，不将带配置的产物作为公共分发资源。门禁通过后按受影响功能核对真实查询、可见桌面交互及从不同工作目录启动的配置路径，正常退出后重新打开窗口；未执行的项明确标为未验证。

启动真实 Runtime 会恢复用户已保存的计划，不得称为完全只读或绝无业务写入。不要为本次验证静默修改任务计划、清理共享 Redis、重启数据库或启动第二归档器。源站实采按[采集开发指南](collector-development-guide.md)的代理及有界样本规则另行证明。

## 输入、证据与职责

源输入、Git HEAD、NTFS 变更身份和已生成证据按当前入口核对；编辑后恢复原字节也不能绕过本轮输入身份检查。锁、身份读取或证据失配时保留现场，不删除他人锁或手工刷新摘要。真实配置不纳入公开源输入和报告正文。

依赖与供应链边界见[依赖治理](dependency-governance-review.md)，装配身份、冻结顺序与显式迁移登记继续受现行架构门禁约束。历史 Qt 的 UI 行数、四档布局、PyInstaller 成品和搬移 smoke 证据不能替代 Electron 检查；历史记录中的测试数量、构建成功或已完成状态不作为本轮验收。

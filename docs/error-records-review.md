# 错误记录查询优化验收

日期：2026-09-26。范围：完成系统审计 P2-13，降低运行记录错误页的 Redis 网络传输、Python JSON 解析和界面刷新开销；不改变错误采集、脱敏、配额及清理权限。

## 正式路径

| 能力 | 当前唯一实现 |
| --- | --- |
| 列表 | `list_error_summaries(project_id, offset, limit, known_revision)`，每页最多 100 条，界面固定 50 条；摘要不含正文、URL、元数据和摘要哈希 |
| 详情 | `get_error(project_id, record_id)`，只在选中记录时读取一条完整记录 |
| 清理 | `clear_errors(project_id, record_ids)`，仍只删除明确 ID；无匹配 ID 不推进修订号 |
| 存储 | 每项目一个原有错误 LIST，最近 300 条；新增一个不含业务内容的整数修订键，不复制错误记录 |

原 `list_errors` 全量接口已退役，生产调用、测试和说明均迁移，没有保留全量兼容入口。Redis Lua 在服务端原子读取当前修订、总数和所需页并构造摘要；已知修订相同时仅返回修订、总数和未变化标志。新增、同 ID 重试替换以及成功精确清理才推进修订。

## 逐项验证

- 隔离 Redis 填入 300 条、每条 64 KiB 的完整脱敏样本，总正文约 18.75 MiB。首个 50 条摘要响应不含 `body`，序列化后小于 20 KiB；同修订静止轮询不返回 rows，响应小于 200 字节。
- 选择 `large-20` 后只返回该条 64 KiB 详情；列表响应没有请求 URL、元数据、正文或正文摘要。
- 单元验证分页、末页、删除后页码回退、参数边界、同 ID 替换修订、缺失详情和无变化短响应。
- 界面验证项目切换丢弃旧结果、50 条分页、上下页状态、未选中不读取详情、选中后读取、刷新保持选择，以及修复确认后精确清理。
- 真实 Redis 继续验证 300 条项目独立配额、100 条归档配额、并发新增保留、凭据脱敏和幂等重试。
- 开启隔离集成测试的完整套件最终为 819 passed、2 skipped；跳过项仅为当前 Windows 用户无符号链接权限。Ruff、依赖一致性、Git 空白检查和 UI 文件 350 行上限检查通过。880×720 与 1320×900 离屏页面检查确认分页、状态、详情和精确清理区可达。
- 正常关闭旧桌面后 `build.ps1` 构建成功；新版 EXE 的 8 秒 smoke 正常退出，退出码 0，随后重新打开交互桌面。

## 保留边界

- Redis 仍是纯内存；服务或电脑重启后错误记录及修订号都会丢失。
- 摘要列表不提供正文预览。完整详情最多仍为 64 KiB，且只有完整读取时才声明原始长度和 SHA-256。
- 页面轮询未变化不传列表，但仍发送一次轻量 Redis Lua 请求；这不是“零请求”。
- 本轮不是依据生产错误 ID 修复问题，因此没有清除任何生产错误记录，也没有清空共享 Redis、修改 MySQL 或重启 Redis/MySQL。

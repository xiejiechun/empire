# 共享下载缓冲按实际响应增长 · 2026-10-29

用户要求取消股票/新闻/日历/通用固定单响应大小限制。本轮改共享HTTP缓冲路径，不改采集范围、来源解析、分页、断点、归档或业务表。

设计：分类response_policy返回由当前共享预算决定的弹性策略，起始仅预留256KiB工作区；收到解压块后、扩展正文前，申请正文三倍加工作区，覆盖增长/复制。已下载后页仍占额度，直到有序消费和发布结束。预算不代表进程RSS。协议明确声明的文件及专用来源结构边界不随本次取消。

无在手数据的新请求可等待初始额度；持有正文的请求扩容只做原子非阻塞申请。共享额度不足时明确失败并清理，不无限持有互等、不增加自动重试、不改写半份数据；降低并发或提高共享预算后可按原断点恢复。无磁盘溢写。可容纳的超过旧8MiB响应应一次完整成功，压缩正文和未知长度均按实际计数，不能只信Content-Length。

生命周期与成本：正常必要请求一次，重试只沿用原网络有界策略；HTTP失败不进入业务入队，原始错误样本继续有界。无新增SQL/Redis业务写入，无缓存或断点重置。兼容现存完整下载配置存储，四个分类数字不再用于HTTP策略；维护推荐工具需明确退出日常建议，当前桌面仍只有两个设置。其存储字段彻底移除另需显式配置迁移，不在启动偷偷改写。

验收：超旧上限、压缩膨胀、单响应超总预算、并发耗尽及时失败、重试与重定向、预取持有、取消和关闭回收、已有严格文件策略及公共安全回归。实采只验证未改语义的共享传输路径，不宣称全来源实采验收。

## 接线补齐

指数的专用结构策略通过replace保留弹性策略类型，避免预取租约被当成固定预留而拒绝。原生BoundedChannel在readexactly分配前申请三倍累计读取量与工作区；远航Snappy在读取输出长度后、分配输出前通过正式响应租约申请解压额度，各表累计计算。保持源协议结构、字段、数值、范围及摘要算法，不增加来源请求。题材原生解密的原始帧也经过同一接收预算。

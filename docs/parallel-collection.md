# 多代理并行采集：2026-09-26

用户规划出口设备从 100 台逐步增加至最多 1000 台，因此下载窗口不再使用旧 64 页常量。设备总数用于资源规划，实际容量仍取决于当前健康独立出口 IP，不能将设备数直接当成速度倍数。

## 日常使用

任务选择代理优先或仅代理，在“站点访问规则”选择自动扩展后保存。日常只调整每个出口 IP 访问该站点的最短间隔；高级容量限制用于保护本机资源或按需设置全站上限。下载资源页提供 100、200 至 1000 台十档容量推荐，默认 100 档为 128 个全局窗口和 512 MiB 缓冲，保存后正常重启生效。推荐不修改网站频率、任务网络方式或单响应/文件边界。任务详情说明并行能力与容量限制，采集出口显示设备与出口 IP 关系及实际请求率。

网站 `max_concurrency=0` 跟随全局窗口，正数只作为更严格的站点保护；全局最多 1024，不会被站点正数放大。现有自动站点可通过显式维护设为跟随全局，固定模式、每出口与直连间隔、全站每秒保护保持原值。设置仍保存在既有 MySQL app_setting，没有新增表或启动迁移。恢复固定模式可在站点访问规则中选择并保存。

容量不是新浪官方许可或真实多机压测结论。以每出口 IP 2 秒为例，2/20/50 个独立出口的理论合计分别约为 1/10/25 次每秒；实际还受响应时间、其他同站任务、页数与归档等待影响。多台设备共享 `exit_ip` 时只计算一个出口。

## 执行与恢复

1. 采集器查询总数并建立批次，按当前健康独立出口、全局/站点容量、字节预算与剩余页数创建有界下载窗口。
2. 每个请求通过统一 HTTP 层，取得健康设备和“站点 + 出口 IP”许可。每台设备最多一个请求，同一出口 IP 对同一站点也最多一个请求。
3. 分页响应可以乱序返回，由单一消费者按页号核实数量、代码与排序边界，原子提交消息与断点。
4. 未提交的后页仅放在有限内存窗口内，不能越过失败前页推进断点。任务失败或取消回收所有预取请求；恢复从确切未提交页继续。
5. 完成全部分页后验证空尾页与总数，再发布完整批次。入队即时唤醒统一归档器，60 秒恢复扫描兜底，成功后清理对应 Redis 消息。

自动模式的容量随健康出口 IP 数变化；在途请求正常完成，后续请求遵守新容量。429 仍冷却站点所有出口。代理全部不可用时按任务设置等待或直连，直连同站点最多一个在途请求并保留直连间隔。

## 插件与职责

- `infra.capacity`：纯容量计算，调度器和页面读取相同结果。
- `infra.proxy_pool`：共享周期目录快照、逐候选只读原子核实、协议解析、连接失败隔离、代理独占连接与取消安全回收，不主动探测设备健康。
- `infra.routing`：全站和单代理许可、直连回退、在途额度、请求率统计。
- `collection.prefetch`：通用有界预取与取消回收，不理解股票业务。
- `collectors.stock_pages`：股票页序校验和断点提交，每页诊断通过独立上下文隔离。
- 采集控制器声明 `parallel_downloads` 能力，UI 插件解释可用容量，不执行业务调度。

股票运行记录新增下载校验耗时和归档等待耗时。未完成运行不能用于直接承诺整轮提速倍数。

## 验证边界

回归覆盖 70 页乱序下载、有序提交、失败页诊断、断点恢复、重复边界拒绝、取消回收；50 个模拟设备使用真实调度代码验证并发及网站速率限制；代理全失效时验证直连不会被多页请求同时挤占。真实 Redis 和 MySQL 使用独立测试命名空间核实自动策略、许可与重启恢复。

以上保留早期并行实现的验证历史，不表示真实 50/100/1000 台设备的公网独立性、源站承载量或整轮提速已经验证。十档推荐、全局限制、扩展模拟及生产配置维护的当前验收见 [出口容量验收](exit-capacity-review.md)；扩大真实设备规模后仍须分阶段观察内存、句柄、错误率、请求率和归档积压。

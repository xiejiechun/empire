# 同花顺远航版日行情、除权事件与历史股本实施方案

2026-10-24 用户授权：编写实施方案后直接实施。研究依据为2026-10-23现场与程序集核实。当前执行P0协议验证；P1结构设计、P2采集、P3查询迁移、P4验收发布顺序推进。来源契约未证明前不创建业务表或伪造采集完成。

## 1. 目标与范围

建立当前沪深北A股每只证券上市至最近已结束交易日的日频基础数据，保存全部取得的历史，后续增量补齐。历史已退市证券的目录和接口覆盖单独核实；不能用当前股票池代表历史全市场。已归档证券退出当前股票池后不删除其历史。

本阶段最终目标为三类基础数据及一套派生查询：

| 数据 | 目标字段 | 边界 |
| --- | --- | --- |
| 不复权日行情 | 证券、交易日、开高低收、成交量、成交额；核实昨收/除权参考价、涨跌幅、振幅、换手率与实际换手率 | 核心量价必须核实单位、精度和完整日期集合；来源参考价不能冒充前一交易日实际收盘价 |
| 除权事件 | 除权除息日、现金派息、送股、转增、配股比例和价格、事件类型；来源支持时保存登记日、派息日、方案身份与实施状态 | 事件日期与公告日期分别保存。K线标记中的除权事件不等于完整分红预案、实施公告和取消历史 |
| 历史股本 | 生效日、总股本、流通A股、来源实际/自由流通股数、变动原因（若提供） | 各种流通口径不得混用；验证起点和区间连续性，禁止用今天股本回填历史 |
| 复权及衍生查询 | 累计因子、前复权/后复权OHLC、按有效历史股本计算的换手率和对应口径市值 | 复用既有计算能力，来源因子或复权K线用于核对。普通股本解禁不自动触发价格复权 |

PE/PB等历史估值不作为本阶段必交项；其财报时点和股本口径需要独立验证。分时、分笔、竞价、盘口回放不在本阶段范围。

## 2. 已取得的证据

- 现场打开远航版深圳燃气601139及鸿特科技300176日K线；可显示价格、成交量、成交额、换手率。当前展示为前复权，不能直接当作不复权原始价格。
- 现场点击300176的K线除权标记，弹窗列示2012-06-14至2026-08-21的派息、转增、配股事件。例如2018-05-29每十股转增9股、红利11元；2026-08-21每十股配4股、配股价3.36元。这证明页面存在相应历史数据，不证明全市场事件完整。
- 本机Hevo.Api.Quotes.dll存在RequestCandleDataAsync(parameters)及RequestCandleV1(data_center,security,fields,period,start_time,end_time,rights_args,...)。
- Hevo.Core.Interfaces.dll的ICandleParameterFactory.Create提供security、fields、status、period、起止时间或timeRange；ICandleQuoteParameters有AdjustTtype、IsExcludeAdjustVolume。参数可表达证券、周期、历史范围和复权选择，但枚举、服务端限制、请求分页和实际返回尚未独立验证。
- Hevo.DataModel.Business.dll可见OHLC、成交量/成交额、turnover_rate、real_turnover_rate、outstanding_shares、total_capital_stock、FLOAT_CAP等字段访问器。字段存在不证明可按日读取全历史，也不证明各股本字段的业务定义。
- 客户端连接观察到8601/8602和9601—9606等端口，包含自有行情模块；不是已经确认的一组公开HTTP REST接口。尚未完成独立协议请求或代理样本验证。
- 已有复权文档明确使用通达信分红/配股及开盘啦行情，当前单证券查询限制3660自然日。要支持上市至今，需要同步改造行情输入、长历史查询及图表读取，不能只增加下载任务。
- 当前系统已有通达信分红和配股业务、同花顺公司资本运作及指数日行情；指数接口不代表个股接口已经实现，公司资本运作也不能替代历史股本。

## 3. 还没有确认的事项

1. 可复现的日线、除权事件和历史股本请求协议、服务地址、字段ID及响应结构。
2. 是否依赖客户端进程、登录会话或付费权限，重启后如何正常恢复；不绕过来源权限。
3. 沪深北老股、次新股、更名换码、长期停牌、配股及多次送转证券能否完整取得上市以来历史。
4. 实际流通股与自由流通股、无限售流通股的准确区别。客户端帮助文字本身存在简化解释，须结合接口字段和样本核实，不能只依字段英文名判断。
5. 来源较早历史是否截断、停牌是否返回占位、成交量是否复权、金额/股数单位、当日数据何时稳定，以及源端修订规则。
6. 除权标记是否足以独立计算，是否另有权息表、复权系数；配股、缩股等特殊事件的适用公式。

当前结论：值得继续做协议验证，尚不能宣布采集接口打通或全历史数据完整。

## 4. 接下来按什么顺序做

### 第一步：验证三类接口，形成可实施结论

先做有界来源探针，不入生产业务库。固定300176的配股及转增作为业务反例，再检查沪深北、老股、次新股和停牌证券。逐项核对首个交易日、末日、年份边界、字段单位及事件前后价格/股本变化。

独立网络探针遵守共享下载、代理优先和频控规则；本轮客户端交互不是共享代理验收。如果发现必须使用私有TCP协议，先明确共享传输扩展和代理支持的设计，再决定实施，不能另起绕过公共资源约束的网络采集器。若必须长期依赖桌面进程，单独说明部署和维护成本，不把点界面/OCR作为默认正式采集路径。

第一步交付：三份接口契约、可取得字段、历史起点、权限/运行依赖、有限样本结果及仍有缺口的证券。不满足者明确不可实施项，不用猜测接口进入开发。

### 第二步：冻结存储和替换方案

日线按证券/交易日结构化保存；事件按可验证业务身份保存；股本按生效日期/变动身份保存，不每天重复写相同股本。保留来源与修订证据。具体DECIMAL精度、字段字典、唯一键、正式SQL、索引、容量实测与迁移设计在接口验证后提交，不能现在凭字段名建表。

日线索引覆盖单证券日期范围及单日全市场查询；历史股本支持截至某日的有效值查询；事件支持证券及除权日期范围查询。按真实业务与查询模式决定是否使用现有表或调整，不按接口数量机械建表。

替换时只保留一条正式行情输入和一套复权算法。通达信分红方案库若仍承担预案/进度查询，不能因K线除权表存在而删除；其保留职责与复权实际事件的归属明确分开。同一除权事件不能在计算中跨来源重复应用。开盘啦原数据保留，相关依赖迁完后退役被替代路径，不无条件停掉所有七项任务或删除历史。

### 第三步：实现采集、补缺和查询

先落地不复权日线，再落地除权事件和历史股本，随后接入现有复权/数据准备/股息率等受影响查询。默认按日收盘后维护，首次补齐上市以来全部可用历史，下一轮补新日期和缺口；近期回查及较早修订检查窗口根据接口契约确定。只凭最大日期不能判定中间齐全。

所有业务沿共享下载/代理/有界预取→统一Redis入队→统一MySQL归档；入队后继续下载，不逐批等待SQL。整轮入队后等待归档完成，成功消息清队。相同内容不写业务DML，失败不推进断点。Redis丢失从SQL真实覆盖恢复。

### 第四步：验收、发布、全市场回填

按适用股票池随机30只不同股票，另加300176等固定反例，经实际共享代理完成来源→规范化→Redis→归档→正式SQL集合与内容核对；全部成功且本轮待归档为0才通过实采验收。不得换掉失败样本凑数。

验收特别覆盖：上市首日、跨年、停牌缺日判定、送转/派息/配股前后、股本生效边界、单位转换、来源修订、重复零业务写入、迟到响应和提交后重放。复权差异逐项归因，不能因厂商算法不同就强行调数。

正式发布完成后再执行完整股票池回填，给出每只证券实际起止、缺口、失败和归档状态。随机样本验收通过不是全市场历史完成。

## 5. 最终用户能得到什么

- 在数据目录按证券查询上市以来全部已验收的不复权日K线、量额和已核实日指标。
- 在同一时间轴查到派息、送股、转增、配股及历史股本变动。
- 查看原始、前复权、后复权K线，并能追溯因子采用的事件和计算口径。
- 按历史有效股本分析换手率和市值，不拿当前股本替代过去。
- 每天自动维护，并明确展示“已完整覆盖”“有缺口”“来源不支持”“尚未采集”。

完成标准是声明股票池内逐证券完整范围核对及归档查询通过，不是任务运行一次或曲线能显示。来源缺失必须列为限制或未完成，不能把目标范围写成既成事实。

## 6. 容量与本轮改动

以5500只、平均15年、每年250交易日估算约2062.5万条日线；若平均25年则约3437.5万条。这仅是规划假设，表/索引空间须按最终字段实测。三类基础事实不需要长期保存成功响应，也不需要把前后复权价格重复存成三份全量日线。

本轮只读取工程文档、客户端界面及本机程序集元数据。研究辅助脚本与依赖在build/ths-yuanhang-research内，未修改客户端二进制、生产代码、业务数据或采集配置。工作区其他主题采集改动属于既有并行工作，不纳入本方案。

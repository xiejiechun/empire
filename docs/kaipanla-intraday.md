# 开盘啦分时及竞价

## 入门与范围

在“采集管理 → 采集任务 → 开盘啦”启动“开盘啦历史分时及竞价”；在“数据浏览 → 数据目录”搜索“开盘啦”，按市场、六位证券代码和交易日查询已归档数据。

采集范围为当前正常上市的沪深北证券，排除已退市证券。沪深从 2021-01-01 与实际上市日期中较晚者开始；北交所还不早于开市日 2021-11-15，不把此前新三板/精选层数据冒充北交所 A 股历史。终点固定为本轮开始时正式巨潮日历的最近已结束交易日，15:30 后才纳入当日。当前股票名单来自已归档新浪名单；公开东方财富上市日期元数据只用于确定上市前范围，不替代开盘啦报价或强制第二行情来源互证。

普通分时与开盘竞价是同一证券日的两个必需响应。普通分时为来源价格/均价点，不是 OHLC bar；午间没有 13:00 点，完整分钟键为 09:30～11:30 与 13:01～15:00。竞价原顺序、同分钟多点、并列相同点与下降量全部保留，不差分，不按分钟覆盖，不补造秒时间或逐笔成交。收盘竞价区间在普通分时末段，未取得另行的收盘竞价委托明细。来源量与标记原值保存，单位和成交语义尚未核实，仅声明价格走势分析可用；不承诺成交模拟、分钟 OHLC、秒级信号或当时旧版本重放。

北交所历史响应可能保留旧证券代码。只有响应代码与当前代码不同且属于历史北交所代码形态时，才通过北交所官方精确代码查询核实：必须唯一对应请求的当前证券、相同上市日并具有有效 ISIN。每轮每个当前/旧代码组合最多一次此核实请求，网络重试仍复用公共预算。正常相同代码不增加查询；核实失败不放行，不猜映射、不靠名称相近合并。规范日记录保留两个实际来源代码及映射证明。

## 日常操作与保存

任务缺省启用、手动执行，代理优先且允许直连回退；已保存的明确网络选择优先。固定间隔、每天时间和重试设置沿用公共任务页面，保存到 MySQL 后重启仍保留，网络/重试策略下一轮生效。每一次实际网络尝试（包括有界重试）生成随机设备 ID 与 Android 机型，不读账号、Token 或模拟器设备身份；不需要一直开着模拟器。429 仍冷却全站，随机身份不绕过频控、代理规则或重试预算。

普通采集补齐所有 SQL 缺失/结构异常/上市关联不匹配的证券日，并回看每证券最近五个必要交易日的修订。Redis 断点存在时从最后成功原子入队位置继续；重新初始化按完整声明范围复核，保留已归档历史。已结束下载并等待归档的轮次优先确认成功，再开启新一轮。更早已归档历史的修订只在重新初始化时发现，不承诺持续追溯全部旧修订。

查询按“查询”提交当前选择；读取回执不覆盖证券/日期编辑草稿。普通分时和开盘竞价分别在页签展示来源序号、分钟、价格及其字段；无数据时列出可能原因，不显示虚构的零条完整日。只读查询不要求 Redis 在线。

## 生命周期契约

| 问题 | 正式规则 |
| --- | --- |
| 初始化范围与完成 | 本轮当前股票池，按上市日、市场起点、正式日历和明确有界全天停牌证据确定必要日；每证券日两个响应都校验、入队和归档，整轮无待归档残留才完成 |
| 必要单元 | 完整证券日；普通分时精确键集合，竞价保留完整返回数组；来源没有竞价秒序号/总点数，只声明完整响应点保留，不能证明上游逐笔无缺漏 |
| 空日与停牌 | 上市前、正式休市与北交所开市前为范围外；明确且有界的全天停牌可排除必要日，临停、未知复牌和错误响应不当空日 |
| 下轮起点与补缺 | 遍历当前池的 SQL 完整性并补缺，最近五个必要交易日复查；不以最大日期或最高成功页替代前面集合 |
| 修订与旧版 | 保存来源时间为业务字段；来源时间不冒充可验证修订版本。以请求观测代次比较当前保存版本，内容/来源时间改变有效更新，迟到旧代次不覆盖当前保存版本；不保存完整旧版本 |
| 中断 | 来源缺口保留最早未完成证券日，后续独立有效日期继续下载，后序成功不推进连续断点越过缺口；入队后不逐日等 SQL，最后下载结束才等待本批全部有效消息成功清队；有缺口仍报未完成 |
| Redis 丢失 | 重建当前范围，逐证券读取 SQL 内容、摘要与上市关联，补缺及五日回看；不能承诺恢复内存中最后一次无变化核验位置 |
| 当前池或来源范围改变 | 范围摘要改变后重建计划，保留既有数据和待归档消息，重新核对关联；不把旧范围进度用于新股票池 |
| 进度 | 必要证券日进度与下载点数分开；已入队点数不是已归档点数，只有整轮确认才能显示完成 |

## 故障处理与验收

源站错误、空数组、错误证券/日期、字段改变、缺分钟或乱序都不推进该证券日的连续断点；后续独立有效日期可以继续，最早缺口和失败数保留，整轮不能显示完成。网络重试耗尽、基础设施或身份核实错误仍暂停。到运行记录查看项目 `kaipanla-intraday` 的错误；来源不支持的真实范围须核实后明确声明，不能无条件把 errcode=1017/1020 当作无交易。

“数据准备”可限定证券及交易日期，检查必需字段、精确分钟键、内容摘要和必要证券日缺口。分时范围采用交易日期，三表同一范围控件采用报告期。价格走势分析与历史选股回放分别呈现；当前股票池存在幸存者偏差，秒级和当时旧版本不可用。范围验证通过不代表全市场历史已采完。

开发专项及实际实采证据分别记录在实现状态与 evidence；程序支持范围不写成实际进度。公共错误/运行记录限量、精确修复 ID 清理、失败留队及成功清队规则不变。

## 技术参考与维护

`collector.kaipanla_intraday`、`data.intraday`、`ui.intraday` 分别提供采集、查询/验收与目录页面。数据集 `intraday.day@1`，job `kaipanla-intraday-v1`，项目 `kaipanla-intraday`。所有请求使用共享下载器、代理、许可与字节预算，未另建请求器或并行预取器。上市日期目录稳定按唯一证券代码排序，500 条一页，核对总数、尾页、严格升序和当前池键集合；每必要响应正常请求一次，业务失败不无限重读。

`stock_intraday` 每来源/市场/当前代码/交易日一行，保存规范有序数组与上市关联，排除原始成功正文。来源代码回溯以实际响应验证，不自行猜旧代码。统一归档器管理 SHA-256、版本、事务及 XDEL；可信摘要命中免 MySQL，冷摘要回 SQL，同内容无业务 DML，SQL 提交后安全重放。持久状态仍每项目仅一条 `collection_state`。

旧版完整业务库通过 `scripts/migrate_business_schema.py` 显式转换结构，应用启动不建表。执行前正常关闭 Empire、待归档队列清零；影子复制和原子切换前后核对全部业务内容、版本及关联集合，旧表作为恢复副本保留。新空库使用 init-db。程序目录 config.toml 保留，数据库服务不变。

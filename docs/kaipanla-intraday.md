# 开盘啦七项历史数据

## 入门

从“采集管理 → 采集任务”选择开盘啦下的独立项目。七项为分时走势、开盘竞价、分钟成交量与成交额、分时成交明细、分钟买卖委托汇总、大单净额走势、历史盘口与日行情摘要。新增项目默认停用、手动执行，不继承旧合并任务的自动计划。

## 日常操作

需要哪项就启用并保存哪项，再执行立即采集。计划存 MySQL，重启保留；代理策略下一轮生效。普通采集补 SQL 缺日并回看最近五个交易日；重新采集重新核验范围，保留已有历史。数据目录提供七个独立按需页面，序列页面每页最多 200 条；数据准备独立检查每项选定证券和日期。

## 历史盘口浏览

从“数据浏览 → 数据目录”打开“开盘啦历史盘口与日行情摘要”，选择市场、证券和交易日后查询。上方为最新价、涨跌额／幅及开盘、最高、最低、换手、金额、振幅；左侧为已归档分钟价格及均价，右侧卖五至卖一、买一至买五，支持切换十档；下方查看估值、股本、内外盘及更多来源字段。红色为高于昨收，绿色为低于昨收，零价格档位显示“—”。鼠标移动到走势上可查看该分钟的价格和均价。

关联分时只读取同证券同日期的独立 SQL 归档，不启动采集，不要求分时查询插件可用。缺分时或该插件停用时盘口仍可浏览，图内显示缺失原因；切换证券或日期后的迟到结果不能混入新查询。查询失败时保留明确标记的旧结果及其原证券日期，不覆盖输入草稿。五／十档选择随页面状态恢复，不写任务配置。

这是静态历史快照，未提供来源应用的全天盘口回放、分笔滚动或竞价叠加。万／亿仅缩写原值；没有证据的成交量和委托量单位仍标注来源单位，不猜测“股”或“手”。原值可从指标提示及更多来源字段查看。

## 数据与边界

| 插件 kind | 接口 | 保存内容与完整性 |
| --- | --- | --- |
| trend | GetStockTrend | 241 个精确分钟键的价格、均价、来源量及标记 |
| auction | GetStockBid | 开盘竞价完整来源数组，同分钟多点保留；无上游总数证明 |
| volume | GetStockVolTur | 241 分钟量额及标记，不提供 OHLC |
| trades | GetStockFenBi2 | 全部分笔字段，同秒多笔保留；Count/total 同时核对 |
| entrust | GetStockBsvolume | 241 分钟买卖委托量额汇总，无券商席位或撤单流水 |
| large_order | GetStockDaDanTrend | 241 分钟大单净额及附加统计，允许负净额 |
| quote | GetStockPanKou | 该日盘口档位、行情、估值与股本摘要，无全天秒级序列 |

按完整响应保存规范业务字段，不长期保存成功 HTTP 原文。来源代码未回显的分笔通过冻结请求证券关联；其余接口核对回显证券和日期。北交所旧代码须有官方映射、上市日及 ISIN 证明；先验证并释放行情响应，再请求身份核实，避免单响应预算下自等待。无法确定的量单位/标记不作猜测转换。当前上市股票池有幸存者偏差，数据不包含历史已退市全量股票，也不提供当时可用的所有旧版本。

## 七项各自的生命周期

以下契约分别应用于上表每一插件，各自使用独立 project/job/dataset，不等待其他六项完成。

| 项目 | 每项的正式行为 |
| --- | --- |
| 用途与范围 | 来源历史分析；2021 年起当前上市沪深北股票，来源错误留缺口，不宣称来源未知范围可用 |
| 初始化边界 | 本轮开始冻结当前股票、正式日历、上市范围与最近已结束交易日；跨日后的新交易日由下一轮负责 |
| 完整单位 | 本接口一个完整证券日；分钟序列验证精确集合，分笔验证总数，竞价保留完整数组，盘口验证必需行情、有效价格、日高低价与 10 档价量及买卖价格顺序 |
| 初始化完成 | 本项所有必要日校验通过、业务归档或确认无需写入且本轮消息清队；后序成功不能掩盖前序缺口 |
| 后续起点 | SQL 内容和生命周期核对缺日；最近五个交易日重查修订；不只依据最大日期 |
| 修订追溯 | 规范内容变化才更新，较早下载代次不覆盖新代次；五日以外修订不保证自动发现；源端计算时间不是修订版本 |
| 中断恢复 | 下载或发布前失败重下载；入队后沿已入队断点继续，消息由归档器重放；SQL 提交后清队失败重复比较并清队，无重复业务 DML |
| 状态丢失 | Empire 重启且 Redis 存活沿断点；Redis 重启后按 SQL 内容、日期集合和上市关联重建，可重查已确认日；不承诺 Redis 跨服务恢复 |
| 操作配置 | 继续补缺；重新采集复核全部声明范围但不删历史；范围改变重建计划，已入队整轮先确认；配置下一轮生效 |
| 进度证据 | 下载、入队、归档、缺口分别显示；开发支持范围与实际已归档范围分别报告 |

## Redis 到 MySQL 与减少写盘

七项复用共享下载、代理、出口频控、字节预算、有界预取、原子入队与统一归档。每个必要响应正常只请求一次，独立页面失败不会推进该项断点。容量背压和项目隔离继续执行，429 冷却全部出口。

校验后将业务与断点原子入 Redis，立即唤醒归档器并继续下载；仅整轮入队结束等待归档。可信摘要命中免 MySQL 查询，冷摘要核对相同内容不执行业务 DML；有效修订才写库。metadata 保存来源时间但排除于业务摘要，防止重复下载只更新时间。成功清除对应消息，失败保留重试。Redis 纯内存，MySQL 普通日志及 binlog 沿现有禁用规则，redo/undo 保留以保障事务恢复。

## 故障处理

未归档不当无成交；空数组、全零占位、错误证券/日期、缺分钟、分笔总数不符、字段变化都必须核实来源。到本项运行记录查看精确错误 ID，修复验证后只清理对应 ID。SQL 失败不会丢弃待归档业务，不启动第二归档器或清空共享 Redis。

## 结构与维护

`stock_market_day` 主键为 `(kind, unified_code, trade_date)`，每项每证券日一条 JSON 业务记录，含 source_code、aliases、lifecycle、data、metadata、内容摘要和版本观测时间。JSON 是规范业务内容，不是原始 HTTP 副本。独立类型共享表不共享断点、摘要或完成状态。

`python scripts/migrate_kaipanla_products.py` 只核查；加 `--apply` 显式迁移。正常关闭 Empire，待归档队列为空后运行，默认读取项目根 config.toml。逐条验证旧摘要与身份，事务内拆分、读回核对业务和版本后移除旧行；可中断重跑，目标冲突拒绝覆盖。旧表完整转换核验后删除，正式建表不再创建；旧合并项目从正式登记退役。七项任务配置初始化为停用手动模式，不迁入旧自动计划。

有限实采验收入口 `scripts/verify_kaipanla.py` 固定仅取 000001.SZ 与 600000.SH 的最近已结束交易日，共 14 个独立证券日；强制代理，禁止直连回退，并核对正式查询与数据准备。保留有效业务，不开启自动计划。

CLI 为 `collect-intraday --kind trend|auction|volume|trades|entrust|large_order|quote`，调用同一正式任务，须先启用对应项。数据浏览不依赖 Redis；结构变化不由启动自动执行。

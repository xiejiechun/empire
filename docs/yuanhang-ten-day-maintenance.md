# 远航十交易日维护实施设计

2026-11-02，用户已授权实施。本文为新策略的设计记录；2026-11-03已完成定向门禁、开发实采与真实桌面检查，范围见[交付记录](evidence/yuanhang-ten-day-delivery-2026-11-03.md)。

## 生命周期

- 五个日期池与原因正文：近期只核验最近十个正式交易日，最新日优先；已知历史缺口在同一项目后续有限轮次补齐。五池每历史轮最多64个完整日期池，原因每历史轮最多256个证券日。不再按20交易日重查已完整的老历史。
- 初始化未完成也先处理近期。历史轮结束必须确认该轮全部已入队消息成功归档，然后回到近期调度；不得逐单元等待归档。
- 五池保持15:30后的日终维护以及每30分钟当天复核至21:00，完整集合替换处理涨停转炸板，不能只追加记录或只比较条数。
- 不复权日线近期采用十交易日区间；近期归档后独立批次补最多64只证券的历史缺口。原因及日线在同一次定时调用内先完成近期批次，再完成有界补缺批次，避免每日计划使历史永久饥饿；五池使用原间隔计划的后续轮次。长停牌为保持来源身份验证可向前包含已知成交锚点，明确这是协议例外。取消周期性全历史请求。
- 权息与股本仍每日每证券一次211完整联合响应；尚无已验证的区间能力，不称其为十日下载。同内容继续零业务写入。
- 更早修订通过已知异常或显式定向核验处理；不承诺自动发现全部窗口外修订。日历缺失报错，不能把工作日当交易日。

## 恢复与存储

业务表及唯一归档路径不变。旧断点须显式维护：保留已入队批次身份及页号，只重规划尚未请求部分；不得删除队列、重置归档成功标记或伪造完成。Redis丢失从SQL覆盖重建，不能因为摘要丢失全池重下。失败不推进断点。

## 成本与验证

五池近期每池最多十个完整日期响应，另加必要分页/身份辅助及共享有界重试；同截止已有可信核验为零业务请求。当天复核每次一个完整日期池。原因按十日内去重证券日计费，历史每轮至多256单位。日线每证券近期一个区间请求，历史有限轮次另计；金融每证券一个联合请求。认证、传输、解压、入队和实际业务写入分别记录，不把减少字节称为减少请求。

必须验证：初始化未完近期优先、历史轮有界、无变化、新交易日、同数不同集合、旧响应、防止归档串行、状态丢失、旧断点安全转换。实采按既定5%完整单元，复用适用来源证据，执行定向发布门禁及真实桌面验证。尚未完成的验证不得记为通过。

新触及且尚无年度覆盖证明的年份，首次区间须包含该年1月1日起的前缀，满足现有年度证明契约；这属于该年初始化，不升级为全部证券全历史重采。完全没有身份/行情锚点的新证券在有界初始化批次取完整响应。

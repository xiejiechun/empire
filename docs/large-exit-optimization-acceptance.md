# 千级出口优化验收方案

制定日期：2026-11-06。状态：**核心实现、隔离专项、资本 C 四组配对及 V3 网络/A/B/目录单轮已执行，部分容量门槛失败；长稳态和有限实采已执行，正式发布与桌面继续执行**。阶段事实见[实施记录](evidence/large-exit-optimization-20261106.md)。实施范围和批次见[实施方案](large-exit-optimization-plan.md)。本文件定义如何取得证据，不预填成功结果。

## 1. 验收原则和判定层次

验收顺序为：不变量专项 → 独立 Redis/MySQL 集成 → 配对性能基准 → 有界真实来源 → 正式发布与真实桌面。正确性失败时停止扩大负载，先修复并重验受影响项；性能达标不能抵消漏采、覆盖错误、提前完成或有效消息丢失。

分别报告 S1000/S3000 受控模拟等级、真实在线出口数、来源样本及正常生产观察；没有真实 1000 节点持续运行证据时，不能称“真实千节点吞吐验收”。旧容量 Mock 通过只作为回归依据，不能代替真实连接、解析、归档链路。

本文数值是待验证的工程准入目标，不是已实现指标。P0 冻结目标和硬件，若某项不可达则报告失败及原因、提出范围/硬件调整，不能测后降低阈值或挑选最快一轮称通过。

## 2. 环境、输入与隔离

每轮证据包含：源码提交及受测文件摘要、未提交差异摘要、Python/依赖/数据库版本、CPU 核数及型号、内存、磁盘、网卡、进程启动方式、全部影响容量的脱敏配置、负载生成器版本、随机种子、测试清单、起止时间和退出码。使用北京时间展示，机器时间保留带时区值。

- 独立 MySQL 使用项目要求的 13348 实例，核实实例身份和建库/读写/清理权限；正式 3307 业务实例不用于压力测试。
- Redis 使用自有命名空间，若测 Redis 吞吐或 Lua 尾延迟，应使用隔离服务或明确无竞争的测试环境；共享实例的普通集成结果不能冒充无干扰性能基准。不重启或清空共享服务。
- 不启动第二生产 Runtime/归档器。受控源站使用本地测试 HTTP/TCP/代理服务和隔离业务存储；全部访问仍穿过正式共享路由、预算、规范化、入队、归档、查询路径。
- 普通性能比较期间避免同步构建、全库扫描和其他基准。不能隔离干扰时标记该轮无效并说明；不把干扰造成的结果删掉不记。
- 原始成功响应由确定性生成器重建；必要字节夹具是合成内容，不长期复制线上成功响应。只保存统计、规范摘要、ID 集合摘要、错误样本及脱敏日志。

首先运行现行[发布预检](../scripts/release_test_preflight.py)适用的环境检查。完整命令和参数以该脚本当前帮助及[发布门禁](release-gate-review.md)为准，不在本方案硬编码凭据或已经失效的测试实例路径。

## 3. 冻结负载与性能测量方法

### 3.1 四类固定负载

| 编号 | 构造和目的 | 存储状态 |
| --- | --- | --- |
| N 网络调度 | 100/300/1000 独立虚拟出口；每 IP 2 秒间隔；响应 100 ms、正文 32 KiB；单站及两站；另测 3 秒响应 | 仅测共享下载/关闭，不声称业务归档通过 |
| A 可信摘要确认 | 每消息 100 条规范业务记录、编码目标 16 KiB（容差 10%）；采用已登记证券单元数据集的正式 writer/查询；固定有限键集循环 | 可信摘要已预热，内容不变、版本合法，正式路径应零 MySQL 访问并成功清队 |
| B 真实写库混合 | 同样规模，80% 同内容可信命中、10% 新业务键、10% 已有键有效修订；固定计划和版本顺序 | 真实隔离 SQL、正式完整 schema；新键数与缓存上限预先预算，因缓存淘汰产生的额外冷查询单列 |
| C 大完整单元 | 每单元目标 512 KiB/约 1000 条记录，容差与实际行数记录；含 HTML/矩阵等已存在来源解析器的合成代表输入 | 解析、规范化、压缩/解压、IPC、冷缓存比较；合法单元不为追求吞吐截断 |

若业务正式契约无法生成上述大小，P0 在修改实现前冻结最接近且合法的夹具、实际尺寸和行数，并说明差异。禁止跳过业务校验、用空 writer、统一空响应或纯字符串替代业务吞吐。A/B 至少覆盖财报、资本运作以及一项按日期归档数据；C 覆盖当前真正热点，不能只选最快数据集。

1000 节点之外还测：重复出口 IP、过期目录、临时故障、身份绑定、慢首项/快后项、单响应来源、聚合批未收齐。一个来源每次完整列表只有一次请求时，以最小必要请求数和正确结果判定，不要求用满千 IP。

### 3.2 可复现配对方法

1. 冻结旧实现 A 和优化实现 B 的源码/依赖/环境；分别使用自有测试数据库及前缀，构造相同业务基线与预热状态。不能拿早前线上 20 秒快照直接作 A。
2. 每个配置先预热 60 秒；核心计时至少 180 秒。进行 4 组配对，顺序 AB、BA、AB、BA；逐轮记录结果，比较配对中位数与尾延迟，不能只报最好值。
3. worker 候选 1/2/4/8、批量候选 1/8/16/32、处理进程候选直接/2/4，只做能回答瓶颈的实验矩阵。选最低资源且达到门槛的组合；避免所有参数笛卡尔积长测。
4. 基准使用固定到达计划，记录预定发起到最终确认的端到端延迟；同时记录实际交换时延。调度器阻塞时不能停止计时或只统计已经发出的快速请求，防止遗漏排队时间。
5. 最终配置进行 30 分钟稳态测试；热身后开始计算趋势。无变化热轮、真实修订、冷摘要、混合大小响应分别记录。
6. 测得处理能力 μ 后，按不超过 `μ / 1.25` 的消息到达速率 λ 做稳定性验收。容量测量与稳定运行是两项证据，不能通过将 λ 降到任意小值来宣称全部业务达标。

### 3.3 指标口径

- 请求：计划数、实际尝试、认证/辅助/重试、成功完成、取消；包含所有出口和直连。
- 网络：实际传输及解压字节、活动连接、建立/复用/关闭计数、句柄峰值。
- 业务：已规范化/已入队/已归档消息、业务行、DML 行、同内容确认、旧版确认、失败保留。
- 队列：可处理与未收齐消息分别计数/估算字节/最老年龄；若字节是估算，报告误差及硬内存指标，不当作精确准入依据。
- 资源：各执行槽、排队、事件循环延迟、主进程及子进程合计 RSS、共享预算、Redis 内存、SQL 排队/事务/锁等待。
- 时间：p50/p95/p99、最大值和样本数。排除样本必须有原因且仍在原始结果清单中。

## 4. 量化门槛

| ID | 验收项 | 通过条件 |
| --- | --- | --- |
| M01 | 指标开销 | 相同负载开/关详细计时的吞吐差异不超过 5%；指标存储不随历史消息数线性增长 |
| M02 | 目录边界 | 1000、1001、3000、5000 项按声明处理；5001 项或超过 8 MiB 明确超限；不静默截断、不修改 RouterProxy、不泄露凭据 |
| M03 | 节点分配复杂度 | 正常单次分配不遍历全部设备；用操作计数证明就绪索引和 O(log N) 定时操作；1000→3000 节点时无到期大批变化的单次调度 CPU 中位数增幅不超过 50% |
| M04 | Redis 目录影响 | 在隔离 Redis 上连续刷新期间，轻量探针 p99 增量不超过 10 ms；超标时不得直接扩大到更多节点 |
| M05 | N 网络层 | 100/300/1000 出口分别达到理想 50/150/500 次每秒的至少 90%，且无额外源端限速、全局/缓冲瓶颈；1000 档即至少 450 次/秒，严格保持单 IP 间隔与在途槽 |
| M06 | 多站共享 | 两站各能取得本站合法出口额度，总在途不超全局；全局为 1024 时不得要求两站各有 1000 个同时在途；3 秒响应按实际并发公式计算目标 |
| M07 | A 归档快路径 | 第一交付目标至少 500 消息/秒；处理期间业务及 collection_state 的 MySQL 访问均为零，全部成功清队；数据集逐项报告，不以最快项目代表全部 |
| M08 | B 混合写库 | 第一交付目标至少 100 消息/秒（按本负载约 10000 规范行/秒，DML 另计）；新数据/修订正确，旧数据和同内容不产生多余业务 DML |
| M09 | C 大单元 | 归档/解析整链能力至少为正式准入到达率的 1.25 倍；相对基线配对中位数吞吐提升至少 50%，且不增加必要来源请求或放宽校验 |
| M10 | 当前代表任务 | 冻结 P0 的现实混合样本后，处理能力至少为该样本实测入队率的 1.25 倍；15 消息/秒仅作为当前负载候选目标，不替代 M07/M08 |
| M11 | 事件循环及桌面查询 | 受控稳态后台循环延迟 p99 不超过 100 ms；正式只读状态查询 p95 不超过 1 秒，不含明确业务大查询的执行时间 |
| M12 | 稳态队列 | 30 分钟中，预热后最后 20 分钟可处理队列无持续正增长；最后 5 分钟均值不得高于第一个稳态 5 分钟均值加 `max(10, λ×1秒)`；最老可处理消息年龄 p95 不超过 30 秒 |
| M13 | 扰动恢复 | 下游暂停 30 秒后恢复、输入为 μ/1.25 时，队列应在恢复后 180 秒内回到原稳态包络；积压/内存硬边界全程不超限 |
| M14 | 资源回收 | 10 轮开始/取消/重试后，许可、预留、任务所有权回到零；连接/句柄回到稳态基线；最后两段各 10 分钟合计 RSS 均值差不超过 5%，同时不超过 P0 冻结的绝对内存包络 |
| M15 | S3000 扩展 | 与 S1000 相同的正确性门槛，网络 N 理想 1500 次/秒至少达到 90%；若全链写库能力不随之增长，必须明确报告可持续的 λ，不能宣称所有业务 1500 消息/秒 |

M07/M08 是不同负载的工程目标，不表示真实源站每秒必然提供这些消息。单机硬件不满足时保持未通过，不能以自动限流掩盖容量不足。RSS 不要求 Python 分配器立即归还每一字节给操作系统，但应用所有权和预算必须归零，峰值与长期趋势必须有界。

## 5. 正确性与故障矩阵

| ID | 注入或操作 | 必须观察到的结果 |
| --- | --- | --- |
| C01 | 同内容重复、可信摘要热命中 | 零 MySQL 访问，版本/TTL 依契约更新，成功 XDEL，不重复业务 DML |
| C02 | 摘要缺失、损坏、过期、有效索引缺失、异常超前 | 回 SQL 核对；不能假命中或直接 ACK |
| C03 | 有效修订后到达旧响应 | 新内容不被覆盖，旧响应不污染缓存当前内容，确认旧版后清队 |
| C04 | SQL 提交前异常、批中一成员失败 | 整批事务回滚，全部未确认成员保留，断点/完成证明不伪造 |
| C05 | SQL 提交后、摘要写前或 ACK 前断开 Redis | 重放后业务无重复 DML、摘要恢复、最终精确清队 |
| C06 | Redis pipeline 部分成功、ACK 回执丢失、历史记录重放 | 按真实已确认状态恢复；同 ID 历史幂等，失败成员不误删 |
| C07 | 同项目多页、不同项目共享业务表/唯一键 | 冲突域串行，合法独立域可并行；最终内容与串行参考实现相同 |
| C08 | 最后一页先到、manifest 先到、等数量不同集合、聚合页缺失 | 不提前完成；必须证明完整集合，最高页号和总条数均不足以清队 |
| C09 | 未知 schema：可归属项目与不可归属消息 | 前者只隔离该项目，后者全局阻断；有效消息保留，恢复走原队列 |
| C10 | 准入等待期间触发隔离，普通与预留发布两种路径 | 提交前拒绝不推进游标/消耗预留；提交后的真实成功不被改成失败 |
| C11 | 重复取消、取消时 SQL 尚未完成、关闭连接很慢 | 保留资源所有权直到真实结束；无孤儿事务、连接或泄漏额度 |
| C12 | 下载乱序、慢首项、后项已完成、单响应/ID 依赖来源 | 只在合法独立单元并行；结果有界，失败不越过连续断点，不额外请求 |
| C13 | 无长度头、虚假长度、压缩膨胀、IPC 复制超预算 | 实际传输/解压及在手结果计费；增长失败及时释放并报错，无半份发布/自等待 |
| C14 | 解析 worker 崩溃、异常结果、重复结束回执 | 原单元失败并回收，不能自行重发 HTTP 或重复入队；重新执行仍按同一业务函数 |
| C15 | 同 IP 多设备、不同站点、code 绑定 | 同站同 IP 单槽；跨站独立；绑定账号不跨节点、不直连 |
| C16 | Hash 删除、ZSET 过期、映射更新发生在发现后分配前 | 候选原子复核拒绝失效旧项；旧连接等在途退出再关闭 |
| C17 | 目录超限/超字节、超大无效项、生产目录变化 | 诊断明确且脱敏，不能以不完整视图认定完整或删除生产项；已知候选仍须最新验证 |
| C18 | 429、403、502、认证拒绝、传输失败 | 429 全站冷却；403/认证不绕过；502 不自动视为节点故障；传输失败按已有隔离和本次排除规则 |
| C19 | 历史大任务与小任务同时运行、同站多项目持续就绪 | 等权任务均有进展；无负载完成依赖的任务不饿死；空闲余量可借用但不可超上限 |
| C20 | 未收齐聚合批时触发队列年龄/内存反馈 | 保留补齐/完成资源；不出现等归档而禁止补齐下载的死锁；已持有正文可正常释放 |
| C21 | 启动保存配置、在线节点增长、重启/降档 | 不自动改站点策略和任务计划；自适应仅改变有效窗口，保存值与生效值显示准确 |
| C22 | Empire 正常重启，Redis 保留；另在独立实例测试 Redis 丢失 | 前者安全重放；后者按 SQL/来源契约恢复，不宣称找回丢失的内存队列 |
| C23 | 正常关闭后代码回退，保存窗口大于旧版上限 | 按实施方案显式处理配置兼容，数据/待归档消息保留，旧版无歧义启动或明确拒绝 |

C19 量化补充：无故障、同成本且持续就绪的同站任务，在 60 秒窗口内各自获得的许可数至少为等权份额的 80%；异成本任务改用调度机会和最大等待衡量，不能要求相同完成数。单项目故障不阻塞独立冲突域；单批过大时以字节/行数预算轮转。

4. 定向阶段使用 [TestPlan 格式](../scripts/release_test_plan.py)列完整测试文件；实际执行 `verify-release.ps1 -TestPlan <清单路径>`，记录未测范围。最终全量阶段按[正式门禁](release-gate-review.md)执行。
5. 不使用旧 Qt UI、搬移或 `-Recover` 作为当前客户端完成条件。源码/依赖/配置变化导致性能或门禁身份失配时，该证据不能作为新版本通过结果。

## 7. 真实来源与桌面验收

真实样本覆盖以下不同处理形态，先复用仍适用的更小充分样本和固定错误反例：

- 同花顺财报/资本运作：证券完整历史、大 HTML/矩阵、无变化维护与有效修订。
- 同花顺指数：近期更新、必要年度补缺、持续 502 的原位置；不能替换失败样本。
- 通达信证券或日期任务：多单元预取、业务入队与整轮归档完成分离。
- 一项聚合列表和一项 Redis-only 盘中任务：集合完整及无 SQL 业务写入。
- 涉及原生/绑定身份改造时加远航有限完整证券；不因公共 HTTP 测试通过而省略原生所有权验证。

按每个受影响来源声明范围约 5% 的最小完整证券/日期/月单元向上取整，至少一个；已有更小充分样本不扩采。记录总体、种子、样本清单、实际比例、请求/重试/字节、入队/写库及未测范围。样本逐项走原始响应→正式规范化→Redis→统一归档→正式查询，对比业务键集合、字段和完成证明；不能只比总数。普通维护、新增完整单元、中断续采及缓存/断点丢失恢复分别核实适用边界。

通过样本后不等待全历史补齐。真实在线节点不足 1000 时记录实际数字，不补造千节点实采结果；不为凑节点数主动逐节点探测或向公共来源施加受控实验中的高负载。

桌面检查：资源/出口显示准确区分在线设备、独立 IP、有效并发与实际请求；采集中/解析中/等待归档能被识别；切页取消只读查询、保存回执不覆盖新草稿、滚轮不改值、窄窗口可操作。验证 config.toml 保留、不同工作目录启动、真实数据库连通、可见窗口、正常退出和重新打开。

## 8. 证据格式与交付判定

每批使用自有 `build/large-exit-<运行标识>/` 保存原始测试输出和基准报告；最终把脱敏且必要的总结放 `docs/evidence/`。以下文件名是交付要求；当前 `baseline.json`、`candidate.json`、`capacity.json` 已有阶段汇总，最终须按全部实际结果重新归约，其余产物不得预填成功：

| 产物 | 必需内容 |
| --- | --- |
| `manifest.json` | 身份、时间、环境、负载/种子、配置、文件摘要、测试范围与最终退出码 |
| `baseline.json` / `candidate.json` | 每轮原始指标及配对关系，不能仅存聚合最好值 |
| `correctness.json` | C01～C23 的适用性、执行命令、结果及证据定位；未执行明确标记 |
| `capacity.json` | M01～M15、各负载/档位、吞吐/尾延迟/资源/队列趋势及失败原因 |
| `real-sample.json` | 来源样本、真实出口范围、集合/内容核对、整轮清队与未测范围 |
| `delivery.md` | 改动、验收状态、发布身份、真实桌面、配置兼容、回退步骤及遗留项 |

完成条件：所有适用正确性项通过；S1000 必需性能项 M01～M14 达标；来源最小充分实采通过；最终正式门禁和同版本真实桌面完成。S3000 的 M15 单独判定，不通过时不能声明扩展等级。未解决外部来源故障列为具体限制及保留错误 ID，不能删除记录制造通过。

最终报告逐项使用“通过/失败/未执行/不适用及原因”。既有源码、历史方案、工具可运行、Mock 成功或文档链接检查都不能替代上述完成证据。

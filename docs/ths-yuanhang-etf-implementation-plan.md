# 同花顺远航版 ETF 采集实施计划

日期：2026-11-16。状态：用户已批准实施；来源、代码、容量、开发实采、生产建表、定向发布与真实桌面验证已完成。日K生产初始化仍在推进，实际范围见[交付记录](evidence/yuanhang-etf-delivery-20261116.md)。

本文保留实施前的范围与阶段设计；用户随后已明确批准实施。实际已核实能力、字段限制及验收状态以[当前契约](ths-yuanhang-etf.md)与证据为准，计划中的候选字段不能视为来源已支持。

## 1. 目标、范围与已核实依据

目标：将远航版“沪深京 → 场内基金 → ETF基金”接入 Empire，提供完整当前目录、页面最新行情和来源历史不复权日K。默认用于行情分析和普通日频研究；不复权价格不等于含分红的完整投资收益。

所有正确采集数据先进入 Redis。目录和日K经统一归档器写入 MySQL；实时行情仅保存 Redis 最新值，不累计历史快照。采集插件不直接写 MySQL，也不自行删除待归档消息。

范围以该页面的动态 ETF 集合为准，包含其中的股票、债券、商品、跨境和货币类 ETF；不把相邻 LOF、封闭基金、T+0 分类或 REITs 整类合并进来。分类重叠时仍以 ETF 集合身份为准。首次只能发现来源当前目录，不能声称已涵盖全部历史退市 ETF。

本期不包含历史净值、基金份额、净申赎、持仓、分红复权、分时/分钟/逐笔历史。这些数据没有在本轮得到来源能力证明；尤其不能用成交额或内外盘推算基金净申赎。

## 2. 三个任务及调度

拟建独立业务包 `src/empire/features/yuanhang_etf/`；任务分类为“基金数据”，平台为“同花顺远航版”，固定来源为 `ths_yuanhang`。名称按当前桌面约定只写数据内容，平台通过分组表达。

| 拟定项目ID | 任务名称 | 输出与完整单元 | 默认计划 |
| --- | --- | --- | --- |
| `ths-yuanhang-etfs` | ETF目录 | 一份完整动态目录 | 每天北京时间18:00；首次手动采集立即执行 |
| `ths-yuanhang-etf-prices` | ETF历史日K | 一个ETF的完整来源历史或明确日期区间，按年发布 | 每天北京时间18:00，近期优先后补历史 |
| `ths-yuanhang-etf-latest` | ETF实时行情 | 按固定目录身份核验的一轮完整最新值 | 每轮结束等待60秒；同任务不重叠 |

实时任务在正式日历交易日09:15—11:30、13:00—15:05采样；已获得当日收盘后有效来源时间的结果后，其余盘外轮次不请求行情。首次或手动明确采样允许盘外取一次最新值，保留真实来源日期。若现有任务入口不能可靠区分手动与自动触发，先通过正式命令契约实现明确区分，不根据调用时间猜测用户意图。

已保存合法计划、代理选择及网站频控优先；不静默修改原任务。目录、实时和日K可独立失败；首次没有可信目录时下游明确提示缺少目录，不从股票表猜ETF。目录更新完成后，下游下一轮使用新目录；一轮开始固定目录版本和目标集合，中途不混入新集合。

目录和日K各自在 `collection_state` 保留每项目一条已归档状态；实时项目仅使用Redis运行状态，不为采样写SQL状态行。MySQL `app_setting` 仍负责三任务的正式配置。

## 3. 正式数据路径与完整性

### 3.1 目录和日K

```text
共享下载/代理/身份/连接池
  → 来源结构、身份、业务键及完整单元校验
  → ingest.publish_page（业务与已入队断点原子进入Redis）
  → 立即唤醒统一归档器，采集继续后续下载
  → 统一规范化、可信摘要、SQL事务及collection_state
  → SQL成功、相同确认或旧版无需写入后，统一XDEL对应消息
  → 整轮确认所有消息成功处理且无残留，才标记可查询
```

适用[共享有界预取](all-collector-prefetch.md)、[代理契约](proxy-collection.md)、[共享下载资源](download-resources.md)及[弹性缓冲](download-buffer-elastic.md)。开发来源核实与实采使用 `use_proxy=true / proxy_fallback=true`，分别记录代理及回退，不能绕过网站频控。并发由健康出口、全局/站点窗口、实际字节预算及剩余单元共同决定。

目录优先获取可证明完整的动态代码集合，再批量补名称/必要身份；同一响应已包含时直接共用。若只能分页，必须验证稳定身份排序或来源快照契约、总数、页边界、唯一集合和尾页。不能靠默认双读、持续重试到碰巧条数相符或静态代码前缀证明完整。

目录缺码、重复冲突、同数异集或结构异常时保留旧目录。来源完整证明目录退出仅更新当前有效性，不删除已归档日K。重新进入目录时重新检查身份及覆盖，不能把旧代码无条件解释为同一永久基金实体。

日K校验日期合法、响应身份、顺序、重复冲突、范围及截断。真实无成交日期不补零、不插值；交易所开市不证明单只ETF必有K线。未知空帧不得宣称历史初始化完成。局部区间只能修改已证明完整的区间，不能替换整个证券年；来源明确撤回日期必须有该完整区间证据。

### 3.2 实时行情

```text
共享下载 → 固定目标集合及字段校验
  → ingest.publish_volatile公共准入和提交前隔离复核
  → 原子发布Redis最新完整结果及版本
  → Redis正式查询/任务内预览
```

复用现有易失业务准入及预览快照能力，不新建第二归档器、消费组、独立限流器或影子SQL行情表。业务校验失败不替换当前完整结果；保留上次值及其原时间，同时暴露本轮失败/过期，不把旧值标为新采样。

分页或分批响应的来源时间可能不同；本地原子发布只保证查询到同一轮完整结果，不宣称源端所有报价同时产生。每证券保留真实来源时间，未知时间明确为空。来源明确暂无报价应在结果中标识，不能与未请求、网络失败或字段损坏混同。

实时任务可在轮前读取已归档目录和日历元数据，但整个采样过程不产生SQL业务或状态写入。无MySQL可用目录时不得拿过期无证明列表继续标全池成功。

## 4. 字段与时间契约

以下为设计输入；P0核实后在唯一正式对象字典中冻结字段来源、类型、单位、必需性和空值规则。此计划不取代将来正式字段字典。

| 数据 | 字段及候选来源 | 契约 |
| --- | --- | --- |
| 身份 | `unified_code`、名称；字段5/55；原生市场另存必要映射 | 统一使用如 `510050.SH`、`159915.SZ` 的证券键；市场由来源确认，不猜原生市场、不加入stock名单 |
| 日K | 日期1，开7、高8、低9、收11、量13、额19 | 不复权原值；日期是交易日期，实际历史首日由来源确认 |
| 最新基础行情 | 现价10、涨幅199112、涨跌264648、量比1771976、涨速48、成交额19 | 百分数与比例、累计与瞬时量分别核实；不重复计算覆盖来源值 |
| 最新其他行情 | 振幅526792、高8、低9、开7、昨收6、外盘14、内盘2820564 | 显示单位与协议存储单位分别记录，不照搬股票每手股数 |
| 净值 | 页面字段3397 | 核实是何种净值及有效日期；来源没有日期则保留未知，不能写成当日已公布净值 |
| 实时估值 | 右侧页面可见，字段和能力待核实 | 独立于净值；只有来源可取且语义明确才纳入可选字段，不计算冒充原值 |
| 时间 | 交易日期、来源报价/更新时刻、净值日期、采样时刻、归档版本 | 各自独立，不用采样时间代替来源发布时间 |

数值以无损十进制字符串规范，SQL候选为 `DECIMAL(28,10)`；按真实极值和精度验证，不静默舍入或溢出。来源NULL、缺字段、零及暂无报价分开；可选NULL不阻断完整性，必需字段缺失使相应用途检查失败。保留源值与价格关系异常标注，不用填零让准备检查通过。

MySQL DATETIME按北京时间保存；内部版本与Redis时刻使用带时区绝对时间，界面不重复加8小时。净值缺公布/可用时间时，不能作为严格历史信号时点输入。

## 5. 生命周期及恢复

| 阶段 | 目录 | 历史日K | 实时行情 |
| --- | --- | --- | --- |
| 初始化 | 校验完整动态集合，整份归档后完成 | 最近十个正式交易日优先；同次调用后独立历史批次最多64个ETF；逐轮补至来源真实历史首日 | 读取可信目录，完成整轮集合校验和Redis发布 |
| 本轮终点 | 轮开始时来源目录版本/观测时刻 | 轮开始固定正式日历已结束交易日；盘中不归档当日日K | 各报价的真实来源日期/时间和本轮采样时刻 |
| 初始化完成 | 完整集合成功归档或相同确认，队列清空 | 声明目录范围内每证券必要年份/区间均有内容绑定证明，全部消息成功清队 | 全部目标身份均有有效响应或明确暂无；暂无单列，不能称行情全有值 |
| 普通维护 | 每日完整小目录例外；相同内容零业务DML | 十交易日回看；停机遗漏区间补足，已可信核验同截止范围可零请求；不周期全历史轮转 | 每轮取当前值；仅保留最新，不追补离线期间的盘中历史 |
| 历史补缺 | 新代码加入、退出标无效 | SQL可信年度/区间证明识别缺口；最近批次完成后有界补缺，避免历史饥饿 | 不适用历史补缺；下次正常采样恢复当前值 |
| 老修订 | 下次完整目录更新 | 窗口外通过已知异常或显式定向重新核验；不承诺自动发现所有旧修订 | 以更新的合法版本替换最新值，拒绝迟到旧版本 |
| Empire重启、Redis存活 | 续原批次；已发布内容交统一归档 | 按已入队位置续采，不等待前批才能继续下载 | 下一轮重新采样，旧结果按原时间展示 |
| Redis丢失 | 重新获取当前小目录，已归档目录保留 | 从SQL内容绑定覆盖重建，只补未确认范围；不能因缓存丢失重下全池历史 | 最新行情及运行记录丢失，重新采样；不承诺恢复丢失报价 |
| 失败/取消 | 未完成集合不替换旧目录 | 失败不推进断点，后项不越过失败前项；已提交内容安全重放 | 不发布半份成功快照，保留上次值并报错 |

首次尚无身份/行情锚点的ETF通过有界历史批次建立证明；近期空响应不能拿来证明不存在。新触及年份沿用现有年度覆盖所需的年初前缀规则，不能只取十天却伪造整年证明。长停牌需要已知成交锚点时说明额外区间及成本，不由普通失败升级为全池重采。

归档版本按证券日期范围合并，覆盖/年度摘要与事实同事务。可信摘要命中完全免MySQL，SQL没有最后一次内存确认时允许保守重核受影响范围，不冒充能恢复丢失的Redis观测上界。

“继续”恢复未完成批次；“重新采集”只重新核验所选范围的完整来源数据，不删除来源范围外历史。目录版本、选择范围与旧断点冲突时明确拒绝混用，提供沿正式命令结束原批次后重规划的结果，不静默跳过。

## 6. 存储设计卡（拟定）

### MySQL粒度、字段组与索引

| 拟定表 | 一行含义与字段组 | 主键及索引 |
| --- | --- | --- |
| `yuanhang_etf` | 当前目录中的证券身份；名称、原生市场、是否当前有效；必要的内容及版本属性 | 主键unified_code；市场/有效性/证券键组合索引按查询EXPLAIN确认 |
| `yuanhang_etf_daily_price` | ETF×真实交易日期；开高低收、成交量额 | 主键(unified_code, trade_date)；索引(trade_date, unified_code) |
| `yuanhang_etf_price_year` | ETF×年份；行数、首末真实日期、键及内容摘要、已核验范围、规范版本、来源市场及必要版本属性 | 主键(unified_code, quote_year)；不增加逐轮/逐日采集状态表 |

固定来源通过数据集归属声明，不重复恒定source列；历史事实不外键级联到当前目录。年度证明不保存第二份K线正文。每证券日期区间的必要版本状态沿现有collection_state单元路径保存，不能无限堆叠每次请求日志；验证实际序列化上限及压缩合并后的区间边界。

相同规范内容不执行业务DML；只更新有效变化行。完整区间确认允许修订区间内事实；旧响应不覆盖新日期，SQL提交后Redis确认失败能够原路径重放。目录完整性与业务状态原子归档，单页不能被误识别为整份目录。

### Redis类型、归属、期限及清理

| 对象 | 拟定身份与结构 | 保留/恢复 |
| --- | --- | --- |
| 目录数据集 | `yuanhang.etf.catalog`；job `ths-yuanhang-etfs`；摘要命名空间 `yuanhang_etf_catalog_v1` | 复用公共ingest Stream、checkpoint、fingerprints及expiry；成功按确切消息ID清队，失败保留 |
| 日K数据集 | `yuanhang.etf.price.range`；job `ths-yuanhang-etf-prices`；摘要命名空间 `yuanhang_etf_prices_v1` | 按ETF日期比较、按年有界发布；公共摘要默认7天/10000项，淘汰回SQL而非丢业务 |
| 最新值 | 拟用 `<namespace>:yuanhang:etf:latest` Hash；完整结果元数据、证券行情与版本；归实时项目 | 最后成功发布后7天TTL；整份原子替换使退出证券不残留，不增加持久历史键；旧版本拒绝 |
| 查询快照 | 若跨页排序需固定结果，复用已有有界预览快照机制 | 使用公共期限及淘汰；只供分页会话，不构成业务历史库，失效需重新查询 |
| 运行及错误 | 复用每项目运行100条、归档100条、错误300条及现有revision键 | 错误正文最多64KiB并脱敏；本次未按错误记录修复，不清理现有错误 |

实时结果带schema版本、轮次身份、目标目录摘要、各证券来源时刻、采样时刻、可用性和版本。7天是内存保留期限，不是新鲜度：交易时段超过180秒未有效采样标过期；来源行情日期及净值日期各自显示，休市/盘外不得误标为实时更新。键的确切字段与Lua发布方式在P1核对公共快照/易失准入实现后冻结并登记，所有写入继续通过公共隔离复核。

### 查询、容量与性能预算

- 目录按有效性/市场/代码查询，默认200条、最多500条；日K按证券日期范围，列表默认200条、最多500条，图表单次最多10000真实点；按指定日期跨ETF查询使用日期优先索引。
- 最新行情支持代码/名称筛选及数值排序，排序后分页；完整结果上限5000个ETF，每证券规范值最多4KiB，整份Redis发布正文最多24MiB。查询读取与处理也受此上限及公共资源预算约束，不在UI下载全池后伪分页。
- 初始目录上限5000个ETF，每证券年度证明最多150年、每年最多366个真实日期；上限是资源边界，不是来源已有数量或历史长度。源端超过边界明确失败并重新设计，不截断完成。
- 容量按P0实际目录数N和各证券真实年数计算。仅作算例，N=5000、每年250行时，一年新增约125万行、五年约625万行；不是实采结果。先以目录含索引64MiB、年度证明256MiB、日K含索引16GiB为部署空间预算，基于真实行宽、历史跨度和最大边界压测决定可交付容量；不能仅凭理论行数宣称满足。
- 目标：目录/最新行情分页P95≤100ms，单证券一年P95≤100ms，单日跨ETF分页P95≤150ms；隔离库10万日K初始归档≤30秒。注明冷/热缓存、机器、MySQL版本、索引实际分配、峰值内存、EXPLAIN、扫描行数及返回字节。
- 预算未达标先优化布局/批读写；确需收窄支持范围或改变预算时说明实测和取舍，不用提高超时或删测试掩盖问题。DDL、全部字段、CHECK、表组及JSON状态上限在写库代码前冻结。

## 7. 请求与写入成本预算

定义：N为目标ETF数，C为一次完整动态目录的已验证必要请求数，B为已验证的批量行情上限，E为去除重叠后的历史补缺请求，A为认证/辅助请求，R为统一有界重试。C、B及平均字节目前未知，P0测量后补录，不能把客户端示例页大小当协议上限。

| 情形 | 基础业务请求预算 | 传输、入队和SQL边界 |
| --- | --- | --- |
| 首次目录 | C；名称已在响应中则不重复取 | 一份完整目录进入Redis归档；只保存当前业务，无逐轮快照 |
| 首次日K | 全历史部分约每ETF一个完整响应；若协议必须分段则计真实分段；每历史批最多64个ETF | 近期和历史重叠消重，完整历史已覆盖近期时不再短查；按年入队，仅首次事实写入 |
| 无变化维护 | 目录每日C是全量小集合例外；日K已可信核验同截止范围时为0，否则至多N个近期区间请求 | 下载过则不能声称零来源成本；相同规范内容零业务DML |
| 新交易日 | 日K至多N个近期区间请求，长期停机须补全部遗漏范围 | 字节随实际区间；仅新增/有效修订事实写库，不能称逐ETF请求数已降低 |
| 实时一轮 | 优先ceil(N/B)；若只支持逐证券则N，须实测代价 | 完整合法结果只发布Redis，无SQL业务DML；盘外无到期事项为0 |
| 精确补缺 | E；同一完整响应与近期复用 | 只处理有可信缺口的ETF/年份/区间，不扫全库正文 |
| Redis丢失 | 目录至多重读C；实时重新采样；日K从SQL恢复缺口后计算 | 不因摘要丢失全池全历史重下；保守重核范围单列 |

每项再加A和R，区分HTTP请求、原生逻辑请求、连接建立及连接内认证交换；复用现有会话不等于不发生业务请求。分别记录线上/解压字节、预取占用、入队条数/字节、实际业务插入/修订/相同确认数量。正常每必要响应一次，不默认重复下载核对。

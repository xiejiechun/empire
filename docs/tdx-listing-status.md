# 暂停恢复终止上市（通达信）

## 入门与范围

采集投资日历 → 公司日历 → 每日特别提示中的“暂停恢复终止上市”。一个项目保存暂停上市、恢复上市、终止上市三类来源事件。用途是查阅证券在什么日期发生这些事件；最后交易日不是必需字段，也不从退市日倒推。普通停复牌、ST、退市整理期和重新上市不属于本栏目完整性承诺。已核实盐湖股份2020-05-22暂停、2021-08-10恢复，以及1999-07-12琼民源终止上市；2019-01-08长油重新上市在本栏目没有记录。

声明查询范围为1990-12-19至本轮启动时的北京时间日期，沪深A股（不按当前股票名单过滤）。该起点是明确的采集边界，不是已证明来源最早记录或全部历史无遗漏；北交所、B股及栏目未提供的事件不宣称覆盖。数据准备按声明范围的有效响应与已归档集合核验，不用事件最大日期代替完整性。

## 日常操作

“最近一个月”的回查按完整月归档边界执行，具体为本月及上一自然月，并非精确滚动30天；更早月份按缺失/无效证明补采。

在采集管理搜索“暂停恢复终止上市（通达信）”，普通采集续跑未入队月份、补缺并回查最近一个月；重新初始化逐日重新核验全部声明历史，保留已归档内容，按新完整月份响应接收来源修订。默认每天北京时间18:00，代理优先、允许直连回退，任务开关、计划与网络策略仍可编辑；已保存配置优先。任务在整轮业务消息已归档并清队后才完成。

在数据浏览的证券基础目录打开本页，按证券代码、事件类型、日期范围筛选，游标分页每页最多200条；说明可按行查看。没有事件的已核验日期与尚未采集日期不同，来源简称也不承诺是历史当日名称。

## 生命周期与完整性

| 项目 | 契约 |
| --- | --- |
| 初始化 | 1990-12-19至固定启动日，按自然月、月内逐自然日查询；当前月只到启动日。 |
| 完整单位 | 每天一次最多1000行的完整响应；达到响应边界、重复业务身份、结构/元数据/总数不符或未知事件类型则失败；每月所有日期校验后原子入队。 |
| 完成 | 全部计划月份入队后统一等待该批所有消息成功处理；下载结束或最高成功页不是完成。 |
| 后续 | SQL月份证明缺失或无效时补整月；每轮重查最近一个月及所有新增/未完成月份。完整证明保存在每项目唯一collection_state，空月也可证明已核验。 |
| 修订 | 完整月份覆盖该范围旧事件，相同规范内容零业务DML；较早观测响应不得覆盖较新核验。观测顺序仅防止已见响应倒退，不冒充来源修订号。更早修订须重新初始化。 |
| 中断 | 月内失败重查该月，入队成功后断点才前移；入队后继续下载，不逐月等归档；SQL提交后Redis失败原队列重放。 |
| Redis丢失 | 依据SQL月份内容证明重新规划；缓存核验可能未更新SQL上界，允许重复核验；不承诺恢复丢失的未归档消息。 |
| 范围冲突 | 活跃断点保存固定终点及fresh模式；普通执行续原范围，fresh与活跃普通范围冲突明确拒绝；不丢待归档消息。 |
| 进度 | 下载日期/已入队月份与归档证明分别呈现；实际范围在验收记录记载，不把代码支持范围写成已采完。 |

## 存储设计卡与字段字典（实现前设计）

一行是同一证券、来源日历日期、事件类型、来源说明对应的来源事件。唯一键为(event_date, unified_code, event_type, record_key)，record_key是规范证券/日期/类型/说明的SHA-256；没有来源ID，不裁定并列说明唯一事实。名称不参与身份，名称修订更新原行；说明修订通过完整月份删除旧事件并新增。NULL说明保留未知；不截断业务字段。

| 字段 | 来源及类型 | 语义与上限 |
| --- | --- | --- |
| unified_code | sc+code → ASCII VARCHAR(9) | SH/SZ证券，含前导零；无当前stock外键 |
| event_date | 请求sdate及返回元数据 → DATE | 本栏目来源日历事件日期；终止上市日记录即来源提供的退市日期 |
| event_type | sj → ASCII VARCHAR(16) | suspended / resumed / terminated，未知值报错 |
| record_key | 上述身份摘要 → ASCII CHAR(64) | 同日同证券不同说明分别保存 |
| name | name → VARCHAR(100) | 来源返回简称，非历史名称证明 |
| description | sjcontent → TEXT NULL | 最多2000字符；早期可能已由来源截短，原值保存 |

正式读写只使用security_listing_event。主键支持日期范围全市场；ix_security_date支持单证券范围；ix_type_date支持类型日期筛选。列表只选身份、日期、类型、名称，不带正文；详情按完整身份点查。正式SQL及EXPLAIN/读取字节/P95由容量实验记录：列表和单证券200行<=50ms，月覆盖<=100ms；5万条实验分配<=128MiB、初始化<=15秒。预估每年最多2000事件、五年1万条；实际最大单月不超过5000条，响应1000行、单条说明2000字符；超过共享消息预算明确失败，不调高公共限制。预计128MiB足够覆盖实验规模含索引，迁移仅新增空表，无复制临时空间。

每月SQL证明包含完整起止、规范内容摘要、来源/规范事件条数、契约及最新SQL核验绝对时间，与事件增删改同事务提交。完整查询审计核对集合摘要而非仅条数。缓存只存月摘要及观测版本，命中免SQL，成功仍清队；旧响应拒绝后不缓存为当前。直接改库前停归档并失效对应摘要及月份证明；应用启动不迁移。

## 故障处理与维护

失败月份不推进断点，来源校验失败不日常双读；网络异常走公共有界重试。页面查询不依赖Redis。来源未给的原因及公告日期不阻断普通事件查阅，不推算最后交易日，不根据名称判断是否退市，也不根据一次退市推断永久不能重新上市。

新增表由scripts/create_listing_event_schema.py显式维护：关闭Empire、队列为0、获取数据库维护锁，核对前后既有表数量/结构及统一状态；不修改既有业务数据。新空库仍用init-db。容量/专项/隔离集成、真实范围及正式发布证据分别记录。

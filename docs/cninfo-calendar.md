# 大 A 交易日期（巨潮资讯）

来源接口：`https://www.cninfo.com.cn/data/tradeday/getMonthTradeDay?month=2026-10`。按月请求，使用 `monthTradeDate` 中的 `tradeDate`、`isTrade` 和校验用的 `week`。不保存完整成功响应或冗余星期字段；星期从日期计算。交易标记完全采用来源返回值，不以周末推算历史或未来安排。

## 采集范围

已核验 1990-11 返回空列表，1990-12 从 1990-12-19 开始返回 13 天；历史起点为 1990-12-19。

首次补齐起点至下一自然年 12 月。2026-09 首次范围为 1990-12-19～2027-12-31，共 445 个月、13,527 个自然日，包含休市日。后续从本月维护到下一自然年年底：2026-09 的范围是 2026-09～2027-12，共 16 个月、487 天；2027-01 时范围变为 2027-01～2028-12。

每轮先按 MySQL 实际日期数检查历史月份，已完整的历史月不请求，缺月或不完整月份会补采。因此 Redis 断点丢失后不必重采全部已归档历史，但仍会重建当前及未来的维护计划。运行期间固定本轮范围，下一轮按北京时间重新计算，避免跨月改变进行中的游标。

普通“立即采集”执行缺月补齐和维护范围；“从头重新采集”明确重查全部历史，不删除既有日历。

## 使用与计划

在“采集管理 → 采集任务”选择“大 A 交易日期（巨潮资讯）”。新任务默认手动，固定间隔预设为 1,440 分钟，可设置每天执行。日期维护一般设置每日一次即可；共享网站间隔在“网站频控”统一管理。

“数据中心 → 交易日历”支持按年/月、上月/下月和回到本月查看；交易、休市、未采集三种状态明确区分。未来日期是来源当前安排，可能变化，每轮维护会更新修订；不是未来交易所公告已全部确认的声明。页面只查询 MySQL，每 15 秒刷新显示，不直接请求网站。

关闭桌面后可运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m empire collect-calendar
```

可选 `--fresh` 重查全量。命令行和桌面共享单实例保护；应用关闭后自动计划也停止。

## 校验与存储

按月要求完整连续日期（首月从 19 日开始），拒绝重复、跨月、缺日、非法交易标记及星期不匹配。空月或来源暂缺不会转换为“全月休市”，而是保留失败月断点和错误样本。成功月份每 60 秒进入普通归档流程，独立 SQL 事务完成后才删除对应 Redis 消息；无效或尚未完成的月份不会覆盖已有日历。

`trade_calendar` 唯一键为 `(source, trade_date)`，当前 source 为 cninfo，字段只有来源、日期、交易标记及最近实际变更时间。事务内读取该月当前记录，只插入新日期或更新变化标记，完全相同的数据不产生业务 INSERT/UPDATE/DELETE。

Redis `archive:observed:calendar.month:cninfo` 按月份保存最新成功观测时间，用于拒绝比最近核验更旧的响应；即使内容不变，也只推进这个内存字段。SQL `updated_at` 额外防止已变更月份倒退。来源接口不提供修订版本号；Redis 重启后观测记录会丢失，但同一 Redis 中的旧队列也不再存在。

断点 `checkpoint:cninfo-calendar-v1` 保存月份计划与下一个月份位置；`archive:progress:cninfo-calendar-v1` 保存最近已归档序号。运行只有在本轮所有月份已提交后才完成。项目运行/归档记录各 100 条，错误 300 条，全部只留 Redis，不归档。修复样本后仅清理已验证的确切错误 ID。

新增业务表通过明确建表操作创建；应用启动不迁移数据库。首次建表及验证记录见 `sql/changes/2026-09-23-cninfo-calendar.md`，完整字段与游标解释见桌面“说明文档 → 交易日历表与月份断点”。

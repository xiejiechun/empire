# 下载资源管理设置验收

日期：2026-09-26。用户要求：下载大小应能在管理后台设置，并明确接下来继续做什么。本轮只扩展已有下载器的管理、持久化与校验入口，不新增公告采集、PDF 解析或下载业务数据表。

后续变更：本文件保留初次下载资源管理的验证历史。当前已扩展规划设备/全局窗口及十档一键推荐，默认 100 档为 128 窗口与 512 MiB，相关配置升级与当前结果见 [出口容量验收](exit-capacity-review.md)。旧九字段与当时默认值不代表现行契约。

## 实现与验收清单

| 要求 | 实现边界 | 验证重点 |
| --- | --- | --- |
| 后台可设大小 | 独立入口“采集管理 → 下载资源”；单响应以 KiB、缓冲及文件容量以 MiB 呈现 | 入口可访问、插件独立启停、页面按需创建、窄窗口保存可达 |
| 小响应与大文件分开 | 可设股票、新闻、日历、通用单响应上限；可设文件上限、目录配额、余量及文件并发 | 超大 PDF 不要求等额内存缓冲；插件更严格文件声明仍有效 |
| 保存重启不丢 | MySQL `app_setting`，`kind=download`、`setting_key=global`，按 namespace 隔离 | 同值不重复写库；失败不改已保存值；重新启动载入新值 |
| 不打断当前任务 | 页面区分当前运行、已保存与待生效；正常重启后统一启用 | 保存不修改当前下载器、不取消当前采集，不隐式重启 |
| 防止不可运行设置 | 后端统一验证范围、整数、最大单响应预留与缓冲关系、文件与目录配额关系 | UI 与直接命令均拒绝非法配置；失败保留草稿 |
| 草稿与交互安全 | 刷新不覆盖编辑；恢复默认只改草稿，仍须保存；数字控件沿用全局滚轮保护 | 切页/刷新保持草稿；保存期间重复操作；滚轮不改数值 |
| 单一配置路径 | 资源数值只存 MySQL；机器目录只保留 `http.download_directory` | 旧 TOML 数值显式拒绝；迁移冲突不覆盖，不新增运行时兼容层 |

资源关系：`3 × 最大单响应上限 + 256 KiB ≤ 全局缓冲`，`单文件上限 ≤ 下载目录配额`。缓冲是下载器的预留预算，不是进程总内存上限；设置大小不是设置网络速度。默认值及生命周期详见 [下载资源边界](download-resources.md)。

## 迁移与生产保护

旧 TOML 的资源数值由 `scripts/migrate_download_settings.py` 显式维护：需正常关闭 Empire，先核对已有 SQL 值；冲突不覆盖，成功持久化后移除旧数值键。配置目录路径保留。应用启动不执行迁移或 DDL。

仅对仍含旧资源数值的配置执行以下命令；在项目根目录先核查，再明确执行迁移：

```powershell
.venv\Scripts\python.exe scripts\migrate_download_settings.py
.venv\Scripts\python.exe scripts\migrate_download_settings.py --apply
```

当时的旧版 `config/local.toml` 已核实没有旧 `[http]` 资源数值，因此不需要在生产执行这项维护；当前正式配置位置已迁至 `%LOCALAPPDATA%\Empire\config.toml`。不输出连接密码，不清空共享 Redis，不删除业务数据、下载文件或生产错误记录。本轮问题来自功能要求及测试，不按生产错误 ID 清理记录。

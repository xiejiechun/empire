# 全部采集任务的共享有界预取

## 日常操作与生效

各站独立拥有全部健康出口槽，例如7个出口支持THS和开盘啦分别最多7个在途请求。同站点任务共享本站槽和许可，各站合计仍受全局下载窗口、缓冲及各自安全阀限制；一站不会仅因占用了设备而抢掉另一站的出口槽。

在“采集管理 → 采集任务”查看任务网络区，在“采集出口”查看站点实际在途数和最近 10 秒请求率。独立下载单元使用同一 `ordered_prefetch`，窗口取健康独立出口、站点/全局窗口、共享缓冲及剩余单元的限制。可用并发是上限，预取窗口包含已下载待校验的结果，两者都不是实际在途请求或成功入库速率。

正常重启使用新版程序后生效；任务计划、网络选择和网站限速继续使用已保存的 MySQL 配置，不重置、不自动切换限速模式。没有健康代理时按既定策略回退或等待；直连窗口为一，同站点本机最多一个在途请求。无需建表、改业务键、清队或重建断点。

## 全部任务的下载边界

| 任务 / 数量 | 可独立预取的单元 | 先决依赖及完整性单位 |
| --- | --- | --- |
| 新浪股票 / 1 | 已知总数后的分页 | 先读总数；按页校验排序、数量、集合及尾页，再发布完整列表 |
| 新浪新闻 / 1 | 单页，窗口固定为一 | 下一页 ID 必须来自前页；初次/fresh 只请求最新第一页，增量遇上轮上界停止 |
| 巨潮日历 / 1 | 计划中的月份 | 仍按月份完整日期集合校验、原子入队；历史补缺和未来修订范围不变 |
| 通达信停复牌 / 1 | 当前自然月/续采段的日期 | 第一完整响应可预取；扩大容量和重复复核依赖该响应，在日期顺序消费者中执行；仍按连续日期有界拆批 |
| 通达信暂停恢复终止上市 / 1 | 当前计划月份中的日期 | 按日期消费，整月日期及事件集合校验后入队；失败月份不跳过 |
| 通达信分红 / 1 | 证券完整历史响应 | 证券顺序消费；失败处保留连续断点，独立成功证券沿用原有侧批归档规则 |
| 通达信增发 / 1 | 已校验完整列表中的不同方案 ID | 先读完整列表；需要补采/回查的 ID 本轮只请求一次，别名共享结果；按原证券顺序组装完整单元 |
| 通达信配股 / 1 | 一份完整列表，必要 HTTP 请求只有一次 | 不拆为不稳定偏移分页，不增加重复下载；之后按证券单元发布 |
| 通达信公司/股票更名 / 2 | 每任务一份完整历史响应 | 不拆响应，三个市场同次原子入队；窗口受本轮单元数限制为一 |
| 同花顺三张财报 / 3 | 证券完整矩阵 | 三任务分别共享 ths 频控，按证券顺序校验及入队；矩阵完整性、来源精度和信号日期限制不变 |
| 同花顺上市发行资料 / 1 | 本轮必要证券 | 先按 SQL 补缺和七天回查规划；跳过可复用证券；来源暂无状态继续沿用独立证明 |
| 同花顺行业 / 1 | 目录返回后的行业成员响应 | 先校验目录；按行业代码消费并核对成员及跨行业集合，完整快照才入队 |
| 开盘啦七项 / 7 | 当前证券的必要交易日 | 沿用已有共享预取、按日期校验与入队；业务别名核实、缺口侧批和回查范围不变 |

合计 22 个正式任务。四个任务不声明独立多请求并行：新浪新闻、配股、公司更名、股票更名。它们也遵守共享下载、预算、频控和取消回收；协议依赖或单响应不是漏接预取，也不要求人为增加请求。

## 生命周期、失败与恢复

本次只改变下载调度，业务粒度、消息 schema、SQL 结构、初始化范围、日常补缺/修订回看和归档完成边界均沿用来源生命周期文档：[新闻](sina-news.md)、[日历](cninfo-calendar.md)、[停复牌](tdx-suspensions.md)、[上市状态](tdx-listing-status.md)、[资本事件](tdx-capital-actions.md)、[财报](ths-financial-statements.md)、[上市资料](ths-listings.md)、[行业](ths-industries.md)、[开盘啦](kaipanla-intraday.md)。新浪股票仍以完整当前列表为单位。

下载可以乱序结束，来源业务校验、规范化及 Redis 发布由原顺序消费者执行。前项失败不推进连续断点；资本事件和开盘啦已有的独立成功侧批仍可归档，但不建立完整轮次证明。来源协议必需的额外请求继续按明确触发条件执行，不为集合校验默认双读。

成功响应直到消费/关闭都计入预留；响应关闭与预取窗口所有者释放额度分开，防止提前释放后积累未消费结果。失败、取消和提前结束由共享预取器回收已完成响应并等待在途请求退出，包括重复取消。源端错误诊断在正文关闭前保存，保持每项目有界、脱敏及原有去重规则。

消息校验入队后继续下载，不逐证券、日或月等待归档。整轮入队结束才确认全部消息成功处理；统一归档器仍负责摘要、事务、旧版防覆盖和成功清队。Redis 存活时从已原子提交位置恢复，预取但未发布结果需重下；Redis 丢失按各来源现有 SQL/范围证明重建，不保证恢复内存最近核验上界。

## 验证边界

`tests/test_all_collector_prefetch.py` 对十类新接入的独立下载适配器检查首项延迟、后项先返回、首项无效和取消，直接使用来源解析器；在首项完成前后项不得解析、发布或确认整轮。原有新浪股票和开盘啦专项继续覆盖共享预取。`tests/test_unit_prefetch.py` 使用真实 HttpService/ManagedResponse 验证不重复预留、结果保留到消费、低缓冲无自等待及关闭前错误样本。来源专项和独立数据库集成继续验证正式查询、生命周期、摘要、修订和清队。

开发与有限实采证据、发布结果和当前断点另记在本次交付记录。并发容量或模拟乱序不代表真实节点源站吞吐，不承诺提速倍数或全历史已经采齐；未完成/异常单元仍须按来源范围处理。

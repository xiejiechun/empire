日期：2026-11-17。状态：本轮交付实施计划，尚未新增运行时能力或执行结构维护。用户要求折算校正必须完成，不能以未校正估算或一句风险提示替代。本文承接[份额与净值实施计划](etf-shares-nav-implementation-plan.md)及[首版交付](evidence/etf-fundamentals-delivery-20261117.md)，只规定后续增量范围；采集和存储继续遵守[采集指南](collector-development-guide.md)、[数据库设计规范](database-design-standard.md)、[统一归档](archive-deduplication.md)和[来源规则登记](collection-rules-standard.md)。

## 1. 目标与当前缺口

正式指标为“ETF净申赎估算（已作折算校正）”，提供本日及前一交易日金额、实际覆盖与排除原因。仍是按日份额和单位净值估算的申赎规模，不是实际现金到账额，也不等同场内资金买卖净额。完成条件同时包含人民币计价依据、有效总份额/净值关联、真实折算事件校正、误差验证及复盘接入。

现有日K只有开高低收、成交份额和成交额，没有每日存续总份额。已有总份额、净值两类事实无需重建；11月16日与前一交易日11月13日只需11月12、13、16三日总份额和13、16两日净值，其他日期按正式日历动态取得。全历史继续有界补缺，不作为近期计算的前置条件。

现有代码中天天基金净值currency固定为NULL；read_etf_flows未接入adjustments，因此即使基本输入齐全也无法形成可用金额。本期必须完成正式关联，不能只增加表而保留该挡板。当前股票权息和股本原生身份仅支持USHA/USHT/USZA/USTM，ETF为USHJ/USZJ；股票送转字段、复权系数及其“无权息”证明未经ETF协议验证不能直接沿用。

此前六只基金资料与两个净值页面的抽查，没有得到覆盖全部ETF及历史期间的独立币种字段；海外资产、人民币比较基准、当前交易报价均不能单独证明指定历史净值币种。这是待完成的来源规则核实，不是已发现这些ETF使用外币。

每类输入只保留一条正式归档与查询链路：结构化清单负责发现事件和范围证明，实施公告提供同一事件的实际参数，不建立两套并行计算。具有官方含义的唯一事件ID优先；没有稳定ID时冻结可验证的来源身份，实施修订不能因比例变化被当成不相干新事件。多来源描述合并只在同一事件关系明确时进行；冲突保留并排除该事件区间，不能自动平均或把后下载者当正确者。

原生211的ETF能力仅作有界候选核实；未证明前不是折算的唯一来源，也不修改股票解析契约。若正式来源只提供全量小清单，可首次取得完整清单并以摘要减写，但须明确它是全量核验及每日成本，不能伪称增量。

P0退出必须有至少一个可复现的已实施折算来源，证明实际比例、生效边界和来源无事件范围如何判断；只有币种/公告概览或仅能做疑似提示不得退出。缺少可信实际事件参数时继续核实官方候选，不把“折算以后再做”作为交付。

## 3. 折算算法与事件边界

令P为上一个交易日，D为当前交易日，Q为以真实份计的总份额，V为D日人民币每份单位净值。区间(P,D]内的已实施事件必须按其实际影响份额快照的生效时点排序。

对于在本日申赎前完成、实际折算比r定义为“新份/旧份”的普通拆分或缩份：

`B = Q(P) × r`

`净申赎份额估算 = Q(D) − B`

`净申赎金额估算 = [Q(D) − B] × V(D)`

普通无事件区间的r=1仅在来源覆盖核验成立时取值。多个单纯单位转换依次复合；若存在已知其他非申赎份额调整，必须按其发生顺序将其数量也换算到期末单位后加入B。来源有“实际折算后存量份额”且基准范围一致时优先使用，不用公告截短比例覆盖更精确实际数量。

固定例：上日1亿份，一拆二，本日2.04亿份，D日净值0.5元。调整后基准2亿份，净申赎估算200万元；未校正将误报5200万元。没有真实申赎且数量精确时，纯折算前后应为0，不得因折算制造资金流。

适用与排除规则：

- 拆分、缩份、首次上市前集中折算、份额合并/类别转换分别确认语义；初始份额无可比前值时不把发行规模当日申购。初次折算作为真实校正反例，但没有两日可比输入时仍不出金额。
- 同日申赎与折算的先后影响申赎份额所属单位；仅在源规则能证明日终差额可比时计算。顺序未知、事件跨多个份额类别或缺少准确调整数量的区间排除，不能机械套乘积。
- 现金分红不直接改变总份额，不能从份额差里扣分红现金。份额红利/红利再投等确实增加份额的事件，只有有据的实际新增份额才能调整；金额不能直接作为份额相减。
- 登记日、除权日、公告日、上市恢复日与实际份额变更日分列；周末和休市期间事件按实际时点进入(P,D]，不能将公告日当生效日。
- 分红复权因子混有现金分红及价格信息，不能直接作为份额折算比例；日K或净值断点只能发现疑点，不能替代实施参数。
- 舍入按实际公告规则处理；只知道截短比例时计算误差上界，无法满足误差预算则排除，不能静默四舍五入。

异常检查使用份额比、净值比、已披露净值增长率、分红及已有不复权行情的联合变化寻找疑点。固定大额真实申赎、行情暴跌、净值迟发和现金分红反例，防止被误判折算；不把某个大幅变化阈值作为自动生成r的依据。

## 4. 单只准入及合计口径

每只ETF按期间生成一个确定状态：可用无事件、可用已校正、缺份额、缺净值/披露延迟、收益口径不适用、币种/单位未确认、事件覆盖未确认、事件参数冲突或异常待核实。同一证券不能在合计中重复；原因可多项但排除计数按唯一身份计算。

进入合计需同时满足真实日期、两日总份额、D日单位净值、人民币计价基数，以及(P,D]事件完整性。没有事件记录和已证明该区间没有事件不是同一回事；仅抓到几个折算事件还不具备全池无事件准入。疑点不能通过折算推断或填0消失。

目标池按所选日期已知上市/有效状态定义；缺少可靠历史状态时继续标“按当前ETF目录回看”，不可把未覆盖或没有行情的证券静默删出分母。收益型货币基金等只在明确类型依据下列为不适用，同时展示总目录、适用和有效三个数量。部分覆盖只显示已覆盖样本合计，不能标全市场。

本期近期数据范围优先最近20个已结束交易日，先补两个指标所需三日份额、两日净值及相关事件。初版正式覆盖以实采来源范围为准，其他历史有界推进。跨境净值迟发留“待披露”，不以最新已披露净值顶替指定日。

证券键统一unified_code；例表code只是说明简写。数字采用能承载源精度的DECIMAL，比例优先保存来源明确的分子/分母，不经float；P0测得精度后冻结，暂按DECIMAL(38,18)规划，超范围拒绝而非截断。源原始比率文本/舍入说明有界保留用于解释，不能替代结构化计算字段。证据URL上限2048、必要事实摘录上限4096字；不长期保存完整成功响应或完整公告PDF进Redis/MySQL。若需下载PDF，走共享文件资源与独立解析，不把“下载成功”当作“字段解析成功”。

查询计划至少包括：证券区间事件与修订详情；按生效日跨证券列表；两个复盘日期的币种区间、事件及完整性批量查询；年度正文审计和恢复规划。列表最多500行，稳定键分页；复盘最多5000证券、两个计算区间，一次批量取得区间涉及事件及覆盖，禁止逐ETF查询或逐ETF回源。为日列表和证券范围分别做EXPLAIN，不因方便给每列建索引。

容量预算先按5000证券压力池：计价依据10万条、事件20万条、年度头15万条，含所有索引目标不超过512MiB；这是测试预算，不是源站已有数量。年度单元最多1000事件/1MiB、单证券总正文最多8MiB，证明版本段沿用已验证有界范围模型且不超过366段；状态仍服从公共16KiB限制。实测不满足时评审实体/查询，不简单扩大公共上限。

## 6. 采集生命周期与成本

计划在同一业务模块登记“ETF计价依据”和“ETF份额变动事件”任务，只有需要独立来源/生命周期时拆成两个任务，不按来源页面数增加固定菜单。category=基金数据，source_name按P0最终正式来源填写；默认结束后等待12小时，保留用户已保存策略。来源明示更快实施发布时再以证据调整默认计划，不暗改已有任务。

| 场景 | 计价依据 | 事件与范围证明 |
| --- | --- | --- |
| 初始化 | 先覆盖近期有效目标池；每轮最多64个完整证券，规则可覆盖一类时保存规则依据与可验证适用范围 | 最近20交易日相关区间优先；全池近期每轮最多64证券或一个来源完整批量窗口，再最多16个历史证券年度 |
| 日常/无变化 | 每7天轮转旧依据，每轮最多64证券；已知规则版本变更及新增产品优先 | 近期10交易日及未来30自然日已公告事件优先；近期单元按12小时到期，批量/窗口能力优先，另有界补历史 |
| 修订与撤回 | 区间更正使受影响依据失效并重算，不覆盖成当前币种的全部历史 | 预案转实施、实际比例修订、取消逐条更新；每月轮转32旧年度；历史修订时效按轮转周期披露 |
| 中断/Redis丢失 | SQL内容证明决定尚未归档范围 | 恢复冻结计划与已入队断点；SQL已归档的完整范围复用，不因丢缓存整池重采 |

若按证券首次完成近期覆盖需要ceil(N/64)轮，12小时间隔会拖慢交付；因此P3/P4用正式采集器的显式近期范围分批连续初始化，每批受相同资源边界且成功清队，不等待日常12小时间隔、不改用户保存的计划、不新增临时调度器。结构维护须正常关闭客户端，已有运行的采集/归档不能与显式初始化争用。

来源P0必须分别预算：初始化、无变化、新增一个完整单元、精确补缺/修订及状态丢失恢复的请求（含认证/辅助/重试）、线上/解压字节、入队量及SQL写入。设完整来源清单页数为P(s,unit)，新详情数为K，则请求预算为ΣP+Σ详情必要请求+有界重试；非变更公告正文不日常重复下载，需发现旧修订的检索仍计请求，不能把重复零SQL写入称零请求。来源不支持日期过滤则注明首次全清单、后续核验周期及实测成本，不能假定有增量接口。

所有来源核实、公告解析与实采都走共享代理/下载/频控/预取；不另写直连下载器。每必要响应正常只取一次，分页集合验证不默认双读。有界单元完整校验后业务与断点原子入队，继续下载；整轮发布完再等全部归档成功及清队。相同内容零业务DML、旧版防覆盖、可信摘要、异常隔离、错误有界保留和精确ID清理全部沿用公共路径。

## 7. 准确性和覆盖验收

“偏差不大”拆成可测的三项，以下是实施目标，尚未实测通过：

1. **校正算法无系统误差。** 已证实无申赎的纯拆分/缩份案例，校正后份额差必须在公告舍入允许范围内为0；正向/反向/多事件单位转换正确。实际比例截短导致的数量误差按上日份额放大，误差上界计入证据，不能用统一阈值掩盖。
2. **有独立底稿的金额误差。** 用官方实施结果、实际数量及独立计算的参考值逐ETF核对，不能让被测函数生成自身期望。单ETF误差目标≤max(1万元,参考金额绝对值×1%)；在参考样本绝对金额合计≥100万元时，Σ绝对误差/Σ参考金额绝对值≤1%；小金额样本合计绝对误差≤1万元，并单独执行纯折算零值检查。合计使用逐项绝对误差，不能以正负相抵通过。精度理论上界已超过门槛的样本不能算通过。
3. **覆盖不掩盖偏差。** 近期正式范围目标为适用ETF有效数量≥95%，每项排除可追溯；已知大规模缺项单独列出，不能用高数量覆盖声称金额偏差≤1%。若有可核验的全适用池净资产分母，再增加已覆盖净资产权重≥99%的“接近全市场”门槛；没有该分母时不输出该声明。低于覆盖目标仍可展示已覆盖样本，但“近期接近全市场可用”验收不通过，来源披露延迟单列。

上述1%约束是同口径折算校正重建的验证目标，不是实际现金流准确率承诺。份额日差乘D日NAV与真实申赎现金还可能因时点、现金替代、费用和实物交割不同而有差异；没有独立申购/赎回实际金额不能验收现金误差。没有足够独立底稿时明确“金额准确性待验证”，不能只用程序自洽宣布≤1%。未覆盖ETF的误差没有可靠上界时明确未知，不将样本门槛外推至全市场。

开发实采按冻结目标约5%完整证券/日期/事件单元，固定种子、总数、清单及实际比例；1741池约88只，只作示例不硬编码。固定加入已实施折算的真实事件，目标至少5个完整事件窗口，至少包含2个非整数比例案例；缩份、同日多事件、重投等若找到真实案例则必纳入，未找到的保留模拟边界并如实注明未实采该类型。不得用全部无事件样本替代折算实采，也不得用原来的份额/净值5%验收替代新事件验收。

事件窗口必须完整采来源所需前后份额、净值、币种及实施依据，至少覆盖事件前2个和后2个交易日；依官方实际生效边界扩展，不能截取页面凑比例。原来源确实无历史份额的事件只能证明解析，不能冒充端到端金额通过；继续选择能端到端验证的事件且保留失败名单。至少3个大额真实申赎非折算案例及3个现金分红反例，验证无误校正。其余必测：逆向折算、零净流、比例舍入、同日真实申赎与折算、取消/修订/迟到旧公告、跨年/休市、多币种份额、货币收益、净值迟发、目录新旧及事件覆盖断裂。

## 9. 客户端呈现

仍位于“市场观察 → 每日复盘 → 资金流向”，主界面只保留本日、前一交易日两项“ETF净申赎估算”金额，旁标“已校正折算”和有效覆盖。存在排除项时显示“部分覆盖”，标记只表示已纳入部分的校正通过，不暗示所有ETF完整。

沿用按需展开的“ETF数据覆盖与缺项”，增加已校正基金数、事件日期/实际比例、币种依据、排除名单及披露延迟；单只详情可追溯上日份额、转换后基准、本日份额、单位净值和计算结果。未校正原始差额只作为核查明细，不作为第二套正式合计。全空时保留“缺少数据来源”，但详情准确区分“待披露、未采集、待校正、来源未返回”。不把管理后台变成满屏公告列表。

# 大小非解禁个股与明细（通达信）

## 如何查看

一个采集任务负责列表发现及对应股东明细，不能把只下载列表当作业务完成。数据目录搜索“大小非解禁”；按证券及解禁日期查询，查看股东名称、解禁原因及数量。

在“采集管理 → 采集任务”搜索“大小非解禁”，可立即采集、继续未完成轮次或重新采集。默认推荐每天北京时间18:00；首次历史请求较多，默认停用，可在任务配置中启用。保存到MySQL，重启保留；网络/计划设置下一轮生效，已保存选择优先。默认代理优先且允许不可用时回退直连。


## 数据范围与更新

列表模式0、明细模式1共用`tdxsj_cgbd_dxfgg`接口，生命周期相同，注册一个采集插件。两张业务表分别保存事件汇总和股东原子明细，不能按接口数量机械拆成两个任务。

列表页容量参数10000000已在2020～2025范围实测：返回14836条；10000只返回10000条。该参数不是内存预算，也不是来源总数保证。正式下载仍由共享下载器限制实际字节，按月份完整响应拆分；不采用非唯一日期排序的偏移分页。列表Count必须等于实际返回行数；第三结果集count不是可靠的全月总数，历史月份可返回0或小于正文的正数（1999-11为1而正文14条）。完整性依据整月一次请求、远高于单月10000条准入上限的10000000容量、响应结构及业务键集合；辅助count大于实际行数仍按截断拒绝。不能把较小count解释为无数据或丢弃其余来源记录。

初始化核验1990-01至下一自然年12月，包括有效空月；支持显式指定月份范围。2026-10-14来源核实在1996-05有记录，核查下限不是来源保证的最早历史。将每月列表与每个必要明细均校验、统一入队后，整轮等待归档成功及无消息残留才算完成。失败保留前序已入队进度，不跳过缺明细。

日常每天18:00重新检查历史及声明未来范围的列表；列表变化、缺少现行证明或明细空缺时补采。未变列表不每天重读全部股东正文；每轮轮换回查一个历史月份以发现列表不能反映的明细修订，重新初始化明确回查全部。未轮到的历史明细独立修订有发现延迟，不承诺完整旧版本回放。

仅重启Empire且Redis存活沿已入队断点继续；Redis丢失从SQL业务及现行完整单元证明重建计划，队列丢失不承诺恢复。范围改变须显式重新初始化，已入队旧批次仍由统一归档消费。

## 字段与日期

列表保留每条来源事实；明细请求粒度为证券、解禁日期及来源原因代码。实测该组合可对应多条不同数量的列表事实，不能按组合去重列表，也不能把共享明细复制给每条列表事实。两者通过请求group_key关联，列表事实另有record_key及出现次数；来源没有字段可裁定每条明细属于哪一条并列列表事实。请求关联字段必须保存。解禁日期是来源计划/生效日期，不等于公告可用日期。来源未给公告时间，不能据此证明事件在历史某日已经公开。

汇总和明细jjsl原单位万股，转为股用精确十进制乘10000；总股本T010也是万股，作为来源提供的比例基数保留，不假定是解禁当日总股本。来源百分比按数量/基数计算，不另存重复比例。行业及名称是来源当次返回值，不代表历史名称/行业版本。名称、行业和总股本基数为可选，缺失名称不阻断普通分析；解禁数量未知仍独立报告质量限制。列表身份不包含这些可修订的名称、行业及总股本字段；同组同原因同数量出现多次用出现序号保留。

## 限制与排错

有效空列表、有效空明细、未请求及请求失败分别表示。列表存在但来源明细为空时保留来源空状态及汇总，数据准备不能把缺少股东内容判成齐全；下轮复查。来源舍入可能使明细数量合计与汇总有小差异，不用填零或篡改来源量解决。

## 存储设计与维护

固定来源tdx；正式路径为一个数据集、统一归档事务写两张有类型表。

| 表/字段 | 类型与含义 |
| --- | --- |
| restricted_share_unlock.record_key / group_key / occurrence | CHAR(64) / CHAR(64) / SMALLINT UNSIGNED，列表来源事实主键、证券/日期/原因代码请求组、同事实出现序号 |
| unified_code / unlock_date / reason_code | VARCHAR(9) / DATE / VARCHAR(128)，请求与业务身份，必需 |
| name / industry / reason | VARCHAR(100/200/1024)，来源名称、行业及原因说明，可空 |
| shares / total_shares | DECIMAL(28,8)，股；未知为NULL，零为来源零 |
| detail_status / detail_count | VARCHAR(16) / INT UNSIGNED，present或source_empty，实际明细数 |
| content_hash / version_observed_at | CHAR(64) / DATETIME(6)，规范内容摘要及北京时间观测版本 |
| restricted_share_unlock_detail.group_key / record_key | CHAR(64) / CHAR(64)，关联请求组及原子事实摘要，组合主键；同组明细只存一份 |
| detail.unified_code / unlock_date / reason_code | VARCHAR(9) / DATE / VARCHAR(128)，明细请求身份及日期索引，关联成本，不是汇总业务副本 |
| holder / reason / shares / occurrence | VARCHAR(512/1024) / DECIMAL(28,8) / SMALLINT UNSIGNED，来源股东、原因、股数、同事实出现次数 |

没有稳定股东记录ID；完整请求组明细按规范事实与出现序号保存，合法同事实并列保留；明细不按列表数量倍乘，不能把共享请求响应当作每条并列列表事实的专属名单。完整月市场事务可删除已撤回事实/明细，仅影响该单位。历史证券不外键关联当前stock，不因退市删除。

正式查询：`WHERE unified_code=:code AND unlock_date BETWEEN :start AND :end ORDER BY unlock_date,record_key LIMIT 201`；全市场按`(unlock_date,unified_code,record_key)`稳定游标；详情按group_key一次最多10000条。分别使用证券日期及日期证券索引；明细主键覆盖请求组关联。完整月市場读取最多10000事件/100000明细，有界核验键、内容摘要及证明。大正文不参与COUNT或列表扫描。

预算：100万明细与10万事件，表及索引≤2GiB；列表200条P95≤100ms，事件详情≤100ms，单月完整事务≤5秒，单消息≤512KiB。真实小样本和隔离放大实测纳入发布。成功源正文不长期保存，仅保留有界摘要与样本证据。

相同内容不执行业务DML，可信缓存命中免SQL，旧观测响应不覆盖较新已确认版本，SQL提交后失败留队重放。每项目一条collection_state保存月市场证明及最终范围，不建逐轮/逐页表。字段/来源规范改变显式失效证明。

新增空表走显式维护入口：正常关闭程序、持单实例锁、队列0、原业务库存核对、严格目标结构检查；启动不DDL。恢复保留配置与原业务，不清共享Redis或删除其他业务。具体开发及实采证据另记，不把支持范围冒充已采完历史。

## 本次验证与实际进度

2026-10-14有限实采：1990-01有效空月、1996-05早期记录、2020-01～02并列列表及多股东、2025-10沪深北、2027-12未来安排，共6个月份574条列表、6154条共享明细；范围内来源集合、必需关联与正式查询通过，待归档0。未采其余历史，不把支持范围写成已采完。默认完整范围数据准备会报告历史缺口；指定已核验范围可分别验收。来源没有公告日期，严格历史信号可用性不通过。

容量：隔离10万列表、20万明细实际测量，110万行空间仅线性规划预测，不冒充百万明细导入。证据：[来源协议](evidence/unlocks-source-2026-10-14.json)、[容量](evidence/unlocks-capacity-2026-10-14.json)、[显式建表](evidence/unlocks-schema-2026-10-14.json)。开发专项18项与完整发布门禁分别记录，最终交付证据另记。

## 实现定位与私有验证

源码归属`features/unlocks`，contract/source/collector/dataset/query/ui各司其职，bundle保留原贡献身份和顺序；共有PAGE/body/results只有`sources/tdx_unlock.py`一份。未改业务键、表、来源范围或保存设置，无启动迁移。

实采验证入口为`scripts/verify_unlocks.py`，必须显式独立MySQL配置、私有UUID资源及新build报告，复用SQL守卫与共享下载/代理/归档，不保存日常策略。容量由对应`measure_unlocks.py`执行原规模协议；个股样本必须提供本轮实际全代理来源报告，当前源绑定不符拒绝。清理失败保留归属记录，按同一入口cleanup-only恢复，不能猜库名删除。开发/实采/发布状态分别见[E6d记录](evidence/architecture-e6d-2026-10-20.md)。

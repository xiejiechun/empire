# 开发目录空间维护

## 日常执行

项目根目录运行 `.venv/Scripts/python.exe scripts/clean_build_artifacts.py` 预览，核对输出 JSON 的清单与容量后，加 `--apply` 执行。默认保留最近 7 天的产物和最新 3 个发布目录的全部内容；可通过 `--days`、`--keep-releases` 显式调整，最小均为 1。本入口是手动维护，不是定时清理，也不在程序启动时执行。

维护入口与发布共享 `.build.lock`，发现正在运行的测试、构建或使用 build 目录的进程时拒绝清理。维护期间不要另开测试或修改待清理目录；普通测试不持有发布锁，进程预检与时间戳复核不能替代操作者的串行执行约束。运行中的正式桌面可以保持打开。

## 删除及保留范围

- 仅选取 `build/pytest-*`，以及已有 `report.json`、`failure.json` 或 `publication.json` 的旧发布目录中的 `pytest`、`pyinstaller`、`staging`、`previous`、搬移测试工作目录。全部后代最后修改时间都须超过保留期。
- 发布根目录、报告、输入身份、`evidence` 和 `steps` 日志保持原位；这些是历史验证证据，不代表当前源码通过。移除旧程序产物后不再保证对应旧包可运行或回退。
- 未知或缺少完成/失败记录的发布目录保留人工核查。含 `auto.cnf` 或 `ibdata1` 的树不会自动删除，数据库不能按普通缓存处理。
- 不删除源码、Git、当前 `.venv`、`desktop/node_modules`、正式 `dist`、正式配置或项目外目录。路径及祖先为目录联接/符号链接时拒绝；候选内的链接只移除链接本身，不递归进入目标。
- 清单生成后逐项复核容量、修改时间和数据库标志；变化时停止。权限或占用错误不会强杀进程、改写只读属性或绕过锁。已完成与未完成项记录在 `build/storage-maintenance/*.json`；部分失败不称全部成功。

## 旧测试数据库与开发副本

数据库退役是独立人工维护：先核实 mysqld 进程、服务配置和实际数据目录，确认实例已停止且仅属于开发验证，再列明具体目录执行。不得强停共享 MySQL、删除正式业务数据，或通过删除 redo/undo 单个文件缩小仍需使用的实例。最近仍需使用的独立 13348 实例继续保留；删除旧实例后，相应旧配置不能继续用于启动或验证。

复制开发目录时排除 `build`、`.venv`、`dist`、`node_modules` 和缓存；测试环境按正式依赖重新建立。禁止在 `build` 内创建指回祖先 `build` 的联接。目录统计必须不跟随重解析点，否则循环联接会重复计算容量。

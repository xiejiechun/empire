# 远航区间归档设计卡

2026-10-26，实施中，未发布。补充既有存储设计；不新增行情副本或业务表。

## 粒度、字段与查询

事实仍为 `yuanhang_daily_price` 的证券/交易日，年度头仍为 `yuanhang_price_year` 的证券/年。完整历史响应继续按年归档；新增区间消息只授权替换声明日期内的集合，区间外不删除。零块响应没有证券身份，不是合法空集合；采集起点包含已知最后成交日，跨年拆分后允许某年为空。

区间消息契约6字段：code、native_market、year、start、through、rows、source_count、key_hash、contract。日期使用ISO日期，start/through同年且有序；rows最多366条，字段沿用原日线数值契约，数量与键摘要必须匹配。完整年度消息契约5仍是明确支持的完整响应协议；金融消息不变。不把短区间伪装成契约5完整年度。

版本状态继续归属每项目唯一的 `collection_state`，通过公共 read_unit/save_unit 只读写一个证券。新增 `price_ranges` 按年份保存不交叠、相邻相同版本已合并的 `[起日,止日,UTC观察版本]` 段，包含明确无成交记录的日期，避免旧响应复活被新版删除的点。每年最多366段，每证券最多150年。完整历史核验按年记录 full_checked，取所有既有年份最小值展示完整历史最后核验。

业务范围查询、价格分析与索引不变。每次归档只读被修改证券年的至多366条事实和一个年度头，重算完整年摘要；不扫描其他证券历史。规划查询读取证券的年度头和项目单元状态，交易日来自正式日历。最大日期不替代连续覆盖。

## 摘要、版本与事务

日线摘要身份细化为证券/自然日，内容为该日期的行或已证明缺行，版本仍为请求开始观察时刻；完整与局部消息共享身份。不能使用整年缓存版本丢弃不相交旧区间。共享摘要上限及TTL保持，缓存失效回SQL。SQL按日期拒绝较旧覆盖，相同观察版本却内容冲突报错；只替换获准日期。事实、年度证明和项目单元版本同事务；同内容事实及年度头不写，仅必要的项目恢复状态推进。成功仍由统一归档器清队。

年度证明只有覆盖从年初连续到声明上界时才代表完整；存在空洞不能推进到后面的最大日期。新增证券由完整历史建立初始覆盖。历史证明缺失只影响该证券，不能导致全池初始化。

## 容量与迁移

不增加1700万条日线的列或索引。版本段JSON不保存业务正文，典型历史年1段、近期年约21段，20交易日完整核验会合并旧段。以75,986年度估算单段状态约8MB，5,578证券各增加20段约12MB，后续须以当前序列化结果实测；极端单年366段约40KB，不宣称典型值为硬上限。按证券有界读取，验收须测最大单元及整项目状态容量，超出公共资源上限不得发布。

上线前正常关闭程序并确认待归档队列为0，独立维护入口将既有年度版本和已核验截止转换为连续段，保留事实、年度内容证明和金融状态。转换前后核对业务数量与证明摘要，旧状态备份仅用于显式回滚。缺少旧证明、版本或非法日期时停止，不伪造已覆盖。启动不迁移；新运行时遇到未转换的已有价格状态明确报维护错误。Redis旧摘要使用新版本命名空间隔离，不能清空共享Redis。

## 生命周期及退出条件

普通维护补遗漏日期并回看5交易日，包含最后成交日锚点；同截止且无缺口/核验到期时0行情请求。20交易日轮转完整核验替代同证券短请求。失败不推进，采集不逐年等待归档；整轮结束再确认成功清队。Redis丢失从SQL覆盖恢复，纯缓存核验上界丢失允许有界保守重核。

必须验证部分删除、旧整年与新区间交错、不交叠旧区间、同版本冲突、冷热摘要、缓存淘汰后重放、跨年空段、停牌锚点、同截止0请求及证券池变化。还需完成随机30股真实代理→Redis→统一归档→SQL、容量和正式发布；本文不是验收证据。
# 断点容量与恢复位置（2026-10-26修订）

整池股票名单和逐股计划是可重建的内存工作区，不写入Redis断点或运行记录。断点中的next_index按scope_hash绑定的完整排序股票池定位；through冻结本轮截止日，force_full保留显式完整核验意图。当前证券成功发布首个年度单元时，current_plan与业务消息原子提交；证券完成后清除该字段。重启只从SQL重建尚未开始的后缀，部分已归档证券继续持久化的原计划。跳过证券仍计入完整池位置，尾部全跳过也进入整轮归档确认；不增加逐批等待。

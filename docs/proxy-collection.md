# 采集出口与动态代理

采集任务可选择本机直连、代理优先（暂不可用时自动直连）、仅使用代理。2026-09-30 按用户要求统一默认“代理优先”，未来新增任务也遵守此默认；用户后续显式保存的选择仍优先，启动不强制覆盖。保存后从下一轮生效，不改变在途请求。

在“站点访问规则”选择自动扩展并保存。日常只需设置“每个出口 IP 访问本站的最短间隔”；容量上限与本机直连设置按需展开。旧配置保留为固定限速，启动不自动改变已保存策略。

“采集出口”同时展示设备编号、无凭据代理入口（主机/IP 与端口）、出口 IP、协议和健康状态，并区分在线设备数与独立出口 IP 数；不会展示账号、密码或完整认证连接串。站点表展示使用中/可用并发、最近 10 秒请求率和回退次数。任务详情直接解释该任务支持并行下载还是存在前后依赖。

例如每个出口 IP 间隔 2 秒：2 个独立出口理论合计 1 次/秒，20 个为 10 次/秒，50 个为 25 次/秒。全站频率保护默认不额外限制，可在高级设置中启用；全局下载窗口和站点并发仍作为资源安全阀。站点并发设为 0 跟随全局，正数只收紧本站。这些是调度上限，不是实测速度。

在“下载资源”选择 100～1000 台的十档规划，一键推荐只填全局容量草稿，保存后正常重启生效。默认 100 档为 128 个全局窗口与 512 MiB 缓冲；逐步增加设备时按当前独立出口使用资源，不必凑满档位。推荐不修改每 IP 间隔、全站频率保护、任务代理开关或单响应/文件上限，详见 [下载资源边界](download-resources.md)。

## 已核实的生产者契约

- `router:proxies:by-code` 是 Hash，field 为设备编号，value 为包含 `code`、`proxy`、`exit_ip` 的 JSON。代理 URL 支持 `http://`、`https://`、`socks5://`、`socks5h://`；目录必须为 JSON 对象并声明有效出口 IP；JSON 内 proxy 无协议时明确使用 SOCKS5H，显式 URL 按声明协议解析。不接受整条目录值为裸连接串。
- `router:proxies:device` 是 ZSET，member 为与 Hash 完全相同的 JSON 原文，score 为过期 Unix 时间。
- 两者通过只读 Lua 和 Redis TIME 一起核实。Hash 删除、ZSET 过期都会停止分配；新设备、重上线和凭据更新在后续分配时自动识别。
- 不修改 RouterProxy 的 key，不输出或复制真实代理凭据到文档、日志或 SQL。
- 一个目录项代表一个代理设备，按 `proxy` 声明的协议和端口连接，不根据端口猜协议。`exit_ip` 是频控身份；多台设备声明相同 `exit_ip` 时，对同一站点共享间隔和一个在途槽。不同协议入口应使用不同且稳定的设备编号。

## 架构与边界

`infra.proxy_pool` 提供 `proxy.pool` 发现及连接池能力；`http.fetch` 按站点组及出口 IP 申请许可。自动模式只执行每出口间隔及显式配置的全站保护，不再将理论容量换算为额外全站间隔；固定模式保留合计间隔。代理策略快照按轮次隔离，避免并发任务串用设置。上下线只影响后续请求，在途请求正常完成或按原超时失败。

在线状态由 RouterProxy 维护，Empire 不主动探测节点健康。请求共享周期目录快照，并在连接释放时唤醒；实际分配前只针对候选项，用 Redis TIME 原子核实最新映射和租约，不为每个请求重复全量读取目录。连接失败的临时冷却仅用于本进程重试，不修改生产者目录。设备下线或凭据更换后的旧连接保留关闭所有权，取消不能留下无人回收的客户端。

每个站点独立使用全部健康出口槽；同一出口 IP 对同一站点最多 1 个在途请求，同站点任务共享该槽与间隔。同一代理设备可以同时访问不同站点，7个健康独立出口可分别为THS和开盘啦各提供最多7个在途请求，不能跨站互斥成合计7个。所有站点合计仍受全局下载窗口和共享缓冲限制，设备正在请求数为跨站合计，可大于1。自动模式按健康出口 IP 数、单出口间隔和高级并发安全阀计算能力。可选的全站每秒请求保护默认关闭。某站收到429冷却该站组全部出口，不冷却其他站点，403不轮换重试。设备下线后的连接须等所有站点在途请求退出才关闭。

代理传输或认证失败后临时隔离该设备，共享下载器立即切换其他设备，不消耗普通请求重试次数。同一请求排除已失败设备，即使其冷却结束或重新上线也不再使用；最多尝试 1000 个设备，所有等待、切换、重试及重定向共用同一个总时限。所有采集任务的普通重试可设置 0～100 次，默认总时限为 120＋max(0, 重试次数－2)×60 秒，100 次为 6000 秒；显式调用时限优先。退避从 1 秒翻倍，最多 30 秒，429 仍按全站冷却等待。可用设备全部失败或目录暂无可用设备时，代理优先模式回退本机；仅代理模式明确报错而不直连。健康设备只是正忙或等待频控时继续等待，不据此回退。直连、来源服务错误和不完整正文按原任务预算重试，502 重试重新分配代理但不保证不同出口 IP。同站点直连最多一个在途请求并保留本机间隔，下一请求重新优先代理。此公共行为适用于通达信分红送转及其他共享下载器调用方，不修改用户保存的任务配置。

新浪股票支持有界并行下载：先查询总数，预取同时受健康独立出口、全局/站点窗口、共享字节预算和页数限制，全局默认 128、最多 1024。严格按页号校验并提交 Redis 断点，然后校验空尾页与结束总数。后页提前完成不会越过失败页推进断点；失败或取消会回收全部预取请求，重启重新下载未提交部分。每页诊断独立，避免并行响应串入其他错误样本。同花顺证券/行业、通达信证券/日期/方案详情及巨潮月份也接入相同的共享有界预取。新浪新闻的下一页 ID 依赖前页，配股与更名为单个完整响应，保持必要顺序及一次请求，不增加无效并行。22 个正式任务的单位、生命周期与验证边界见 [全部采集共享预取](all-collector-prefetch.md)。

运行记录分别显示本次下载校验耗时和等待归档耗时。业务消息入队后立即唤醒归档器，60 秒恢复扫描负责兜底；SQL 提交、相同内容确认或旧版本确认成功后清理对应业务消息。并行下载不承诺源站跨页快照一致性，原有数量、排序、重复、缺页和尾页校验继续执行。

## 验证

测试覆盖目录过期、删除/重上线、凭据变化与旧连接回收、凭据特殊字符、代理隔离与直连回退、禁止回退、全组 429、共享速率及取消释放。真实 Redis Lua 和 MySQL 配置重启/重复保存验证使用独立测试命名空间，清理仅限测试数据。

并行回归包含 70 页乱序返回后的有序发布、失败页的精确诊断与断点续采、取消回收，以及 50 个模拟设备经实际调度器运行的并发/限速测试。这不代表已对 50 台真实设备完成源站压测；真实扩容后依据请求率与错误记录调整网站上限。

上述为早期验证记录；100～1000 台规划及本次扩展后的模拟/集成结果见 [出口容量验收](exit-capacity-review.md)。容量配置、模拟设备数、真实设备测试必须分别陈述。

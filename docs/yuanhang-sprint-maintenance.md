# 远航涨停冲刺：增量与历史核验分开执行

2026-11-02，按用户确认保留20个交易日历史轮转周期。范围仅为涨停冲刺；其余四池和历史原因任务不改变。

## 业务与生命周期

原任务 `ths-yuanhang-sprint-limit-up` 保留已保存计划、盘中采样及日终归档入口。初始化仍按正式日历从1990-12-19补齐全部缺失日期池；日常只处理新增、精确缺口及最近5个交易日的到期回看。相同截止日且没有缺口时业务请求为0。

新增 `ths-yuanhang-sprint-limit-up-history`，默认每日北京时间18:30执行，只核验已覆盖且不属于近期5日的到期历史日期。沿用原20交易日分桶和停机补查，不负责重复初始化，不重新下载近期窗口。可独立暂停、恢复和重新核验；停用或长期离线会使历史修订发现延期，不能把近期更新成功当作历史核验完成。

两任务使用同一个来源解析、下载/代理/频控、有界预取、业务数据集、摘要及统一归档器。每轮单元入队后继续下载，只在整轮结束确认归档清队。每任务有独立断点及运行记录，无同任务重叠。已经入队的旧中断批次先按原边界收尾；新轮次使用各自范围。Redis存活时继续该任务断点；Redis丢失从SQL及可用摘要合并的覆盖/核验证据恢复，缺少的缓存确认允许有界保守复查。

## 来源能力与四类成本

现有来源以单个日期查询完整池，每页100成员；未证明日期批量或可靠历史变更标识，不编造跳过依据。每个必要完整页正常请求一次，认证辅助及网络重试仍由共享路径计数。初始化预算为缺失日期的完整分页总数；日常预算为最近5日到期集合与精确缺口的并集分页数；历史预算为已覆盖老日期的到期集合分页数，正常每天约全历史1/20。任一阶段失败不扩大为全历史重采。

既有8754交易日、无缺口且新增一天的反例：原442日期合并轮次拆为近期5日期与历史437日期两个独立执行，历史修订周期不变。总必要来源请求量不因拆分自动减少，近期任务请求由442降至5；同截止重复完成后为0。字节按各完整响应实际计量；每完整日期最多入队1条压缩消息；相同内容无业务DML，可信摘要命中免SQL。每条消息继续受480KiB上限约束，不将理论预算称实测收益。

## 存储设计及查询

不新增表、字段、索引或业务副本，不执行DDL或丢弃数据。`yuanhang_limit_pool`与`yuanhang_limit_member`仍由原数据集单一路径写入，业务粒度和唯一键不变。两个登记job_key共享原摘要命名空间，各项目仍仅有一条`collection_state`；每行沿用有界日期版本映射，最多36600日期。正式规划及准备检查合并两行核验证据；冷缓存SQL归档同样核对两任务的版本上界，拒绝迟到旧响应覆盖另一任务较新确认的内容。

原SQL状态及摘要无需迁移，新增任务第一次读取即可沿用原初始化证明。新增项目配置由现有任务控制服务保存；旧任务配置不覆盖。容量增加仅为一个有界任务状态及其按既定限额保存的运行/错误记录，不增加常驻全业务缓存。

# ETF 每日份额、历史净值与净申赎估算实施计划

日期：2026-11-17。状态：用户已授权开始实施。协议核实与首版设计冻结见[实施契约](etf-fundamentals.md)，开发、建表、实采和发布按各阶段分别记录，未完成项不计通过。

份额/净值首版实施结果见[交付记录](evidence/etf-fundamentals-delivery-20261117.md)。用户后续明确要求完成折算校正，计价依据、事件采集、校正算法及误差门槛统一由[折算校正增量实施计划](etf-flow-adjustment-implementation-plan.md)规定；该部分尚未实现，不以未校正金额替代完成。

## 1. 目标与范围

在现有 Empire 业务库与采集框架中，新增上交所 ETF 每日总份额、深交所 ETF 每日基金规模、天天基金 ETF 历史净值明细三个独立采集任务。份额按同一业务事实共表，净值/收益独立存储；现有远航目录、日K和最新行情继续履行原职责。

先让最近三个已结束交易日的份额与最近两个已结束交易日的净值可查询，使每日复盘的“本日、前一交易日”有条件计算；随后有界补齐来源实际支持的历史。最近可用不等于全历史初始化完成，开发验收、生产归档进度和分析可用性分别报告。

本期包括：完整来源明细、历史保留、增量/补缺/修订、任务内数据预览、独立数据准备检查、每日复盘只读计算。不会用成交量、成交额、价格涨跌或个股资金替代基金份额或净申赎。

来源归档不依赖分析输入齐全：份额任务不等待净值任务，净值任务不等待份额任务。净申赎估算检查负责关联两类输入及单位、折算和币种，不能因一个输入缺失阻止另一个来源的合法数据归档。

## 3. 任务与正式路径

以下身份为候选，P1核对无冲突后冻结。实现通过内部白名单和贡献登记，不增加第二个 Runtime、归档器或调度器。

| 任务 ID | 来源 / 分类 | 拟定数据集 / 消息归档单元 | 默认计划建议 |
| --- | --- | --- | --- |
| `sse-etf-shares` | `sse` / ETF份额 | `etf.share.day`；上交所一个完整来源日期集合 | 固定12小时，任务结束后计时 |
| `szse-etf-shares` | `szse` / ETF份额 | `etf.share.day`；深交所一个完整来源日期集合 | 固定12小时，覆盖夜间及次日复核需求 |
| `ttjj-etf-nav` | `ttjj` / ETF历史净值 | `etf.nav.range`；单证券一个明确日期区间，按年度边界有界发布 | 固定12小时，补迟披露和近期修订 |

默认计划是初始推荐，不是固定来源更新时间的证明。P0按发布时间和实测成本核定后写入 `TaskContribution.default_schedule`；用户已保存的合法计划优先，不因重启或默认升级被覆盖。单任务不重叠；不额外创建定时自动化或轮询服务。

公共链路固定为：共享下载/代理/频控 → 来源校验与规范化 → `ingest.publish_page`原子发布业务及已入队断点 → 统一归档 → MySQL事务 → 可信摘要与成功XDEL → 正式查询。

三个任务分别登记job、数据集、来源、表组、版本契约、`fingerprint_plan/fingerprint_subset`、数据准备和采集规则。共享同一份额表必须声明完整写域，接受现有归档协调器的冲突串行规则；不能仅因来源不同自行假设可并行写库。

## 4. 存储设计卡

### 4.1 两张核心事实表

| 拟定表 | 粒度、来源与主键 | 字段组与索引 |
| --- | --- | --- |
| `etf_daily_share` | 来源×ETF×份额业务日期；多来源事实主键`(unified_code, share_date, source)` | `total_shares`、有据可查的来源发布时间/来源版本、必要的值阶段与版本观测属性；二级索引`(share_date, unified_code, source)` |
| `etf_daily_nav` | ETF×来源披露日期；固定来源ttjj，主键`(unified_code, nav_date)` | 净值/收益类型、净值或收益业务字段、单位/币种、申赎状态、分红送配说明、来源类型与版本属性；二级索引`(nav_date, unified_code)` |

两张是核心事实表，不是未经设计就承诺全部物理对象只能有两张。P1需同时冻结内容绑定的覆盖证明：优先复用现有年度/区间覆盖模型；确需新增覆盖索引对象时，必须说明业务粒度、字段、容量和恢复收益，一并评审，不增加逐轮日志表或独立每日完成状态表。

### 4.2 候选字段字典与约束

| 字段/字段组 | 候选声明 | 含义及约束 |
| --- | --- | --- |
| `unified_code` | `VARCHAR(9)`，ASCII、二进制比较、NOT NULL | 六位证券代码加`.SH/.SZ`；历史不外键级联当前目录或stock |
| `source`（仅份额） | 有界ASCII字符串，NOT NULL | 白名单sse/szse，约束来源与市场对应；不互相覆盖另一来源事实 |
| `share_date` / `nav_date` | `DATE NOT NULL` | 来源实际业务日期，不用下载日期替代；净值可包含非A股交易日 |
| `total_shares` | 候选`DECIMAL(28,10) NOT NULL` | 单位统一为份，页面万份按精确Decimal乘10000；是否允许零按源协议确定，负值不作为合法总份额 |
| `value_kind` | 有界类型标记 | 区分单位净值与收益口径；未知口径不进入估算 |
| `unit_nav` / `accumulated_nav` | 候选`DECIMAL(28,10) NULL` | 仅用于真正净值口径；源端空值保留NULL，不以收益字段或成交价填入 |
| `daily_change_pct` | 候选`DECIMAL(28,10) NULL` | 百分数值；保留所选正式来源精度，不为对齐网页两位显示而改变归档原值 |
| `income_value` / `income_basis_shares` / `yield_7d_pct` | 候选DECIMAL、可空 | 收益值、对应每多少份的基数、七日年化；历史基数必须有对应日期依据，未知不猜100或10000 |
| `currency` | 候选`CHAR(3) NULL` | 来源有据才填写；估算金额汇总须验证同币种，未知不默认人民币 |
| `purchase_status` / `redemption_status` | 候选`VARCHAR(64) NULL` | 按来源保存状态，不据状态文字反推出实际申赎数量 |
| `distribution_text` | 候选`VARCHAR(1024) NULL` | 保存网页分红送配说明；不是已经验收的折算事件模型 |
| 来源类型/阶段/发布时间/版本 | P0后逐项冻结有界列 | NAVTYPE等来源标记与业务指标类型分开；暂定/确认不能只凭机器时钟推断，来源未给发布时间则NULL |
| `version_observed_at` | `DATETIME(6) NOT NULL` | 需要更新业务时保存该有效版本的观测依据；北京时间，不为每次重复观察刷新业务行 |

以上类型、长度和字段名是P1候选，不能直接作为已批准DDL执行。实测精度超出候选必须改设计并重验，不能截断有效数值或文本。核心字段结构化，不保存整份业务JSON或原始HTTP响应；零、NULL、缺记录、来源暂无、未采集和失败分开。

### 4.3 正式查询、完整性和容量

- 单证券日期范围走主键；单日跨ETF走日期索引。列表默认200、最多500条，稳定键游标；图表最多10000点，超限要求收窄范围。复盘批量读取至多三个份额日期、两个净值日期，不做逐ETF SQL查询。
- 份额完整性单元是来源完整日期集合。先核对完整响应的来源总数、分类、身份集合及分页，再按明确目标范围保存；不先过滤当前目录再拿过滤后数量证明来源完整。源端退市/更名/申赎代码等身份差异单独核实。
- 净值完整性单元是单证券明确日期区间。验证日期唯一/排序、总数、首末与分页边界；不按交易日历生成假净值行。源端明确空单元与下载失败不能混用。
- 覆盖证明绑定完整单元、目标集合、业务键和内容摘要、规范版本与确认范围，随业务和项目状态同事务提交。不能只用最大日期、条数或complete布尔值。变更必需字段时显式失效旧证明并补齐。
- 以1741只、每年250交易日算，份额约43.525万行/年、217.625万行/五年；净值/收益按实际披露日期估算，货币基金及非交易日记录另计。此前1,603,527条是来源审计规模，不是SQL已有行数。
- P1须给出一年/五年正文及索引字节、覆盖/状态序列化、消息、初始化临时空间预算；P3在独立库测量平均/P95/最大单元、实际表空间、峰值内存和EXPLAIN。候选目标：单证券一年P95≤150ms、单日分页P95≤200ms、两项复盘合计P95≤500ms；明确冷热条件和机器，未测不得宣称达标。

## 5. 初始化、增量、补缺与恢复

| 阶段 | 两所份额 | 天天基金净值 |
| --- | --- | --- |
| 轮次范围 | 冻结正式日历已结束交易日及来源可用截止；确认全市场/ETF过滤契约 | 冻结可信目标目录、来源查询截止及已验证日期参数；跨境迟披露单列 |
| 首次优先 | 最近三个已结束交易日；数据尚未发布则保留待补，不能以空结果完成 | 最近两个已结束交易日所需真实净值，近期完整披露窗口一起取；来源未披露保持缺项 |
| 历史初始化 | 向来源实际最早可查日期补齐；按完整来源日或已证实区间分批 | 按每证券真实历史起点、分页和年度边界补齐；不宣称来源记录等于成立以来从未遗漏 |
| 轮内历史上限 | 初始建议最多20个完整来源日，超字节/预留预算进一步收紧 | 初始建议最多32只完整历史证券；单证券内部按合法完整区间拆批 |
| 普通维护 | 合并新增日期、未最终确认日期及最近5交易日回看；深市夜间数据按来源证据在次日复核 | 新披露范围与最近10交易日对应自然日期窗口、已知缺口合并；周末真实收益记录保留 |
| 长停机 | 补足SQL覆盖中遗漏的所有必要日期，按有界批次推进 | 从可信覆盖恢复遗漏区间，不能仅拉最近10天导致停机缺口永久遗漏 |
| 老修订 | 近期窗口外按月执行有界轮转核验；以P0成本确定每轮单元数并报告整池周期 | 同样按有界证券/年度区间轮转；不每日全历史重下，不承诺来源未提供的历史旧版本回放 |
| SQL可信同截止 | 只有来源时效和待修订规则确实允许才免请求；次日确认需求不能被旧成功掩盖 | 不因热摘要命中自动判源端无新版本；到期修订窗口仍需必要业务请求 |
| Redis存活重启 | 从已入队断点继续下载，前批交统一归档，不等待前批才能续下载 | 同左；目录版本或选择冲突先按正式流程结束旧批次再重规划 |
| Redis丢失 | 从SQL业务覆盖和每项目collection_state恢复未确认范围 | 同左；只保守重核受影响区间，不能缓存丢失就重下全池全部历史 |
| 失败/取消 | 不推进失败单元；合法完整兄弟批次可处理，但不能宣称整轮完整 | 未收齐分页保留，不以最后成功页掩盖残留；来源缺值与漏采分别报告 |

初始化完成必须同时满足声明范围无未解决采集缺口、覆盖证明有效、所有已发布消息成功归档或确认无需写入并清队。来源确实缺字段可完成“忠实保存来源”的检查，但依赖该字段的净申赎用途仍不能通过。

P0冻结每个来源的确切发布时间、暂定/确认规则和可验证增量能力后，可收紧以上回看窗口及批量数；调整须有请求成本和修订时效证据，不由技术实现自行降低业务新鲜度。

## 6. 请求成本与减少写入

设N为动态目标ETF数，`P_s(d)`为来源s在日期d的全部必要页面，`P_n(c,r)`为证券c区间r的净值页面数，A为必要目录/辅助请求，R为共享有界重试。普通每必要响应一次；额外确认/尾页请求必须说明协议原因与上限。

| 情形 | 份额请求预算 | 净值请求预算 | 入队与SQL要求 |
| --- | --- | --- | --- |
| 全历史初始化 | 声明日期集合上`ΣP_s(d)+A+R`，已证实区间/批量能力优先 | `ΣP_n(c,history)+A+R`；不能把单只首屏当作全历史 | 按完整单元入队，仅首次事实/有效修订写业务；大单元先整批容量准入 |
| 无变化维护 | 到期回看/待确认完整单元的必要请求，确无到期事项才为0 | 到期近期窗口的必要页数，不能把SQL零写入称为网络零成本 | 同内容零业务DML；可信摘要命中连collection_state也免SQL访问 |
| 新增一个完整单元 | 新来源日期的必要完整页；次日复核另计 | 一只证券一个新披露窗口的必要页 | 重叠窗口合并，只新增/有效修订行写库 |
| 精确补缺/老修订 | 只取选定日期/区间，核验替代相同范围普通请求 | 只取选定证券区间，与近期窗口消重 | 不同内容才更新；增量片段不走整份历史替换 |
| 恢复 | SQL可信覆盖决定必要重查范围 | 同左 | SQL提交后Redis失败走原消息重放，不重复另建写入路径 |

以2026-11-16核查的网页20条分页口径，1741只完整净值主记录共约80985个非空页；若协议确需每证券一个空尾页，则约82726次业务请求，再另计辅助/重试。该数字是历史规模预算，不是正式七列采集已经完成；P0重新按正式接口、额外字段和最小确认需求核定。移动接口能大页获取主字段，不代表同时提供网页状态/分红列，不能据此把完整明细预算写成1741次。

按来源、阶段分别记录请求、连接/认证、线上/解压字节、入队条数/字节、业务插入/修订/相同确认及等待归档耗时。老历史核验的每轮上限与整池周期须实测后明确，未覆盖范围如实报告。不能用无限重试或重复全池核验掩盖协议错误。

## 7. 公共采集入库约定

本节引用[采集指南](collector-development-guide.md)、[归档](archive-deduplication.md)、[schema隔离](schema-isolation-review.md)、[代理](proxy-collection.md)、[共享预取](all-collector-prefetch.md)和[下载资源](download-resources.md)，不增加ETF专用替代实现。

1. 开发核实、排错和正式采集全部共享下载器；代理优先、允许直连回退，尊重已保存策略。共用站点/出口频控、429冷却、重试、全局窗口和字节预算，不换出口绕过冷却。
2. 有界预取按业务顺序校验和原子发布。共享入队器在所有等待结束、提交Redis前复核隔离；拒绝不推进断点，提交后真实成功不伪造失败。
3. 批次入队立即唤醒统一归档，采集继续。只在整轮入队后等所有消息成功处理和清队；60秒扫描兜底，保留背压/隔离等待。

## 8. 每日复盘接入契约

新增只读批量查询接入既有`market.review.query` / `review.market`链路；数据预览放任务内，分析仍在“市场观察 → 每日复盘”，不新增重复菜单。前端默认北京今天、可选日期、显式刷新，查询不触发采集；页面切换取消只读查询，滚轮不改日期，保留现有草稿与交互边界。

对所选交易日D和上一交易日P，净申赎份额候选为`Q(D)-Q(P)-已证实非申赎份额变动`；估算金额为净申赎份额乘D日真实单位净值。前一交易日指标另需P之前的交易日份额。因此以2026-11-16为例，两个指标需要11-12、11-13、11-16三日份额及11-13、11-16两日净值，不能把该示例硬编码到程序。

- 标注“ETF净申赎估算”，说明不等同实际现金到账额；单位一致、币种已确认才汇总。
- 货币收益字段不能代替单位净值。折算、合并、份额单位改变等需要可靠事件依据；网页分红文本不能自动当作已解析折算因子。P0/P1若无法建立校正依据，该事件范围不进入可用估算，不伪造校正值；确需新事件数据集另行设计，不隐含增加采集范围。
- 每只ETF需连续两个交易日有效份额、当日有效净值及适用质量条件。真实零份额变化显示0；缺输入、未知单位或未确认修订不得填0。
- 部分覆盖时显示部分样本合计及分子/分母、缺份额/缺净值/口径不适用/折算待核实数量；覆盖为0显示“缺少数据来源”。不能把有值部分冒充全市场完整合计。
- 目标池优先采用已验证的对应日期范围；若仍按当前ETF目录回看，必须固定标注并绑定该目录摘要，不宣称历史全市场。休市和未收盘不套上日值；公布延迟单列，不用最新净值顶替指定日。
- 建立独立数据准备检查：份额、净值明细、净申赎估算分别证明各自声明范围；来源缺字段可以忠实归档，不自动获得估算用途通过。

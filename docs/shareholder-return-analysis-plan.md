## 日常运行建议与盘后时效

本轮只读保存策略确认停复牌为`enabled=true / mode=interval / interval_seconds=43200`，`daily_time=18:00`虽存在但在interval模式不生效。12小时从每轮结束后等待，执行时刻会漂移，不能保证15:30之后有一次成功。**建议用户日后通过现有“采集管理→采集任务→通达信停复牌”改为每天18:00并保存**，本阶段不代为改变策略。日历也须正常更新；18:00是安排时间，不是来源完整或成功保证，网络/源站/归档失败仍须检查。

现有调度可满足“应用当时运行、任务启用且成功完成”的每日盘后核查，无需新调度系统。应用未运行时不会后台采集。Redis保留且策略相同的到期next_due在重开后可触发一轮；未完成active也由现有恢复流程处理，不意味着补跑每个错过的18:00。Redis丢失、next_due不存在或保存策略改变时，现有`next_due`按启动当前时间计算；晚于18:00启动可能安排次日18:00。因此不能承诺关闭软件后已自动补齐；重开检查不满足时，通过同一任务的立即采集触发正式补缺与末覆盖日回查，失败保留断点和明确原因。

盘后提示应写出“所需最近已结束交易日/15:30、来源覆盖日期、实际确认时间及证据来自SQL还是匹配可信摘要”。原10-21覆盖至当天但13:40确认，证明在门槛之前，不能证明收盘后完整来源。上轮正常回查已恢复10-21门槛，不等于10-22盘后证明。本轮01:49处于10-22收盘前，不新宣称当日盘后通过。

数据准备只读，不自动运行任务或刷新时间；没有盘后证据时，相关价格集合/交易约束检查继续阻断并提示立即采集、待统一归档后再检查。Redis不可用仍按既有SQL证据判断，SQL有真实盘后证据可通过，仍盘前则失败。来源查询日期按`source_dates`保留；停复牌生效日期用于成交约束，二者不能替换。对于不使用交易约束的O2，盘后停复牌是独立限制而非新增必需项。

# 数据准备：一项工作只负责一种数据

同花顺股票定期前十大栏目保存完整来源名单（最多20个当前成员），按全部身份、数量及比例汇总核验，不按十行裁剪或要求末位并列。000065显示11或12个并列成员，000430的2026-03-31流通股东有11人且末两人数量不同，均由全名单汇总核验。详情仍最多40个当前及退出成员。超过上限、重复身份和汇总错误仍判失败。

进入一级“数据准备”，选择因子研究、策略回测或长期价值研究及具体方向。默认长期价值研究/经营财务趋势；证券留空为当前全池，不隐藏单只股票默认值。页面分“研究就绪/缺口”“MySQL已有数据”“研究条件”。研究模板引用唯一能力目录，只把本次必需输入及其计算依赖纳入分母；未选融资融券、债券持有人等不阻断基础研究。

本页研究清单、库存、逐项检查和问题样例均采用紧凑行距，保留原字号和完整详情，方便同屏比较更多项目。

打开页面只读库存元数据与相同范围旧报告；无缓存显示未核验。点击“精确盘点 MySQL”扫描当前数据库全表行数、证券/指数数和日期边界，库存不受研究草稿范围限制，也不证明完整。估算超过500万行的大明细表只核实行数，其他统计保持未核验；单条SELECT上限15秒，失败/超时不填0。元数据最多1000表/20000字段，不读取业务正文或配置凭据。所有表分时读取，不宣称原子全库快照。

“检查本次用途”只运行所选方向必需检查，“详细扫描全部项目”运行目录全部项目。“查看”支持来源集合已完成/未完成/未核验、缺口、已接入、能力规划；主表分别显示集合、质量、用途。开发测试不参与业务数据完成判断，计算仍须满足真实输入依赖。局部检查通过而覆盖未通过时，质量显示“已查部分通过”，其余范围不自动判为可用。

展开证券与日期输入范围，修改后明确提示草稿未检查；旧报告绑定其原范围。检查可取消，页面回收后恢复草稿、筛选和选择，不自动重新启动被取消的深检。查看选中数据和打开采集任务复用现有正式页面；复制或导出JSON报告包含范围、检查时间及有限样例，不触发补采或业务写入。研究范围目前不提供命名配置的跨程序重启保存。

研究条件单独说明当前池的幸存者偏差、固定样本选择偏差、历史日期/公告可用日期、因子矩阵与标签、基准和回测模型的不足。当前版本财报可用于现在查看历史趋势，不能提前用作过去信号。尚未登记的TTM、现金流指标、因子矩阵及回测引擎不冒充已经计算。

数据准备只保留 **A 股日频回测、股票估值，以及股东、资金流、融资融券等策略因子**。当前工作数量以页面为准，逐项用途筛选见[回测与估值准备范围](data-preparation-scope.md)。清单中的待开发项目仍需核实来源、历史范围和查询契约，列入计划不表示已经能采到。

保留股票池、上市与终止上市、停复牌/ST、原始日行情与复权、财报与股本分红、交易规则/费用、指数基准及成分、估值计算和证券策略因子。开盘啦日摘要归入“股票行情”，其余六项归入“策略行情”，作为量价、竞价和资金流分析原料；需要按策略截止时点生成日频因子，采集完成不表示因子已经计算好。无风险利率用于收益比较与折现，仍保留。

按用户要求移除退市整理期记录；每日涨停价和跌停价使用日行情已有字段，不单独列为准备项目或采集任务。同时移出新闻全文及版本/证券识别、公告文件与文字解析、宏观统计、汇率、ETF 专项和交易所逐笔事件准备。已有新浪新闻任务、浏览入口和业务数据继续保留，运行计划仍按用户保存的设置执行。这里调整的是准备范围，不会删除新闻或其他业务数据。

每项已归档范围与用途验收分别显示。当前行业和指数成员只适用于当前筛选与估值分组，不能回填历史；历史成员另列。暂停恢复终止上市栏目不提供退市整理期或唯一最后交易日，移除整理期准备不代表已能模拟该阶段的特殊交易。

## 股本和市值统一查看

在“数据准备”选择“历史盘口与日行情摘要”，查看其字段和范围；再从“数据浏览 → 数据目录”打开同名开盘啦页面，在股本/估值区查看所选证券日的总股本、流通股本、总市值、流通市值及实际流通市值。总股本、流通股本复用同一份日摘要，已移除“总股本和流通股本记录”和“来源公布的自由流通股本”两个独立待采集项。

`actualcirculation_value` 是来源实际流通市值（金额），不是直接公布的自由流通股数；本次没有证明自由流通股数或其定义，不能用市值除股价后冒称来源公布值。交易日快照不等于股本公告日、变更生效日或完整变更事件档案。缺字段保留未知，零值及股本关系矛盾须按具体估值用途核实，行情检查通过不表示任意股本/市值公式已经验收。

在“工作类型”切换到“计算”，可查看“按收盘价计算与核对市值”的规划；价格、股本及来源市值都引用日摘要，不再等待独立股本采集。该计算项仍未接入计算实现，不因输入已采集而显示完成。目录变化使旧准备缓存不再命中，首次重新检查建立现行报告，旧缓存按七天期限自然过期；无需清空Redis或重新采集已有股本。

## 股票当前所属指数

按用户指定的同花顺zs完整目录采集各指数及当前成员，以“指数编号＋来源证券编号”识别成员。同一股票可以属于多个指数，直接保留来源关系，不裁定指数归属。每日刷新，只保存当前成员，不要求历史起止日期或转板记录；行业分类独立。进入“数据准备”选择“股票当前所属指数”查看字段、完整集合和三天内时效，开发测试与实际数据分别判断。来源明确“暂无成份股数据”时保留目录和状态，已有成员仅作历史参考，准备显示来源限制，不伪装真实零成员。目录分组为网站分组，不冒充官方类型；历史调样和权重仍为独立待开发项目。操作与生命周期见[当前指数及成分](ths-indices.md)。

## 怎样才算够用

页面先显示清单和本轮未确认状态，再按项目逐项更新；上方呈现当前检查项目及完成数量。进度轮询只读有界检查证据，不新增SQL、不读取完整业务正文。一轮检查中禁止叠加刷新，结束后可点击“检查本次用途”；切页取消后保留范围草稿，需手动再次检查。三表使用当前所选用途、证券与报告期，开盘啦分时按所选证券与交易日期，其他项目仍按自身范围。数据尚未检查完不能显示通过，旧范围快照不能冒充新范围。

交易日历的时效按每月 SQL 确认及可用的统一 Redis 摘要共同核验。缓存必须具有有效摘要、规范且不异常超前的版本、未过期索引，并匹配 SQL 已读取的完整月份内容；只能补充更晚确认，不掩盖缺日或异常 SQL 证据。Redis 未启用、不可用或证据无效时使用 SQL 确认；证据过旧则保留“待验收”，不为变绿额外写库或刷新缓存。历史范围和必需字段仍独立验收，未来安排仍允许来源修订。

以估值分析和通常的日频策略回测为基础用途。**一份数据可以由一个来源独立完成，不要求几个网站相互印证。** 检查的是能否正确取得、保存和使用这个来源提供的数据：必需字段、单位、去重、日期、分页和明显异常。来源自身记录、页数、返回范围及本地保存结果可用于检查，不强制拿第二个网站作证明。

- 按声明的证券、市场、日期范围验收。写清来源支持起点、已采区间和已知缺口，范围外的历史不足不否定范围内可用。声明范围内漏页、解析错误或缺少关键字段仍须处理；不能把自己的漏采改称来源限制。
- 字段分为必需和可选。来源事件编号、版本号、公告链接、精确到秒的公布时刻及完整旧版本历史不作通用门槛。没有来源编号时使用稳定业务组合键；没有版本号时明确内容比较和旧响应处理规则，不伪造来源版本。
- 时间精度按用途确定。停复牌、上市退市等成交约束按生效日期判断；日频数据通常不需要秒级时刻。财报、股东和资金流等作为选股信号仍要说明公布日期或可用日期，不能提前使用。来源只提供修订后值可以采集使用，但须说明它不适合严格重放修订前的信号。
- 多来源比较、严格历史时点重放、盘中策略和审计溯源按实际需要增加，不作为所有采集项目默认的完成条件。策略因子按实际公开日期使用；来源缺少过去可知版本时注明限制。

“已准备好”表示本项在声明范围和用途内可用，不表示所有年份、所有市场、所有策略都适用。相同内容免写、旧响应防覆盖、失败保留队列及归档成功清队等公共存储规则继续执行。

例如，“历史停复牌”必需市场/代码、停牌开始日期、复牌日期（来源尚未给出时可空）、全天/临停类型；名称、原因、公告时间和来源修订号可选。只用单一来源也可以通过，不要求先做公告采集或跨网站核对。通达信采集器按 2004-12-27 至今逐自然日核验完整响应、原始计数及业务键集合，来源日历关联完整后归档；数据准备同时检查现行完整性版本、连续覆盖和缺失来源日期，不以运行成功替代验收。停复牌插件仅遇源端完全重复时追加完整响应复核后决定能否合并重复；装满响应另按其容量边界扩容。这是该来源异常与边界处理，正常未装满且无重复的完整日只读一次，不能推广成所有采集默认双读。

## 怎么划分项目

- 独立接口及生命周期的数据分别采集和补齐；网站同一栏目不是合并依据。同一完整响应已包含全部所需业务时，可显式声明共享响应组以一次请求取得，并分别检查各业务内容。例如指数成分名单和成分权重、融资余额和融券余量仍各自保留数据准备项。
- 同一条记录的字段不机械拆开。日线中的开盘、最高、最低、收盘、成交量是同一条日线；一份分红送转方案中的现金和送转比例是同一方案；停牌及对应复牌是同一事件的起止。
- 不同输入、处理过程或完成范围单列。例如前十大股东与前十大流通股东分别核验，共享一个完整HTML采集任务；股本与股价输入之后另做市值计算。
- 采集与计算分开。股价和股本分别采集，市值另外计算；PE/PB/PS 和股息率分别计算，不伪装成一个“估值采集”项目。
- 跨数据核对单列。行情漏了哪天，需要合并日历、上市、退市和停牌记录才能判断，另列“核对股票行情缺了哪些天”；三张财务报表之间的核对也单列。
- 仅用于配合的数据不阻止当前采集项目完成。计算和核对项目确实需要输入时，才显示“要先准备好哪些数据”。本项完成不代表使用它的回测或其他项目也完成。

## 主要拆分示例

检查结果按用途、证券和日期范围缓存到 Redis 7 天；重新打开页面或重启 Empire 优先读取相同研究范围缓存，不延长有效期；无缓存不自动扫描。“检查本次用途”强制运行，完成后覆盖该范围缓存并重新计时。缓存包含失败和待验收结果，但不保存中断的检查；普通发布和无关插件变化不使数据结果失效；开发验收每次读取当前版本证据。业务检查契约、相关查询可用性或数据库范围变化时不复用。数据发生变化后需主动重新检查才能看到最新状态，界面显示实际检查时间。Redis 服务或电脑重启会丢失缓存；不可用或保存失败会提示未缓存。

正式缓存键为 `<namespace>:preparation:report:<SHA-256>`，身份包含研究模板版本、研究用途/方向/扫描方式、规范用途/证券/日期范围、数据准备目录与贡献的业务检查契约（含 cache_revision）、相关查询能力可用性及数据库范围。完整报告 JSON 不包含业务正文和凭据，不进入 MySQL 或归档队列；`SET EX 604800` 原子替换及过期，读取不续期。采集完整性、来源质量、用途条件和用途可用性均保存在报告中；开发证据回源当前版本重新组装，不扫描业务历史、不改写缓存或延长TTL。检查逻辑、来源规则或必需字段发生语义变化时，开发者须提升对应贡献的 cache_revision；测试文件、发布证据时间、界面与无关插件不参与数据缓存身份。本次身份修正首次需重新检查，旧身份记录按原有效期自然过期，不启动历史格式兼容路径。每份最多 8 MiB，损坏或不完整报告回到现行检查入口，Redis 故障不阻止检查。

## “6 项检查”不是“6 个采集功能”

一份数据仍要检查必需信息、重复、声明范围内的漏采、明显错误、更新情况及日期用途。这是检查同一份数据的质量，不要求一个采集器顺带开发其他数据。可选字段缺少应在检查说明中标注，不返回失败或等待补齐；不适用的检查说明原因后通过。

功能检查核对任务登记、保存规则、查询检查能力和当前版本测试记录。测试文件存在不算通过，代码变化后旧证据失效，测试跳过也不算通过。开发证据在详情独立展示，不参与业务完成分母；业务检查及必要输入通过才显示“所查范围可用”。

独立接口和生命周期的采集输出分别登记任务与结果范围。2026-10-13用户修订：同一完整HTML已包含三个持有人栏目，可显式登记同一response_group，由一个任务一次下载并校验三栏，再统一入队和同事务归档；三个准备项继续各自核验正文、集合、时效及用途，不能用任务运行成功一起打勾。响应组须精确共用来源、项目、job_key、数据集及采集能力。任意一个来源独立通过即可完成；第二个来源未接入或有问题不拖住第一个来源。多个来源不能仅靠各过几项检查凑成通过。

## 清单更新与历史缓存

目录从正式契约移除相关项目，其采集、计算依赖和插件登记同步检查；不通过页面隐藏留下第二套准备清单。旧目录检查结果的缓存身份不同，不会让已移出的项目重新出现；旧缓存按原来的七天有效期自然过期，无需清空 Redis。

新闻不再登记 PreparationContribution，也不再为准备页面执行全历史新闻聚合核查；其采集、归档、分页浏览与新闻修订路径继续使用原实现。股票、日历和其他保留项的质量门槛不放宽。

## 开发接入与验证

唯一目录入口是 [preparation_catalog.py](../src/empire/features/preparation/catalog.py)，按证券基础、事件、其他市场数据、处理工作等职责组织声明。Requirement 的 kind 区分工作类型，boundary 说明本项边界，related 仅表示配合使用，dependencies 只用于确实需要输入的处理项目。目录启动校验身份、引用、依赖环以及采集项目不依赖其他项目完成。

## 显式只读扫描入口

维护时可执行 `.venv/Scripts/python.exe scripts/scan_preparation.py --detailed --output <报告.json>`；默认项目根目录config.toml，`--config`显式覆盖。不带`--detailed`只精确盘点MySQL。入口只启动查询插件及可选Redis读取证据，不启动采集、调度、入队或归档，不写业务/配置/摘要或报告缓存。报告记录扫描起止时间、未运行查询插件、逐表库存与各项检查；检查期间的临时输出可能为部分结果，以finished_at及checking为准。

来源检查器复用当前正式数据路径；财报核心金额、来源集合、时效与历史信号条件不放宽。动态实存数量属于扫描时点，不能作为永久规则或全市场完整率。

## E3业务与公共协议边界

检查聚合、研究需求目录、缓存及页面位于 `features/preparation`；股票、日历和停复牌的SQL审计属于各自业务。`contracts/preparation.py` 和 `contracts/preparation_scope.py` 继续是唯一公共证据/贡献及范围契约，研究选项的值和标签不变。发布根与资源证据读取保留 `core/preparation_release.py`。

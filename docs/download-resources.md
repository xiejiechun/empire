# 下载资源边界

## 日常使用

在 **采集管理 → 下载资源** 设置下载大小与容量。规划出口设备支持 **100、200 至 1000 台，共十档**；选择档位后，一键将推荐的全局下载窗口和共享缓冲填入草稿。默认选择 100 台，默认响应大小下推荐 **128 个窗口、512 MiB 缓冲**。逐步增加设备时不必一次接满，实际只使用当前健康独立出口 IP 所能提供的容量。

页面按容量、内存响应和文件下载区分参数，并分别显示当前运行值、已保存值与重启待生效状态。推荐不会自动保存，也不会修改单响应上限、文件大小/配额/并发、网站每 IP 间隔、全站每秒保护或任务代理开关。修改后点击保存，配置直接写入 MySQL `app_setting`；正常退出并重新打开软件后统一生效，不会自动重启或打断当前采集。

“恢复默认”只改编辑草稿，仍须保存；未保存草稿不会改变运行值。界面刷新不覆盖正在编辑的草稿。磁盘上的下载目录属于机器路径，仍由本机 `%LOCALAPPDATA%\Empire\config.toml` 的 `http.download_directory` 指定，不在这个页面修改。

下载大小不是应用总内存大小，也不是网站允许的请求速度。网站频控决定何时能发请求；字节预算决定能同时保留多少响应。预算暂时用完时等待，不算采集失败；单个响应超过当前生效上限时停止该响应，不推进对应断点，也不会通过轮换代理绕过限制。放大字节上限不会让网站响应或网速变快。

当前股票、新闻和交易日历使用有界内存响应。未来公告或年报 PDF 应使用已经提供的文件流式契约，不能把整个文件塞入 JSON 响应缓冲或 Redis。本轮没有新增公告采集任务、PDF 解析、OCR 或文件浏览页面。

## 默认限额与调整原则

1 MiB = 1,048,576 字节，1 GiB = 1,024 MiB。

| 契约 | 单响应传输/解压正文上限 | 全局内存预算中的预留 |
| --- | --- | --- |
| 新浪股票响应 | 各 1 MiB | 3 MiB + 256 KiB |
| 新浪新闻响应 | 各 4 MiB | 12 MiB + 256 KiB |
| 巨潮日历响应 | 各 512 KiB | 1.5 MiB + 256 KiB |
| 通用内存响应 | 各 2 MiB；正式采集器使用自身响应分类 | 三倍正文上限 + 256 KiB |
| 文件响应 | 默认各 256 MiB | 固定 256 KiB，不按文件总大小预留内存 |

全局下载缓冲预算默认 512 MiB，所有来源、直连与代理共享。结构化正文组装按“三倍正文上限 + 256 KiB”预留，覆盖 bytearray 容量增长/重新分配、最终字节串副本和有界解压/诊断工作区。默认股票每页预留 3.25 MiB，128 个窗口合计 416 MiB；默认缓冲还保留余量，不表示启动即分配全部内存。实际还须满足网站许可、健康独立出口数、站点安全阀和剩余页数，不能直接把窗口数视为并发吞吐。

保存时统一检查：全局缓冲必须至少容纳当前最大的单响应预留，即 `3 × 最大单响应上限 + 256 KiB ≤ 全局缓冲`；单文件上限不得超过下载目录配额。设置过小会使合法响应超限，设置过大则降低同一预算可容纳的并行响应数。建议先使用默认值，发生真实超限后核对来源数据大小，再按实际需求调整，而不是随代理数量成倍放大每页大小。

缓冲预算不是进程内存硬上限。Qt、HTTP/TLS 底层连接、解析后的 Python 对象、Redis/MySQL 客户端等另占内存。页内业务条数校验继续保留；扩容前仍须检查实际进程峰值。

## 十档容量推荐与网站保护

推荐按规划设备数把窗口向上取整至 128 的倍数，最多 1024。缓冲取以下两项较大值，再向上取整到 256 MiB：①全部股票窗口预留的 1.2 倍；②全部股票窗口预留，加新闻/日历/通用各一份预留及当前文件并发的工作区。修改股票响应上限后重新推荐，得到的缓冲也会变化；若自定义上限导致推荐超过 4096 MiB，明确报错，不默默缩小窗口或改动单响应设置。该推荐是本机资源规划，不是对站点请求速率的推荐，也没有测量电脑可用内存或源站承载量。

以下使用默认响应及文件并发设置；不是要求实际同时接入这么多设备。

| 规划设备档位 | 推荐全局窗口 | 推荐缓冲 MiB |
| --- | --- | --- |
| 100 | 128 | 512 |
| 200 | 256 | 1024 |
| 300 | 384 | 1536 |
| 400 | 512 | 2048 |
| 500 | 512 | 2048 |
| 600 | 640 | 2560 |
| 700 | 768 | 3072 |
| 800 | 896 | 3584 |
| 900 | 1024 | 4096 |
| 1000 | 1024 | 4096 |

网站“最多同时请求数”设为 0 表示跟随全局窗口；正数是更严格的站点保护，实际不超过全局窗口。自动站点的并发同时受健康独立出口 IP 数约束；固定站点保留原固定访问节奏。后续全局扩容不自动放宽手工设定的正数站点安全阀。如发现窗口增加但并发仍低，应先看实际出口 IP、网站保护、缓冲预算或剩余页数，不应直接缩短每 IP 间隔。

多台设备共享同一 `exit_ip` 时只算一个出口；1000 档也不会凭空创造 1000 个独立 IP 或 1000 页数据。当前新闻、日历仍顺序采集，股票支持独立分页预取。容量和瓶颈展示只反映调度状态，不承诺倍数提速。

## 内存响应与并行预取

统一读取器先检查声明长度，但不把 `Content-Length` 当作完整证据。实际读取同时累计传输字节和解压后正文；只支持明确的 identity、gzip、deflate，使用有界增量解压，拒绝不支持的编码、损坏压缩流及不完整/不一致的长度。HTTP、HTTPS、SOCKS5 与 SOCKS5H 代理进入同一读取器。

发请求前预留额度；额度覆盖下载、后页等待前页、按序解析校验和 Redis 提交，消费完后释放。后页只保留有界正文，轮到它时才解析。预取补充尝试非阻塞预留，额度不足先处理已提交的最前页；没有可消费页时才等待额度。这样避免后页占满预算后，调度器只等额度却不消费前页。

失败、取消、任务结束及 HTTP 插件停止都要关闭响应、回收预取任务并归还额度。关闭响应不删除已经进入 Redis 的有效待归档业务消息。后页不能跨越未成功前页推进断点，股票最终总数、尾页及完整性检查保持不变。

## 大文件流式路径

`FilePolicy` 由业务插件声明稳定文件名、预期格式签名以及可选 SHA-256；管理后台保存值是统一文件大小上限，插件仍可声明更严格的上限。对于 PDF，可声明 `%PDF-` 签名；这只验证文件头，不等于完整 PDF 语法、安全或可解析性检查。

下载以小块写入专用目录中的独占临时文件，边读取边统计大小和摘要。完整传输、长度及声明校验通过后，独占发布目标文件；同名目标已存在时失败，不覆盖。未完整下载的文件不会以成功文件名出现，不接受未经业务声明的 206 分段响应。

| 管理项 | 默认值 | 作用 |
| --- | --- | --- |
| 规划出口设备 | 100 台 | 一键推荐的容量规划档位，100～1000，步长 100 |
| 全局下载窗口 | 128 | 在途下载的全局安全阀及预取窗口上界，最多 1024 |
| 全局下载缓冲 | 512 MiB | 全局响应缓冲预留预算 |
| 单文件上限 | 256 MiB | 单文件实际传输与解压正文分别不得超过的值 |
| 下载目录配额 | 2 GiB | 下载目录已占空间与活动文件最大预留总量 |
| 磁盘安全余量 | 128 MiB | 下载仍须保留的磁盘安全余量 |
| 文件下载并发 | 4 | 同时进行的文件下载上限，允许 1～64 |

上述资源数值统一存于 MySQL `app_setting` 的 `kind=download`、`setting_key=global`，以 `namespace` 隔离。没有保存值时采用上述默认值；相同值不重复写库。配置保存失败时保留原已保存值与当前运行值，不显示为保存成功。缩小配额不会删除已有文件；重启后若已有占用超过额度，将拒绝新的文件准入。

专用文件目录默认当前用户数据目录 `Empire/downloads`，Windows 通常为 `%LOCALAPPDATA%\Empire\downloads`。可在 TOML 的 `http.download_directory` 设置绝对路径。下载前按文件最大值预留磁盘额度并检查可用空间；写入期间继续检查剩余空间。目录内已有文件和遗留临时文件都会计入占用，不为腾空间自动删除它们。目录不允许经过符号链接/目录联接；文件名不能含路径，不能覆盖别的文件。

目录扫描、配额准入及写入/发布使用工作线程，不在事件循环上等待磁盘或存储锁。准入期间取消会等实际准入结束，再清理已创建的文件写入器；写入期间取消会等该次写入结束，再清理确切拥有的临时文件。重复取消也不能提前把仍在线程中操作的文件交给别的清理者。

完整下载进入发布提交点后，取消不再撤销已提交文件：等待真实发布完成并返回文件路径、字节数和摘要，避免目标已发布而调用方只收到取消、失去文件引用。正常失败及提交点前取消只清理由当前下载器确切拥有的临时文件，不能删已有目标文件。

进程或电脑异常退出可能遗留 `.part-*` 文件；没有自动扫删策略，需确认其来源及不再被使用后再维护。已发布文件保留，不自动归档进 MySQL 或清理。未来文件业务必须定义引用入库、保留、恢复和清理规则；Redis 应仅保存状态/引用，不能保存整份 PDF。

下载与 PDF 解析/OCR 是不同资源阶段。流式下载不能替代解析阶段的页数、像素量、内存、CPU、时限及并发限制；这些尚未实现，不能宣称本轮已经支持完整公告业务。

## 提前终止的诊断

超限或读取完整性失败时最多保留 64 KiB 脱敏错误样本。未读完正文时 `body_complete=false`，`original_bytes` 和 `original_sha256` 为空，因为完整长度及摘要尚不可知。`observed_bytes` 只表示实际已观察到的正文量，`sample_sha256` 是最终脱敏样本的摘要，不能当作完整文件摘要。

完整读取后仅因样本截断而保留前缀的错误仍可提供完整原文长度/摘要。资源超限属于响应/资源问题，不是代理节点连接失败，不隔离代理、不自动切换代理重试同一超大正文。

## 旧配置的显式迁移

旧版本曾在 TOML 的 `[http]` 下保存 `buffer_budget_bytes`、`download_quota_bytes`、`disk_free_margin_bytes`、`file_concurrency`。现版本不再把这些数值作为第二个配置来源；发现旧字段会明确提示先迁移，不静默忽略或与 MySQL 混合生效。

迁移必须通过显式维护入口 `scripts/migrate_download_settings.py`：正常关闭 Empire，核对待迁移的数值及已有 SQL 下载配置，将旧值合并到完整现行配置并校验后提交，再退役 TOML 旧数值键。已有 SQL 配置发生冲突时不得覆盖；机器目录配置保留。不需要修改业务表结构，也不删除 Redis 队列、业务数据或下载文件。具体命令与实测结果见 [下载设置验收](download-settings-review.md)。

已保存的旧九字段 SQL 下载配置另由 `scripts/migrate_download_capacity.py` 显式补齐规划设备和全局窗口字段；运行时不接收残缺旧结构，不在启动时补写。维护时可用 `--recommend-devices 100` 明确应用 100 档推荐，并仅在指定 `--follow-auto-sites` 时将现有自动站点并发改为跟随全局；固定模式、访问间隔、全站频率保护和任务代理开关均不改变。先核查再加 `--apply` 执行，同一 SQL 事务提交，详见 [出口容量验收](exit-capacity-review.md)。

## 验收入口

检查无长度头、虚假长度、gzip/deflate 膨胀、提前终止、前页慢后页快、预算耗尽、取消、Redis 入队失败、大文件校验失败、磁盘配额、路径边界与不覆盖。所有路径核查结束后额度回到零；读取器原始整改结果见 [首批四项整改验收](priority-one-review.md)，管理设置的保存、重启与迁移历史见 [下载设置验收](download-settings-review.md)，当前十档推荐、容量扩展及验证边界见 [出口容量验收](exit-capacity-review.md)。

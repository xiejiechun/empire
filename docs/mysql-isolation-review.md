# 数据库浏览与持久化隔离验收

日期：2026-09-26。范围：延续基础优化，避免浏览慢查询占满归档、配置及采集进度回源的应用执行资源；不新增业务功能或数据库表。

## 逐项核查

| 项目 | 实际实现 | 验证 |
| --- | --- | --- |
| 执行和连接隔离 | 浏览 2 线程/2 连接，持久化 1 线程/1 独立连接；两池均禁止 overflow | 真实 MySQL 两个 `SLEEP(2)` 浏览占满连接时，配置保存、读取和归档事务在 1 秒测试期限内完成，浏览仍在执行 |
| 排队有界 | 浏览最多 16 项等待，持久化最多 32 项等待；准入先于线程池提交 | 小容量确定性测试验证满队拒绝、执行/等待计数、取消排队后恢复额度 |
| 正式调用迁移 | 3 个浏览页面用 read/read_engine；配置、归档、进度回源、日历计划用 control/engine；删除旧 `_call` | 全量调用检索与集成回归；测试中的清理写入也不再使用 read |
| 取消安全 | 未开始的排队操作可取消；已开始 SQL 保留所有权直到结束，多次取消不提前归还额度 | 连续取消三次，成功及异常线程均完成后才释放；真实事务取消后仍正常提交，调用方收到取消而非虚构回滚 |
| 失败与退出 | 新请求拒绝；已接收操作排空；关闭线程后释放连接池；启动失败清理双池 | 单元验证重复取消关闭、关闭中提交、排队排空、启动失败、重新启用及无遗留工作线程 |
| 事务/队列规则 | 完整业务事务、可信摘要免 SQL、失败留队及成功删除不改 | 真实 SQL 事务失败回滚；原缓存信任、股票/新闻/日历归档、提交后重放回归均通过 |
| 可观测性 | 运行状态页新增两通道执行/等待、容量/满队拒绝指标 | 880×720 与 1320×900 离屏布局、数值断言；下方操作区保留，指标表可滚动 |
| 文档同步 | 架构、实现状态、原审计后续状态、软件内说明同步更新 | 文档搜索和帮助页测试通过 |

## 保留的边界与下一步

- 这里隔离应用线程、连接和排队，不保证同一个 MySQL 服务的磁盘、CPU、行锁互不影响；不能宣称慢查询对服务完全无影响。
- 归档和配置有意共享单一持久化通道以保持简单串行事务；完整股票事务不拆分。一个长事务仍可能延迟其后的保存操作。
- 满队返回可理解的失败，不隐式重放写入；归档继续保留消息并按既有机制重试，用户保存不会虚报成功。
- 取消已开始的 SQL 不是数据库 KILL，也不保证回滚。关闭等待受连接/读写超时及具体 SQL 行为影响，不承诺瞬间退出。
- 本轮不添加主动代理探测、不改变下载额度、不迁移数据结构，也未做真实百/千出口压测。

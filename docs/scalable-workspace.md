# 可扩展的采集管理工作区

## 信息组织

一级入口固定为工作台、数据浏览、采集管理、系统设置、说明文档。采集项目是可检索的业务对象，不是一项菜单。数据类型通过数据目录访问，不为每个新来源增加二级标签。数据浏览只展示“数据目录”和当前打开的数据页，切回目录可继续检索。

- 工作台：项目数、运行数、失败任务、待归档消息，以及最近 5 次采集。
- 数据目录：按名称、用途、业务分类、来源检索，每页 25 项。
- 采集任务：按名称/ID/来源检索，按业务分类、网站来源组和状态筛选，每页 25 项。任务详情与列表分开滚动，宽窗口左右分栏，窄窗口上下分区。编辑草稿按任务 ID 保留，切换分页不丢失。
- 网站频控：按组名或域名检索、分页；关联任务显示总量和最多 5 个示例，完整任务可在任务页按来源筛选。
- 运行记录：采集历史由后台过滤项目和状态再分页；归档/错误继续按单个项目有界查询。项目选择器支持输入检索，错误清除仍按确切 ID 执行。

## 注册协议

TaskContribution 声明 category 与 source_name，rate_group 保留真实网站频控身份。没有分类的任务进入“其他”，不会依靠任务名猜测业务分类。采集执行和存储规则仍由各插件定义。

PageContribution 为可浏览数据声明 catalogued=True、category、source；目录自动收录。已有业务页面使用统一 navigate(id) 打开。普通管理页面仍放在固定分类中，说明文档继续一级直达。

注册新采集能力仍是显式开发行为，需要实现采集器、业务数据契约、查询页面并登记。这里没有添加无法执行的占位采集任务，也不是任意 URL 的通用采集器。

## 数据查询与生命周期

桌面使用 collection.control.workspace 查询当前工作区，tasks/sites/history 每次最多 100 项，当前 UI 固定 25。任务详情只查询当前页采集器的 health，最近记录也只返回当前页各任务一条。overview 只返回汇总和最近 5 条，不携带所有完整任务状态。

页面每 3 秒刷新当前筛选结果，输入检索有短暂防抖。切换筛选、分页或完成保存后丢弃旧请求结果，避免旧数据覆盖新视图。项目名称索引及来源/分类选项以轻量元数据返回，便于选择器检索。

桌面只为打开过的页面创建 Qt 控件。保留已打开页面以延续查询与草稿；停用贡献页面时释放控件。未打开的数据页面没有查询定时器。

## 验证和边界

自动化模拟 500 个采集项目、50,000 条历史记录，确认分页正确、任务 health 只访问当前页、首页最多 5 条记录。另模拟 500 个数据入口，确认目录分页与过滤、二级导航至多目录加当前页、页面按需创建。验证空结果禁用操作和跨分页恢复任务草稿。

这次调整覆盖单机桌面管理层，保持现有单实例调度、共享网站频控、Redis 运行状态和 MySQL 配置持久化。它不是对 500 个采集器同时联网运行的吞吐承诺。调度状态目前仍在同一 Redis 控制文档中保存；后续若实际并发规模增加，应依据测量继续拆分状态读写与执行资源配额。业务队列、归档成功清理和已有存储规则保持不变。

# 东方财富采集优化

2026-11-05，用户授权优化检查发现的六项问题。先记录设计，再实施；不改变已有用户计划，不迁移业务表，不清理生产数据。

## 设计

资金榜同轮采用唯一维护计划：正式日历验证、近三日/半小时复核和最多五日补缺由查询入口一次产生；采集执行复用已选日期，明确历史日期不额外探测最新页。无任务轮次采用SQL缺口查询，避免将全部历史日期传回Python再扫描。首次/恢复仍检查正式日历完整，不把缺日当休市。

收盘维护窗口随原子入队断点保存，整轮归档后完成标记；恢复成功和完成后标记失败重试均能补标记，不能把历史补缺误记作收盘复核。旧断点保留原范围，不假定新字段已经存在。

盘中快照新增摘要确认快径：在正式隔离准入内，由原Redis原子脚本检查版本、摘要、索引和正文存在性；有效且相同只确认，不压缩或传完整正文。缺失/过期/变化回原保存路径，最终仍重新原子核对；保持72小时正文绝对到期和容量限制，无新物理键。

两采集器接入公共运行成本上下文，失败/取消仍保存已观察请求/重试/字节。资金榜原逻辑请求及成功响应大小同步记录。

回购先通过共享代理下载器核实UPD筛选、排序及分页能力；不能仅因字段名是更新日期就认为覆盖所有历史修订。实现选择以实测和来源契约为依据，记录正常维护、历史回查和状态丢失恢复成本；不得把局部查询伪装成全历史集合证明。

实测UPD单引号日期筛选有效：5705方案中2026-11-01以来317份，UPDATEDATE仅102份，不能替代UPD。采用每三天至少一次全历史核验，其间按最近已归档核验日期回看三自然日；初始化、缺少可信SQL范围、显式重新采集仍全量。有限增量不能发现UPD不变的旧修订，最多三天全核发现。增量全批归档清队后计算当前SQL规范摘要，再经同一队列提交范围证明；声明最近全历史核验时刻，不把局部源集合摘要标作全历史证明。使用原collection_state行的有界coverage字段，新增contract=2/full_observed_at区别组合证明，不新增表/索引或自动迁移。旧contract=1完整证明及在途消息继续按其原完整语义处理。约5705行的SQL摘要核对成本须实测，避免用省网络掩盖过量查库。

容量排查定位到PyMySQL中文长说明逐字转义占主要CPU时间。三个TEXT字段使用UTF-8字节绑定，仍经参数化批量写入既有utf8mb4列；不拼接正文、不改变内容摘要或NULL。驱动十六进制编码约增加一倍说明传输字节，但批次保持有界，换取首次导入CPU下降。专项覆盖中文、emoji、引号、反斜杠、换行、NUL和空值逐字读回。

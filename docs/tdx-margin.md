# 通达信个股融资融券

## 如何查看

任务 `tdx-margin`，采集与查询走共享基础设施。入口为采集管理的“个股融资融券（通达信）”，数据预览按证券与交易日期筛选。本文记录契约；开发、实采及发布状态分别见验收证据。

## 数据范围与更新

用户指定每页10000条、每股一个完整响应。接口 `CWServ.tdxsj_rzrq_gg`，Params 为 `["2","1",code,"","1","1","10000"]`。2026-10-30 代理核实寒武纪返回1521条、总数1521、104650字节，日期2020-07-20至2026-10-28。不补造没有返回的交易日，不据此推断标的资格。

完整单位是一只证券的来源全历史。核对三结果集列、Count、页码1、总数、严格倒序且唯一的日期、非负有限数值及10000上限；总数超限或截断失败，不把第一页当完整。初始化/普通维护/fresh均一次完整历史核验；这属于用户指定的全量核验与差异入库，不是来源增量。默认每天北京时间19:30，保存配置优先。

按证券共享有界预取，按序原子入队、推进断点；只在全部证券入队后等待整轮归档清队。局部失败从失败证券恢复，已入队数据由归档器重放，不逐证券等待归档。Redis丢失后SQL保留已归档业务，下一轮重新逐证券核验，不承诺恢复丢失的内存进度。当前名单加已有历史证券组成默认范围；新轮次纳入新增证券，退市历史不随名单删除。未完成轮次遇到名单变化时保留原断点，须先显式核实范围；不能直接用新名单解释旧索引。

预算：N证券正常N次业务请求，无认证及目录请求；HTTP、网络及已核实的来源cache查询超时共用任务保存的请求重试预算（默认2次），不叠加预算。初始化/无变化/新增日/历史修订均N次完整响应，字节为各股历史响应之和；10000条的硬上限和共享generic正文上限共同限制。入队每证券一条有界压缩消息，无变化热摘要免SQL，冷摘要仅比较与状态确认；新增/修订只写变化行。每日全历史核验发现所有来源返回范围的修订，未提供历史版本或公布时刻。单证券补缺可显式指定该证券，普通失败不扩大到全池重采。

## 字段与日期

存储设计卡：固定来源tdx；一行是证券/交易日期，主键`(unified_code,trade_date)`，日期全市场索引`(trade_date,unified_code)`。证券头保存完整集合内容摘要、数量、日期边界和规范版本，明细保存7项来源数值。头和明细同事务提交，无外键级联当前stock名单，无整份业务JSON；不保存成功原始响应。

|来源|结构化字段|单位和语义|
|---|---|---|
|T001|trade_date|交易日期，YYYYMMDD转换DATE；不是公布时间|
|bt009|market_volume|万股，页面融券卖出占比的成交量分母|
|bt010|market_turnover|万元，页面融资买入占比的成交额分母|
|ClosePrice|close_price|元，页面融券金额计算使用的收盘价|
|T003|financing_balance|万元，融资余额|
|T004|financing_buy|万元，融资买入额|
|T006|lending_balance|万股，融券余量|
|T007|lending_sell|万股，融券卖出量|

数值使用DECIMAL(28,8)，不截断额外精度，不将NULL或异常转为零。平安银行停牌历史存在bt009/bt010/ClosePrice同时NULL，而融资融券原值有效，三项行情上下文允许NULL。页面派生值在正式查询计算：融资偿还=前一记录余额+当日买入-当日余额；融券偿还同理；最早记录按页面公式以前值0展示，并标明边界；融券余额=余量×收盘价（万元）；融资融券差值=融资余额-融券余额；两项占比=买入/成交额与卖出/成交量×100，零分母或缺行情上下文显示未知。派生值不重复落库。

正式查询：单证券日期范围、日期全市场均稳定游标分页每页最多200；相邻前值随查询读取，不让分页改变计算结果。完整性审计按证券读取至多10000日期，比较SQL规范正文摘要和头证明。初始容量预算以6000证券×每年250日规划，一年150万/五年750万行；隔离实测21证券/20000行（含单股10000行）分配4,210,688字节，按该样本线性投影五年约1.58GB；这不是全市场已存量。列表P95目标100ms、完整证券审计1秒、10000条初始化10秒、重复零业务DML；实测列表P95上界14.828ms、10000条历史181.421ms、最大单元导入0.547秒、重复业务DML为0。详见[容量证据](evidence/tdx-margin-timeout-capacity-2026-11-12.json)。

## 限制与排错

只有来源返回的历史可用；空集合必须带有效页码与总数0。来源返回整数`-1009`、精确`cache语句执行超时`且无业务结果集时，通过共享下载器按原证券、原参数重试，仍受代理、频控、总时限和资源边界约束；预算耗尽明确记录来源错误码和超时原因，保留失败位置。其他来源错误及结构异常仍直接失败，不能解释为空记录。来源无公布时间、无修订序号，采用请求开始观测版本阻止迟到响应覆盖；不声称严格历史版本回放或无未来信息的交易信号。数据准备中融资与融券两项分别检查，共享同一响应和归属。

显式维护新增证券头与日明细两表，维护前持锁并核实队列为空、既有业务完整，启动不建表。容量、来源反例、冷热摘要、旧响应、提交后重放、归档清队及真实桌面均须在发布前提供证据。

范围恢复唯一入口为 `scripts/migrate_margin_checkpoint.py --config <程序目录/config.toml> --previous-scope <原有序证券名单.json> --backup <新备份文件.json>`，默认只预检，加 `--apply` 才提交。正常关闭软件后运行；工具取得现有单实例锁，核对队列为空、旧名单摘要和数量、完整证券断点以及原批次已入队页成功归档。仅当当前名单的已完成证券仍组成连续前缀时，更新范围摘要、数量和索引，保留原批次、截止日、页数和累计条数，从第一只未完成证券继续。新证券穿插已完成前缀、旧名单不匹配或归档未确认时拒绝维护；可明确选择从头核验，已有SQL数据保留。备份独占创建，提交比较断点和revision并回读，重复同范围不写；该入口无来源请求、无SQL业务DML，不清业务队列。

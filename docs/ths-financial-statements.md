# 同花顺三大报表

三个独立采集项目：ths-income（利润表）、ths-balance（资产负债表）、ths-cashflow（现金流量表）。任务保存、代理与固定间隔沿用采集管理；每个项目可独立启停。来源是 basic.10jqka.com.cn 的 benefit/debt/cash JSON，各证券各表正常请求一次。

## 生命周期与范围

| 项目 | 契约 |
| --- | --- |
| 用途 | 财务分析，保存来源当前展示的历史报表；没有公告日期，不授权历史选股信号使用。接口金额本身为万/亿舍入值，保留精度，不能宣称原始精确金额。 |
| 初始化 | 当前股票目录中的沪深北证券，按市场代码排序，逐证券取得来源全部 report 报告期；不推断退市股票覆盖。 |
| 完整性单位 | 一只证券的一张完整表；核对日期唯一、降序、有效且不晚于当前日期、矩阵行列、科目身份及核心科目结构；来源金额缺值保存未知，合计矛盾原样保存并在查询/数据准备标记；空表拒绝，不冒充无财报。来源没有独立总数，依据单响应全历史矩阵协议；不承诺来源未提供的季度。 |
| 初始化完成 | 本轮所有证券单元入队且公共完成确认无残留；来源覆盖与数据准备分别报告。 |
| 后续 | 每轮从股票池首个证券开始，全历史回看修订及补缺；没有只检查最大日期的捷径。 |
| 修订 | 按请求开始时间排序，拒绝迟到旧请求；这不是来源修订号，无法识别源站返回的旧缓存。不同内容才写业务表。 |
| 中断 | 单证券校验后原子提交消息与下一证券断点；已入队不重下，继续后续证券；整轮末才等待归档。SQL 提交后确认失败由公共归档重放。 |
| 状态丢失 | Redis 存活按断点续采；丢失则从当前股票池首个证券重查，SQL 已有内容比较避免重复写入。 |
| 范围变化 | 股票池摘要不符拒绝混用断点，用户重新初始化建立新轮；已归档报表保留。 |
| 普通/重新初始化 | 普通优先继续断点；完成后新轮全查。重新初始化从首个证券重查，不删除历史。策略下一轮生效。 |
| 进度 | 显示已入队证券数和报表数；支持范围不等于已归档范围。未核实的公告日期、源端缺报及舍入精度明确显示。 |

归档使用三张独立业务表，业务键为来源、市场、代码、报告期、来源报表口径（本接口 report）。科目保留来源名称与单位，不将摘要行混入明细；不计算单季度/TTM，不将不同报表相互依赖。请求失败或校验失败不得推进断点。来源观察到的期间集合存入统一 collection_state，正式查询按集合与内容摘要验收；旧历史不会因本轮来源缩短而删除。

旧版完整业务库通过 scripts/migrate_business_schema.py 显式转换结构，新空库使用 init-db；启动不建表。维护前正常关闭 Empire 并检查待归档队列，核对原表数量与内容摘要，完成后重开。实际验收范围、缺口与发布证据另记，不以本说明替代实采验收。

## 批量验证与来源质量（2026-09-30 修订）

采集管理中的完成表示来源完整响应已保存，并不代表每期可直接用于估值。数据浏览的三表增加“来源质量”列；选择“需核查”报表可看到缺少的核心科目金额、合计差额和舍入容差。来源 `false`、`--` 和空字符串保留为未知，不能补成零、套用别的科目或删除整期；源站金额矛盾不自动改写。数据准备分别核验集合覆盖、核心值、金额质量和公告可用日期，缺核心值或已知合计矛盾仍失败。

报告期采用标准日期并限制在 MySQL DATE 可存储范围（1000 年起）至当前日期；真实样本平安银行含 1989-12-31，不再以 A 股开市年限制公司历史财报。非法日期、重复/乱序、矩阵截断、未知金额格式/单位、缺核心科目结构继续报错且保留失败位置。初始化、按序断点、整轮末等待归档及后续全历史修订回查均不改变。

本次放宽的是无损采集准入，业务键、已规范金额和 SQL 表结构不变。此前被拒绝单元按原断点补采并建立新的覆盖/摘要；此前成功单元仍符合新结构。质量结论每次由当前规范业务内容重新计算，不缓存旧的“质量通过”，旧完成/覆盖标记不能替代核心值与质量验收。因此无需批量改写原业务或清除无关断点。

维护时可运行 `.venv/Scripts/python scripts/verify_ths_statements.py --output <证据文件>`。它按沪深北分层及金融行业代表证券核验三表，沿用共享下载/路由和正式入队、归档、查询；使用随机隔离命名空间和测试来源，结束仅删除测试自身记录。尊重已保存的任务代理策略，不保存成功原始响应，不重设生产断点。输出证券集合、每表期间集合/摘要、质量问题和开发验证结果；不把分层样本冒充全市场验收。正常采集仍单响应一次，不增加每轮双读。


## 长历史报表入队大小（2026-09-30 巡检修复）

三表消息契约升级为 schema 2：证券及口径信息只传一次，科目名称只传一次，报告期各自保存完整金额/精度矩阵。归档规范化后仍为原来的完整业务行，业务键、SQL 内容、集合摘要、版本顺序、单证券原子断点和整轮末等待归档均不变。没有截断报告期、丢弃空值或扩大公共 512 KiB 单批上限；仍超限则保留失败断点。

部署前正常关闭程序并由旧版统一归档处理待归档消息，核实队列为 0 后才切换 schema。运行时只接受 schema 2，旧消息不会被静默清除；不增加旧版解码兼容路径。数据库无 DDL/业务转换，现有规范内容与摘要不变，无须重采已经确认的前序证券；本次失败证券按原断点重发。

新增专项验证长名称、多科目、120 报告期矩阵的往返无损、单批字节数、缺列/重复列/坏精度拒绝、超限不推进以及默认上限下端到端归档。巡检记录见 `docs/evidence/ths-watch-size-repair-2026-09-30.json`。

正式浏览通过现有主键先选取分页身份再读取正文；六位证券代码精确匹配，前缀搜索仍支持，避免历史数据增多后扫描/排序全部 JSON 正文导致查询超时。


## 科目与年度预览（2026-10-02）

三表页面先按代码或前缀查询证券，再选择证券横向比较全部已归档报告期；年度视图仅选择 12 月 31 日。科目固定在左侧，报告期按最新到最旧排列，一级标题用底色、二级标题及小计用加粗、普通科目用缩进区分。金额单位可选择元、万元、亿元，选中或悬停查看原始元值及来源精度。

参考源站普通企业、银行、保险、证券的科目顺序和层级，界面离线匹配最相近结构。已存储数据未含原始标题层次，因此不宣称逐证券复刻源站布局；未知科目单列且不遗漏。展示切换不改变业务记录、摘要、采集与归档生命周期。源站缺值显示“—”，质量异常报告期显示提示，保留公告日期限制。


## 数据准备的范围与用途

三表按所选证券及报告期范围核对来源日期集合、全证券内容摘要、核心金额和本表合计关系。当前财务分析缺公告日作为限制，历史选股仍必须补公告/可用日期。数据可用仅覆盖列明的核心金额及金额关系，不表示任意估值公式输入齐全。证券/日期选择只影响只读验收，不影响采集生命周期、消息、SQL状态或摘要有效期；范围外内容损坏不能被范围筛选掩盖。无报告期的来源范围保持未确认，不推断软件漏采或来源无报告义务。

## 压缩传输中断

HTTP 200且解压出部分JSON仍不算成功；缺少压缩流终止标记时，共享下载器按任务已保存的请求重试次数有限重试。耗尽后保留当前证券断点，不入队部分报表；继续采集会重新请求未完成证券。来源金额缺值、矩阵异常与金额矛盾保持原有质量语义，不借网络重试填零或跳过证券。

## 归档状态的有界读取

冷摘要归档只读取本证券的完整报告期集合及摘要、版本和项目 progress/manifest，并在同一事务内局部更新。其他证券的集合继续保留，财报正文、金额精度、旧版本比较及来源生命周期不变。完整范围审计仍读取全状态；完成等待回源只读 progress。这是客户端传输优化，不能当作全历史已采完或已测得磁盘收益的证明。

## 共享有界下载与恢复

下载调度按 [全部采集共享预取](all-collector-prefetch.md) 的本项目行执行。可独立单元并行下载，来源校验、入队和断点按原业务顺序；协议依赖保留必要顺序，正常必要响应不重复读取。失败或取消回收全部请求及额度，未入队预取结果继续时重下；原生命周期、修订范围、正式查询及整轮末归档确认不变。已保存任务与站点配置优先，程序更新后正常重启使用新版，无需迁移业务数据或清理既有断点。

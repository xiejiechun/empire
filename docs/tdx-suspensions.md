# 通达信沪深 A 股历史停复牌

## 日常操作

任务名为“沪深 A 股历史停复牌（通达信）”。首次使用前先显式执行 [停复牌表结构变更](../sql/changes/2026-09-29-tdx-suspensions.md)，并在网站访问规则中保存 `tdx.com.cn` 的共享频控。然后在“采集管理 → 采集任务”运行该任务。

首次初始化从 **2004-12-27** 开始，逐个自然日请求到运行时的北京时间当天。来源按证券排序，同证券事件可能在偏移分页边界重排；现每次只取第 1 页的完整日集合，起始容量 1000 条，装满时扩大容量重取整日，最多 10000 条且仍受共享响应字节上限约束。只有返回行数小于请求容量、原始 A 股行数与来源计数相等且业务集合通过核验时，才确认该日完整。完整响应若含完全重复记录，须再次取得完整日响应，全部内容及重复次数一致才合并；同键内容冲突或复核变化仍拒绝。不拼接偏移分页，不以去重掩盖漏行。B 股不参与 A 股计数；北京 A 股（4、8、920 开头）参与计数但不进入沪深业务表。空日须有有效零计数与日期回显。任一天失败均保留未发布月份断点。

逐日核验通过后优先按自然月组成一个归档消息；超过配置的单次入队字节上限时，按连续日期拆成较小范围，全部范围预检通过后按顺序发布。单日仍超限会报错保留断点。批次进入 Redis 后立即通知统一归档器，采集继续下一批，不逐批等待 MySQL；归档器独立消费，60 秒扫描只作遗漏唤醒恢复。整轮入队结束后等待本轮全部消息处理成功才显示完成，不能仅凭最后一页成功确认。

## 后续从哪里开始

- 只重启 Empire、Redis 仍运行：断点只保存日期范围、月份索引和下一未发布日期，约数百字节，不重复保存完整月份计划。从下一未发布日期继续，已有待归档消息由归档器独立处理；月内下载结果尚未入队时会重采该未完成范围，不跳过日期。
- Redis 服务或电脑重启：临时断点和待归档数据丢失，从 MySQL 连续覆盖上界当天重查，再向后补齐。无 SQL 覆盖时从 2004-12-27 开始。
- “重新采集”：主动重新核验全部历史；日常中断恢复请用“立即采集 / 继续采集”。是否自动续跑仍服从已保存的执行计划，手动任务需再次点击。

例如已归档至 2005-01-31、2 月只下载一半，应用重启后从 2 月未发布范围开始；若 Redis 也重启，则从 1 月 31 日重查再补 2 月。超大月份拆分后，从最后一个成功入队日期范围的下一天继续。

MySQL 的 `collection_state` 保存本项目最后 SQL 确认的连续日期上界。普通后续采集从这个上界当天重新检查，再采到新的北京时间当天。例如已确认到 2026-09-28，2026-09-29 运行时会检查 9 月 28、29 两天。重查一天用于取得来源后来补出的复牌时间；不会根据 Redis 断点猜测永久覆盖范围。

“重新采集”会再次从 2004-12-27 核验到今天，但保留已归档事件。相同内容命中可信 Redis 摘要时不访问 MySQL；摘要缺失、损坏或过期时回 MySQL 比较。完全相同不写业务表，较新的有效变化才更新，迟到旧响应不能覆盖新版本，后来响应把复牌时间变回空值也不能抹掉已知复牌时间。来源后来不再返回某条历史事件时，不自动删除 MySQL 记录。

Redis 是纯内存临时层：保存待归档消息、断点、摘要和有界运行记录，不保存完整历史。只重启 Empire 且 Redis 仍运行可以续跑；Redis 或电脑重启后这些临时状态会丢失，程序以 MySQL 连续覆盖上界重新规划。成功响应原文不长期保存，错误样本按项目最多 300 条、单条 64 KiB，只在 Redis 中保存并脱敏。

## 业务范围与字段

仅保存上海、深圳 A 股。业务唯一键为 `source + market + code + suspended_at + resumed_at（含未知） + 来源说明及原因摘要`。SQL 用非空 `resume_key` 表示复牌时间，未知时用内部索引占位值；`record_key` 是来源说明和原因的 SHA-256 身份摘要，两者共同参与主键，查询仍返回原业务字段，不暴露占位值或摘要。这样不同复牌时间以及同一时间下通达信并列给出的不同说明/原因均分别保留。字段包括市场、代码、名称、停牌及复牌时间、类型、来源说明和原因。DATETIME 按北京时间写入 MySQL；内部版本和 Redis 消息使用带时区绝对时间。

来源历史记录可能同时给出“停牌1天”和同日明确的停复牌时间（例如 2005-06-17 的 000921，09:30～10:30）。同日复牌按明确时间归类为 `intraday`，原始说明仍保存在 `source_note`，不改写时间或丢弃事件。复牌早于停牌等无效时间仍拒绝；此规则不表示已跨来源核实该事件。

停牌说明是可选文字，来源 `sj=null`、空串或纯空白统一保存为 `source_note=""`；不写成“None”，不编造时长。仍根据停复牌时间及现有分类规则处理：同日明确复牌归为盘中停牌，未给出复牌时间沿用未复牌分类，保留 `resumed_at=null`，不将其解读为已确认全天结束。数字、数组等错误说明类型仍拒绝。示例：000950 在 2005-10-10 的说明和复牌时间为空，原因“临时停牌”。

停牌原因同样是来源可选文字；`sjcontent=null`、空串或纯空白统一保存为 `reason=""`，不编造原因。数字、数组等错误类型仍拒绝。例如 000602 在 2006-05-08 的来源记录提供停复牌时间和说明，但原因为空。

按用户确认，不同复牌时间的来源记录分别保留，包括未知复牌记录；不选择较晚日期覆盖，不再合并未知与已知状态。例如 600002 停牌时间同为 2006-02-08，复牌 2 月 9 日与 2 月 17 日分别存两条。完整业务键及内容均相同才去重；同批次相同完整键的文字冲突仍报错，诊断包含证券身份、来源日期及差异字段。跨轮同键内容修订按观测版本比较，迟到旧响应不覆盖。保留来源不同区间不代表已裁定唯一回测交易约束。

旧版升级先关闭 Empire，等待积压正常归档（不删除消息），再执行 [身份迁移维护](../sql/changes/2026-09-29-suspension-identity.md)。原业务行不删除，迁移核对数量及原字段摘要；旧规则曾合并记录，因此只重置本项目覆盖、摘要和断点，从 2004-12-27 重新核验补回，其他项目不变，启动不自动迁移。

来源页面的历史起点经检查为 2004-12-27。本数据用于估值分析和普通日频回测中的成交约束，以停牌、复牌生效时间为准。它不保存公告编号、秒级时刻、来源修订号或来源曾经展示过的完整旧版本，也不承诺严格历史版本回放；原因文字不能当作早于其可用时间的选股信号。单一来源在声明范围内通过字段、日期、分页和明显错误检查即可，不要求另一网站交叉印证。

在“数据浏览”的数据目录搜索“历史停复牌”或“通达信”打开页面。左侧常驻来源日历，支持年份输入、月份选择、前后翻月及“今天”；点击日期立即查询通达信该日返回的已归档记录，默认选中今天。勾选“全部历史”可按沪深市场、证券代码前缀检索已补齐来源日期的历史，点击日历日期会回到单日查询。每页显示 50 条已归档来源记录，支持上一页、下一页及完整说明查看。页面显示来源日历的连续补查上界，未完成日期无结果不能解释为该日无记录。

点击任意表头切换升序/降序，默认按证券代码升序；排序由 MySQL 在所有匹配记录上执行，同值时以稳定业务身份确定顺序，非当前页本地排序。筛选和排序变化返回第一页，切页保留排序；翻页期间若有新数据入库，可点击查询/刷新从第一页重新查看。页面按需读取 MySQL，不自动轮询业务数据，切页期间保留筛选、选中日、显示月份和排序。

复牌时间为空显示“来源未提供”，不代表目前仍停牌。000411 的 2006-07-10 停牌记录与 2006-07-31 复牌记录分别出现在各自来源日历日；即使两条的停牌时间都是 7 月 10 日，7 月 10 日查询也不会显示 7 月 31 日才出现的记录。“全部历史”可看到两条，行数不等于独立停牌次数。数据准备页另行显示范围、唯一键、质量和时间证据。

2026-09-29 通过共享下载器复核：来源 2006-07-10 返回 000411“今起停牌 / 进行股权分置改革的提示性公告”，复牌时间为空；2006-07-31 返回“今起复牌 / 修改对价方案的沟通结果公告”，复牌时间为当日 09:30。两条均保留 2006-07-10 09:30 作为停牌时间。曾按停牌日期筛选造成日期混淆，现已改用来源日期集合 `source_dates`，通过显式维护和重采补齐，见 [来源日历修复](tdx-source-date-fix-2026-09-29.md)。

`source_dates` 在日响应日期回显核验后从真实查询日记录，不按时间或文字猜测；月内去重时保留全部出现日，跨月归档按并集补齐。迟到响应可以补充此前未知的出现日，但不能覆盖较新的内容。可信摘要的身份包含来源日期集合，避免将不同日期的迟到响应误判为已处理。完整日集合契约为 `suspensions.period@3`，旧版消息须在维护前完成归档。显式入口 `scripts/migrate_suspension_identity.py` 保留业务数据，重置旧分页覆盖、摘要及断点，建立 `collection_integrity_version=2` 并从历史起点重新核验。未知来源日期的旧记录会使数据准备验收失败。其他数据集仍使用各自现行契约。

## 存储与恢复

业务记录保存在 `suspension_event`；本项目在 `collection_state` 只有一行。摘要按事件业务键以及日期覆盖段分别管理，默认最多 10000 项、最后确认后 7 天过期。插入、更新、SQL 相同确认、可信摘要命中和过时版本确认都由统一归档器删除对应 Redis Stream 消息；SQL 或提交后的 Redis 操作失败则保留消息安全重放。

表结构只通过显式维护入口建立，应用启动不迁移。手工修改或删除 SQL 业务记录前必须停止归档并失效 `suspensions/tdx` 摘要；重放旧批次还要处理覆盖状态，优先重新采集产生新批次。


## 日频数据准备的日期目标（2026-10-02）

日频验收使用正式 trade_calendar 的 cninfo 明确交易标记，查最近一个已结束交易日，不在休市日强求当日补查。开盘前、集合竞价、午休及盘中均以此前已结束交易日为目标；覆盖全沪深A股的验收界点统一为北京时间15:30，含适用板块的盘后阶段，不把09:15至15:30误写为连续交易。

日期覆盖与 confirmed_at 必须共同满足：覆盖至目标交易日，且成功核验不早于该日15:30。长假不按三个自然日自动过期；缺失或无效日历保持未确认，不按周末或假期推算。仍保留真实历史缺口、来源日期、业务键、质量检查；2004-12-27以前仅标注来源范围。该调整只改变只读验收，不改变逐自然日采集、恢复、Source_dates及统一归档，不重建或更新SQL/Redis证明。

## 共享有界下载与恢复

下载调度按 [全部采集共享预取](all-collector-prefetch.md) 的本项目行执行。可独立单元并行下载，来源校验、入队和断点按原业务顺序；协议依赖保留必要顺序，正常必要响应不重复读取。失败或取消回收全部请求及额度，未入队预取结果继续时重下；原生命周期、修订范围、正式查询及整轮末归档确认不变。已保存任务与站点配置优先，程序更新后正常重启使用新版，无需迁移业务数据或清理既有断点。

## E3代码归属与验证范围

来源身份、日期规则、规范化、归档、正式查询和页面归入 `src/empire/features/suspensions/`，定位见包内README。来源日期集合、并列记录、未知复牌、版本比较、恢复与成功清队规则保持。公共准备契约与控件继续使用原唯一公共路径，无启动迁移。

空私有库的有限真实归档验证必须从2004-12-27开始，不能给近期样本补造此前的连续覆盖。近期固定错误日期可另外只读复核来源，但不能因此声称近期全链路或全历史已通过；尚未复现或未修复的错误保留原ID。具体本轮执行事实与限制只记入阶段证据。

跨日合并拒绝冲突时，`merge_event → bounded_batches → execute → CollectionRecords` 保留 `metadata.conflict` 的完整业务身份、两个实际来源日和差异字段值，公共记录服务统一脱敏并限制大小。只补诊断，不改变来源身份、合并拒绝、断点、SQL 或归档路径。原错误没有这些字段时不能按今天的成功响应猜补。当前业务缺口与用途结论见[业务完整性账本](business-integrity-status.md)，旧阶段证据保留原结论。

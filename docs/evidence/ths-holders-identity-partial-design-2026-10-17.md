# 空名债券按报告隔离的实现设计

项目 ths-holders；本轮目标错误 55376fb168204134a251b2749a6a07e7，相关同类 ID 见 identity-followup 证据。原规则整证券拒绝，导致可识别的股东及具名债券报告也无法保存；本轮修复此行为。

业务粒度与身份：holder_report / holder_member 仍只保存身份完整的报告和成员，唯一键、字段、索引、正式列表/详情 SQL、版本防覆盖与历史保留不变。不为未知债券编造名称或业务键。三栏仍同一个消息、同一个 SQL 事务；仅明确的空名债券报告允许隔离，其余结构错误仍拒绝整证券。

消息 schema 5 增加必需的 gaps 数组，最多100项，每项仅包含 kind=bond_holders、report_date（ISO日期）、source_panel（页面块内定位，最长100字符）和 reason=instrument_name_missing。定位只用来指示来源缺口，不充当跨响应债券身份。未识别报告正文不存 SQL 或新缓存。

collection_state 现有每项目一行的单位证明扩展 source_gaps（同消息有界数组）；不新增业务表。三栏各自的有效报告集合证明不混入未识别报告；债券栏目 availability=source_gap，其余栏目可独立完整。单位/栏目摘要绑定 gaps，完整范围 manifest 禁止含缺口。既有完整证明的报告集合语义不变（contract4）；从未成功的两只证券由新采集建立部分证明，旧完整证明无需全池失效。准备缓存修订号递增，使旧结果失效；债券准备保留具体报告期缺口，顶十和流通股东不再被牵连。

归档：同内容零业务DML；来源缺口变化参与指纹，避免可信缓存跳过证明修订。较旧响应仍按单位及报告观测版本拒绝覆盖，事务提交后重放与成功清队复用统一路径。指纹无缺口时保持原规范摘要，以沿用可信完整数据；有缺口时加入 gaps。队列 schema 仅接受5，发布前核实待归档0，不保留旧消息兼容分支。

生命周期：首次及日常仍核验当前股票池。缺口证券的有效报告可以入队，不推进连续断点，不发布整轮完整证明；继续后续证券，整轮末确认所有有效消息归档。空名报告记录为可查询来源缺口，不再每次生成泛化原文错误样本；运行末仍明确说明未完整，不能冒充全成功。后续来源补齐名称时，重新采集替换该证券证明、清除相应缺口，历史有效报告不删除。Redis丢失从股票池首重新核验，SQL缺口仍可见。

容量：最多100条缺口，每条定位100字符，额外消息/状态预算64KiB以内；现有报告100份/栏、成员400/报告、详情1MiB与审计10报告/4000成员保持。验证实际序列化预算、三栏正式查询、缺口来源日范围提示、不把空名当空栏目。

验证：空名+具名同日独立块、多个空名、错误日期/定位/表结构不被放行、后续证券继续、连续断点与完整manifest、只含空名的债券栏目、未知数量、冷热摘要、旧响应、事务重放、来源修复后完整证明。严格代理随机30股加300398/601515固定反例；来源→Redis→统一归档→SQL与缺口集合核对，待归档0。最后文档审阅、统一发布、真实桌面及精确ID错误清理。只有实际验证的新处理行为覆盖的旧泛化错误才能清理，缺口留在正式准备结果，历史失败运行不改写。

当前为实现前设计，尚不代表以上功能、实采或发布已经完成。

旧版在关闭前可能仍有schema4待归档消息；通过唯一维护入口 scripts/migrate_holder_source_rows.py --pending-only 预检，关闭程序并取得单实例锁后加 --apply，无损转成schema5并增加空gaps。保留业务正文、批次、页码和来源观察版本；原子比较原消息后追加新信封并移除旧信封，失败保留原文。启动不转换，不删除有效业务，转换后由统一归档器正常处理和清队。source_gaps_digest认证SQL中的来源缺口集合。

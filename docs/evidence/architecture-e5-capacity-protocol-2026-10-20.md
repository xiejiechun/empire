## 范围与不变约束

本批将分红、配股、增发及复权迁入各自业务包，同步调用方并退役24个旧模块；不改变表、消息版本、任务/插件/页面身份、来源参数、金额/日期语义或恢复算法。公共 preparation 契约保持既有路径。复权仍在同一连接快照内读取行情、日历和资本事件。组织等价须经逐符号审阅、业务专项及真实管线证明，不能仅凭 AST。

容量运行使用 D 已实现的 PrivateStorage：实际生产/测试 server_uuid 必须不同，测试实例为显式13348；新 UUID 库、Redis namespace及 owner；SQL守卫覆盖实际会话；归属核实后清理。共用 source_verification 的取消、正常关闭、清理失败和 cleanup-only 恢复路径。正式请求前先通过工具反例和真实 SQL smoke。运行时正常关闭 Empire，不修改生产设置、任务、断点、摘要或业务数据。

## 输入与执行

1. 在同一生产只读事务中读取当前股票池、tdx站点/全局下载设置、分红完整现存行及 tdx-dividends 统一状态。冻结规范摘要、实际 UUID、读时刻、行数/字节量与文件输入摘要。生产旧记录只复制到私有库，不删除或改写生产。
2. 私有库保留旧业务记录和有效历史发现证明，namespace改为私有身份；仅有已归档报告期及有效历史证明能减少历史发现请求，不能伪造证明。来源运行走正式分红 collector、共享下载/代理/预取/入队/归档/query，一次执行当前完整声明池。必要响应默认一次；重试、回退如实记录。
3. 只观察正式返回值及成功入队内容，不另造采集器。记录真实计划日期集合、各期来源规范行数/集合内容摘要、组装池内集合、正式入队及SQL查询集合内容。成功原始响应不保存。源池外行计入来源容量，不能以过滤后行数代替。
4. 保存 SQL 中本轮来源未再出现的历史记录差异（数量、身份与摘要）；不得删旧历史以使准备检查通过。管线一致、来源容量与完整历史准备结果分别报告。旧报告的5条差异及56145/629/5580数字仅作历史比较，不复制到新测量。
5. 正式 `CapitalDataPlugin('dividends').list_events(code='600007', limit=51)` 连续计时10次，计时包含原 mysql.read/SQLLane 等待与解码；不替换成直接连接适配器、不只计SQL执行。每次返回集合内容须一致，记录全部原始计时。

## 冻结预算与判定

| 指标 | 原阈值 |
| --- | --- |
| 本轮全部计划期的真实来源行数 | ≤100000 |
| 实际计划报告期数 | ≤1000 |
| 私有SQL全表 JSON payload 字节之和 | ≤134217728 |
| 最大单条 SQL payload 字节 | ≤65536 |
| 上述10次正式查询最大耗时（P95上界） | ≤1500ms |

SQL JSON 字节采用 `OCTET_LENGTH(CAST(payload AS CHAR CHARACTER SET utf8mb4))`，与旧完整容量口径核对；同时记录规范来源字节，二者不混用。容量报告必须绑定本轮最终正式代码、SQL契约与工具；路径迁移后重新运行，不刷新旧hash。来源不可用、计划不完整、预算超限、输入漂移、查询内容不一致、pending非0或任一清理失败均不能通过。

本次纯组织迁移的容量观测覆盖完整股票池，不能冒称已满足“随机30股严格代理实采”。若审阅发现来源/解析/集合/恢复实质变化，必须额外登记种子与原名单，执行随机30不同股票加固定失败证券，不换样；全部代理链路及集合内容通过且本轮pending=0才能通过该项。开发允许代理失败回退，回退结果不能充当严格代理证据。

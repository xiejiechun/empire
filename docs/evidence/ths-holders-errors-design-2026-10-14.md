# 股东研究错误修复设计（实施前）

处理对象为 ths-holders，300 个确切错误 ID 按时间登记在 ths-holders-errors-2026-10-14.json。调查脚本曾将八证券详细探针覆盖到全证券调查文件；现已独立保存探针，重新执行全证券调查，不沿用被覆盖的证据。

业务粒度沿用报告父表及当期/退出成员子表；三栏整证券校验、一次原子入队、统一事务归档。生命周期沿用当前股票池窗口复核、首缺口续采、整轮末确认，失败不推进连续断点，Redis 丢失重读。

成员主键仍为 (report_key,member_group,seq)，seq 改为组内规范行位置。新增 source_rank SMALLINT NULL，仅债券保存页面原始排名（1～9999、可并列或缺口）；股票为 NULL。来源名称/ID/股份类型仍参与独立重复检查，不能通过重排吞掉重复身份。债券旧 seq 明确迁为 source_rank，再按旧行次序规范化 seq；报告业务键、原数值、名称及观测版本保留。退出比例来源为横线时 ratio 保存 NULL，当前比例仍必需；数量仍必需，不填零。

变动公告当期人数上限 200，退出人数上限 200，报告总成员上限 400；定期股票当期也上限200（实采发现84人且有来源双汇总）、债券10，定期仍核对来源数量和比例汇总。真实反例公告159人/退出149人。汇总比例允许最多100.15且不超过100+当前人数×0.005（两位百分比累计舍入）；个人比例仍不超过100，数量汇总原显示精度校验不变。汇总矛盾、未来日期、缺债券名称、缺必要数量保持失败。

正式详情按报告键读取最多400行、上限1MiB；审计每批10报告、最多4000成员，证券/日期游标索引不变，无来源排名索引（仅完整详情显示）。年度/五年常规定期预算沿现有设计，公告人数增长按实际报告计，极限每报告约0.8MiB文本预算；补充最大单元和隔离性能验证后更新容量证据。

显式维护新增列、可空退出比例及有界CHECK，重排旧债券序号并重算报告内容摘要，逐报告核对旧字段等价及总量/观测版本。维护前正常关闭桌面、待归档为零、取得单实例与SQL维护锁；DDL不可事务回滚，每步可重入，保留恢复所需证据。旧来源摘要及collection_state覆盖证明、Redis断点失效，重采重建contract2；消息schema2正式路径不接受旧消息，维护前要求队列零。任务配置、其他项目、原错误记录不修改。

验证包括大公告/退出、退出未知比例、债券并列与rank11、100.01汇总、过界及同数异集拒绝；原始来源→规范化→Redis→统一归档→正式查询，重复零业务DML、冷热摘要、修订、旧响应、事务后重放、成功清队。逐登记ID关联实采结果，正式发布验证后只清理已覆盖缺陷且实采完整成功的ID；源站质量错误保留。

进一步核实完整页面可仅提供股东人数、十大股东与持股集中度三个业务区块，缺少流通与债券栏目；同时没有对应日期标签或栏目标记且十大股东完整校验通过时，声明栏目未提供，不代表没有持有人。伪缺日期、缺区块、残存栏目标记、无效十大股东均仍失败。

## 1. 目标与决策

采用“小内核、统一公共服务、按业务组织插件包”的渐进结构。优化目标是让修改者准确找到一项业务的完整实现、知道影响哪些消费者、用对应证据确认修改结果。

业务包是代码归属单位；采集、查询、页面插件仍是运行时启停单位。一个业务包可以提供多个插件，一个来源响应也可以产生多个页面。纯解析函数、格式化函数和普通控件不额外注册成可启停插件。

保留现有 PluginManager、能力依赖、统一下载/代理/频控、入队、归档、摘要、SQL 执行通道、任务调度和页面生命周期。继续内部显式白名单与统一发布，不引入任意第三方目录扫描、代码热更新或按业务复制基础设施。

期望的修改边界：

| 修改 | 主要归属 | 仍需共同处理的内容 |
| --- | --- | --- |
| 页面文字、布局或交互 | 本业务 UI 与相关测试/说明 | 通用控件缺陷才进入共享 UI |
| 来源字段或解析修复 | 本业务来源/契约与专项测试 | 按现行要求完成实采及归档查询验证 |
| 新增独立业务 | 新业务包与一项中央白名单 | 必要 SQL 设计/维护、文档覆盖与测试登记 |
| 公共下载或归档规则修改 | 唯一公共实现 | 受影响消费者、恢复及并发回归 |
| 跨业务计算 | 独立计算业务与输入公开契约 | 字段含义、日期可用性、缺值及调用方迁移 |

“只改对应插件”是局部业务修改的目标，不是公共契约变化时的承诺。目录收拢不能代替依赖控制或端到端验证。

## 3. 目标结构与依赖规则

目录名称统一使用 `features`；共享实现暂留现有正式位置，避免先做无收益的全仓搬家。示意：

```text
src/empire/
  core/                       现有内核与运行时
  contracts/                  跨业务公共协议、贡献声明类型
  plugins/infra/              唯一连接、下载、代理及资源服务
  plugins/pipeline/           唯一入队、归档、摘要流程
  plugins/collection/         唯一调度与记录服务
  plugins/ui/                 管理页面与明确的公共控件
  features/
    builtin.py                显式内部业务包白名单
    news/
      bundle.py               组装本业务插件及其现有贡献声明
      contract.py             本业务公开类型、身份和规范规则
      source.py / collector.py
      dataset.py / query.py / ui.py
      README.md               定位入口与权威文档、测试链接
    holders/
      bundle.py / contract.py
      source.py / collector.py / dataset.py
      query.py / audit.py / ui.py
```

这不是每个包必须具备的文件清单。复杂功能按职责继续拆分；测试可按业务分组放在 `tests/features/`，隔离集成仍归现有 integration 测试入口。不在运行包内嵌测试框架依赖。

依赖规则：

1. 内核与通用归档/调度不导入具体业务。业务通过已有贡献契约接入；公共基础设施不反向读取业务私有模块。
2. 业务间只使用公开契约或已声明的查询能力，不导入对方 collector、UI 或私有辅助函数。跨业务计算本身归独立业务。
3. 本业务的 source、dataset、query 可共享纯业务契约；不能通过调用采集执行器取得字段规则。
4. `requires` 和可选能力维持当前语义。Redis 可选证据不能变成 MySQL 浏览的硬依赖；不能机械把 `context.optional` 全部改成必需依赖。
5. 公共任务定义类型从控制器实现移至 contracts，所有调用方同批更新，旧导入不留转发层。
6. bundle 组合既有任务、数据集、页面及 preparation 声明，避免复制同一项元数据。启动收集顺序确定；只构造声明时不连接数据库、不发请求、不创建 Qt 页面。
7. SQL schema、文档覆盖及迁移入口仍为各自权威路径。业务包声明归属并不意味着每个来源都建表，也不允许启动时执行 DDL。

需要先明确归属的实例：财报 `chain` 摘要逻辑应归财报契约；开盘啦产品身份与日期范围规则应与采集执行解耦；`holder_html` 同时服务股东与资本运作，须保留一处公共来源辅助，不能移成股东私有代码后让资本运作反向依赖。

## 4. 实施批次、交付物与退出条件

每批独立提交、执行适用验证后发布。发生契约差异时停止扩大迁移，先解决本批问题。A/B 已进入实现与验收，进展见 [首批记录](evidence/architecture-ab-2026-10-19.md)；其余项仍按下列退出条件实施。

| 批次 | 具体任务与落点 | 交付物 | 进入下一批的条件 |
| --- | --- | --- | --- |
| A：发布可追踪 | 加固唯一 verify-release/build 入口；覆盖全过程的所有权、完整输入摘要、暂存构建与最终发布切换 | 发布身份记录、并发/编辑/失败注入回归 | A1～A4 全通过，失败不会替换正式程序 |
| B：定位与诊断 | 复用 doctor、运行快照、正式查询、scan_preparation；增加有界按项目诊断和模块归属/依赖报告 | 只读报告、静态基线与已知依赖债务清单 | D1～D3 全通过，现有依赖不增加 |
| C：装配与新闻样板 | 抽出纯 TaskContribution；新闻回归 features/news；业务声明回包，中央只收集与校验 | 新闻业务包、白名单收集器、精确装配快照 | C1～C4、R1～R4、U1～U3；旧路径清退 |
| D：股东复杂样板 | 共享 HTML 辅助先归位；迁移一采集器、三栏契约、查询/审计与页面 | 股东业务包及影响范围清单 | 保持一次 HTML 响应三栏、单任务和三独立页面；H1～H3 |
| E：逐业务推广 | 财报、开盘啦、事件等按独立批次迁移；跨业务计算接公开输入契约 | 各批迁移与退役清单 | 按职责判定的查询/UI/存储对采集执行器依赖归零；跨业务私有导入归零；每批回归/发布完成 |
| F：文档与共享热点 | 业务说明单源分块、确定性聚合；公共 API 增量纳入严格类型检查；按数据判断共享热点 | 文档构建、测试选择报告、类型边界及必要的小范围职责拆分 | M1～M3、T1～T3；无收益的重写不进入范围 |

A 与 B 可分工开发，但共享发布、数据库维护和桌面操作串行；C 前必须能取得可信基线。F 的文档引用及类型规范可随 C/D 先落地，全面推广在样板稳定后进行。

新闻作为第一样板，覆盖单来源分页、修订、归档和查询，组织变动较小。它不证明股票随机 30 样本或多栏目行为。股东作为第二样板验证复杂性，避免同一批同时修改目录、来源解析、表结构和生命周期。

暂不排固定工期或“提速倍数”。C 完成后，依据实际改动文件、定位过程、测试耗时和缺陷再估算 E；文件数、token 或耗时下降需同类任务实测。

## 5. 可执行验收标准

### A. 发布身份、互斥和配置

| ID | 方法及反例 | 通过标准 |
| --- | --- | --- |
| A1 | 同一正式目录同时启动两次发布；分别在测试、打包、发布切换阶段触发 | 第二次明确拒绝；不存在第二套构建/发布所有者；失败与取消只释放自己的锁 |
| A2 | 测试前后、打包中和最终切换前分别修改受保护源输入 | 输入包括代码、测试、SQL、依赖、构建脚本、源资源、帮助正文及所需文档 JSON；任何变化均不能产出通过证据或替换正式包；生成的测试证据/构建清单属于输出，独立计算摘要并绑定源输入身份，避免自引用 |
| A3 | 制造测试失败、打包失败、配置不可写、复制中断、目标被占用 | 原可运行程序及原配置保留；暂存目录有本次归属；不删除他人锁、不强杀服务；恢复路径可验证 |
| A4 | 核对报告、暂存包和最终 EXE | 同一记录绑定 Git 提交、完整输入摘要、测试报告摘要、依赖及产物摘要；配置逐字节一致且不进入 Git/公共分发；真实窗口与不同工作目录启动验证单列 |

发布所有权与现有打包锁须合并设计，避免父入口持锁后子入口再次抢锁死锁。直接运行 build 也必须遵守同一所有权及证据要求；不能只保护一种入口。真实 config.toml 单独执行本地保留验证，不进入公开源输入清单或公共分发包。源输入清单和允许生成的输出清单在测试前冻结。

### D. 只读诊断与影响定位

| ID | 方法及反例 | 通过标准 |
| --- | --- | --- |
| D1 | 对有错误、暂停、待归档、来源缺口各选一个项目 | 返回项目/精确错误 ID、阶段、next_due、断点、队列、隔离状态、声明范围及正式查询摘要；每项带获取时间与状态，不冒充原子快照 |
| D2 | 关闭诊断所用测试 Redis 或 SQL；超时、超大错误样本 | 单侧失败保留另一侧证据；单项目默认 SQL 最多 10 次、Redis 最多 20 次、单次 I/O 最多 5 秒、整体 30 秒、报告 1 MiB；错误摘要最多 50 条，正文仅按确切 ID 单独读取且最多 64 KiB；达到限额明确报告未完成/截断，不通过全历史扫描获取摘要 |
| D3 | 对诊断前后测试库、队列、摘要、错误与任务状态做比较 | 不启动采集/归档，不写业务，不推进断点，不刷新摘要时效，不清错误；异常也不泄露凭据 |

### C. 装配与依赖

| ID | 方法及反例 | 通过标准 |
| --- | --- | --- |
| C1 | 迁移前后导出排序清单 | 插件 ID、provides/requires、任务 ID/默认策略、dataset/schema/project/摘要 namespace、页面导航及 preparation 业务语义字段精确相同；实现模块/工厂/测试路径按显式迁移映射比较，新路径存在且保留原验证；不能只比较总数 |
| C2 | 注入重复插件/provider/dataset、错误项目归属、缺依赖及循环；另测有效 Envelope 的未知 schema | 非法装配在采集启动前拒绝并指出声明；运行中未知 schema 仅在现行精确归属条件成立时隔离项目，未知数据集、归属不明或结构不可读仍全局阻断；消息保留 |
| C3 | AST 检查绝对/相对 Import/ImportFrom，按模块职责与业务归属判断依赖，审查动态导入例外 | 新增依赖债务为 0；样板跨业务私有导入为 0；逐条跟踪原 16 条依赖的去向，E 完成时 query/UI/dataset 对采集执行器的反向依赖为 0；不能用旧目录消失或动态导入冒充边界修复 |
| C4 | 搜索旧导入、注册、维护脚本及测试入口 | 当前执行路径旧入口引用为 0；无 old/new 双注册、转发适配、双写；历史 evidence 原样保留，当前说明同步 |

### R. 公共运行及数据恢复

- **R1**：同一规范输入重复采集，业务 DML 为 0；可信摘要命中 MySQL 访问为 0；有效修订写入、迟到旧响应不覆盖、成功消息删除。故障样本包含 SQL 提交后 Redis 确认失败及安全重放。
- **R2**：覆盖缺页、相同条数不同业务集合、必需关联字段缺失、分页同键重排、来源空值和超限响应。不得以数量相等替代集合与内容核对；错误不推进完成断点。
- **R3**：手动触发与定时到期并发、暂停恢复、取消预取、插件失败清理。单任务最多一个执行；等待间隔从本轮结束起计算；所有请求/额度回收；资源未清理完不能再建立第二所有者。
- **R4**：后批次下载与前批次归档重叠；采集按序入队继续前进，仅整轮末等待归档。即刻唤醒及 60 秒恢复扫描保留；失败业务消息留队、成功即清队；不创建第二队列/下载器/调度器。

### U. 生命周期与真实桌面

- **U1**：停一个采集器只令相关任务不可用；控制器、历史、其他任务继续。停页面插件不停止采集或查询。共享服务有依赖者时拒绝直接停用或按显式级联处理，不能要求任何插件都可以无影响关闭。
- **U2**：页面按需创建，切页取消只读请求，不取消已提交写命令；刷新保留未保存草稿、稳定选择与滚动；可变值控件滚轮规则不退化。
- **U3**：正式 EXE 验证原任务设置、next_due 适用行为、插件偏好、查询和导航；保留稳定身份。不同工作目录读取程序同目录配置；真实窗口与离屏测试分别记录。

### H. 股东专项与实采适用范围

- **H1**：保持一个股东采集任务、一次必要 HTML 响应处理三栏、三个查询/页面独立贡献；`response_group='holders.reports'` 语义不变。资本运作继续通过同一公共 HTML 辅助复用，不依赖股东私有实现。
- **H2**：来源排名并列/缺口、栏目空响应、窗口变化、旧记录补齐、部分证券失败后继续及下轮从缺口恢复均有专项。证券间不得新增逐批等待归档；来源缺失不填零或伪造完成。
- **H3**：新增、实质修改或修复来源解析时，执行现行随机 30 股共享代理准入，并额外保留已知失败证券。冻结池摘要、种子、名单；不换样；真实来源→规范化→Redis→统一归档→MySQL 正式查询的集合与内容全部成功，本轮待归档为 0。直连回退不能充当代理验收。

纯组织迁移须以规范输入输出、身份清单和恢复回归证明语义不变，并完成范围明确的正式端到端抽验；不能把“移动文件”用作实际行为改动的豁免。涉及采集执行装配、请求、恢复或消息契约的变化，按实质修改执行准入；仅位置/导入映射变化的，不适用判断须有逐项等价证据。新闻等非股票项目明确 30 股票不适用，按分页/覆盖/修订/查询验证。当前重打包不重新声称完成所有来源实采，也不要求无变更的全市场重采。

### M. 文档与 AI 定位成本

- **M1**：每业务只有一个定位入口，列公开契约、关键文件、数据归属、生命周期、专项测试及权威说明链接。三类演练分别为改页面文案、修来源字段、新增独立业务；前两类选用已确认根因只属于本业务的案例，不修改 core/共享下载归档/其他业务。若实际根因属于公共契约，必须修唯一公共路径并扩大消费者回归，不能复制业务补丁来满足指标。新增独立业务最多增加一项中央白名单，必要 SQL/文档登记单列。
- **M2**：业务说明采用一份权威正文，确定性聚合供现有离线阅读器使用。生成两次字节相同，主题增删/重命名、help 链接、页面/任务/表键覆盖精确核对；旧集中正文不再手工维护，不保留两份权威内容。
- **M3**：当前指南、实现状态、coverage 和审阅机制同步改路径；新增行为必须更新相应正文，不能只刷新摘要。历史证据不重写；旧架构数字清理或通过正式声明计算。文档门禁通过与人工语义审阅分别记录。

根协作约定保留跨业务的稳定约束和唯一入口，业务细则引用所属业务的权威说明，动态事实保留在 evidence。整理时逐条保留有效要求并核对引用；不能通过删除约束、复制多份规则或不断追加历史经过来降低修改者的定位成本。

### T. 测试、类型及性能

- **T1**：从现有贡献、模块归属和依赖生成改动影响报告，引用既有专项/集成/UI/实采证据。缺失、失败或跳过的适用项不能算通过；公共协议或未知动态依赖扩大回归范围。选择性测试只加快开发反馈，不能替代正式发布门禁。
- **T2**：样板公开契约、贡献与公共调用边界进入严格类型检查；Any 例外逐项说明。先增加覆盖边界，不以全仓无类型错误作为一次性迁移前提。
- **T3**：相关实现修改前冻结同机、同依赖、固定数据、负载、预热/重复次数、统计指标与容许退化阈值；覆盖启动、装配、业务查询及 UI 渲染。纯组织迁移也须满足预登记的容许波动；超阈值必须修复或缩减本批范围，不能事后调宽阈值。样板先测基线再冻结数值，基线未建立即不能开始以性能为目标的改造。禁止仅凭理论并发或行数宣称加速；网络吞吐与本机结构治理分开评价。

测试反馈耗时单独分解为收集、环境初始化、用例执行和回收。若私有库建表是主要耗时，可研究按真实依赖准备最小完整测试结构，但须保留每用例私有数据库与所有 SQL 的归属防护；不得共享不同用例的可变业务数据、跳过必要表校验或放宽事务/重放断言。优化前后用例集合、断言目的与跳过原因逐项核对，速度收益另外实测。

## 6. 数据、发布与回退边界

本计划的组织迁移默认不改业务表、主键、消息 schema、Redis 键、来源版本顺序、配置路径或用户保存策略。迁移调用方与退役旧代码在同一批提交完成。持久化身份保持不变，旧待归档消息必须能通过同一正式流程重放。

发现必须改变持久化契约时，拆为独立存储任务：先补业务粒度、字段、正式查询、索引、容量、完整性及迁移设计，核查队列/已有数据后走显式维护。禁止夹带启动迁移、历史格式兼容读写或数据删除。

任何身份漂移、业务查询差异、旧消息不能重放、草稿丢失、配置变化、公共资源重复所有权或适用测试缺证据，都停止该批发布。没有存储改动的批次可在正常关闭后回退代码与程序包，并保留程序配置和待归档数据；验证旧程序查询/重放后恢复。涉及存储变更的任务必须另有经过核查的回退/前向修复方案，不能用 Git 回退冒充数据回退。

实施时每批交付：目标与非目标、受影响业务、前后身份/依赖比较、退役清单、验证命令与结果、实采范围/不适用理由、发布身份、配置及真实桌面证据、未完成项。实施授权已收到，常规开发步骤自主执行，依赖批次未通过退出条件时不扩大迁移。

## 7. 第一批建议

首先实施 A 的发布身份闭环及 B 的有界诊断，消除多人/多聊天协作时“测试对象与发布对象不同”和“需要用户搬运错误”的问题。随后交付 C 的新闻样板；用真实修改演练确认定位和扩展边界改善，再进入股东复杂样板。

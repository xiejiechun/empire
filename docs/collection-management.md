# 采集中心与统一管理

本次改造将插件生命周期、采集任务执行、站点访问规则和出口状态分开。桌面默认打开工作台总览；采集任务、运行记录、站点访问规则和采集出口归入“采集管理”，股票列表、财经快讯和交易日历归入“数据浏览”。

## 如何使用

1. 在“采集管理 → 采集任务”选择任务。默认启用、仅手动运行，不因打开应用或启动插件请求网站。
2. 设置执行方式：手动、固定间隔或每天定时。固定间隔从本次运行结束计算，每日时间使用北京时间，不依赖 Windows 时区。
3. 选择网络方式：本机直连、代理优先并允许自动直连，或仅使用代理。点击“保存执行计划”。设置不会因界面自动刷新被覆盖；只有点击保存才写入。计划立即生效，请求重试和网络方式在下次任务开始时生效。
4. “立即采集 / 继续采集”会继续未完成的分页；没有未完成断点时创建新批次。“从头重新采集”创建新批次，运行中不能重复启动。
5. “暂停任务与计划”同时取消当前采集并禁用计划，保留入队数据与断点。继续前勾选启用并保存，再执行。
6. 在“采集管理 → 站点访问规则”选择站点，保存“每个出口 IP 访问本站的最短间隔”；自动模式按独立出口 IP 数扩展。高级设置提供本机间隔、并发安全阀及可选全站频率保护。新浪子域名共用 `sina` 组，巨潮子域名共用 `cninfo` 组，已有冷却继续保留。
7. 在“采集管理 → 运行记录”切换采集、归档和错误三个标签。采集和归档各保留每个项目最近 100 条；错误保留每个项目最近 300 条。股票结果在“股票列表”查看。
8. 错误页可查看阶段、请求地址、状态码、元数据和脱敏原文样本。先修复并验证，再选择具体错误、勾选已完成修复验证，点击“清除已修复记录”。期间新产生的错误不会被一并清除。

任务执行间隔是“多久更新一轮业务数据”；网站请求间隔是“分页、月份等 HTTP 请求至少相隔多久”。重试次数为单个请求的额外尝试次数，适用于网络异常及 429/502/503/504；业务校验失败不会盲目自动重新创建批次。仍启用的定时任务会在下次计划继续尝试，手动任务由用户处理。

## 架构与扩展

| 层 | 职责 |
| --- | --- |
| 插件内核 | 依赖、启停、资源回收；不解释采集计划 |
| `collection.control` | 内部任务定义、参数校验、计划、互斥执行、恢复、运行记录 |
| `collection.records` | Redis 归档历史、错误样本和精确删除；不进入 MySQL |
| 采集源插件 | 实现 `checkpoint_revision()`、`execute(fresh, baseline_revision)`、`health()`，处理源分页及业务校验 |
| `http.fetch` | 域名归属、跨插件共享限速/冷却、请求重试、统一响应字节预算与文件流式资源控制 |
| 入队与归档插件 | Redis 消息和断点原子提交、即时唤醒归档、60 秒恢复扫描、MySQL 提交后删除队列消息 |
| 页面插件 | 通过能力接口操作后台；不在 GUI 线程访问数据库 |

新采集器需在内部白名单注册 `TaskContribution`，声明能力、显示名、描述和网站组。任务表、计划编辑和运行记录复用统一管理器，无需复制一套计时器或按钮。控制器不静态依赖全部来源；停用一个采集器只让对应任务显示不可用，其他任务继续运行。

## 持久化与恢复

- 任务配置保存到 MySQL `app_setting`（kind=task），网站请求间隔保存到同表（kind=site），下载资源使用同表 `kind=download`、`setting_key=global`。按 namespace、kind、setting_key 唯一定位；点击保存立即提交，不等待归档，相同配置不写库。
- Redis `<namespace>:collection:control:v1` 保留下次执行时间、活动状态、配置运行副本与每项目最近 100 条采集历史。MySQL 是配置权威来源；旧 site-intervals 键不再读写。
- 只重启 Empire 保留已有 next_due；Redis 或电脑重启后配置仍在，固定间隔从应用启动重新计算，每日定时取下一个北京时间时间点，手动与禁用任务不自动执行。断点、未归档数据、运行与错误记录仍为易失内存数据。
- 已有安装正常退出、待归档队列为空后显式运行 `python scripts/migrate_collection_state.py`，核对迁移前后业务数据；旧分钟配置转换已完成并退役，运行时仅接受秒配置。启动不自动改表。

- 每次运行先记录游标基线版本，再执行来源。进程异常退出后重用同一运行 ID；若游标已超过基线并完成采集，仅等待对应批次归档，不再次拉取新快照。
- 错过的执行时间启动后补一次；不补发每个错过周期、不并发启动同一任务。完成后计算下一次时间。
- 正常退出取消当前工作并保留分页断点；再次手动执行或到达下一次计划时可续采。应用关闭期间不采集；尚无后台常驻或 Windows 计划任务。
- “完成”以完整列表通过校验并发布到 MySQL 为准，入 Redis 后处于“等待归档”；不完整批次继续留在 Redis，不覆盖当前股票列表。

三类记录仅存于 Redis，不发布到归档队列，不写入 MySQL。归档记录键为 `<namespace>:collection:archives:<project_id>`，错误记录键为 `<namespace>:collection:errors:<project_id>`。错误原文每条最多 64 KiB，统一脱敏后保留。完整读取时可给出原始长度/摘要；提前终止则显示原文未读完、完整长度/摘要未知，同时显示已读正文量与脱敏样本摘要。超过各自限额时淘汰最旧记录；查看或采集成功不会触发错误自动清理。

归档记录区分 `processed_count` 与 `written_count`：前者是成功核对的业务记录数，包含可信摘要命中、SQL 内容相同和旧版本确认；后者才表示发生业务写入的记录数。工作台和运行状态中的队列数字是 Redis 待归档消息数，一条消息可承载一页中的多条业务记录，不能用它推断新闻或股票条数。

错误页每次只读取 50 条摘要，列表不包含正文、请求地址或元数据；选择记录后按 ID 读取一条完整详情。记录没有变化时，周期轮询只返回修订号和总数，不重复传输整页。修订号键仅用于列表失效判断，随 Redis 内存状态一同丢失，不是第二份记录或审计历史。

## 资源等待与超限

网站许可、全局/站点窗口和下载字节预算共同约束采集；代理增多不会无限扩大响应内存。缓冲额度暂时用完时等待，不算请求失败；单响应超限、压缩损坏或不支持的编码则停止该响应，不推进断点，不把问题当作代理离线而不断换出口。股票/新闻/日历的默认正文上限分别为 1 MiB、4 MiB、512 KiB，统一缓冲默认 512 MiB、全局窗口默认 128。可在“采集管理 → 下载资源”按规划 100～1000 台十档一键推荐；只填容量草稿，不放宽响应大小、网站每 IP 间隔或代理开关。保存到 MySQL 后正常重启软件统一生效，页面区分当前运行值与已保存待生效值，不自动终止采集。网站并发为 0 跟随全局，正数只收紧本网站；设备数和独立 IP 数分别展示。限额不是软件总内存上限或网速限制，也不改变 Redis 待归档数据保留规则。

未来 PDF/年报应声明文件流式契约，默认文件上限 256 MiB、内存预留 256 KiB，另受磁盘配额和文件并发约束。文件上限、配额、余量和并发也由下载资源页管理；目录机器路径继续留在本机 TOML。当前没有公告任务和 PDF 解析能力。开发与维护参数见 [下载资源边界](download-resources.md)。

## 配置边界

采集中心管理当前有实际业务意义的计划、请求重试和网站间隔。数据库连接、Redis 容量保护、归档批大小及内部插件声明仍由配置文件管理；业务消息入队后立即唤醒归档器，另每 60 秒恢复扫描。选股、回测和公告尚未实现，本次不展示这些功能的占位页。
# 固定间隔支持秒（2026-09-23）

采集任务的“每次结束后等待”以秒输入，支持 1～2592000 秒（最多 30 天），例如 30 表示本次任务结束后等待 30 秒再运行。同一任务不会重叠执行，调度器约每秒检查一次，实际启动受事件循环和网站共享频控影响。

执行计划在 MySQL 中统一保存，Redis 保留运行副本，间隔字段为 `policy.interval_seconds`。旧分钟设置仅在显式维护时乘以 60 转换，保留已有 next_due；运行时统一使用秒。手动模式、每日定时和网站请求频控保持原规则；归档即时唤醒，60 秒恢复扫描独立运行。

验证：178 项测试通过，覆盖秒级边界、旧分钟设置转换、结束后计时及界面保存；Ruff 检查通过。

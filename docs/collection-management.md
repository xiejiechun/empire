# 采集中心与统一管理

本次改造将插件生命周期、采集任务执行、网站请求频率分开。桌面默认打开工作台总览；采集任务和运行记录归入“采集管理”，网站频控归入“系统管理”，股票列表、财经快讯和交易日历归入“数据中心”。

## 如何使用

1. 在“采集管理 → 采集任务”选择任务。默认启用、仅手动运行，不因打开应用或启动插件请求网站。
2. 设置执行方式：手动、固定间隔或每天定时。固定间隔从本次运行结束计算，每日时间使用北京时间，不依赖 Windows 时区。
3. 点击“保存执行计划”。设置不会因界面自动刷新被覆盖；只有点击保存才写入。计划立即生效，请求重试次数在下次任务开始时生效。
4. “立即采集 / 继续采集”会继续未完成的分页；没有未完成断点时创建新批次。“从头重新采集”创建新批次，运行中不能重复启动。
5. “暂停任务与计划”同时取消当前采集并禁用计划，保留入队数据与断点。继续前勾选启用并保存，再执行。
6. 在“系统管理 → 网站频控”选择网站组，保存请求最小间隔。新浪子域名共用 `sina` 组，巨潮子域名共用 `cninfo` 组，不允许各插件自行放宽频控。已有冷却继续保留，下一次申请发送许可时使用新间隔。
7. 在“采集管理 → 运行记录”切换采集、归档和错误三个标签。采集和归档各保留每个项目最近 100 条；错误保留每个项目最近 300 条。股票结果在“股票列表”查看。
8. 错误页可查看阶段、请求地址、状态码、元数据和脱敏原文样本。先修复并验证，再选择具体错误、勾选已完成修复验证，点击“清除已修复记录”。期间新产生的错误不会被一并清除。

任务执行间隔是“多久更新一轮业务数据”；网站请求间隔是“分页、月份等 HTTP 请求至少相隔多久”。重试次数为单个请求的额外尝试次数，适用于网络异常及 429/502/503/504；业务校验失败不会盲目自动重新创建批次。仍启用的定时任务会在下次计划继续尝试，手动任务由用户处理。

## 架构与扩展

| 层 | 职责 |
| --- | --- |
| 插件内核 | 依赖、启停、资源回收；不解释采集计划 |
| `collection.control` | 内部任务定义、参数校验、计划、互斥执行、恢复、运行记录 |
| `collection.records` | Redis 归档历史、错误样本和精确删除；不进入 MySQL |
| 采集源插件 | 实现 `checkpoint_revision()`、`execute(fresh, baseline_revision)`、`health()`，处理源分页及业务校验 |
| `http.fetch` | 域名归属、跨插件共享限速、冷却、请求重试 |
| 入队与归档插件 | Redis 消息和断点原子提交、60 秒归档、MySQL 提交后删除队列消息 |
| 页面插件 | 通过能力接口操作后台；不在 GUI 线程访问数据库 |

新采集器需在内部白名单注册 `CollectionTask`，声明能力、显示名、描述和网站组。任务表、计划编辑和运行记录复用统一管理器，无需复制一套计时器或按钮。当前所有已注册来源是管理插件的显式依赖，停用来源前需要停用依赖它的管理插件。

## 持久化与恢复

- 任务设置、下次执行时间、活动执行记录及每个项目最近 100 条运行历史，保存到 `<namespace>:collection:control:v1`。
- 网站间隔覆盖值保存到 `<namespace>:collection:site-intervals:v1`；优先于 TOML 的初始值。域名归属和并发上限仍在 TOML 声明，修改后重启生效。
- 设置是少量控制数据，留在纯内存 Redis；只重启 Empire 可恢复，Redis 服务或电脑重启会丢失设置、断点、待归档数据和记录。采集与归档历史各按项目分别保留 100 条，错误各保留 300 条。成功 HTTP 原文不持久保存；规范化业务字段进入队列，股票发布到 MySQL 当前 `stock` 表，新闻按 ID 去重归档到 `finance_news` 历史表。此运行历史不是长期审计库。
- 每次运行先记录游标基线版本，再执行来源。进程异常退出后重用同一运行 ID；若游标已超过基线并完成采集，仅等待对应批次归档，不再次拉取新快照。
- 错过的执行时间启动后补一次；不补发每个错过周期、不并发启动同一任务。完成后计算下一次时间。
- 正常退出取消当前工作并保留分页断点；再次手动执行或到达下一次计划时可续采。应用关闭期间不采集；尚无后台常驻或 Windows 计划任务。
- “完成”以完整列表通过校验并发布到 MySQL 为准，入 Redis 后处于“等待归档”；不完整批次继续留在 Redis，不覆盖当前股票列表。

三类记录仅存于 Redis，不发布到归档队列，不写入 MySQL。归档记录键为 `<namespace>:collection:archives:<project_id>`，错误记录键为 `<namespace>:collection:errors:<project_id>`。错误原文每条最多 64 KiB，保存原始长度与 SHA-256 并标记截断。超过各自限额时淘汰最旧记录；查看或采集成功不会触发错误自动清理。

## 配置边界

采集中心管理当前有实际业务意义的计划、请求重试和网站间隔。数据库连接、Redis 容量保护、归档批大小及内部插件声明仍由配置文件管理；归档保持每 60 秒。选股、回测和公告尚未实现，本次不展示这些功能的占位页。

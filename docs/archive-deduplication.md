# 统一归档去重规则

有效业务消息仍先进入 Redis，入队后立即唤醒归档器，并每 60 秒恢复扫描。归档器对规范化内容计算 SHA-256，不对原始 HTTP 响应或采集时间计算去重摘要。

**用户确认的统一要求：所有当前及未来采集插件，归档处理成功后必须删除对应 Redis 待归档业务数据。即使 MySQL 已有相同内容、没有执行 INSERT/UPDATE，也必须清理；确认旧版本无需写入同样清理。归档出错保留重试，尚未收齐的分页继续暂存。统一归档器负责执行，插件不得绕过。**

此处清理对象是待归档业务内容；摘要、断点、执行计划、有界运行记录及错误样本仍按各自既定规则保留。

| 情况 | MySQL 处理 | Redis 待归档业务消息 |
| --- | --- | --- |
| 可信摘要相同 | 完全不查询、不写 MySQL，含统一状态表 | 确认后删除 |
| 摘要缺失，SQL 已有相同内容 | 查询确认，不执行业务 DML，补摘要 | 确认后删除 |
| SQL 不存在 | 插入并提交事务，记录摘要 | 提交后删除 |
| 内容或来源修订版本有效变化 | 按插件规则更新并提交，替换摘要 | 提交后删除 |
| 旧版本迟到 | 不覆盖新数据，不把旧内容缓存为当前内容 | 确认过时后删除 |
| SQL 或后续 Redis 操作失败 | 保留已提交结果，重试时重新核对 | 保留并安全重放 |

删除使用消息的确切 Stream ID，同时 XDEL。不会清空整个队列；未完成股票批次和未成功归档的数据继续保留。归档运行记录仍每项目最近 100 条，与待归档业务消息无关。

## 插件契约

数据契约必须实现 `fingerprint_plan` 和 `fingerprint_subset`，声明比较单位、规范业务内容及 `FINGERPRINT_VERSION` 版本结构和比较规则。统一层校验维数、日期、规范精度、时区和股票批次格式，解析后比较，不比较任意字符串数组。通用归档器负责读取缓存、筛选待核对数据、SQL 提交后更新缓存，之后再确认进度并删除消息。SQL writer 必须返回 `confirmed` 业务键，仅包含真正与 SQL 一致的内容；不得将被拒绝的旧内容填入确认列表。整份股票确认键为 current。

| 数据 | 业务比较单位 | 版本顺序 |
| --- | --- | --- |
| 股票 | 来源整份列表，规范股票字段及节点 | 批次开始时间、批次 ID |
| 新闻 | 来源及新闻 ID，正文等全部业务字段含来源修订时间 | 来源修订时间、观测时间 |
| 交易日历 | 来源及月份，完整日期和交易标志 | 观测时间 |

Redis 可信命中仅推进缓存版本，不访问 SQL。缓存缺失回 SQL 核对时，业务内容不变不写业务表，但可更新每项目一条 collection_state 的进度和版本；业务与状态共用事务。摘要不包含批次、页号、采集时间等易变元数据。

## Redis 缓存与配置

`<namespace>:archive:fingerprints:v1:<dataset>:<source>` 是 Hash；dataset 为 stocks、news 或 calendar。字段为 current、新闻 ID 或 YYYY-MM；值为 JSON，包含 hash 和 version，后者为按顺序比较的字符串数组。

同名加 `:expiry` 的 ZSET 保存业务键及过期时间（Redis 服务器 Unix 秒）。读写时原子清理过期项，写入后按到期时间淘汰超限项。两个键同时设置空闲 TTL。过期和容量淘汰只影响摘要，不丢弃待归档业务数据。

可信命中须同时具有合法 SHA-256、符合数据集契约的版本、有效且未过期的索引；索引缺失、无穷、非整数或超出当前 TTL 范围都不能作为证明。观测超前本机 5 分钟、新闻来源修订超前观测 5 分钟仅禁用缓存快径，不拒收来源数据。回 SQL 成功后可正常清队，但不缓存异常版本，并精确移除对应旧证明；SQL 失败仍留队。

`stocks:committed` 只保留最近成功核验的显示/进度，不是归档清队权威。缺少可信统一摘要时回 SQL，损坏 committed 不会触发旧批次清理；损坏或远未来 checkpoint 也不能授权删除未完成股票页。正常可信命中仍零 MySQL 访问。

| archive 参数 | 默认 | 范围与作用 |
| --- | --- | --- |
| fingerprint_ttl_seconds | 604800（7 天） | 1～31536000 秒；最后成功确认后的有效期 |
| fingerprint_max_entries | 10000 | 1～100000；每数据集/来源最大业务键数 |

配置在 `%LOCALAPPDATA%\Empire\config.toml` 的 `[archive]` 下填写，应用重启后生效。Redis 纯内存模式不变，服务重启后摘要丢失，归档自动回 SQL 核对。

## SQL 手工维护

手工修改或删除业务行前正常停止应用，失效对应来源的两个摘要键。仅操作确切键，不执行 FLUSHDB。旧批次重放修复还需核对 stocks:committed 及 collection_state 中的版本/observed，优先重新采集产生新批次。

SQL 统一状态仅保存最近 SQL 确认的进度与版本，不能恢复后续仅在 Redis 确认的所有观测，也不承担未归档断点恢复。

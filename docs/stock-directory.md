# 当前 A 股目录与任务归档

## 日常操作

“采集管理 → 采集任务”支持归档任务。归档立即停止计划并取消当前采集，保留任务配置、采集断点和全部已归档业务；已入队正确数据仍由统一归档器处理。默认列表隐藏归档任务，进入“采集管理 → 归档任务”，选中后点击“还原任务”。还原沿用原计划和启停状态，原先暂停的任务仍需启用并保存。状态保存于 MySQL，Redis 或电脑重启不丢失。

同花顺股票目录采用用户指定 board/all、page/1、size/10000 地址，正常一轮只请求一次。推荐每天北京时间18:00完整核验，计划可编辑；使用公共代理优先、重试、THS站点频控和下载缓冲。原新浪任务保留可归档还原。股票目录仍只有 stock 一份；所有来源走同一规范化与归档写入器，不保存第二份目录。

## 来源与生命周期

| 项目 | 契约 |
| --- | --- |
| 范围与用途 | 来源当前沪深北证券目录，代码、名称、市场、统一代码；不保存价格字段或历史成员名单，不推断上市/可交易状态；来源可含尚无行情证券。 |
| 初始化 | 获取本轮的一份完整响应；连续序号、14列、证券链接身份、业务键唯一、请求身份、完整表格和空单页分页栏共同证明集合。非空且少于10000；达到上限或仍有分页拒绝。 |
| 完成 | 完整集合通过后分块规范化入队；整轮全部成功归档且清队才完成；内部分块不是再次HTTP分页请求。 |
| 后续与修订 | 下一轮重新读取一份当前目录，发现新增、退出和更名；完全相同内容不写业务表；不追溯历史版本。 |
| 中断 | 下载/校验失败不推进断点；已验证分块入队后继续发布，不等待每块归档；入队中断恢复时重取完整响应并以集合摘要核对，发生变化开启新批次，不混合两份响应。 |
| 状态丢失 | Redis丢失重新获取当前完整响应，SQL中的最近目录版本防止旧消息覆盖；不承诺恢复丢失的待归档消息。 |
| 普通/重新 | 已入队完整轮次先确认；普通恢复未完成相同集合，重新采集建立新批次；旧不完整批次由统一消费流程处理。 |
| 证据 | 开发反例、隔离归档和实际HTTP/SQL集合分别报告；来源单页协议不提供独立总数，不增加日常双读，缺少完整单页标记不能用条数猜测完整。 |

目录请求使用本地固定的同花顺 chameleon 1.7 校验协议及当前时间生成临时 Cookie；不读取浏览器资料，不下载或执行动态脚本。校验环境没有网络、文件和 Python 接口。正常轮次仍只请求一份完整响应，网络失败复用公共有界重试；401/403 不推进断点或覆盖旧目录，源站协议改变需更新实现。

## 存储设计卡

沿用 stock，无 DDL 或业务JSON新增。粒度为当前证券，主键 unified_code（CHAR(9)，六位代码加市场），name 为已有VARCHAR(100)；来源由受限登记 sina/ths 和 collection_state 的当前完整目录状态记录。正式SQL仍按 unified_code 或市场/名称有界查询，索引沿用主键，无历史正文扫描。每来源任务每项目一条collection_state；读取目录按 namespace+dataset=stocks 的两条已登记状态取最大版本，不以某个任务的旧publication解释另一来源写入的目录。

唯一股票摘要范围为两来源共用的当前目录（stocks/current）；来源切换不得命中另一份已被替换的旧摘要。旧消息按共同开始时间与批次有序；冷缓存SQL锁定并比较两项目目录版本，当前内容与本项目状态同事务提交。完全相同的规范内容不执行业务DML；新SQL确认可以保留原内容publication。旧的 stocks/sina 摘要不再作为正式证明，维护时显式失效，不改其他数据集。

容量：来源请求上限10000条，最大响应由正式股票下载设置限制，推荐8MiB（实测5578条约4.15MiB）；共享预算按3倍单响应+256KiB校验。入队按80条分块，正常最多127个消息，避免单消息超过512KiB。SQL仅当前目录约万行，查询每页最多500；不增加年度/五年累积容量。表字段和索引布局未改造，本次仅新增来源协议与共同目录摘要，沿用既有表容量基线。

迁移：正常停机并核对待归档Stream、当前stock数量及目录状态；显式保存新浪任务归档和同花顺推荐计划，将股票单响应上限提高到8MiB并保持其他已保存配置，失效确切旧股票摘要。已有stock和新浪状态保留，新同花顺整轮确认前仍可查询原目录；启动不迁移。旧状态保留真实来源，不能改标为同花顺实采。

## E3代码归属与有限验证

股票契约、双源采集、归档、正式查询和页面归入 `src/empire/features/stocks/`，唯一定位入口为包内README。`api.current_directory` 复用调用方连接，不重开事务；publication持有唯一标记校验，确认回调由业务bundle显式登记并注入原公共确认提供者。缺失、重复或错归属的处理器在服务构造前拒绝，无隐式业务导入回退。任务、页面、数据集身份与已保存设置不变，无需执行数据库迁移。

开发验证入口 `scripts/verify_foundation_sources.py` 复用共享下载/代理和UUID私有存储，完整核对两来源各自目录到正式分页查询的集合及内容，并检查本轮待归档为0。两个来源不要求条数互相相等；完整目录请求不等于随机30次股票请求。仅开发验证使用私有实例，不能将此入口改指生产库。

# 通达信实施ST与撤销ST

## 日常操作

采集管理→任务分别提供“实施ST（通达信）”“撤销ST（通达信）”，数据浏览搜索实施ST或撤销ST，按六位代码或前缀查询，每页最多200条。默认北京时间每天18:00核验，代理优先、不可用时受频控回退直连。计划保存至MySQL，下一轮生效，已有用户配置优先。两个插件、项目及数据准备检查独立，关闭一个不阻断另一个。

## 生命周期

| 项目 | 契约 |
| --- | --- |
| 用途与范围 | 查阅通达信实施/撤销风险警示栏目；SH/SZ/BJ按来源实际返回保存，历史旧代码不改写。不以该栏目单独裁定每日ST/*ST/正常状态 |
| 初始化 | 请求1990-01-01至本轮启动北京时间日期，实施参数2，撤销参数3；每栏目一次完整POST，容量30000，达到上限明确失败 |
| 完整单位 | 完整响应列、来源总数、页号、证券日期唯一集合、市场、名称与原因上限全部校验；SH/SZ/BJ包括空市场一次原子入队，分别独立事务归档 |
| 完成 | 整轮入队后等待全部三个市场归档成功并确认无本轮残留，不以最高页码代替完成 |
| 后续与修订 | 每轮重新核验来源全部历史，发现范围内新增、缺口及修订；没有来源版本，以请求开始的绝对时间防止迟到旧响应覆盖，不冒充公告日期 |
| 中断 | 入队前失败不推进断点；入队后三市场原子发布断点为awaiting_archive，恢复直接等待归档，不重复下载；SQL提交后清队失败安全重放 |
| 状态丢失 | Redis仍运行时读取断点续跑；Redis/电脑重启丢失临时状态，重读完整响应与SQL比较，不承诺恢复丢失消息 |
| 操作 | 立即采集与重新初始化均核验完整历史，未归档轮次先继续；跨日只影响下一轮请求终点，不混用本轮范围 |
| 进度 | 一次完整响应、规范事件数、来源数、三个市场归档确认分别呈现；开发验收与实际归档范围写日期证据 |

实施ST包含首次风险警示、ST与*ST转换、撤销退市风险警示但继续实施其他风险警示等来源事件；撤销ST按栏目原值保存。前后简称不是自动状态分类规则。当前证券简称不重复存储，行业为接口当前标签，没有历史行业归属日期。无公告可用日期，不保证历史选股信号回放。完整来源集合没有所选证券事件是合法空结果，不能据此推断始终正常。来源核实样本实施最早1998-04-28、撤销最早1999-04-28，不把请求起点称为来源已有覆盖。

## 存储设计卡与字段字典

两个独立数据集st.implementation.market、st.removal.market共用security_st_event，实体为来源风险警示事件。固定来源tdx由登记校验；event_kind为implementation/removal。完整归档单位为栏目与市场，不增加逐轮业务表。

| 字段 | 类型、来源与含义 |
| --- | --- |
| event_kind | VARCHAR(16) ascii，来源栏目，必需 |
| record_key | CHAR(64) ascii，SHA256([统一代码,日期,前简称,后简称,原因]) |
| unified_code | VARCHAR(9) ascii，code+sc，0=SZ/1=SH/2=BJ；前导零保留，旧代码保留 |
| event_date | DATE，rq，来源实施或撤销日期；非公告可用时间 |
| old_name/new_name | VARCHAR(200)，prename/lastname；NULL为来源未给，不填补或反转 |
| reason | VARCHAR(2000)，ssyy，来源原因；NULL及空白规范为NULL未知，非空原样保留，超限失败不截断 |
| csrc_industry/tdx_industry | VARCHAR(200)，zjhhy/tdxhy，来源“无”转NULL；没有历史归属日期 |
| source_occurrences | INT UNSIGNED，当前协议严格为1；同栏目证券日期重复失败，不吞掉重复 |

无扩展JSON。主键(event_kind,record_key)，ix_st_security(event_kind,unified_code,event_date,record_key)支持证券范围，ix_st_date(event_kind,event_date,unified_code,record_key)支持日期全市场及稳定游标。历史证券不外键关联当前stock。

正式证券查询：WHERE event_kind=:kind AND unified_code=:code AND event_date BETWEEN :start AND :end ORDER BY event_date,record_key LIMIT 200；全市场列表使用(event_date,unified_code,record_key)游标，最多200。覆盖审计每栏目最多30000行，比较规范键、内容摘要、来源数及三市场collection_state契约证明；无正文历史扫描或逐证券N+1。查询只依赖MySQL，Redis摘要为可选时效证据。

修订写入锁定该栏目市场全集，批量差异写入，移除被来源修订替代的记录；其他栏目市场不受影响。业务与项目collection_state同事务。相同内容零业务DML；可信摘要命中免SQL，过时响应不覆盖，成功含无写入均由统一归档清队。证明与规范集合绑定，内容不一致时数据准备失败；规则升级须显式维护及重采。

容量：真实来源约3949事件，两栏目单响应分别约381KB/188KB。预计一年5000、五年10000事件；每栏目少于30000硬上限。隔离25000事件导入、修订、重复及EXPLAIN测量见容量证据，表及索引预算128MiB、200行列表/证券范围P95≤50ms、完整覆盖≤500ms、初始导入≤10秒。响应、预取和入队沿公共预算，三消息整体准入；超过消息上限明确失败，不提高公共限制。合成容量不是生产吞吐或全历史实采证明。

## 显式维护与故障处理

关闭Empire并等待待归档Stream为0，scripts/create_st_event_schema.py先预检，再--apply建立唯一新增表；复用维护单实例锁及SQL锁，核对已有表数量、结构和状态摘要不变，DDL隐式提交。无旧ST布局需要转换，不删除已有业务；启动仅检查不建表。新增表可安全续跑维护，业务已写后不回退旧快照。

重复日期、数量不符、缺字段、未知市场、截断或异常日期均失败且不发布；网络故障使用共享有界重试。错误每项目最近300条，采集/归档运行记录各100条，成功原文不长期保存。SQL失败保留消息；只清确切已修复错误ID。行业和原因缺值分别说明，不以猜测填补。

## 验收

专项tests/test_st_events.py及tests/integration/test_st_archive.py覆盖来源到正式查询、同数异集、冷热摘要、修订、旧响应、缺行业补齐、SQL失败、提交后确认中断与成功清队，独立页面懒加载与草稿保留。无独立页协议，因此多页预取边界不适用；使用共享单完整单元预取，三市场入队后才等待。实际范围、网络路由及正式部署结果单列日期证据。

## 存储设计卡（实施前约束）

固定来源 ths_yuanhang。三类业务表：

| 表 | 粒度与唯一键 | 作用 |
|---|---|---|
| yuanhang_limit_pool | trade_date,pool_type | 完整池集合及源总数、过滤口径、键摘要/内容摘要、契约版本；含已明确的合法空池 |
| yuanhang_limit_member | trade_date,pool_type,unified_code | 各池自己的结构化成员事实；不同池值和NULL不合并 |
| yuanhang_limit_reason | trade_date,unified_code | 独立证券日原因栏目及可用性；跨池只采写一次 |

父头是完整来源池的真实集合证明，不是运行日志。collection_state仍每项目一行，保存SQL核验版本与进度；Redis热摘要核验不刷新业务观察时间。相同内容零业务DML，旧消息不覆盖较新核验；来源无修订号，只能防止已知观测顺序倒退，不能识别服务器晚返回的陈旧缓存为旧版本。

### 字段字典

身份由来源 market_id 17→SH、22→SH、33→SZ、151→BJ 显式映射。客户端内置MarketData.xml确认22是Shanghai Risk，151是北京A股（USTM）；2023-11-03涨停池实际返回871478/151，保留原历史证券代码。market_id为空但market_type明确GEM→SZ、STAR→SH时使用该来源板块；冲突、未知仍拒绝，不按代码猜市场。source_market_id保留原编号或NULL，identity_basis记录market_id/source_board。编号为空且仅有HS时，先查询已归档明确池身份，缺失时使用共享新浪精确证券查询，分别记pool_history/sina_lookup；已知市场冲突直接失败，关联代码不能替代原代码。该辅助协议从题材模块移至sources/security_identity.py，只有一条下载解析路径。SQL统一证券键unified_code，不外键关联当前股票名单。

| 来源字段 | 存储与含义 |
|---|---|
| name、market_type | VARCHAR(80/32)，原名称和来源板块类别；必需 |
| latest | 十进制价格，元 |
| change_rate、turnover_rate | 十进制百分点，保留负涨跌幅 |
| currency_value、sum_market_value、turnover、order_amount | 十进制金额，元；流通市值、总市值、成交额、封单额 |
| order_volume | 来源封单量；样本与元/价格相符，完整单位证据未冻结前界面保留来源名称 |
| rise_rate | 来源涨速；客户端五分钟涨速标签，时间窗口待补证 |
| limit_up_suc_rate | 0～1比例，不能与百分点混用 |
| first/last_limit_up/down_time | 来源Unix秒，转换北京时间且必须属于查询日；NULL保留；源字符串0保留为Unix零哨兵（SQL北京时间1970-01-01 08:00:00），页面显示未知（来源0），不当作事件发生时间 |
| open_num、high_days_value、is_new、is_again_limit | 非负整数；后两者只允许0/1/NULL；high_days_value不猜解码 |
| high_days | 原N天M板文本，不推导为连续板数 |
| reason_type | 来源原因摘要，最多4096字符 |
| limit_up_type、limit_down_type、change_tag | 原状态文本，分别最多128/128/80字符 |
| 941948930 | top_concept，可选概念文本最多1024字符；现有样本NULL |
| reasonrevealedList、reasonKindList | reason_text/ reason_kind有界TEXT，分别最多65535/4096 UTF-8字节 |

数值采用精确十进制解析和规范字符串传输，不经过二进制浮点再舍入。候选SQL DECIMAL(48,24)，整数部分实际约束小于10^22；超过精度失败，不截断。最终容量测量须包含该精度成本。缺字段与显式NULL不同；源新增未声明字段不自动作为JSON业务存储。

### 查询、容量及迁移

## 生命周期与请求成本约束

初始化按正式A股日历从1990-12-19逐交易日探查到固定的已结束交易日，各池独立保留合法空响应，不把最早非空样本冒充支持起点。近期优先并以有界历史计划持续补缺；当前股票名单不限制历史证券。增量为新增日期池，而非全历史下载后去重。日常北京时间18:00，近期5交易日回看，老历史20交易日轮转；来源失败或停机延后并补过期核验，不无声降低频率。

工作范围消重为新增/缺口∪近期∪到期历史核验。相同截止且未到期0业务请求；每个必要页一次，正常不双读。来源每页100：列表请求Σmax(1,ceil(池人数/100))；详情为去重证券日数；认证、辅助、失败重试另外统计。身份缺失的响应每页至多100个代码一次有界SQL查询；仅未核实代码增加精确身份查询，辅助请求及传输字节计入采集统计，后续从已归档明确身份复用，不额外下载整份股票目录。热摘要0业务DML，冷摘要回SQL比较，不因Redis丢失全历史重下。

每完整单元校验后与断点原子入队，继续下个单元，不逐单位或小计划等待归档；整轮结束才等全部消息清队。一次执行连续推进64日池/256原因的小计划，共用同一批次及全轮页序，断点只保存当前计划；原因另有稳定键游标。失败保留范围，后页成功不掩盖前页。SQL可信证明恢复已归档范围，Redis丢失不承诺恢复未归档消息；未确认单元允许重采。初始化、无变化、新增日、局部缺口、修订、两种重启分别测试请求范围与入队/写库成本。

完整池规范正文上限8MiB，压缩临时消息上限480KiB，SQL仍按字段保存。共享预取额外预留完整单元三份空间，HTTP借用单响应额度，关闭响应不提前释放完整单元额度，消费或取消后统一回收。极端池实测2020-02-03跌停2983只、30页；不能将最大10000只声明当作任意正文长度均能成功入队。

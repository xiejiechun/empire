# 100～1000 台出口容量与一键推荐验收

日期：2026-09-26。用户要求：出口设备逐步增加，管理后台提供 100、200 至 1000 台十档一键推荐，当前采用 100 台推荐。范围为容量设置、统一调度、目录分配效率及相关取消回收，不新增业务采集器，不降低网站每 IP 频控，不以模拟测试宣称真实千出口吞吐。

## 用户操作与当前目标

在“采集管理 → 下载资源”选择规划出口档位并生成推荐，检查草稿后保存，正常退出并重新打开软件生效。默认响应大小下，当前 100 档为 **128 个全局下载窗口、512 MiB 共享缓冲**；1000 档为 1024 窗口、4096 MiB。完整十档表及计算规则见 [下载资源边界](download-resources.md)。

一键推荐只修改 `planned_exit_devices`、`max_parallel_downloads`、`buffer_budget_bytes` 三项。单响应上限、文件大小/配额/并发、网站每 IP 间隔、全站每秒保护、任务代理开关均保留。推荐和恢复默认只改变草稿；保存成功后也不热替换在用额度，避免运行中的请求使用两份资源池。

规划设备不等于在线设备，更不等于独立出口 IP。实际并发受健康独立出口 IP、站点安全阀、全局窗口、字节预算与剩余页数共同限制；设备逐步加入时动态利用实际容量，不必等档位全部到齐。股票支持独立分页，新闻和日历继续顺序采集。

## 逐项核查

| 用户要求或风险 | 实现边界 | 必须核查的证据 |
| --- | --- | --- |
| 十档一键推荐 | 100～1000，步长 100；公共纯契约计算，UI 与维护入口共用 | 十档结果、自定义响应重算、越界/错误类型拒绝；推荐只改三字段 |
| 当前采用 100 台推荐 | 128 窗口、512 MiB，以 SQL 正式配置保存 | 维护前后配置核对、重启读取生效值；不是只改代码默认 |
| 取消旧 64 硬限制 | 单一路径读取当前全局窗口，最大 1024 | 容量/HTTP/预取/页面不残留 64 窗口常量；旧历史文档明确标记 |
| 网站仍受保护 | `max_concurrency=0` 跟随全局；正数只收紧站点 | 同 IP 共享槽、全局/站点封顶、固定策略不变、429 全组冷却、回退直连单在途 |
| 有界内存与有序发布 | 预留包含后页等待，按序校验/提交，释放后再填窗 | 前页慢、后页快、预算不足、失败/取消与额度归零，失败不跨页推进 |
| 目录不随请求全量扫描 | 周期快照共享，实际分配逐候选原子核实映射/租约 | 大目录扫描次数有界；已删除/过期/凭据变化候选不得被旧快照分配 |
| 连接关闭取消安全 | 退役客户端在关闭完成前保有所有权 | 关闭阶段取消和重复取消仍回收，不能丢失客户端引用 |
| 瓶颈可理解 | 区分容量配置与当前出口/预算/网站限制 | 页面数据与实际调度共用正式计算结果，不显示虚构提速倍数 |
| 编辑与重启安全 | 保留草稿、滚轮防误改、只读查询可取消、写入不随切页取消 | 推荐后刷新、保存回执与新草稿、窄窗口保存栏、正常关闭/重开 |
| 单一正式配置 | 完整十一字段保存同一 `app_setting` 行 | 旧九字段显式维护、重复执行零变化、事务失败不部分更新；无 DDL/业务数据删除 |

## 显式配置维护

应用启动不会自动迁移 SQL 下载结构或改写网站策略。正常关闭 Empire 后，先只读核查，再执行：

```powershell
.venv\Scripts\python.exe scripts\migrate_download_capacity.py --recommend-devices 100 --follow-auto-sites
.venv\Scripts\python.exe scripts\migrate_download_capacity.py --recommend-devices 100 --follow-auto-sites --apply
```

`--recommend-devices 100` 明确应用 100 档容量；`--follow-auto-sites` 只将已有自动站点并发安全阀设为 0，后续跟随全局。固定站点不变；访问间隔、全站频率保护、任务开关和非容量资源设置均保留。不提供这些选项时只升级旧结构，不暗中重配网站。

维护入口取得单实例锁，同一 SQL 事务校验并提交下载与明确选中的站点配置，无数据库结构修改，不删除业务表、Redis 队列或下载文件。连接密码和代理凭据不进入输出。旧 TOML 资源数值的维护入口仍只承担 TOML 退役职责，不成为运行时兼容路径。

## 验证边界与下一步

配置允许 1000 台规划、模拟多出口调度通过、真实 1000 台设备压测是不同结论。本轮不宣称源站许可、真实独立公网 IP 数、吞吐倍数或进程 RSS 已在真实千出口负载下验证；512 MiB/4096 MiB 是下载预留预算，不是整个 Python/Qt 进程的内存上限。

真实设备逐步增加时，应分阶段记录请求率、超时/429、活动连接与句柄、进程内存及 Redis 待归档积压，再决定是否提高站点正数安全阀。不要为了“用满设备”缩短每 IP 间隔或绕过全站冷却。容量扩展本身不代表其他审计项完成；后续异常 Retry-After、跨源重定向凭据、后台任务健康状态已另行实施，证据见 [请求异常与后台健康验收](runtime-safety-review.md)。

# 远航规划与成本统计优化

2026-11-05，用户确认六项范围后授权实施。本记录先于实现建立，验证结果随后补充。

## 范围与生命周期

保持八项任务、十交易日维护、五池收盘复核、64证券/64日期池/256证券日补缺上限、金融每日联合全序列及原断点契约。初始化、近期核验、已知历史补缺仍使用原来源→Redis→统一归档→查询路径；不迁移表、不清理业务或队列。Redis丢失仍以SQL覆盖恢复，失败不推进断点。

1. 日线近期计划只解释涉及年份的区间与十个目标交易日，保留长期停牌成交锚点及新年度前缀初始化。
2. 连续覆盖直接校验和连接区间；结构、版本、排序、重叠及应合并相邻区间的验证保持，写入按日版本算法不变。
3. 日线补缺分64证券读取，累计找到64个待办后停止；已开始证券计划及恢复边界继续固定，未扫描证券不得当作已核验。
4. 五池调度与执行复用同轮计划；近期只读必要年份/日期证明，历史缺口按原完整日历检查，避免以缓存代替完整性。
5. 原因分页同轮复用正式日历，近期SQL仅传十日关系；不保存跨轮未经失效验证的日历缓存。
6. 下载成本按运行上下文独立累加，包含真实尝试、重试、HTTP认证及原生认证交换、观察到的传输与解码字节。取消/失败保留已观察成本，不保留URL、凭据、正文；复用有界运行记录，不新增Redis键或SQL日志。

## 验证设计

模拟长期历史且近期全齐，比较日期展开量、规划SQL调用数与结果集合；覆盖跨年、停牌、缺口、异常区间、迟到版本、64单位边界及中断恢复。共享统计验证并发隔离、失败/重试/取消、部分读取及认证；来源专项、隔离集成、公共安全回归和现行发布门禁按影响执行。来源参数和解析未改变的证据核对后复用，必要新实采沿用既有有界完整样本，记录实际范围，不为性能测量重复全池下载。

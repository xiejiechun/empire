# 界面只读状态验收

## 正式路径

所有需要后台 `runtime.invoke` 的只读页面统一使用 `plugins.ui.queries.QueryScope`。当前覆盖股票、新闻、交易日历、运行记录及错误详情、工作台、采集出口、下载资源读取和采集管理工作区。

QueryScope 按页面及请求键提供：

- 将 `runtime.invoke` 的同步异常转换为已失败 Future，使同步提交失败和后台 Future 失败走同一处理路径。
- 对同一请求键替换查询时先取消旧读；页面销毁时取消全部仍持有的读。
- 分别记录 loading、success、error、closed 状态以及最后成功/失败时间。
- 解析成功、失败与丢弃旧结果使用不同入口，旧结果不会推进最后成功时间。
- 刷新失败且页面已有内容时，状态明确显示当前失败、旧数据及最后成功读取时间。

任务执行、配置保存和精确清除错误不进入 QueryScope。它们继续由页面直接持有 Future；切页或页面销毁不将写命令误当作可取消读取。

## 请求身份与取消

股票按搜索词、偏移和市场核对；新闻按搜索、重点、游标、首屏上界及页码核对；日历按月份核对；记录按项目、偏移、修订和记录 ID 核对。切换条件会立即请求取消并清除页面引用。

如果 Future 尚未开始，取消会阻止执行。如果数据库线程已经开始、取消返回失败，它可以在后台正常结束，但页面不再持有它；测试也模拟了这种返回，确认旧股票、新闻、月份和其他项目记录都不会覆盖新条件。

## 页面工厂隔离

桌面外壳捕获单个 `PageContribution.factory` 的异常，在原导航位置创建局部错误卡片，显示脱敏原因和“重试打开页面”。重试会移除错误卡片并重新调用同一正式页面工厂。一个页面失败不会中断导航同步、其他页面或主窗口定时刷新。

## 自动验收

- `invoke` 同步抛错不会从股票页面 tick 向外传播；服务恢复后刷新成功。
- Future 失败保留已有股票行，并显示“当前刷新失败”和旧数据标记。
- 排队旧读可取消；已经运行、不能取消的旧读返回后丢弃。
- 项目、记录详情、筛选和月份变更均不会应用过期结果。
- 页面销毁取消读，但下载设置保存 Future 不取消。
- 页面工厂首次失败只显示局部错误，第二次重试成功恢复真实页面。
- 全部 UI Python 文件仍不超过 350 行检查上限。

本轮在真实 Redis/MySQL 隔离测试范围执行全套自动测试：855 项通过；另有 2 项仅因当前 Windows 账户没有符号链接权限而跳过。Ruff、严格 mypy、依赖一致性及差异空白检查均通过。测试不重启共享服务、不清空共享 Redis，也不删除业务数据。

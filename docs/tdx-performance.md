# 通达信财报解读

## 入门与日常操作

在“采集管理 → 采集任务”分别搜索业绩预告、业绩快报、业绩披露时间、业绩报告、股东户数。五项是独立插件和任务，可单独启停。默认每日北京时间18:00，代理优先且允许代理不可用时回退直连；可保存计划和网络策略，已保存设置优先。计划保存到MySQL，重启保留；网络策略下一轮生效。

在“数据浏览”目录搜索对应名称，输入六位证券代码或统一证券代码、起止日期后点查询。报告类日期筛选指报告期，户数指统计日。每页最多200条，按游标翻页；切页保留编辑草稿。数据页面只读已归档业务，采集完成与数据准备检查分开呈现。

## 数据说明

| 数据 | 业务身份 | 数值、日期及限制 |
| --- | --- | --- |
| 业绩预告 | 证券、报告期、公告日 | 预计范围原文和预告类型，不从自然语言推算上下限，不当作实际利润。 |
| 业绩快报 | 证券、来源公司编号、报告期、公告日及三个同比口径 | 净利润、资产、净资产为元；EPS元/股，ROE及变化为百分数。来源方案总数按公司编号计，同一方案的多同比行全部保留；来源没有营收。 |
| 业绩披露时间 | 证券、报告期 | 首次预约、三次变更、实际披露分别保存；当前剩余天数按北京时间计算，预约不能当实际公告。 |
| 业绩报告 | 证券、报告期 | 净利润、营收、经营现金流为元，EPS元/股、ROE百分数；是财报摘要，不替代完整三大报表。早期来源公告日等于报告期，不能直接用于严格历史信号。 |
| 股东户数 | 证券、统计日 | 户数为户，平均流通股为股/户，前十大汇总股数为股，比例百分数。来源无公布日，统计日不能当信号可用日；没有股东姓名明细。 |

空值保持未知，不补零。固定来源为通达信，证券使用unified_code，不依赖当前股票表存在。所有表只保留当前已知版本，不提供历次修订回放。来源撤回历史记录不会自动删除，集合变化会在数据准备中暴露。

## 生命周期与故障处理

| 项目 | 初始化及后续范围 | 中断、补缺及修订 |
| --- | --- | --- |
| 四项报告 | 1980年季度末至来源目录最新报告期，首次及每轮均核验全部季度，包含有效空期。目录只列20/21期，不能当全部历史。 | 按已入队报告期及市场位置续跑；每轮发现缺口和历史修订。Redis丢失重新核验声明范围并与SQL比较。 |
| 股东户数 | 最新来源目录与SQL已知证券的并集；每轮逐证券核验全部来源可得历史。 | 保留退市证券历史，最新目录与证券历史同键冲突拒绝；最新真实记录不在历史时并入该证券单元。Redis丢失重新建计划。 |

“重新采集”重建下载阶段计划；已进入等待归档阶段先确认原轮次。部分市场已入队后重新下载该报告期若来源内容变化，拒绝混合两个响应，需明确重新采集重建范围。失败不推进对应断点，SQL/Redis失败保留消息供重放。Redis为纯内存，服务重启丢失临时队列及断点，不承诺跨Redis重启续跑。

正常每个必要完整响应只请求一次，共享有界网络重试；完整响应先验证来源总数、业务键集合、报告期及列契约，才按市场拆分消息。快报规范列矩阵使用zlib-json-v1无损压缩传输，展开上限8MiB，校验流、长度和条数；不是原始响应缓存。任何市场消息超过512KiB，本期不发布，不能靠截断通过。采集与归档并行，全部单元及范围证明入队后才等待本轮全部归档成功。成功、相同内容或迟到旧版确认均统一清队；没有SQL写入也不保留业务消息。

## 数据库参考

正式表为earnings_forecast、earnings_quick、earnings_disclosure、earnings_report、shareholder_count；结构化核心字段，没有业务JSON。每表record_key为身份SHA256，content_hash为规范内容SHA256，version_observed_at为北京时间观测时刻。内容相同不写业务DML，可信Redis摘要免SQL，较旧响应不能覆盖新版。每项目只有一条collection_state，报告市场键为报告期|市场，户数键为统一证券代码，保存有界单元证明及整轮manifest。

使用scripts/init_tdx_performance.py显式新增表，启动不迁移。维护前正常关闭程序、持单实例锁并确认待归档队列为空，核对原有业务数量；不同已有目标结构拒绝覆盖。设计、字段映射及迁移证据见docs/evidence/tdx-performance-design-2026-10-12.md。

## 技术参考与验收

全部正式请求容量10000：预告[yjyg]为["0",报告期,"","1","1","10000"]；快报[yjkb]为[报告期,"","1","1","10000"]；披露[yjpl]和报告[yjbg]为["0",报告期,"","1","1","10000"]；户数[gdhs]最新为["0","","1","1","10000"]，证券历史以六位证券替换第二项。接口前缀CWServ.tdxsj_cbjd_，共享tdx频控和下载预算。

2026-10-12实测10000分别返回预告1877、快报122（61方案）、披露5544、报告5578、最新户数5574行。个股报告及披露历史接口忽略容量仍仅40条，正式路径用全市场报告期；户数证券历史10000生效，000001当时24条、600000为21条。这些是本次观测，不保证未来来源范围不变，不承诺非季度或上市以来全部历史。

五表隔离容量各100000行，含5000证券×20合成期：200条分页最高约15ms，覆盖流式查询初测最高约651ms，另测日期/证券索引定位单元的正式审计SQL，分配约56～99MiB/表。单查询Python分配最高约415KiB，不能当完整进程内存或冷磁盘时延。开发验收、生产已归档范围及最终部署另见带日期证据，支持范围不等于已经采完。

本次全历史预告有一条来源预计正文为空（601919.SH、2013-12-31、公告2014-01-17），保留NULL，字段数据准备明确显示限制，不填造正文。披露预约和户数统计日不能作历史信号；业绩报告早期可用日期限制同样单独呈现。

最新快报实测有两条来源声明明日公告日期（601958.SH、601139.SH，2026-10-13）。该字段按来源保存；历史信号检查按当前存储版本观测日核验，未来声明不作为已可用信号。

预告、快报和业绩报告均有来源提前声明的明日公告日期（2026-10-12观测到2026-10-13）。来源公告日期保留原值，不能作为已经公布的证明；历史信号检查标记限制，分析用途单独呈现。实际披露日和户数统计日仍严格校验不晚于响应观测日。

## 实现定位与开发核验

六类业绩/户数/持股变动的实现集中在features/performance，原独立业务身份、页面、任务计划及来源校验不变，公共preparation契约保留原公共路径。开发命令scripts/verify_tdx_performance.py要求显式独立测试MySQL配置、种子、随机30股、共享代理和build中新报告；完整来源单元在私有UUID库/命名空间经规范化、统一归档及正式查询核对集合和内容。验证进程限定季度/月份和户数证券计划，报告明确范围，不更改日常完整历史策略、不把有限manifest当全历史准备通过。2022-03-31报告来源总数反例保留；来源实际披露日超前仍拒绝。原有错误只在确实修复并验证后按精确ID处理。

测量入口measure_tdx_performance.py与measure_shareholder_changes.py复用同一私有资源生命周期，显式--test-settings及build中新--output；核实实际server_uuid与资源归属，取消和清理失败不能PASS。五表各100000行与股东变动100000行的原查询、次数和预算保持；输出全部原始样本及完整内容核对。使用历史真实规范行仅作为放大fixture，不冒充本轮实采或全市场范围。

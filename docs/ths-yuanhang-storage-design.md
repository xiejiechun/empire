# 远航版历史行情存储与生命周期设计卡

2026-10-24，实施设计，尚未部署。本文在业务表实现前明确粒度、字段、查询、容量及迁移；不表示表已创建或采集通过。来源依据和阶段退出条件见[实施方案](ths-yuanhang-implementation.md)。纯来源解码和规范化已进入 `src/empire/sources/yuanhang_wire.py`、`yuanhang_history.py`；数据库登记须在实际数据集实现时同步，不将规划表加入现行 schema 清单。

## 业务实体与唯一路径

固定来源为 `ths_yuanhang`，所有证券身份使用 `unified_code`。不覆写既有来源固定为开盘啦的 `stock_daily_quote`。新表不会外键级联到当前股票表，证券退出当前股票池仍保留历史。复权调用方迁移到远航版后使用唯一行情和事件输入，不跨来源拼接同一事件；开盘啦历史与通达信方案库保留其原用途。

| 规划表 | 一行的含义 / 主键 | 归档单位与用途 |
| --- | --- | --- |
| `yuanhang_daily_price` | 一证券一交易日；`(unified_code, trade_date)` | 完整证券年；原始 OHLC、成交量和成交额 |
| `yuanhang_price_year` | 一证券一年的来源内容证明；`(unified_code, quote_year)` | 与该年日线同事务；不是逐轮日志或最大日期快照 |
| `yuanhang_corporate_action` | 来源同一天合并后的权息参数；`(unified_code, ex_date)` | 单证券完整事件序列；不能据此声称保留每份公告方案 |
| `yuanhang_capital` | 一证券、一股本口径、一个生效日；`(unified_code, capital_kind, effective_date)` | 单证券完整股本序列；不同口径允许不同日期网格 |
| `yuanhang_series_proof` | 证券事件序列或股本序列的当前来源证明；`(unified_code, series_kind)` | `actions` / `capital` 两类；仅范围、计数、摘要和规范，不存业务正文 |

三个来源请求分别可能失败，不将日线、事件、股本捆绑成“一个成功即全部准备好”。计划三个采集项目，各自声明数据集与生命周期，复用同一正常认证服务。事件和股本均由各自的一个完整响应负责，不能按三个股本字段重复请求。共用网站频控，不新增归档器或私有队列。

## 字段字典与数值契约

身份列 `VARCHAR(9) CHARACTER SET ascii COLLATE ascii_bin NOT NULL`；业务日期为 `DATE NOT NULL`；当前数值规范采用 `DECIMAL(28,10)`，最多18位整数和10位小数，超过范围或精度明确失败，不能舍入后冒充原值。HxLong直接解码为 Decimal，binary64 通过最短可往返十进制转换，未知/null不改零。股数暂保留 decimal，因为不能凭现有整数样本裁定全历史永无小数。

| 表 / 字段 | 原生来源 | 单位与约束 |
| --- | --- | --- |
| 日线 `trade_date` | 字段1 | 请求所属证券交易日；按源日期保存，停牌缺日不补假K线 |
| `open/high/low/close` | 7 / 8 / 9 / 11 | 元，不复权；必需、正值，最低≤开收≤最高 |
| `volume_shares` | 13 | 股，非手；必需、非负 |
| `amount_yuan` | 19 | 元；必需、非负 |
| 事件 `ex_date` | 1 | 除权生效日，不是公告日；不能作为提前已知信号日期 |
| `bonus_ratio` | 454 − 460 | 每原股送股；454已包含转增，不再与460相加 |
| `transfer_ratio` | 460 | 每原股转增；非负 |
| `rights_ratio` | 455 | 每原股配股；非负 |
| `rights_price` | 456 | 元/新增配股股；有配股时须为正，无配股时保留源值 |
| `cash_per_share` | 463 | 元/原股；非负，沿用来源现金口径，不猜测税后收益 |
| 股本 `capital_kind` | 402 / 407 / 380 | `total` / `circulating` / `free_float`；固定枚举 |
| `effective_date` | 各字段所在表的1 | 来源生效日；不得按行号拼接或提前回填 |
| `shares` | 402 / 407 / 380 | 股，正值；380为自由流通股，已用样本实际换手率核对，不能据此宣称所有证券的定义已核完 |

字段899/900是普通流通股的比较日与变动量；2988暂返回高位标记空值，不能作为有效实际流通股变动。正式股本变动查询拟由同口径相邻余额作差，并明确标为计算结果；首个余额无前值时变动量未知。471为显示说明，当前不作为计算字段或完整公告存储。昨收、参考价、PE/PB及可选日指标未纳入本版必需字段。

证明字段：`source_count`、`row_count` 为无符号整型，`first_date/last_date` 可空但仅在已验证合法空集合时均为空；`key_hash/content_hash` 为64位十六进制摘要；`contract_version` 为无符号小整型；`version_observed_at` 为北京时间 `DATETIME(6)`。日线头额外有 `quote_year`、本次请求核验上界 `verified_through`；序列头有完整请求范围及各口径计数的有界结构化列，不保存整份响应 JSON。

请求观察时间必须在请求发出前取得并沿消息传递，不能在迟到响应归档时重新打时间。来源未给可信修订版本，本版只承诺阻止已知较早请求覆盖较新确认，不承诺识别源服务端缓存回退或严格历史版本重放。规范版本变化须显式失效覆盖证明。

## 来源完整性与合法空集合

逐响应核对 V2 请求ID/instance、完整字节边界、解压上限、表描述、HX声明行数、证券扩展身份、必需字段、日期排序/唯一性、范围与行内容。必需字段分表时核对日期集合，不能只比行数。股本允许各口径稀疏日期不同；不把这一例外用于日线与事件。

年度日线从已验证完整响应按日期分割，父头保存每年键集合和内容摘要。缺失年度不可由最大交易日推断完成；新股之前的年份不创建伪覆盖。日线起点与上市日期核对；北交所源返回转板前历史时保留，并分别显示源历史起点与北交所上市日，不能机械丢弃较早数据。

2026-10-24实测：刚上市的301718有2条日线、3个股本点，但事件响应为17字节零表头；不存在的USZA999999日线和事件也返回同形零表头。因此**单凭零表响应不能证明“没有分红”或“证券有效”**。解析器已区分 `EmptyHistoryResponse`，但不自动转为完整空集合。正式空事件验收仍需同一证券有效性和来源无事件语义证据，完成前该证券事件状态保持未知，不因日线成功给事件打勾。

常规完整单元只下载一次。开发时000001全历史与单独1991年218条一致是边界专项证据，不把重复分年下载固化为每轮双读。当前样本不能证明其他证券、所有停牌与特殊缩股情况；遇到负送转等未支持语义不得硬套普通复权公式。

## 正式查询、索引与预算

以下SQL为实现契约，命名以本设计为准；查询参数绑定，不拼接用户输入。分页每页最多500条；单证券长历史通过稳定日期游标读取，不维持旧3660自然日限制。全市场按日游标查询，避免 OFFSET 和日历逐日N+1。

```sql
SELECT trade_date, open, high, low, close, volume_shares, amount_yuan
FROM yuanhang_daily_price
WHERE unified_code=:code AND trade_date BETWEEN :start AND :end
  AND trade_date>:after ORDER BY trade_date LIMIT 500;

SELECT unified_code, trade_date, close, volume_shares, amount_yuan
FROM yuanhang_daily_price
WHERE trade_date=:day AND unified_code>:after_code
ORDER BY unified_code LIMIT 500;

SELECT ex_date, bonus_ratio, transfer_ratio, rights_ratio, rights_price, cash_per_share
FROM yuanhang_corporate_action
WHERE unified_code=:code AND ex_date BETWEEN :start AND :end
ORDER BY ex_date LIMIT 500;

SELECT effective_date, shares FROM yuanhang_capital
WHERE unified_code=:code AND capital_kind=:kind AND effective_date<=:as_of
ORDER BY effective_date DESC LIMIT 1;

SELECT quote_year, source_count, row_count, key_hash, content_hash,
       verified_through, contract_version
FROM yuanhang_price_year WHERE unified_code=:code
ORDER BY quote_year LIMIT 150;
```

日线二级索引 `(trade_date, unified_code)` 支撑单日截面，主键支撑证券历史；事件二级索引 `(ex_date, unified_code)` 支撑事件日筛选。股本主键覆盖截至日取值；确有全市场股本事件查询需求再测量 `(effective_date, unified_code, capital_kind)`，不默认给每列加索引。跨证券估值先批量读有界证券范围所需股本区间，再按生效日关联，禁止每只每日查询一次SQL。

容量假设：5578只、平均15年×250日约2092万日线；平均25年约3486万。每日新增约5578行，每年139万行，未来五年约697万行（未含新上市）。日线六个DECIMAL约78字节，另有身份、日期、InnoDB与二级索引成本；暂按每行200字节规划约4.2～7.0GB日线，实际应以隔离放大测量替换，不把估算当实测。证明头按证券年约8～14万行；事件/股本分别按每股200/1000个点做压力上界，同时测试历史长证券。

预定性能门槛：单证券500行页面P95≤200ms，单日全市场500行页面P95≤300ms，单证券年度正式审计≤1s；年度归档≤2s，重复归档业务DML为0。隔离测试至少记录EXPLAIN、扫描量、读取字节、冷/热延迟、表及索引空间、放大导入吞吐、重复与1%修订、峰值内存；超限须优化或实质评审，不能只提高超时。上述门槛尚未执行，不登记 `measured`。

## 生命周期与事务

| 问题 | 计划实现 |
| --- | --- |
| 初始化终点 | 冻结本轮当前A股集合及最新已结束交易日，逐证券请求完整源历史；每年日线与完整事件/股本分别归档。全池全部适用单位核验通过、正式查询内容一致、本轮待归档0才完成 |
| 日常增量 | 默认每日北京时间18:00，沿用用户保存策略；日线补齐SQL缺年并回看本年，已知失败单位优先重试；事件与股本单次完整响应更新 |
| 较早修订 | 每周分摊证券全历史回查，工作量与频控有界；不承诺两次回查间及时识别早年修订。不重复下载已经在本轮全量响应中的年度 |
| 相同内容 | 统一摘要命中免SQL并清队；回源相同内容无业务DML。不能为刷新核验时间更新每条日线 |
| 有效修订 | 同单位比较键集合与内容，仅更新实际变化；迟到旧消息不覆盖。源明确删除事件须以完整响应确认，未知空响应不可删除历史 |
| 中断与Redis存活 | 原子发布业务消息及已入队断点，下一次从未入队单位继续；不逐年等待归档。整轮入队后才等待全部成功清队 |
| Redis丢失 | 从SQL证明头及正式内容恢复；丢失未归档消息按源重新取得，不能承诺恢复最后内存核验时间 |
| 当前池退出 | 保留全部历史；不自动删除、不以新池整份覆盖业务 |
| 从头采集 | 重新验证来源全历史，不清库；既有有效事实在新单位完整验证后才更新 |

归档单位主从记录、内容证明、旧响应顺序与每项目唯一 `collection_state` 同事务；状态和摘要更新沿既有框架。归档成功包括插入、修改、相同和过时确认，均由统一归档器清除对应消息；错误保留。长期响应原文不入SQL/磁盘，错误样本沿共享限额和脱敏；认证响应正文不留错误样本。

## 身份、迁移和交付

账号绑定以 RouterProxy `code` 为键，不按IP；IP只参与共享频控。游客密码和会话不是业务数据，不放在上述业务表或Redis错误样本。正式身份管理须单独明确受保护存储、实际客户端设备身份来源、节点缺身份时的可见错误和失效恢复。不能在身份不足时自动复制本机账号或重复注册绕过源拒绝；已有本机游客正常登录成功不代表每节点独立身份供给完成。

新增表通过显式维护入口创建；启动不迁移。维护前核查运行中Empire/归档所有权、队列、已有数据数量和可用磁盘；完成DDL及隔离容量/事务验证准备后再执行。上线按 `schema.sql`、结构契约、业务归属、设计卡、恢复清单、程序内说明同步登记。既有开盘啦/通达信记录不迁写为远航版事实，不做来源冒名转换。

正式路径迁移顺序：实现新数据集和有界查询→随机30股代理真实全链路及固定反例→切换受影响计算调用方→门禁及可见桌面→全池初始化和审计。全量初始化按用户已授权执行，但多节点身份、合法空语义、基础集成和容量门槛未完成时不得冒充已具备运行条件。开发验收、抽样实采和全池实际进度分别报告。

# 更名行业字段与用途验收调整

## 设计与日常使用

用户于2026-10-06确认补齐更名接口返回的证监会行业和通达信行业，不新增独立行业任务。两个更名任务、事件身份、历史范围和每日18:00计划不变。数据浏览的更名页面增加两个行业列；来源没有值时显示空白，不填入其他来源的行业。行业标签没有历史生效日期，只表示接口本轮返回值，不能据此还原历史行业。

普通数据分析用于浏览、筛选来源更名记录：证券、日期、事件身份、来源集合和更新时效仍是必需证据。来源缺名、名称链断点、公司早期旧新名称方向疑点保留数量和定位，作为用途限制，不要求补齐全部名称链才可查阅。历史选股回测仍按原名新名、连续链和方向核验，不能把来源更名日期当公告可用日。

## 存储设计卡

粒度仍为一种证券名称事件，唯一键(name_kind,record_key)，record_key仍由证券、日期、原名、新名计算；行业变更更新事件内容，不创建新事件。security_name_change新增csrc_industry和tdx_industry两个VARCHAR(200) NULL utf8mb4_bin列，分别对应zjhhy和tdxhy。NULL及来源“无”表示未提供；非空文本保留原值，长度超过200或类型异常拒绝完整响应。完全相同事件的行业不同属于冲突，不能静默选一个。

正式列表、单证券历史、范围浏览仍使用现有日期/证券索引，每页最多200行，投影增加两个列；覆盖检查每类型最多30000行并将行业纳入摘要。行业为展示字段，不新增未使用的行业索引。预计五年25000事件、两类型硬边界少于60000事件，两个标签最多1600字节/行，表及索引预算128MiB；实际响应使用每市场行业组合字典加索引，避免重复标签放大Redis单次发布。字典有规范排序、无重复及全部索引使用校验，SQL只保存解码后有类型的行业列，不保留业务JSON或第二份字典表。页面P95≤50ms、覆盖P95≤500ms、25000事件导入≤10秒，重新实测绑定现行DDL和实现。

## 生命周期、完整性和迁移

线协议升级为schema2、完整性contract2、摘要命名空间v2；运行时拒绝旧消息，不兼容双写。每轮仍一次完整历史响应，三个市场原子一次入队，之后等待整轮归档；字典编码不改变事件键集合、出现次数和断点规则。相同内容零业务DML，行业修订更新原事件，迟到响应不覆盖新版本，成功统一清队。

显式维护先正常关闭Empire、持单实例及SQL维护锁、确认待归档为0；只加两列，逐事件核对原有字段数量与摘要不变，不删除业务记录。失效两个项目旧摘要及覆盖证明，通过正式任务全响应重新采集补齐行业和contract2。Redis已完成断点按其完整性契约版本复核，旧完成状态不能跳过新版实采；启动不DDL。失败后保留已加列和旧记录，可再次运行维护；缺新版覆盖证明时数据准备不得通过。

## 故障处理和交付

来源结构、行业冲突、字典损坏、总数或容量异常均不推进断点；网络复用共享有界重试。专项覆盖来源→规范化→Redis→统一归档→查询，含旧记录补齐、行业修订不改事件身份、重复无DML、冷热摘要、旧响应、提交后重放、清队及两种用途。实际补采数量、字段覆盖、错误与待归档、发布和桌面验收另存日期证据，不把方案当作已实现保障。

显式行业升级维护会在待归档为0时通过公共断点CAS重置旧契约断点，包括SQL已提交但旧断点仍等待归档的情况；新版断点、无关任务及执行计划保持原值。队列非空拒绝重置，随后新版采集重新取得完整响应，不沿旧完成状态跳过行业补齐。

完整来源证明存在时，指定证券没有更名事件是普通查询的合法空结果，不作为漏采；这不能证明证券的首个名称。历史名称回放仍按独立用途检查，不将无事件等同于初始名称已知。

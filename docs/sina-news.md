# 新浪 7×24 全球实时财经新闻直播

入口为 https://finance.sina.com.cn/7x24/ 。采集插件使用该网页实际调用的公开接口 `https://app.cj.sina.com.cn/api/news/pc`，全分类 `tag=0`，每页 `size=50`。后续页面保持 `page=1`，传上一页 `min_id` 为 `id`、`type=1`，按新闻 ID 向前翻页。

## 使用

在“采集管理 → 采集任务”选择“新浪 7×24 小时全球实时财经新闻直播”，点击“立即采集”。新任务默认仅手动；如需持续更新，选择固定间隔、设置 1 分钟并保存。间隔从本轮完成后计算，应用关闭时停止采集。

“数据浏览 → 财经快讯”查看已归档新闻，支持正文/标题搜索、重点筛选、分页、复制正文与打开来源。首页每 15 秒刷新已入库内容，不额外请求新浪。页面按 `(published_at, news_id)` 游标翻页；进入下一页后固定本次首屏上界，新新闻不会挤动已打开的后续页面，回到并刷新首页才进入新一轮视图。总数只在首屏计算，后页不重复 `COUNT`，不使用深层 `OFFSET`。

空搜索直接使用现有 `(source, published_at, news_id)` 排序索引，不再执行无意义的标题/正文 `LIKE '%%'`。输入搜索词时仍保持“标题或正文包含”的现有语义，因此会做数据库包含匹配；当前没有默认增加中文全文索引或搜索服务。业务消息入队会立即唤醒归档器，60 秒扫描仅用于恢复遗漏通知；仍不承诺逐秒推送。

命令行与桌面共用管理器和单实例锁：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m empire collect-news
```

`--fresh` 对应从头扫描最新窗口、建立新增量基线；保留已归档新闻。正常重启和继续采集应使用默认续跑。

## 范围与断点

首次或明确 fresh 只请求第一页，最多 50 条。后续从最新页开始，只有尚未接上上轮已归档 ID 时才向前翻页；遇到 ID 不大于上轮上界的新闻后，处理完当前页即停止，不再请求下一页。`refresh_pages` 已取消，旧断点中的该字段也不再强制多页刷新。消息与下一页断点在同一 Redis Lua 操作中提交；Redis 仍运行时，应用暂停或异常后从 `before_id` 续跑。

Redis 已关闭 AOF 和自动快照，Redis 服务或电脑重启会丢失未归档数据、断点、下次执行时间和记录，MySQL 中的任务与网站配置保留；再次采集按首次单页处理，已入库新闻保留，不自动补齐停机期间的历史缺口。

本轮上界 `upper_id` 只有在全部已入队页面确认归档后，才变成 `high_watermark`。校验失败不会推进该页断点，SQL 失败不会丢待归档数据。来源返回的历史窗口有界；如果已经翻到空页但仍未接上旧断点，会记录缺口错误，不自动跳过。此插件不是全历史新闻下载器，也不能发现已离开刷新窗口的所有历史修订或撤稿。

## 存储与共享规则

- `finance_news` 是历史业务表，以 `(source, news_id)` 去重；同一新闻按来源修订时间及观测时间更新，迟到旧响应不覆盖新版本。不采用股票整表替换策略。
- 保存标题、纯文本正文、发布时间、来源修订时间、重点标记、分类、来源链接、最早/最近观测时间。原始完整 JSON、编辑人员、阅读数、评论等不入库，媒体文件不下载。
- 新闻和股票的 `app.cj.sina.com.cn`、`vip.stock.finance.sina.com.cn` 同属 `sina.com.cn` 频控组，共享网站间隔、并发和 429 冷却；重试也走相同限制。
- 项目 `sina-news` 的采集/归档记录分别保留 100 条、错误样本 300 条，均仅 Redis。样本正文最多 64 KiB；修复验证后按记录 ID 清除，保留新到错误。
- 新闻归档按页独立事务，已处理行数包含重复确认和修订，不等于新增数量。已入库新闻历史不随操作记录配额清理。
- 归档在事务内批量读取当前页已存在新闻，业务字段及来源版本相同则跳过 SQL 写入；迟到旧版也跳过。仅观测时间变化不更新 `version_observed_at`，该字段现在表示最近一次实际写入版本的观测时间。来源修订时间变化需写入，防止旧版本覆盖。

表字段和 Redis `checkpoint:sina-news-v1`、`archive:progress:sina-news-v1` 的参数说明，见桌面“说明文档 → 财经新闻表与增量断点”。新增业务表只通过明确执行的建表操作创建，应用启动不迁移数据库。

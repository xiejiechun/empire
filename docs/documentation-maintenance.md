# 说明文档设计与维护

## 用户如何找到说明

程序内“说明文档”是正式离线使用入口，分为入门、日常操作、数据说明、故障处理、技术参考。左侧选择主题，中间阅读；上方显示分类和主题，“本页章节”跳转到二级标题。搜索跨所有分类，相关主题以 help: 链接在程序内打开。“入门首页”恢复起始阅读位置。

- 入门：第一次使用、功能范围、规划与已接入的区别。
- 日常操作：查询、采集计划、代理、资源保存、生效时间、进度和数据准备。
- 数据说明：各数据的查看方法、来源范围、更新方式、日期、单位和用途限制。
- 故障处理：按症状给出可执行检查，说明重启和配置保留边界。
- 技术参考：字段、业务身份、SQL、Redis、断点、版本和维护契约。

操作主题不堆放 SQL、协议实现或历史测试数量。动态实采进度和有日期的发布证据保留在项目记录，不写成永久支持规则。每篇只有一个一级标题，标题须与 topic 登记一致，至少有一个二级章节；日常操作先说明入口与动作，再说明保存、生效、结果和限制。

## 正式资源与覆盖登记

唯一程序内正文为 src/empire/plugins/ui/storage_reference.md，阅读器和检查器共享 help_content.py 解析，不另维护网页或运行时兼容格式。README 和桌面指南只给入口与概览，来源专项文档提供完整生命周期及验收证据，避免反复复制长操作说明。

[覆盖登记](documentation-coverage.json) 把每个实际注册的页面 ID 关联到一个或多个说明主题。检查器从现行 bootstrap 构建插件声明但不启动、不联网、不读取真实配置；新增、退役或变更登记必须与实际页面集合精确一致。每个页面必须至少有一篇非技术参考文章。一个共用规则可服务多个独立页面，三表可以共享来源说明，不必复制正文。

## 每次开发的同步步骤

1. 在开始设计时列出受影响的入口、操作、数据、配置、日期和故障行为。
2. 实现完成后更新程序内对应主题；新增页面同时更新覆盖登记。新增数据补来源、范围、单位、更新、恢复、缺口和用途限制。
3. 同步 README / 桌面概览、实现状态及受影响的架构、存储、恢复、来源文档；纯实现调整若不改变用户行为，记录具体原因。
4. 执行文档契约与相关回归，确认标题、分类、内部链接、表/字段和功能覆盖。
5. 在最后一次代码修改后，显式记录实际审阅：

```powershell
.\.venv\Scripts\python.exe scripts/documentation_contract.py review --note '本次新增或改变哪些功能，更新了哪些说明及限制'
.\.venv\Scripts\python.exe scripts/verify_documentation.py
```

代码改变而正文未变时，review 拒绝只刷新摘要。仅当审阅确认无需修改用户说明，可追加 --unchanged-reason 并写明具体原因；不得用“无影响”或测试全绿替代实际核对。变更业务行为时必须修改说明，不能使用该参数逃避同步。

## 门禁如何防止遗漏

[审阅记录](documentation-review.json) 保存 src/empire Python、维护脚本、SQL、示例配置和打包定义的 SHA-256，以及正式说明内容摘要。文件新增、删除、修改或说明变化都会使旧记录失效。scripts/verify_documentation.py 和 verify-release.ps1 执行相同核对；发布前缺登记、缺文章、链接错误或旧审阅会失败。build.ps1 也先检查文档，直接打包不能绕过。

这是结构覆盖和审阅时效约束，不能自动证明自然语言语义与实现完全相符；开发者仍须逐项核对操作、默认值、限制和实际验证。审阅不是新一轮用户审批，也不意味着实采全范围或真实设备验收已完成。审阅记录不含连接信息或业务数据。

## 交付与验证

界面变更执行相关 UI、导航、文档回归及正式发布门禁，正常重建程序并重开真实桌面。纯正文变更可仅验证文档和相关回归，同步外置资源并说明未重建 EXE。离屏截图用于检查排版、长标题、窄窗口及章节导航；不冒充真实桌面部署验收。

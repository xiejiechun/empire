# P2-11 未知 schema 按项目隔离

2026-09-27 后续复核发现的发布锁等待竞态已修正：普通和预留发布在全部准入等待结束后、提交 Redis 命令前统一复核全局及项目隔离；提交后的成功结果不因随后发生隔离而伪造为失败。新增 11 项并发边界回归，详见 [收尾复核](final-foundation-review-2026-09-27.md)。

## 审阅结论与实施边界

只有消息通过 Envelope 结构校验、数据集名称精确命中已登记贡献、job_key 在该贡献的 projects 中明确登记，才允许按项目隔离。不能靠项目名称清洗、前缀或未知消息自报归属来缩小保护范围。未知数据集、未登记任务及无法按当前结构读取的未来版本继续全局阻断。

隔离消息原位保留在 Redis Stream，不复制业务正文、不写 MySQL 隔离表、不推进成功标记，也不删除。归档器只保存有界消息 ID 与项目映射，和正常归档索引共同受 index_max_entries 限制。一个项目出现未知版本后，该项目已索引的所有批次暂停处理，其他已发现项目继续轮转；发现之前已经成功提交的数据不撤销。

任务发布业务页时检查隔离项目，包含已获得整批预留的发布。暂停期间不推进断点或消耗预留；其他项目正常入队。全局 schema 阻断和 Redis 容量保护继续生效。项目隔离可能在当前响应下载之后被发现，已下载的当前页由原有背压等待流程保留。

## 恢复与可观测性

后台每 60 秒按数量、正文累计字节和协作时间预算轮转复查隔离 ID；手动归档可立即复查。契约读取能力恢复后消息重新加入原归档路径，同一项目仍有未知消息时继续隔离。重启后从原 Stream 重建隔离状态，无需永久隔离键或配置双写。运行状态展示隔离项目与消息数，归档健康显示异常。

Redis 服务重启仍遵循既有纯内存丢失边界。恢复读取能力不是归档成功证明；消息最终仍必须经过规范校验、事务提交或无需写入确认，再由统一归档器删除。

## 验证

真实 Redis 的随机测试命名空间覆盖未知消息在正常消息前、中、后的位置、独立项目继续处理、隔离消息原位保留及恢复重放。归属不明、无法解析的未来版本保持全局阻断。入队测试覆盖带整批预留的受影响项目被阻止、断点和预留不变，以及其他项目正常发布。完整发布门禁另覆盖已有归档公平性、容量、事务重放和界面回归。

隔离诊断按登记的正式项目 ID 记录；已进入正常索引的消息转入隔离时只计一次容量。两项均有回归断言。索引达到上限或 Redis 达到全局水位时仍可触发全局背压，项目隔离不承诺突破资源上限继续采集。

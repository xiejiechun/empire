## 2. 为什么现在的栏目会有问题

补充逐行核实：只读检查Redis已保存报告，最新报告时间为2026-10-12 15:02:33（北京时间），范围为601139/数据分析。share_capital 行的 registered=false、source=未接入、status=未开发；六项数据检查全为unknown，理由均为“未接入数据检查插件”，开发检查也无通过项。free_float行同样如此。当前源码也没有为这两项登记PreparationContribution。因此这些行显示“未确认”的直接原因是没有连接已有盘口数据的检查路径，根本没有执行其股本SQL检查；不能把上节SQL异常或601139缺记录说成这些行当前状态的触发原因。缓存证据见[逐行检查结果](evidence/preparation-capital-row-2026-10-12.json)。本次未读取可见桌面实时选择，以上明确为已保存报告和源码路径核实。

1. 目录把 share_capital 定义成“上市以来全部股本变化事件”，free_float 定义成“来源公布自由流通股数”，都没有对应贡献登记。实际上已接入的 historical_quote 包含每日总/流通股本及市值，目录没有体现这些现有能力。
2. 每日快照和变更事件混为一谈。trade_date 是行情所属日，不是股本公告日或法定变更生效日；连续快照相减不能证明完整股本变更历史。
3. 字段口径混淆。SQL 有 total_shares、circulation_amount、actualcirculation_value，第三项在当前正式映射中是金额；没有自由流通股数专列。用它除以股价得到的是派生估计，不能标为“来源直接公布股数”，也不能凭字段名认定它符合某个指数公司的自由流通规则。
4. 当前盘口检查主要校验结构、行情必需值、买卖档位、摘要和证券日覆盖；没有针对上述股本关系的用途检查。既可能把未接入的重复规划显示成缺能力，也可能把盘口基础通过误读成股本估值通过。
5. market_value 计算依赖未接入的 share_capital，忽略同一日摘要已提供股本及来源市值，形成无谓的依赖阻塞。

相关实现位置：contracts/preparation_events.py、preparation_processing.py、market_storage.py；plugins/data/kaipanla_products.py、kaipanla_products_preparation.py；plugins/collectors/kaipanla_products_source.py；plugins/ui/kaipanla_quote_format.py。

## 3. 栏目调整决定

| 现有栏目 | 规划处理 | 正式数据路径与边界 |
| --- | --- | --- |
| 历史盘口与日行情摘要 | 保留唯一采集项；详情明确含“行情、股本、市值、来源估值指标、买卖档位” | 继续 historical_quote → 开盘啦查询 → stock_daily_quote，不另建采集或复制表 |
| 总股本和流通股本记录 | 从独立待采集清单移除，合并到日摘要的“每日股本快照”字段组 | 用 total_shares、circulation_amount 按证券日检查；不承诺公告日或全部变更事件 |
| 来源公布的自由流通股本 | 移出现有能力的重复待采集清单，改为日摘要详情中的口径说明 | 已有“来源实际流通市值”；直接公布自由流通股数仍未证明。将该缺口列在扩展能力说明，不冒充完成，也不阻塞总/流通股本 |
| 计算股票市值 | 改为“按收盘价计算与核对市值”，保留计算性质 | 仅依赖 historical_quote 的价格与股本字段组；并列显示来源公布值和计算值及差异，不覆盖原值 |
| 计算市盈率/市净率 | 保留独立计算用途；详情提供来源现成PE/PB入口 | 来源PE/PB属于日摘要；自己按财报可用日期重算是另一能力，不能因已有来源倍数就冒充完成 |
| 计算市销率、股息率 | 保留 | 本次SQL核查不能证明日摘要已有同口径结果，继续复用正式输入 |
| 其他六项开盘啦产品 | 保持各自独立 | 各自来源、证券日覆盖及用途验收，不受股本失败牵连 |

独立股本“事件档案”和直接公布的自由流通股数若以后确有业务需求，再单独明确来源、公告/生效日期和存储设计。本次默认估值与普通日频分析不因此新增任务。

## 4. 数据准备页面的组织

页面保留一份正式目录，通过筛选切换三个视图，不新增另一套人工进度表：

- **已有数据**：已接入的证券基础、股票行情、公司事件、财报、行业与指数、交易规则等。每项展示真实来源和实际范围；表存在不等于范围通过。
- **计算与核对**：复权因子/行情、含分红收益、市值及估值重算、三表核对、行情缺日核对。依赖到所选证券/日期及必要字段，不要求上游全市场先完成。
- **待建设能力**：尚无正式提供者的独立交付物。已有数据的不同字段或页面入口不重复计数，明确区别“未开发”和“已开发但所选范围缺数据”。

业务分类仍可筛选；新闻及已移除的重复项不重新加入。当前指数成员不能冒充历史成分或权重，指数名单不能冒充完整基本资料；三张财报分别检查。本次没有全库逐项业务完整性验收，不能依据表目录估算行数给这些项目判通过。

主表建议列：数据名称、工作类型、来源/提供能力、所选范围覆盖、用途可用性、最近检查时间。开发测试证据放入详情，不与实际归档进度混成一个完成率。

日摘要详情按字段组展开：

| 字段组 | 检查内容 | 结果影响 |
| --- | --- | --- |
| 日行情 | 开高低收、成交量额、收盘状态、必要交易日集合 | 影响价格分析和日频回测 |
| 每日股本 | 总/流通股本存在性、非正值、大小关系、来源精度 | 只影响需股本的估值或规模因子 |
| 来源市值 | 总市值、流通市值、实际流通市值、单位及异常关系 | 保留来源口径，显示与自行计算不同的结果 |
| 来源估值 | PE、静态/动态/TTM、PB等字段及分母限制 | 不承诺严格历史可知财报版本 |
| 盘口 | 档位结构与排序、快照时间 | 不将日级快照用于重建完整逐笔事件 |

结果继续分采集完整性、来源质量、用途条件和最终用途可用性。新增字段组是同一采集项内部检查，不登记多个 PreparationContribution 来重复认领同一任务。原始快照可查阅、价格用途可用与股本用途不可用可以同时成立，主表必须带所选用途，不能只显示无解释的红色“有问题”。

缺口详情列证券、日期、字段、实值、规则、受影响用途和处理建议。异常分为缺记录、缺字段、零/占位值、关系矛盾、精度待核实、口径未明确、缺历史可用日期。不能填零、裁剪流通股本至总股本、用最新值回填历史或自动删除异常。

# 插件贡献边界验收

## 范围

本轮关闭系统审计 P2-15，目标是让新增数据类型和单个采集器启停不再要求修改多个中央业务分支。实现仍是代码内白名单，不开放第三方包发现、任意路径导入或运行时动态安装。

## 正式路径

- `DatasetContribution` 声明数据集集合、摘要命名空间、版本契约、增量或聚合模式、任务到项目身份、完成判定和聚合运行标记。`DatasetPlugin` 构建时拒绝重复数据集及摘要命名空间。
- 统一归档器向 catalog 查询模式、项目、完成状态、摘要和聚合标记，不再固定分发股票、新闻、日历，也不再调用记录服务中的 job→project 映射。
- `TaskContribution` 是任务定义的唯一契约。`collection.control` 只静态依赖 Redis、MySQL、HTTP 和记录服务；执行、计划和页面投影按任务能力判断对应采集器是否在线。
- MySQL 基础插件只校验 `app_setting` 与 `collection_state`。`data.stocks`、`data.news`、`data.trade_calendar` 分别校验自己的业务表并提供 schema 能力；对应采集器只依赖自身 schema。
- 没有保留旧 `CollectionTask`、固定 job 映射、查询插件归档确认方法或第二套数据目录。

## 故障行为

| 场景 | 结果 |
| --- | --- |
| 单个采集器未启用 | 对应任务显示 `unavailable`，不能启动；控制器、其他任务和历史仍可用 |
| 采集器重新启用 | 对应任务通过同一能力恢复，不重建控制器 |
| 某业务表缺失或结构不符 | 对应数据插件和采集器失败；MySQL 核心及其他业务查询继续运行 |
| 未注册或重复数据集 | catalog 明确拒绝；消息不由其他数据类型误处理 |

## 验收证据

- 仅测试用第四数据类型 `metric.sample.page` 通过一个增量 `DatasetContribution` 完成规范化、项目归属、队列调度与统一归档调用；生产归档器和记录映射未增加该类型分支。
- 控制器测试移除一个采集能力后仍可读取任务快照，任务显示不可用；恢复同一能力后可再次运行。
- 隔离 schema 测试令 `finance_news` 校验失败，股票和日历查询插件仍保持运行。
- 股票、新闻、日历真实 Redis/MySQL 集成测试继续覆盖提交、缓存命中/丢失、旧版本、失败留队及确认清理。

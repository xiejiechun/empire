# 数据预览排序与查询边界

本轮延续任务内预览的唯一正式查询路径，未新增业务表、索引、缓存、采集或归档路径。用户操作说明在程序内“查看结果”。实施验证见 [本轮记录](evidence/preview-usability-2026-10-30.md)。

## 请求与分页

`preview.read` 增加可选 `order={field,direction}`，方向为 asc / desc。桥接仅接受当前任务栏目已登记的列；项目、栏目、规范筛选和排序共同绑定游标。各业务查询再次使用自己的字段白名单，前端不能传 SQL 表达式。原有未指定排序的调用保留原默认次序和分页契约。

SQL 排序通过 `plugins/infra/query_order.py`：业务查询提供分页前的完整过滤关系、字段表达式和非空唯一身份。排序值先做空字符串规范，NULL 与空文本始终置后，业务身份升序打破同值。使用键集分页，不下载全历史再排序。第一条查询只读最多 limit+1 个排序值和身份，第二条查询在同一连接事务内读取至多 limit 个正文，按已得到的身份顺序返回，避免长正文进入排序附加负载。默认 MySQL 事务隔离下同次读取使用事务快照；不同翻页请求不是一致快照，不保证跨请求期间修改排序值的记录不会移动。

Decimal 游标保留十进制字符串及类型，SQL 比较端显式转 DECIMAL(65,30)，避免隐式 DOUBLE 丢失精度。循环小数比例在计算结果端也显式限定精度，避免 MySQL 内部中间值与返回值的舍入差异引发跨页重复。JSON 内数值先按业务白名单转十进制再排序，JSON null 不转换成零。

每条排序及正文读取语句最多执行15秒；排序语句通过 SET_VAR 设置最多32MiB排序缓冲和1MiB完整文本排序键长度，仅作用于本语句，不修改共享服务配置。超过资源上限明确失败并提示缩小范围，不回退到局部排序。两次有界读取不等于全表访问成本为常数；非索引、正文或计算字段可能扫描筛选范围。正文数量有界，既有桥接帧上限仍然有效。

## 业务字段

- 个股融资融券：在分页前连接同证券上一条来源日记录，偿还额、金额、占比和最早记录标志按正式公式排序；上一条可位于筛选开始日期之前。
- 行业融资融券：融资余额与融券余额先按既有万元/亿元换算计算差额，再排序。
- 指数行情：价格关系和成交量额质量标志使用与正式查询相同的空值规则。
- 上市资料：来源可用状态取同次事务读取的 collection_state 证明；不以是否存在历史资料代替当前来源状态。
- 停复牌：来源日期排序使用筛选范围内 MIN(source_date)；仍以证券、生效时间、复牌键及记录键组成完整身份，分页后只补读本页的真实来源日期集合。
- 增发送配：使用现行 payload 字段白名单，金额数值比较；未添加 JSON 存储副本。
- 财报：报告目录按证券、名称、报告期、币种与期间口径排序；完整证券历史里的科目比较在完整加载的集合内进行，不将某一页报告期作为完整历史。
- 资本运作：列表移除正式查询未投影的长正文空列，正文继续由已有详情读取；不增加自动加载全部详情的请求。
- 盘中池：仅对既有有界完整快照排序，数值用 Decimal；分页游标包含快照版本、筛选、排序和位置。快照失效报错，不自动换版本。不产生 SQL 业务写入。

## 界面与验证边界

公共表格的业务列均提供排序，操作列除外。表格列选择与行距按当前任务栏目保留，详情返回恢复查询；嵌套完整明细的排序与查找不改变上级列表。完整明细金额比较不用 JavaScript Number，保证大整数和小数精度。

隔离 MySQL 测试逐列执行703个 SQL 列的两个方向，共1406种组合；盘中五栏目的135列使用快照契约。跨页反例另外覆盖金额、重复值、NULL、计算列、JSON、长文本、来源日期复合身份及状态证明。界面巡检覆盖51个登记入口、76个可见栏目；真实桌面和正式发布结果单独记录，不以隔离测试替代。

# 当前实现与验证边界

已接入新浪沪深北股票列表、新浪 7×24 财经新闻和巨潮 A 股交易日历，具备统一执行计划、按出口 IP 共享的站点访问规则、断点恢复、结果浏览和系统诊断。公告、历史行情、选股、回测及券商功能尚未实现。

## 当前能力

新增采集功能的现行开发入口为 [开发指南](collector-development-guide.md)，由 AGENTS.md 要求执行；历史验收文档不替代新来源的业务契约和专项测试。

2026-09-27 收尾复核：P2-11 发布等待期间隔离状态变化的并发缺口已修正并补测；本轮未发现需要继续扩张重构的证据。真实容量、备份恢复与真机无障碍验收仍不能标为完成。详见 [收尾复核与剩余事项](final-foundation-review-2026-09-27.md)。

- 未知 schema 按明确登记的数据集与任务归属隔离项目，消息原位保留，其他项目可继续归档；归属不明仍全局暂停。后台有界复查恢复契约并重放，运行状态展示隔离项目与消息数。详见 [契约隔离验收](schema-isolation-review.md)。

- 桌面页面按工作台、数据浏览、采集管理、系统设置、说明文档组织。股票页支持市场筛选、搜索、分页和复制，刷新按来源及统一代码保持所选身份；交易日历支持按月查询并区分未采集；表单有未保存提示与撤销，刷新不覆盖输入。
- 任务支持手动、固定间隔和每日定时；同一任务不重叠，暂停保留断点。插件启用只提供能力，不自行触发采集。
- 同域名组共享 HTTP 请求间隔和 429 冷却，重试也经过频控；界面修改网站间隔作用于后续请求。
- 本机直连、代理、代理回退、重试与重定向统一经过同一 routing 正式路径；测试只替换 transport/Redis，不替换限流算法。采集管理只使用有界 `workspace` 查询和完整网站策略保存，不保留旧全量快照、整数间隔适配器或第二套许可实现。详见 [HTTP 与采集管理正式路径验收](http-formal-path-review.md)。
- 异常限流头安全回退，合法长冷却保留，超出表示能力的整数保守阻断；等待可以取消，不清除站点冷却。跨 origin 跳转清除认证与 Cookie（含客户端自动合并值），拒绝 HTTPS 降级，正文和文件共用保护。
- 归档、调度、代理发现及 Redis 监测的关键循环意外退出会明确显示运行失败，服务暂时异常及依赖异常显示运行异常。后台错误摘要按插件有界且统一脱敏；不自动重启故障循环、不重放可能已提交的写入，正常停止不误报。
- HTTP 统一有界读取并约束传输/解压字节；采集器选择响应分类，预取与下载共享默认 512 MiB 缓冲和 128 个全局下载窗口。在“采集管理 → 下载资源”按 100～1000 台十档一键推荐容量，并可分别设置各类单响应、文件边界和磁盘资源；推荐只填容量草稿，不修改网站频率或任务代理开关，保存 MySQL 后正常重启生效。网站并发 0 跟随全局，正数收紧该站点；实际并发按健康独立出口 IP、网站保护、预算与剩余页数限制。文件可按契约流式写入临时文件，完整校验后不覆盖地发布。详见 [下载资源边界](download-resources.md)；没有因此新增公告业务、PDF 解析或 OCR，也未宣称真实 1000 出口吞吐已经验证。
- 有效响应校验和规范化后先入 Redis，游标与分页原子提交；入队立即唤醒归档器并每 60 秒恢复扫描，完整列表在一个 MySQL 事务中发布，随后确认和删除对应队列消息。
- MySQL 使用 stock、finance_news、trade_calendar 保存三类业务数据，collection_state 每项目一条已归档状态。Redis 摘要须通过版本结构、时间、格式和有效期校验，可信命中完全免 MySQL；其余回源时业务与状态同事务确认。股票 committed 仅为进度，不独立授权清队。不完整列表或失败事务不会替换当前列表。
- 三类业务查询插件只依赖 MySQL。Redis 不可用时，已归档股票、新闻和交易日历仍可浏览；独立的 `archive.confirmation` 及其采集、归档依赖链明确暂停，不伪造 Redis 临时核验状态。恢复 Redis 不重启查询插件。
- 数据集和任务改为内部白名单贡献：数据贡献声明身份、版本、归档模式和项目映射，任务贡献声明采集能力与界面元数据。控制器不再强依赖全部采集器；单个采集器停用只影响对应任务。MySQL 只集中校验核心表，各数据插件校验自己的业务表。详见 [插件贡献边界验收](plugin-contributions-review.md)。
- 股票整份批次在取得总数后、发布首条消息前预留全部剩余分页和完成标记的 Redis 入队容量；其他任务不能占用已预留槽位。成功发布才消耗预留，失败、取消及提前结束释放剩余额度，断点恢复重新计算剩余量。配置不可能完成时在首条消息前明确暂停，不再形成“归档等待 complete、采集等待归档释放”的条件死锁。详见 [整批入队容量验收](batch-capacity-admission-review.md)。
- 三类来源采集器共享小型组合式生命周期辅助能力：容量等待、入队重试、归档确认和诊断失败保护只有一条实现路径；股票、新闻、日历的业务分页与校验规则仍独立。入队、确认、记录、checkpoint 和三类运行结果具有 Protocol/TypedDict 契约，公共边界由严格 mypy 及拼错关键字负例检查。详见 [采集器契约验收](collector-contracts-review.md)。
- 全部后台只读界面请求通过公共 QueryScope 管理同步/异步失败、按键取消、页面销毁和最后成功时间。筛选、月份或项目变化立即取消旧读；不能取消的在途旧结果返回后按请求身份丢弃。刷新失败保留并明确标记旧数据，写入命令不随页面取消。页面工厂失败局部显示错误卡片并可重试，不影响桌面外壳。详见 [界面只读状态验收](ui-read-state-review.md)。
- 核心导航、搜索、筛选、表格、详情和状态具有稳定读屏名称；搜索统一支持 Ctrl+F，任务与网站规则通过原保存按钮支持 Ctrl+S。列表、表格、标签栏和主按钮具有可见键盘焦点，不以占位文字代替语义名称。自动验证通过 Qt QAccessible 接口读取实际名称；Narrator/NVDA 和 Windows 高对比度仍需人工核验。详见 [键盘与读屏语义验收](accessibility-review.md)。
- 键盘焦点采用条目级标记，不给整个列表、表格或标签栏添加蓝色外框；输入边界、未选复选框和滚动条滑块达到 3:1 项目对比度目标。Windows High Contrast 启用时启动过程不加载固定桌面配色，交由原生调色板渲染。具体颜色、自动计算和真机边界见 [焦点与非文本对比度验收](theme-contrast-review.md)。
- 工作台队列统一称为“待归档消息”，最近运行使用“采集记录数”；归档运行记录分别保存和展示已处理记录与业务写入记录。可信摘要、SQL 相同确认和旧版本确认属于成功处理但不冒充业务写入，统计缺失时显示“—”而不推断。详见 [归档统计口径验收](archive-count-semantics-review.md)。
- Windows 本地发布统一使用 `verify-release.ps1`：锁定环境后依次执行静态检查、完整隔离测试、四档 DPI 布局、打包和不连接业务服务的 EXE smoke。制品嵌入版本、commit、dirty 状态、依赖锁摘要及构建工具信息，并在运行状态页可识别；`build.ps1` 不再自动安装或容忍不同构建器。详见 [构建与发布门禁验收](release-gate-review.md)。
- 唯一依赖锁已为 41 个 Windows/CPython 3.12 wheel 绑定 SHA-256，新环境强制哈希安装。发布门禁生成依赖清单并把组件数、锁摘要和清单摘要绑定到制品；可选在线 PyPI 元数据逐包记录失败与覆盖局限。更新按 Qt、validation、database、network、Redis、build 和 test-quality 兼容组推进，不整体追新，详见 [依赖与供应链治理验收](dependency-governance-review.md)。
- 打包目录可整体搬移，运行时只从随包只读资源定位模板和 SQL，不依赖仓库父目录或当前工作目录；本机配置固定在 `%LOCALAPPDATA%\Empire\config.toml`，旧仓库配置仅显式迁移。发布门禁覆盖中文/空格非仓库目录、首次配置引导和再次校验，详见 [独立分发与配置路径验收](portable-distribution-review.md)。
- 说明文档具备发布契约：当前扫描 README、AGENTS、docs、deploy、SQL 变更记录和内置说明的本地链接，并把五张正式表、示例容量、用户配置路径及 MySQL/Redis 持久化边界设为可失败检查。脱敏发布基线纳入版本管理，详细截图和业务数据仍只留本机，详见 [文档契约与稳定证据验收](documentation-governance-review.md)。
- 发布门禁还会运行隔离容量基线：以生产代理池和 HTTP 路由覆盖 10/30/50/100 个虚拟独立出口、50 设备共享 10 出口、故障重试、429、取消及 1000 次上下线/取消，输出阶段延迟、吞吐、RSS、句柄和最终清理状态。该结果只证明确定性模拟模型，不代表真实 100 台、公开源站或数据库吞吐，详见 [隔离容量与资源稳定性验收](capacity-evidence-review.md)。
- 故障恢复具有单一维护手册和只读 MySQL 清单工具：源备份与隔离恢复库按五张正式表的结构、数量和内容摘要比对，恢复目标必须与源库不同且以 `_restore_drill` 结尾；工具不执行建库、删库或恢复生产。当前没有登记已验证备份，真实 RPO/RTO 不冒充已完成，详见 [故障恢复与隔离演练手册](recovery-runbook.md)。
- 桌面页面由外壳统一激活/停用：隐藏页停止全部子 QTimer 并取消只读查询，切回立即恢复；只读页最多缓存 8 个，淘汰后恢复筛选、稳定身份选择与滚动。采集任务、网站规则、运行记录和下载设置等编辑/写入页面常驻，切页不取消写命令或丢失草稿，详见 [页面生命周期与有界缓存验收](page-lifecycle-review.md)。
- Redis 中采集、归档、错误三类记录分别按项目保留 100、100、300 条。错误样本每条最多 64 KiB，统一脱敏；完整原文有完整长度/摘要，提前终止则标记未读完，完整长度/摘要未知，单列已读量与脱敏样本摘要。失败重试的错误同样保留，后续成功不自动清除。
- 运行记录页提供三个标签；修复并验证后可按选中 ID 精确清除错误，不影响操作期间的新错误。
- 错误记录页按 50 条分页读取无正文摘要，选择后才按 ID 读取一条完整详情；Redis 修订号未变化时轮询不重复传输列表。底层仍只有每项目一份有界错误 LIST，不新增 SQL 错误表或长期副本。

## 本次存储调整

旧的原始事件、SQL 隔离和多表股票快照结构改为当前 `stock` 业务表。结构调整由显式 SQL 执行，不是启动迁移或应用升级自动步骤。实际变更记录位于 `sql/changes`。切换时核验现有 5,566 条当前股票的身份字段一致。

临时完整性证据留在 Redis 同一业务队列。显式从头重新采集后，游标证明已被替代的旧不完整批次可以释放，并留下 `superseded` 归档记录；已完整有效但因数据库故障等待发布的数据不能据此删除。

## 当前边界

应用关闭后不采集，没有后台常驻服务。每日计划使用北京时间但不自动避开节假日。三类 Redis 记录是有界操作记录，不是长期审计数据库。Redis 已采用纯内存模式，服务或电脑重启会丢失待归档数据和控制状态。股票当前列表不支持历史任意时点股票池或可复现回测。

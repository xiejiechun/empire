# 当前实现与验证边界

已接入新浪沪深北股票列表、新浪 7×24 财经新闻和巨潮 A 股交易日历，具备统一执行计划、共享网站频控、断点恢复、结果浏览和系统诊断。公告、历史行情、选股、回测及券商功能尚未实现。

## 当前能力

- 十个桌面页面按工作台、数据中心、采集管理、系统管理组织。股票页支持市场筛选、搜索、分页和复制；交易日历支持按月查询并区分未采集；表单有未保存提示与撤销，刷新不覆盖输入。
- 任务支持手动、固定间隔和每日定时；同一任务不重叠，暂停保留断点。插件启用只提供能力，不自行触发采集。
- 同域名组共享 HTTP 请求间隔和 429 冷却，重试也经过频控；界面修改网站间隔作用于后续请求。
- 有效响应校验和规范化后先入 Redis，游标与分页原子提交；每 60 秒检查归档，完整列表在一个 MySQL 事务中发布，随后确认和删除对应队列消息。
- MySQL 使用 `stock` 保存当前股票列表、`finance_news` 保存历史新闻、`trade_calendar` 保存交易及休市日期。成功请求原文不持久保存，不累积历史完整股票列表；更新不完整或事务失败时当前列表继续可用。
- Redis 中采集、归档、错误三类记录分别按项目保留 100、100、300 条。错误原文样本每条最多 64 KiB，附原始长度、SHA-256、截断标记和脱敏信息。失败重试的错误同样保留，后续成功不自动清除。
- 运行记录页提供三个标签；修复并验证后可按选中 ID 精确清除错误，不影响操作期间的新错误。

## 本次存储调整

旧的原始事件、SQL 隔离和多表股票快照结构改为当前 `stock` 业务表。结构调整由显式 SQL 执行，不是启动迁移或应用升级自动步骤。实际变更记录位于 `sql/changes`。切换时核验现有 5,566 条当前股票的身份字段一致。

临时完整性证据留在 Redis 同一业务队列。显式从头重新采集后，游标证明已被替代的旧不完整批次可以释放，并留下 `superseded` 归档记录；已完整有效但因数据库故障等待发布的数据不能据此删除。

## 验证范围

自动测试覆盖字段和页边界校验、断点与计划恢复、单任务互斥、共享频控、MySQL 提交与 Redis 确认之间的故障恢复、不完整和旧批次处理、记录限量、脱敏、截断，以及精确错误清理的新记录保护。

界面回归覆盖分组导航、页面增减后的状态保留、异步旧查询丢弃、市场分页、草稿与保存时序保护、错误详情及修复确认。集成测试使用真实 Redis/MySQL 的专属命名空间和来源标识，只清理测试拥有的数据；不清空共享库。具体执行结果以本轮交付验证为准，本文不沿用旧架构的测试数量作为新架构验收结论。

## 当前边界

应用关闭后不采集，没有后台常驻服务。每日计划使用北京时间但不自动避开节假日。三类 Redis 记录是有界操作记录，不是长期审计数据库。Redis 已采用纯内存模式，服务或电脑重启会丢失待归档数据和控制状态。股票当前列表不支持历史任意时点股票池或可复现回测。

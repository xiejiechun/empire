# 重要股东持股变动（通达信）

## 如何查看

采集管理 → 采集任务选择“重要股东持股变动（通达信）”；数据浏览目录搜索同名项目。数据页按证券和变动截止日期查询，使用对应业务索引和稳定游标，每页最多200条，不加载全历史正文再切页。来源页面的数据日期实际为月份，不是公告日。

## 数据范围与更新

页面月份目录只有最近约14个月；2026-10-13核实接口可直接查询2025-08、2024-09、2020-01、2010-01。不能把页面最早选项2025-09当作接口历史起点。初始化按1990-01至当前月份核验完整响应（空月份也必须收到有效协议），日常重新核验同一范围以补缺和发现历史修订；每日北京时间18:00默认计划可编辑，保存后下一轮生效。历史起点1990-01是核查下限，不表示当时存在记录。

每个月请求一次，参数固定`["0","asc","YYYYMM","","1","1","10000"]`。10000容量边界、总数或列结构不符时失败，不以不稳定偏移分页拼凑完整集合。整月校验后按市场发布，继续后续下载，整轮入队后才等待归档。继续采集沿用已入队断点；重新初始化重建下载计划，待归档阶段先确认原轮次。Redis丢失后重新核验全部范围，相同内容由共享摘要/SQL确认，不重复写业务。

显式指定月份使用 `scripts/verify_shareholder_changes.py --start YYYY-MM-01 --end YYYY-MM-01`，相同起止月份就是一次指定数据月份采集。先正常关闭桌面，脚本调用已登记组件和统一归档器，结束后重新打开；不创建第二套采集路径。未完成断点与范围不同时须显式重新初始化，已入队数据继续按原流程归档。

日期参数必须是月份第一天 `YYYY-MM-01`；非法结束日期在发请求前明确报错。

指定月份完成只证明该范围；数据准备请求默认全历史时，单月完成不能替代1990核查下限至当前月份的连续覆盖证明。

开发和实采范围分别记录于本次evidence；支持范围不等于已归档范围。

## 字段与日期

| 来源字段 | 业务列 | 含义与类型 |
| --- | --- | --- |
| code/sc/name | unified_code/name | 沪深北证券身份、来源名称，VARCHAR(9/100) |
| 请求月份 | data_month | DATE，月份第一天；由T003所属月份验证 |
| T003 | change_end | 变动截止日期，DATE，必需 |
| T013 | change_start | 精确来源开始日期，VARCHAR(10)，YYYY-MM-DD或YYYY-MM，可空；月份不能补造具体日 |
| T004 | announcement_date | 来源公告日期，DATE，可空；可能晚于截止日及采集日 |
| T005 | actor | 变动人，VARCHAR(512)，必需 |
| T006 | price | 成交均价，DECIMAL(28,8)，元/股，可空 |
| T007 | shares_changed | 带符号变动股数，DECIMAL(28,8)，股；来源未知保留NULL并显示质量限制 |
| T008 | shares_after | 变动后持股，DECIMAL(28,8)，股，可空 |
| T009 | reason | 变动原因，VARCHAR(512)，可空 |
| T010/T011/T012 | leader/position/relationship | 领导人姓名、职务、与领导人关系，VARCHAR(512)，可空 |
| 完整响应重复次数 | occurrence | 相同来源事实的出现序号，SMALLINT UNSIGNED；保留合法并列记录 |

NULL保留未知，不填零。来源无稳定事件ID；完整月份/市场为原子替换单元，记录键由除名称外的规范事实及相同事实出现序号SHA-256构成。序号不是跨修订稳定ID。修订月删除已撤回事实并写新增/变化事实，未涉及月份保持历史；同内容零业务DML，旧观察版本不覆盖。

## 限制与排错

无公告日期或公告日期晚于观测时间的记录不能作为当时已知的选股信号；变动生效与公告可用时间分别解释。来源没有完整旧版本，不支持严格历史版本回放。相同条数不同集合、正文篡改、缺必需字段均不能通过完整性核验。错误与待归档数据沿用共享恢复和保留规则。

部分早期开始日期只精确到月，保存原精度；已核实2014-06有来源变动数量NULL，照实保存，范围内数量缺值使字段/质量检查不通过。采集完成仅证明完整来源集合已归档，不代表来源每条记录可直接用于计算。最早来源日期仍是来源声明，不对历史事实的正确性作跨来源裁定。

## 存储设计与维护

唯一正式业务表`shareholder_change`，固定来源tdx，不存整份JSON。主键record_key；月份市场核验使用(data_month,unified_code,record_key)，证券日期查询使用(unified_code,change_end,record_key)，全市场范围使用(change_end,unified_code,record_key)。列表有界201条、详情一条、月市场最大9999条；覆盖核对规范正文、业务键与collection_state同事务的计数/摘要/契约。SHA摘要命中完全免SQL，归档成功清队由统一归档器执行。

初步容量预算：100万条（按年20万、五年100万）表和索引<=2GiB、200条查询P95<=100ms、完整月市场归档<=5s、单入队消息<=512KiB；真实样本与隔离放大测量在交付证据登记。完整响应受共享通用正文预算，入队采用有上限的压缩矩阵，SQL仍为有类型列。

结构通过显式维护新增表，不启动迁移；维护前正常关闭Empire并核实队列为0、原业务数量，维护后逐表核对。已有目标表结构不同拒绝覆盖。恢复使用保留原表/程序配置，不删除其他业务或共享Redis。

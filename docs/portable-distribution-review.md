# P3-28 独立分发与配置路径验收

原验收日期：2026-09-27；2026-09-30 按用户要求改为程序目录配置，以下为现行规则。

## 正式路径

打包后的 `Empire` 目录是完整程序目录，可以整体复制到普通账户可读的任意 Windows 目录。程序不再通过 `Empire.exe` 的父目录猜测仓库根目录，也不从当前工作目录读取资源：Qt 图标、空白配置模板、SQL 初始结构和内置说明均随制品放入只读资源目录，运行时通过 PyInstaller 资源根定位。

连接配置固定为 `Empire.exe` 同目录 `config.toml`；源码运行使用项目根目录 `config.toml`。不依赖工作目录、快捷方式起始位置或 LOCALAPPDATA。以下其他本机状态仍位于 `%LOCALAPPDATA%\Empire`：

- `downloads`：未显式配置时的文件下载目录；
- `empire.log`、`empire.lock`、插件状态：日志、单实例锁和本机界面/插件状态。

`--config <绝对或相对路径>` 仍是显式维护、恢复演练和隔离环境的正式覆盖入口；运行时不搜索旧配置、不双写。相对 `http.download_directory` 以配置文件所在目录解析；迁移前核对，需要保留原下载位置时使用原位置绝对路径。本次不搬移数据库数据。

复制带配置的目录会同时复制密码，真实配置必须排除在 Git 和对外分发之外。`build.ps1` 重建前保存已有本机配置，完成或失败时恢复，不让 PyInstaller 清理掉配置；发布门禁暂存真实配置、用空白模板测试后恢复。

## 首次运行与迁移

默认配置不存在时，Empire 从随包空白模板创建程序目录 `config.toml`，随后停止并提示填写连接信息。目录不可写时明确报错，不悄悄回退用户目录；请将完整程序放在账户可写位置。双击无控制台版时以窗口显示错误；不会用空白默认值连接服务、创建表或自动迁移数据库。编辑完成后再次打开即可。

旧用户配置及旧版仓库内 `config/local.toml` 不再作为运行时兼容搜索路径。关闭 Empire，选定已核实旧文件后执行一次显式迁移：

```powershell
.\.venv\Scripts\python.exe scripts\migrate_program_config.py --source "旧配置绝对路径" --destination "D:\程序目录\config.toml"
```

维护入口必须显式选择来源，未传 destination 时默认项目根目录；校验后复制，目标相同则幂等成功、不同则拒绝覆盖。旧迁往用户目录的脚本退役。它不打印配置内容、不删除旧文件，也不连接 Redis/MySQL。旧文件仅作为历史副本，不再被运行时读取。

配置语法可在不连接 Redis/MySQL 的情况下检查：

```powershell
dist\Empire\Empire.exe check-config
dist\Empire\Empire.exe --config D:\isolated\config.toml check-config
```

## 自动验收

发布门禁在打包后把整个程序目录移动到 `build` 下带中文和空格的临时层级，暂存真实配置后执行 EXE smoke 和配置验证：首次启动在 EXE 同目录创建模板并以退出码 1 提示；第二次 `check-config` 成功。LOCALAPPDATA 只隔离用户状态，不改变配置位置。结束时恢复真实配置及程序目录，清理门禁自己的临时目录。

单元测试另覆盖资源根与 EXE 配置位置分离、工作目录和用户目录变化、首次配置只创建一次、相对下载目录解析、无效迁移拒绝及不同目标不覆盖。离屏 smoke 不代替真实服务连通和可见主窗口验证；该验收不是安装器、代码签名或跨机器连接保证。

# 新版桌面采集管理接入实施文档

日期：2026-10-29。原始实施计划；已开始首批源码接入，实际完成和未完成项以[接入记录](evidence/desktop-collection-integration-2026-10-29.md)为准，尚未完成新版EXE发布。

## 1. 目标与交付范围

先将现有采集能力接入新版 Electron + React + Ant Design 桌面管理界面，复用 Python Runtime、任务调度、下载、代理、身份、Redis 入队及统一归档。交付物是本地桌面程序，不部署网站、不开放业务 HTTP 端口。

界面沿用已认可的 V5：单层顶部导航、采集管理侧栏、平台→采集项两级树；任务详情保留“运行与记录 / 资源与身份 / 采集说明”，轮次卡片及事件详情抽屉。补齐功能，不再次整体改版。原始设计见[桌面设计稿](../work/desktop-redesign-react/DESIGN.md)，当前差异见[功能核对](../work/desktop-redesign-react/FEATURE-PARITY.md)。

首期必须覆盖：

|模块|首期交付|
|---|---|
|采集任务|完整动态任务目录、搜索/筛选、进度、执行计划、启动/继续/重采/暂停、批量操作|
|已归档任务|后台分页、保留配置和数据、归档及还原|
|运行与记录|任务内运行轮次、采集/归档/错误联合展示、跨任务查询、精确错误清理|
|站点与出口|独立出口IP和设备关系、站点使用情况、频控配置及冷却状态|
|共享下载资源|当前/已保存/草稿、容量推荐和校验、待重启提示|
|平台身份|动态平台列表、节点参数、申请/登录/当前操作、刷新及过期提示、服务启停|
|采集说明|真实任务专项范围、生命周期、限制、请求参数和存储去向|
|桌面基础|服务状态、插件不可用提示、单实例、正常关闭/重启、配置路径及本地打包|

不在首期重写采集算法、改造业务表、迁移历史数据、重做全部数据浏览/研究页面。未接入的数据页面明确标记，不能让预览报表成为正式查询入口。首期是采集管理交付，不能称全客户端迁移完成。

## 3. 架构、模块和依赖边界

```text
Empire.exe（Electron main）
  ├─ React 页面 → 有限 preload API → IPC 操作白名单
  └─ 隐藏启动 EmpireBackend.exe（stdio）
       └─ Runtime → 现有管理服务 → 原采集/下载/Redis/归档/MySQL
```

建议新增 `src/empire/desktop_bridge/`，按 transport、schemas、operations、queries、lifecycle 拆分；其职责仅为协议、序列化、受控映射及查询组合，不直接另写 SQL、Redis 或采集逻辑。复杂查询应扩展现有所属服务，由桥接调用。

正式前端建议置于 `desktop/`，保留预览目录作为设计参考。公共层拆分 main、preload、shared/contracts、renderer/features/collection、sites、exits、resources、identities 及公共表格/查询/命令状态。迁移可复用的V5组件，移除正式构建中的 fixture、DEMO记录和模拟成功提示；不复制预览业务状态作为第二套任务管理。

业务插件仍贡献任务及能力；UI插件贡献可序列化页面元数据，React静态注册表按受控view_key映射组件。任务ID来自后端，不能使用income等演示别名建立人工映射；前十大股东与流通股东等数据视图不能擅自注册为独立采集任务。后端未提供的能力显示不可用及原因。

### 4.1 传输与命令可靠性

- 使用UTF-8 JSON与Content-Length分帧，stdout仅协议，stderr仅有界脱敏诊断。首期建议单帧上限2 MiB、只读在途最多8个、命令待处理最多16个；溢出返回明确忙碌/过大错误，不无界堆积。错误详情单独按需读取。
- 请求包含request_id、session_id、operation、params；查询另含scope_id、generation。schema拒绝未知操作、非法任务/平台、超限分页及错误字段类型。
- 结果区分success、rejected、partial、unknown，保留后端真实保存结果。特别是MySQL保存成功但Redis同步失败，不能包装成“全部失败”诱导重复写入。
- 写命令增加operation_id，由应用级command store持有；切页不取消，重复点击不重复提交，同会话有界去重。命令接收不等于任务完成。
- 后端断线后结果未知，不自动重发写操作；查询真实计划/任务/归档状态后再展示。去重不承诺跨进程重启恰好一次。
- 首期优先可见页面有界轮询，无需先建设事件推送系统：任务/当前运行2秒，站点/出口5秒，身份10秒；每scope最多一个在途查询，隐藏暂停、命令结束立即刷新，失败退避到30秒。这些是UI刷新周期，不改变采集及基础设施周期。
- 请求取消仅作用于只读scope；迟到响应依据generation丢弃。页面销毁不取消写命令及SQL实际执行线程。轮询不读取原始响应全文或全量历史。
- 精确大整数使用字符串；时间传UTC时间戳并在界面明确北京时间；null为未知，不转换成零。

### 4.2 任务与配置

使用正式policy字段：enabled、mode、interval_seconds、daily_time、request_retries、use_proxy、proxy_fallback；archived由专用命令管理。固定间隔1～2592000秒，从任务结束后计时；重试0～100。前端校验提升体验，最终以后端校验为准。

草稿以真实task_id保存，后台刷新和旧保存回执不得覆盖新编辑；保存带本地draft_revision，回执只确认对应草稿版本。外部已保存值变化时显示冲突，用户可重新加载或明确提交当前草稿，不默默覆盖。首期不新增数据库配置版本列。

单次启动尊重enabled/archived/active；重新采集显示任务fresh_description，保留已归档数据。暂停同时停用后续计划。批量启动使用后端batch，启用所选任务并使用已保存配置，跳过运行中项目，保留草稿。还原沿用后端原计划/启停行为，不自动发起新一轮。

站点配置完整保留scaling_mode、proxy_interval_ms、min_interval_ms、total_interval_ms、max_concurrency、max_rps；三个间隔独立，不能随UI模式切换覆盖。429全站冷却不可被保存或切换出口绕过。资源草稿使用现行下载配置校验与推荐算法，active/saved分别显示，保存后只提供正常重启入口。

### 4.3 进度、轮次与统一事件

必须区分：计划停用、空闲、采集中、等待归档、完成、失败、来源缺口、服务不可用；“已停用”不抹去上一轮结果。完成单元数、总量、业务条数、页/批次各自有单位，未知总量显示已完成数量及不确定进度，不编造百分比。

只有本轮全部入队消息确认成功处理才显示完成；采集与归档继续独立推进，不新增逐页等待。redis_only显示Redis快照保存及不写MySQL；none显示无需归档，不伪造待归档数量。连续覆盖上界、失败单元、来源身份缺口和已采范围按现有字段呈现，不把开发验收当全量已完成。

运行卡片来自真实分页记录，不固定生成三轮。“本轮”没有运行则为空态；历史不存在不能补造。联合时间线优先用已有task_id、run/batch等稳定关联键；实施M0先建立字段对应表。缺失关联的历史记录单列“未关联记录”，不能仅按相近时间强行归入某轮。

如现有公共记录缺少必要关联，在共享运行上下文/记录生产入口统一补充新记录标识，限定Redis有界运行元数据，不建SQL逐轮表、不长期保留响应正文。旧记录不自动迁移或推断。相同时间以稳定记录ID排序；各来源分页完成前不可宣称全轮事件已加载。

### 4.4 身份与出口

平台与站点频控组不是同一个概念，身份平台列表来自catalog，出口按独立exit_ip聚合且允许展开设备。同IP设备不重复计为可用并发。展示在线数、独立IP、当前容量和最近10秒请求率；没有字段则显示未知，不从理论容量推断吞吐。

身份需分别展示申请状态、当前进行中操作、上一次已结束操作、登录结果、协议版本、创建参数来源和未知首次时间。读失败保留上一成功快照并标明时间/过期；刷新不触发登录或注册。服务启停影响同平台共享项目，后端确认结果前不切换成成功状态。禁止提供“失败后重新注册”捷径。

## 5. 桌面生命周期与安全边界

- 保留同一Python业务锁；Electron单实例锁仅负责聚焦窗口。新旧UI不得同时运行两套调度/归档后端，不删锁、不绕过锁。桥接使用原Runtime装配与插件启停偏好。
- EmpireBackend.exe与Empire.exe同目录；默认config.toml解析保持现行程序目录语义，源码为项目根目录。不得为迁移改成cwd/resources/LOCALAPPDATA，不透传数据库密码。默认缺失模板与显式--config缺失报错分别验证。
- 后端打包需支持stdio，现有console=False GUI包不能直接复用。Electron以shell:false及隐藏窗口启动；sandbox/contextIsolation启用、nodeIntegration关闭、CSP限制本地资源、禁止任意导航及远程代码。
- 握手区分进程就绪和服务就绪；依赖失败仍能看状态，不把Runtime.ready当数据库或调度全部可用。
- 正常关闭：拒绝新命令→取消只读→等待已接收写命令→原Runtime逆依赖收尾→等待线程/SQL及后端退出→释放锁→关闭外壳。超时显示真实阶段，不能强杀数据库或删除锁。
- renderer崩溃仅重建界面、重新读状态；stdin EOF走相同正常收尾。后端崩溃显示中断及未知命令结果，不静默重启并重放。Redis重启丢失临时状态的既有限制必须保留。

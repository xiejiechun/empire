# 同花顺当前行业与成分股票

## 范围与生命周期契约

独立项目 `ths-industries`，数据集 `industry.snapshot`，任务 `ths-industries-v1`，分类“证券基础”，来源“同花顺”。以用户指定的 thshy 行业目录及其成分股为范围，仅保存最新行业名称、编号、证券代码、名称和市场；不采历史归属、调入调出事件、行情或历史指数。

| 项目 | 契约 |
| --- | --- |
| 用途 | 当前行业筛选和估值分组；不能用当前成员还原历史行业或作当时已知信号 |
| 初始化边界 | 本轮取得的完整行业目录及每个行业全部成分股；目录有完整闭合结构，每行业以 page/1/size/1000 按六位代码升序取得单个完整响应 |
| 完整性单位 | 整个目录与全部成员为一个发布单元；校验目录键唯一、详情身份、单页结束标记、从 1 连续编号、1～999 行、代码严格递增及跨行业唯一；剩余分页、达到请求上限、等数量换键式重复、空响应及校验脚本均拒绝 |
| 初始化完成 | 完整单元通过公共入队器写 Redis，统一归档器提交或确认相同/旧版并成功清队后完成 |
| 后续起点 | 每轮重新读取一次目录及每行业一次完整响应；请求数为目录行业数 + 1，不追加小页或双读；网络失败仍复用公共有界重试 |
| 修订与删除 | 一次 SQL 事务替换当前集合，移除本来源已退出的成员/行业；相同业务内容不写业务 DML；不保存变化历史 |
| 旧响应规则 | 来源无修订编号；整轮开始绝对时间作为请求代次，较早请求不得覆盖较晚已确认整轮，不声称是源站原始版本 |
| 下载中断 | 完整单元入队前没有持久下载断点，下轮从目录重新获取；不会发布半份成员；内存仅有规范成员，不持久化成功原文 |
| 入队/提交后恢复 | 原消息由统一归档器重放，已有 awaiting_archive 断点只等整轮确认；Redis 存活时不重复下载已入队完整单元 |
| Redis 丢失 | SQL 最新完整集合仍可查询；下轮完整刷新，不承诺恢复内存核验时间或未入库数据 |
| 配置与操作 | 立即采集刷新最新集合；重新初始化也完整刷新，已经入队待归档的轮次先完成。任务频率和网络策略沿用公共配置 |
| 资源与请求 | 共享 ths 频控、代理、下载字节预算和有界重试；本地计算 v 校验值；完整响应采用现有 generic 响应预算，达到 1000 行即报错，不自行扩容或拆页重试 |
| 实际进度 | 开发支持范围与实际已归档完整集合分别验收；未完成一轮不宣称数据准备通过 |

## 保存与查看

源码入口：采集管理 → 采集任务 → 同花顺当前行业；数据浏览目录 → 同花顺当前行业。任务配置保存在 MySQL，下轮生效；数据准备独立检查字段、键集合、完整范围、质量、时效和当前用途限制。是否已发布到正式 EXE 以有日期的交付记录为准。

## 来源限制与故障处理

来源分页不是跨请求原子快照，整轮是在一段时间内的观察。源端校验、剩余分页或排序变化须失败并保留旧完整集合。没有稳定来源版本号，无法识别源站自己返回的旧缓存，核验时间不等于归属生效日期。日常刷新不保存历史变动。

结构维护必须通过显式脚本，应用不自动建表；维护前正常关闭 Empire 并核对队列和既有业务数据。具体开发、实采和发布结果另记有日期的 evidence，不以本文作为已完成证据。

完整响应返回空 m-pager，或明确 page_info=1/1；还必须有完整表格、对应行业身份、连续序号、唯一升序证券且少于 1000 行。若 size 参数未生效而仍有多页，或响应达到上限，失败并保留旧集合。若来源仍返回 upass 登录页，同样停止，不把登录页当空行业。

命令行 `python -m empire collect-industries` 显式启动本任务的采集插件及公共依赖，执行一轮后退出；不启动其他采集任务。

## 完整性证明更新

完整响应来源规则为契约 2，collection_state.contract_version=2，公共摘要命名空间为 ths_industries_v2。旧契约 1 的状态或摘要不能满足当前数据准备；结构和业务字段不变，重新采集完整集合后重建证明，不增加历史或启动迁移。升级前须正常退出并核对待归档为空；下载中没有分页断点，入队后的单消息恢复机制不变。

数据准备页面通过公共接口读取六项逐条证据；仅开发测试、归档证明和当前用途检查同时满足，才显示本项已验收。当前行业检查不能放行历史选股回测。

# 采集规则登记规范

## 用户入口与职责

“采集管理 → 采集任务”选择具体任务，在“运行详情、任务配置”旁打开“采集规则”。规则只读、可复制、可按章节定位；不请求来源，不启动任务，不保存配置。运行刷新不重置阅读位置，切换任务更新对应规则。计划范围与实际已归档范围分开，实际状态仍看运行详情和正式数据查询。

来源维护者负责规则准确性。唯一结构化登记为 `src/empire/plugins/collection/rules.json`，以正式任务ID为键；页面通过公共只读组件展示。生命周期和字段的详细说明复用程序内正文，不另建第二套采集执行逻辑。资源随包发布、重启生效，不存MySQL配置或Redis。

## 每个任务必须填写

1. **请求**：逐个列出必要目录、业务接口和明细接口，HTTP方法、用途、完整地址或动态路径模板。参数逐项给名称（位置数组用下标）、取值/默认值、生成或设置位置、业务含义。无参数明确说明；未公开协议位说明已核实用途及未知部分，不推测；不得登记账号、Cookie、签名或代理凭据。
2. **范围**：明确证券/市场范围、开始和结束规则、是否包含边界、时区、未来安排、来源最早能力与程序规划边界的区别。来源没有统一最早日期时写清楚按什么响应确定，不能编造日期。静态现状类标明无历史范围。
3. **初始化**：目录发现、分页/完整响应方式、校验单元、入队和最终完成边界。
4. **增量**：起点、补缺、修订回看范围、重查周期；全量重查型明确普通轮次仍全量，不笼统称只采新增。
5. **恢复**：普通继续与重新采集的差别，下载/入队/待归档中断，Redis保留或丢失的恢复依据及限制。
6. **存储**：准确job_key、dataset、Redis队列与字段、断点、摘要命名空间、SQL业务表和统一状态行。公共展示使用当前程序namespace和数据库名；不展示连接密码。复杂多表写清主表、明细和关联关系，字段与身份引用数据库参考。
7. **限制与依据**：来源窗口、缺失字段、旧版防覆盖、成功清队/失败留队；关联来源正文和实际实现路径。支持范围不作为采完证明。

任务配置只编辑现有正式配置项；来源固定参数和自动生成的日期不是新配置入口。来源发生变更时同步实现、规则和正文。尚未核实的语义必须说明，不以示例值冒充线上固定值。

## 已实施检查与验证

`scripts/documentation_contract.py` 的正式文档检查精确比对全部采集任务、job_key、dataset和摘要命名空间，检查规则必填项、参数结构、来源实现路径、SQL表和说明主题存在。新增或退役任务须同步登记，缺失或错配拒绝发布。结构检查不能代替来源语义审阅；请求参数专项回归与实际实现对照。

规则资源纳入源码及文档审阅摘要；逐任务规则正文纳入对应功能摘要。修改后按[说明文档维护](documentation-maintenance.md)执行显式review及文档检查；UI变更执行正式发布门禁、打包和真实桌面验收。规则显示不需真实请求来源，不能因此声称重做全市场采集验收。

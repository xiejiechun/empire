# 通达信九项采集优化

2026-11-05，用户授权九项全部实施。仅修改通达信采集与必要的归档证明、查询、说明和测试；不改用户计划、业务身份、生产结构，不清业务数据，不发送跨聊天消息。

## 生命周期与成本

初始化及明确重新采集仍校验全部声明范围；完整单元缺失/损坏必补。日常报告最近两年、持股变动最近三个月、解禁最近三个月及未来月份优先复查。近期单元按现有任务下次维护时间到期，手动缺省一天；历史按稳定身份分为90组轮转，并以90天最长核验年龄兜底。新证券及最新户数变化立即查历史，未变化户数最长30天复查。所有跳过均需SQL完整单元证明；可信统一摘要只能在内容摘要匹配时补充时间，Redis丢失回SQL，不靠最大日期代替集合。

财报和持股变动复用未到期单元数量/内容摘要组成完整范围清单，不刷新其核验时间。新增一个季度/月仅新增必要响应加到期回查；状态丢失按SQL证明恢复，不自动全池重采。无变化维护只有必要目录及到期完整响应，网络重试/字节实测记录；不承诺固定吞吐。

分红保留报告期批量正式来源路径。按报告期维护有界摘要证明（最多1000期），放现有collection_state的manifest扩展内，与最终清单同原归档路径提交，不新增表/索引或逐轮历史。维护仍进行一次有界SQL历史读取和内容核对（最多100000条、128MiB规范内容），下载必要报告期后合并历史，仅变化证券重新入队；本项减少网络及入队成本，不宣称已消除SQL历史读取。旧证明缺扩展时保守完整重建一次。报告期撤回不能误删其他历史；保留原有集合差异审计语义。新证券/历史目录未证明时完整核验。

解禁月列表与龙虎榜目录使用公共有界预取；需要后续明细时只保留有界规范目录，复用当前所有者额度顺序读明细，避免嵌套窗口等待。父目录占有预取额度期间不再嵌套第二个窗口，单证券的明细也顺序读取；目录层提速不等于所有场景吞吐提高。发布顺序及失败不越过原则不变。

停复牌、上市状态、解禁的未提交完整单元使用有界内存暂存（每采集器最多8MiB、最多10000项、30分钟），只存校验后的规范结果、原观察时间与范围身份，不存原始响应/新Redis键。到期、fresh、范围改变、完成或停用清理；重启丢失只增加重下成本，不改变SQL证明。整月/跨组最终校验失败清理材料，不发布半套。

业绩与解禁一次构造压缩正文，预算预检和正式发布复用；不同页码仅替换元数据。20项通达信任务接入现有measured_run，失败/取消也保留实际请求、重试和观察字节。

## 查询、完整性与迁移

业务表粒度、字段、查询、索引和容量上限沿现行字典；只扩展每项目一条collection_state的有界核验摘要，不存业务正文副本。分红扩展字段为按报告期键的count/digest/observed_at，原证券身份与manifest集合摘要继续核对；无DDL和启动迁移。冷证明回SQL、可信热摘要确认、同内容零业务DML、迟到旧版和提交后重放仍由统一归档实现。

分红最终manifest携带各报告期核验时间，每轮通过原归档器更新一条collection_state；不将观测时间加入业务指纹，也不以清单缓存命中跳过这些不同年龄的证明。证券业务单元继续使用统一指纹快径。该状态更新不是分红业务DML，旧清单不能覆盖较新的状态。

来源不再返回的旧方案仍保留，维护组合与证明计算覆盖当前证券最终保留的完整集合；历史目录要求本轮来源出现的键另行核对，不能拿库里旧记录冒充来源已返回。已经退出当前股票池的证券历史不删除，也不因缺少其当前证明而使整个当前股票池重采。父目录后的明细开始前非阻塞补足保留内容与最小响应额度，额度不足明确失败，避免与共享下载器的安全检查冲突。

时效按单元回查策略核验，不把新manifest时间冒充全部旧单元刚查过。历史修订最长90天（户数30天）发现；需立即全历史核验使用重新采集。个股融资融券全历史响应约定保留，仅接入成本统计。

## 验证与交付

覆盖无变化、新增、精确缺口、旧修订、同条数不同集合、坏/过期/异常超前证明、Redis丢失、范围变化及失败恢复；检查少请求且完整清队。预取验证乱序、取消、低缓冲无自等待，压缩次数验证每业务组一次。来源原始响应→规范化→私有Redis→SQL→正式查询集成，实采使用既有充分有界样本及代理优先共享下载。静态/文档/架构/定向发布门禁和真实桌面后记录实际证据；本方案不代表已完成。

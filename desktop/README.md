# 新版采集管理桌面 · 接入开发版

本目录已接入原有Python服务，任务与命令不是模拟数据。当前为源码接入版本，尚未替换dist/Empire正式程序，也未完成新版EXE发布门禁。原有设计预览仍在work/desktop-redesign-react，未删除或改为生产入口。

## 双击启动（本机）

双击 `dist/EmpireDesktop/Empire.exe`。这是Windows无控制台启动器，打开本项目新版Electron界面，依赖项目中的desktop、.venv和已安装Electron；不是可单独复制到另一电脑的完整安装包。

配置固定为该启动器同目录的config.toml，首次从原dist/Empire/config.toml原样复制，以显式--config传给后端；现有不同配置拒绝覆盖。启动工作目录不会改变配置位置。旧客户端与新版共用业务锁，请先正常退出旧客户端。原dist/Empire/Empire.exe及设计预览继续保留。

重建本机启动器使用 `python scripts/build_desktop_launcher.py --config-source dist/Empire/config.toml`，持有共享构建锁、检查原程序已退出、构建前端并执行启动参数与协议测试。此入口仅生成本机开发启动器，不替代完整独立程序的正式发布门禁。

## 启动与退出

在项目根目录安装Python开发依赖和Node依赖后：

```powershell
npm.cmd --prefix desktop ci
npm.cmd --prefix desktop run build
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
npm.cmd --prefix desktop start
```

源码后端使用项目`.venv/Scripts/python.exe`及项目根目录`config.toml`，启动会运行原有服务和已经保存的计划，不是只读诊断模式。Redis/MySQL密码不进入前端。真实验证前须正常退出旧Empire；若旧窗口或维护任务占用原业务锁，新后端明确报错，不能删锁重试。

通过窗口关闭或“正常退出”等待采集、归档和连接收尾。关闭中不再接受新命令，已接收写命令不会因切页取消；数据库故障可能让收尾等待，不强杀。恢复原客户端时先确认新版后端退出，再启动原EXE。现有预览无需关闭，因为它不连接生产后端。

## 日常操作

- 采集任务按真实平台和任务ID展示；搜索、状态/业务分类与分页均由后端处理。选中任务查看真实运行状态、专项说明与资源入口。
- 执行计划支持手动/固定间隔/每日；保存立即更新计划，重试与代理策略下一轮生效。编辑器关闭保留本次会话草稿，刷新不覆盖输入；Ctrl+F搜索，计划内Ctrl+S保存。
- 立即采集/继续与重新采集走同一个原有控制服务。重采前展示项目专项说明。暂停同时停用未来计划。批量启动启用所选并使用已保存配置，返回逐项成功/跳过/失败。
- 归档收起任务但不删业务数据；还原保留原计划和启停行为。
- 运行卡片与事件来自实际记录；未知单元数不补成100%。没有轮次关联的历史放在“未关联记录”，不根据相近时间拼接。
- 共享资源显示当前生效/已保存/草稿；容量推荐只生成草稿，保存后须正常重启。站点三个间隔独立保留。
- 身份页面只读刷新不认证；服务启停影响平台共享项目。读取失败会显示过期提示；凭据和代理连接串不传入界面。
- 任务内错误页只清除明确已修复并验证的确切ID；未解决及并发新增记录保留。
- 数据预览直接位于“采集管理 → 选择采集项 → 数据预览”，不再设置独立的数据浏览导航。按数据类型选择栏目及证券、日期等条件，支持翻页和完整记录详情；日期/月默认值直接显示。读取已有正式数据，不触发采集；盘中 Redis 快照与 MySQL 归档数据分别标识。空结果不代表已采齐，股票任务展示统一当前股票列表。

## 当前限制

仍复用原bootstrap（含Qt页面声明导入），尚未完成纯元数据UI装配及插件动态可见性迁移。55 个采集项目已接入任务内数据预览，其他研究分析页面尚未迁移；未退役设计预览或旧客户端页面。正式前后端联合构建身份、完整结果schema、发布打包、恢复包及全量端到端发布验收仍待后续阶段。

本轮未对真实任务执行手动重采、修改保存计划或清理错误；命令路径、去重、草稿竞争通过隔离测试，真实环境完成读取、互斥和正常关闭验证。正常启动原Runtime会恢复已保存计划，不能把整个启动过程称为“绝无业务写入”。

## 2026-10-29 预览设计还原

正式接入版沿用 V5 预览的单层顶栏、分组侧栏、平台→采集项目录、三张轮次卡片和统一事件表。跨任务记录从任务标题进入抽屉；站点规则从采集出口或任务的资源与身份进入。Ctrl+K 搜索功能，Ctrl+B 收起侧栏，右上角切换明暗主题；正常退出位于设置菜单。

最近一轮与历史轮次共用进度摘要，技术数据收在运行详情内。进度只使用真实完整单元数；历史缺少数量显示“—”。本轮入队量不等同于当前待归档量。原预览目录未修改。

## 2026-10-29 同花顺启动依赖修复

新版后台仍须初始化 QCoreApplication：同花顺请求校验使用本地 QJSEngine，Electron 只替换桌面窗口，不替代这项采集依赖。后台入口在 Runtime 启动前创建无界面的 Qt 核心应用，持有至全部采集线程退出。无需打开旧 Qt 窗口。

若历史轮次曾出现“同花顺请求校验需要已初始化的 Qt 应用”，正常退出并重新打开新版客户端后，使用立即采集沿原恢复规则执行。已失败的运行历史如实保留，不会改成成功。本次核实并按确切 ID 清理了资本运作 2 条、股东研究 1 条对应错误样本，其他错误保留。

## 2026-10-29 运行与记录重构

运行页改为单轮摘要、统一事件表及历史轮次选择器，移除三张重复轮次卡片。历史选择器读取仍保留的最多100轮；查看历史时可直接返回当前。轮次没有关联标识时不把所有任务事件冒充本轮，未关联记录仍独立切换查看。

左侧所有可见的运行任务均显示采集百分比，不再仅显示选中项。百分比以 completed_units（缺失时 processed_units）除以 total_units 计算；未知总量显示采集中，不伪造进度。百分比表示采集单元进度，100% 不代替本轮归档完成；等待归档在运行摘要明确显示。详情继续显示实际数量、处理单元和累计入队记录，技术诊断收在更多运行信息。

## 归档记录范围

运行与记录的“归档”显示当前采集项目保留的全部归档记录（跨轮次），同时显示完整日期时间、已处理数量及可用的实际写入数量。归档批次标识与采集运行标识不同，缺少明确映射的记录不强行归入当前轮次；采集与错误仍按所选轮次查看。每项目归档记录最多100条，Redis重启会丢失运行记录，已入库业务数据不受影响。

# Redis preparation-report

## 用途与归属

数据准备四项检查结果。PreparationCache 由数据准备服务写入，页面先读取完整报告；开发验收证据另行加载。目录现限定为回测、估值及证券策略因子；移出新闻、退市整理期、每日涨停价和跌停价，以及独立总/流通股本和自由流通股本规划，会改变目录契约和缓存身份，旧报告不能复用，按原七天期限自然过期，不删除业务数据或其他 Redis 键。总/流通股本复用日摘要，但行情检查通过不等于股本关系或任意估值输入已验收。

## 结构与身份

逐项证据可包含reason=source_limit与observed_at：分别说明来源用途限制和实际来源/归档证据时间。报告的checked_at只是执行时间。详情中的outcome区分未检查、检查失败、来源受限与通过，blocking仍独立决定本用途是否可用；完整性缺口不能改成非阻断限制。资本证券范围与停复牌只读时效规则升级后使用新cache_revision，旧报告自然到期，不清理共享键。

键模板：`<namespace>:preparation:report:<scope_digest>`

类型：**String / JSON**。

checked_at、scope、checking=false、checked_requirements/total_requirements、research、rows、cache_sha256 等完整报告；research为本次必需输入统计及研究条件，rows含required角色和来源集合状态；未选项目保留未核验；每份数据的四项业务检查共同保存，规范序列化校验摘要。最大 8 MiB。

研究模板版本3包含products具体产物及独立区间名义现金股息率；分红行关联同一结果，包含未检查/已计算/数据阻断/来源受限及功能未实现状态。已计算名义派息包含逐笔键、金额、范围、公式版本及实际证据时间；不存第二份长期业务数据。主题总检查不被独立产物通过覆盖。旧模板缓存自然过期；新范围、用途或契约使用新身份，重新检查重算，具体派息和股息率在缓存读取时重新核验当前输入，旧数值不直接复用；其余数据检查仍保留原时间，不刷新来源证据。

## 读写与关联

时效缓存核对前后使用同一栏目内容摘要，SQL并发修订时不把新内容的确认时间用于此前已审计的旧内容。

声明中的analysis_quality_limits和cache_revision参与缓存身份；持有人按证券证明及显式来源质量限制检查，旧规则结果不复用。缓存分别保留采集完整性、来源质量、用途条件和用途可用性；有限制不冒充来源正常，未知和真实缺口仍阻断。

键摘要绑定研究模板版本、study/focus/scan（用途、方向、全部或必需项）、所选范围、业务检查契约/cache_revision、相关查询是否可用及数据库范围。普通发布或无关插件变化不使所有业务缓存失效；重新检查覆盖本范围结果，未完成结果不缓存。

## 保留与恢复

SET EX=604800 秒（7 天），读取不续期；重新检查完成重新计时。软件重启可读，Redis 服务重启丢失后显示未核验并等待手动检查；结果为检查时快照，不是实时采集进度。

Empire Redis 采用纯内存模式。Redis 服务或电脑重启丢失本库内存值；只重启 Empire 且 Redis 仍运行不等于丢失。业务查询以 MySQL 为准，不能把本键当永久数据或备份。

## 维护与相关说明

实现归属：`features/preparation/cache.py`、`query.py`、`products.py`。查询诊断有界且脱敏；维护按确切项目/来源/ID执行，不清空共享 Redis。

[数据准备](help:数据准备)、[数据库职责与查阅](help:数据库职责与查阅)


检查范围新增index_codes列表，与股票codes分开；两者和日期、用途共同参与缓存身份，指数代码变动不能复用其他范围结果。七天缓存不承诺期间数据未变化，需要最新状态点击重新检查。

公司资本运作新增募集资金、募投项目、收购兼并、股权投资、参股IPO、股权转让、关联交易、质押、冻结九项独立结果；共享一次来源响应但分别核对栏目集合，缺解除不影响融资栏完整性。

公司资本运作采用规范数值零（-0.00归零）核对来源与SQL；原来源未知值仍为空，准备报告不补造数值。

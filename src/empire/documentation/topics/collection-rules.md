# 查看采集规则

## 入口与操作

进入“采集管理 → 采集任务”，选择任务后打开“采集说明”。默认只展示采集内容、时间范围、更新方式、Redis待归档键和MySQL业务表。键名可单独复制。断点、摘要、运行记录及配置位置放在“更多存储位置”；恢复细则和来源参数分别展开查看，不再默认展示大段JSON。旧桌面规则页保留章节阅读。说明只读，不发请求、不修改配置或编辑草稿。

## 如何理解范围和参数

每个接口列出方法、完整地址或路径模板、每个参数的取值来源与含义。固定协议位不是用户可调选项；未公开的内部含义明确标注。自动日期由任务计划生成；无统一历史起点的来源使用当前可见最早记录说明。初始化、普通增量、补缺、修订及重新采集分别说明，不能把全量复核误解为只采新增。声明范围与实际已归档进度分开，后者在运行详情和数据浏览核实。

## 存储与生效

规则显示当前配置的Redis命名空间和MySQL数据库名，不显示密码；分别列出Stream业务队列、envelope字段、job_key、dataset、Hash断点、摘要桶、业务表及collection_state状态行。远航五池另列盘中快照键：盘中只存Redis、不写MySQL，快照最多保留72小时且受容量限制；日终才按共享队列归档。多个任务共享队列并由统一归档器处理，成功或确认无需写入均清除对应消息，失败留队。断点不代表已归档。SQL字段、身份和关联见来源专项说明及数据库参考。

规则随程序发布，重启后生效，无需保存。任务执行和网络配置仍在“任务配置”保存到MySQL，网站频控与下载资源仍使用各自正式入口；规则页面不增加日期或接口参数编辑入口。Redis服务或电脑重启会丢失待归档消息及临时断点；规则说明自身不会替代恢复和范围验收。

## 缺失与维护

当前所有正式采集任务均登记规则。若显示规则不可用，检查程序发布资源；不要据此推断数据已经完整。新增任务、来源参数、生命周期或表归属变化须同步规则、来源正文和专项回归，正式文档门禁检查逐任务覆盖及登记一致性。自动结构检查不证明来源每个未知协议位已公开，也不证明历史采集已完成。

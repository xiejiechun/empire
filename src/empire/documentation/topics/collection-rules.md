# 查看采集规则

## 入口与操作

进入“采集管理 → 采集任务”，展开来源并选择具体任务，点击运行详情、任务配置旁的“采集规则”。通过顶部章节选择定位参数、范围、生命周期或存储去向，正文支持选择复制。切换任务更新规则，运行状态刷新保留当前阅读位置；任务配置的未保存草稿继续保留。规则只读，点击或阅读不会启动采集、访问源站或保存配置。

## 如何理解范围和参数

每个接口列出方法、完整地址或路径模板、每个参数的取值来源与含义。固定协议位不是用户可调选项；未公开的内部含义明确标注。自动日期由任务计划生成；无统一历史起点的来源使用当前可见最早记录说明。初始化、普通增量、补缺、修订及重新采集分别说明，不能把全量复核误解为只采新增。声明范围与实际已归档进度分开，后者在运行详情和数据浏览核实。

## 存储与生效

规则显示当前配置的Redis命名空间和MySQL数据库名，不显示密码；分别列出Stream业务队列、envelope字段、job_key、dataset、Hash断点、摘要桶、业务表及collection_state状态行。多个任务共享队列并由统一归档器处理，成功或确认无需写入均清除对应消息，失败留队。断点不代表已归档。SQL字段、身份和关联见来源专项说明及数据库参考。

规则随程序发布，重启后生效，无需保存。任务执行和网络配置仍在“任务配置”保存到MySQL，网站频控与下载资源仍使用各自正式入口；规则页面不增加日期或接口参数编辑入口。Redis服务或电脑重启会丢失待归档消息及临时断点；规则说明自身不会替代恢复和范围验收。

## 缺失与维护

当前所有正式采集任务均登记规则。若显示规则不可用，检查程序发布资源；不要据此推断数据已经完整。新增任务、来源参数、生命周期或表归属变化须同步规则、来源正文和专项回归，正式文档门禁检查逐任务覆盖及登记一致性。自动结构检查不证明来源每个未知协议位已公开，也不证明历史采集已完成。

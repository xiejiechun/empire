# 连接与容量参数

参数来自程序目录 `config.toml`，空白示例随程序发布；本文不展示实际密码。实际以配置和界面保存值为准。复制带配置的程序目录会同时复制凭据，对外分发必须排除真实配置。

| 参数 | 含义与默认值 |
| --- | --- |
| app.environment | 环境说明，隔离由 redis.namespace 决定。 |
| redis.host / redis.port | Redis 地址，默认 127.0.0.1 / 6379。 |
| redis.password | Redis 密码，可由 EMPIRE_REDIS_PASSWORD 覆盖。 |
| redis.db / redis.namespace | 逻辑库默认 0；键前缀默认 empire:dev。改前缀相当于使用另一套进度空间。 |
| redis.url | 可选连接 URL，优先于拆分参数，可能包含凭据。 |
| mysql.host / mysql.port | MySQL 地址；示例端口 3307，未配置时默认 3306。 |
| mysql.user / mysql.password | 认证用户及密码；密码可由 EMPIRE_MYSQL_PASSWORD 覆盖。 |
| mysql.database | 业务库名；启动不自动创建或迁移数据库。 |
| mysql.connect_timeout | 连接超时默认 5 秒；读写超时当前固定 20 秒。 |
| http.download_directory | 专用下载目录；默认用户数据目录 Empire/downloads，Windows 通常为 %LOCALAPPDATA%\Empire\downloads；显式配置建议绝对路径。 |

连接配置修改后重启。Redis 要求 noeviction，当前按用户要求关闭 AOF、自动 RDB 和日志输出；服务或电脑重启将丢失全部内存状态。MySQL 3307 已完成维护，binlog、普通查询、慢查询和错误日志输出关闭，旧日志已清理，见 sql/changes/2026-09-23-low-write.md。InnoDB redo/undo 保留，属于事务恢复所需文件。应用启动不修改服务全局设置。

## HTTP 下载资源契约

在“采集管理 → 下载资源”设置下列资源数值，保存到 MySQL 后正常重启软件生效。页面中的单响应以 KiB、缓冲和文件容量以 MiB 显示，数据库统一保存字节整数。网站频控决定请求节奏，资源上限决定大小与可持有的响应数量，不是下载速度限制。

| download payload 字段 | 默认值与用途 |
| --- | --- |
| planned_exit_devices | 默认 100；100、200 至 1000 共十档容量规划，不是当前在线数或独立 IP 数。 |
| max_parallel_downloads | 默认 128、最多 1024；全局在途下载安全阀及预取窗口上界。 |
| buffer_budget_bytes | 536870912（512 MiB），所有项目、直连及代理共享的下载缓冲预留预算，不是进程总内存上限。 |
| stock_response_bytes | 1048576（1024 KiB），股票单响应的传输与解压正文各自上限。 |
| news_response_bytes | 4194304（4096 KiB），新闻单响应的传输与解压正文各自上限。 |
| calendar_response_bytes | 262144（512 KiB），日历单响应的传输与解压正文各自上限。 |
| generic_response_bytes | 2097152（2048 KiB），通用内存响应上限；正式采集器使用自身响应分类。 |
| file_response_bytes | 268435456（256 MiB），文件传输与解压后的统一上限；插件可另外声明更严格值。 |
| download_quota_bytes | 2147483648（2048 MiB），下载目录占用与活动文件最大预留总量上限；不足则拒绝新文件，不删已有文件。 |
| disk_free_margin_bytes | 134217728（128 MiB），文件下载须保留的磁盘安全余量。 |
| file_concurrency | 默认 4，范围 1～64；文件下载仍遵守站点频控和缓冲预算。 |

保存时校验 `3 × 最大单响应上限 + 256 KiB ≤ buffer_budget_bytes`，保证每种内存响应至少能取得一份预留；同时要求 `file_response_bytes ≤ download_quota_bytes`。结构化响应按“三倍正文上限 + 256 KiB”预留缓冲，覆盖 bytearray 容量增长、组装副本和有界工作区；默认股票每页 3.25 MiB，128 个窗口共 416 MiB。缓冲预算不是进程总内存硬上限，也不会预先一次分配全部额度。发请求前取得额度，后页等待按序处理时继续占用，处理完、失败或取消才释放。额度暂时不足先消费前页，不算请求失败，也不能越页推进断点。

一键推荐将窗口按 128 的倍数向上取整。缓冲取“全部股票窗口预留×1.2”与“股票窗口预留加新闻/日历/通用各一份、文件并发工作区”中的较大值，再向上取整到 256 MiB。默认响应设置下，100/200/300/400/500/600/700/800/900/1000 台分别推荐窗口 128/256/384/512/512/640/768/896/1024/1024，缓冲 512/1024/1536/2048/2048/2560/3072/3584/4096/4096 MiB。自定义响应过大、推荐超过 4096 MiB 时拒绝生成，不暗中改小响应或窗口。推荐不会缩短网站每 IP 间隔，也不等于这些设备均在线或真实吞吐已验证。

大文件使用 FilePolicy，默认文件/传输上限 256 MiB，缓冲预留 256 KiB，流式写入专用临时文件。完整传输及插件声明的签名/可选摘要验证通过才发布；同名文件存在时不覆盖，目录不跟随符号链接或目录联接。目录扫描、配额准入、写入与发布在工作线程执行；准入/写入阶段取消等待实际操作结束后清理确切拥有的临时文件。发布提交点期间取消则等发布完成并返回文件结果，避免丢失已提交文件引用。异常退出遗留文件与已有文件仍计入目录配额，不自动扫删。未来公告业务应只将状态/文件引用放入 Redis，另行定义保留、恢复及 PDF 解析/OCR 限制；当前并未新增公告功能。

读取不单信 Content-Length，同时限制实际传输与解压正文，使用有界 gzip/deflate 解压；超限或不完整时终止，不隔离代理、不切换出口重复尝试同一超大正文。提前终止的错误原文明确标记不完整，仅保留有界脱敏样本、已读正文量与样本摘要。

## ingest 容量保护

| 参数 | 含义 |
| --- | --- |
| high_watermark / low_watermark | 共享 Redis 内存达到高水位暂停、低于低水位恢复；默认 0.70 / 0.50，要求 0 < low < high < 1。 |
| max_queue_entries | 本项目消息队列与所有未消耗整批预留的合计上限，默认 100000；达到上限暂停，不删除未归档消息。 |
| max_page_bytes | 单次入队消息正文限制及整批准入的每消息最坏预算，默认 262144，即 512 KiB。 |

股票取得总数后、发布 `start` 前一次预留 `start + 剩余分页 + complete` 的容量；断点恢复只预留剩余分页和 `complete`。普通新闻、日历及其他批次不能占用已经预留的槽位。消息成功写入 Stream 才消耗预留，发布失败、取消或提前结束释放未使用部分；同一任务不能重复预留。容量不足时在首条业务消息前显示暂停原因，不会先留下一个永远收不齐的批次。

预留只存在于当前进程，不写新 Redis key，也不替代正式 Stream 和断点。Empire 异常退出时内存预留消失，重启后按已有断点重新计算；已经入队的消息不因此删除。内存水位反映整个共享 Redis，预留是按正文上限做的准入估算，不是 Redis 物理内存担保；外部写入仍可能触发 Redis `noeviction` 或水位保护。本机配置可与默认值不同，容量参数重启后生效。`archive.index_max_entries` 必须不小于 `ingest.max_queue_entries`，否则启动拒绝该配置。

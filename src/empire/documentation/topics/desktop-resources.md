# 连接与资源

## 代理与采集出口

任务“执行计划”里可以设置“优先使用代理”和“代理不可用时允许回退直连”。通常保留当前设置；关闭回退后，代理不可用时不会自动改用直连。

“采集出口”用于查看当前出口情况。多个任务会共享站点访问限制，等待许可不一定是程序卡住。站点限流时不要反复重新采集。

## 平台身份

从任务“资源与身份”或侧栏“身份管理”查看平台身份和当前操作。身份服务可能由同平台多个任务共用，调整前注意影响范围。刷新页面只是读取状态，不会自动重新认证。

## 何时修改资源

“共享资源”只设置“同时下载数”和“下载临时内存上限”，同时展示当前生效值和已保存值。点击“保存设置”后，正常退出并重新打开才能生效；刷新不会覆盖正在编辑的数值。HTTP响应按实际大小申请共享额度，不再受原股票、新闻、日历或通用单响应限额限制；文件和磁盘保护仍保留。

下方显示正在下载数、缓冲预留额度和等待下载资源的数量。缓冲预留包括使用共享预算的计算输入与结果，不等于程序总内存；无资源排队也不代表没有网站限速或出口等待，这些原因在任务运行详情查看。通常保持现有设置，调高上限不保证提速。

同时下载数允许设为 1～4096，已有设置不会随 IP 数量自动提高。下方“当前有效下载窗口”表示本轮实际准入上限；归档积压、缓冲接近用满或后台响应变慢时会暂时收缩，压力解除后逐步恢复。页面显示收缩原因与等待准入数量，已保存的值保持不变。同站多个项目轮流取得准入机会；正在下载及完整单元收尾仍受既有资源和频控限制。

下方还显示后台解析与校验正在处理、等待的工作项，以及归档最近扫描的可处理消息和待补齐批次。工作项不等于股票或业务行数。扫描超过3秒会显示距上次扫描的时间并标注仅供参考；状态缺失或读取失败显示不可用，不能按零积压判断。可据此区分网络下载等待与后台处理等待。

持续存在可处理积压时，程序用最近成功归档速率估算下游能力，并在恢复下载窗口时预留约 25% 的处理余量。低负载时不把当前完成速度当作容量；临时估计会在长时间空闲或监测不可用后失效。此反馈用于控制积压，不能保证任意来源均达到相同吞吐。

多个大响应同时耗尽预算时，本次响应会明确报资源不足，释放额度并保留原采集进度；可降低同时下载数或提高内存上限后恢复，不会自动反复下载或写入半份数据。

站点访问规则可从侧栏“运行与配置 → 站点访问规则”弹出，也可从任务“资源与身份”进入。列表每5秒刷新，显示各站点最近10秒实际发起的请求总数（包含重试）及当前在途的并发请求数；两者都汇总同站点所有任务，累计请求数不等于同时并发数。没有请求显示0，统计缺失显示未知，读取失败会提示数据过期。关闭弹窗返回原页面。点击“编辑规则”修改，保存会影响同站点任务，不会解除来源要求的限流等待。

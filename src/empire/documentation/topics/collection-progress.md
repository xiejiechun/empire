# 采集进度与运行记录

## 四种数量分别看

| 状态 | 表示什么 |
| --- | --- |
| 下载 / 核验 | 响应已取得并检查；不等于入库 |
| 成功入队 | 规范数据与断点已原子写入 Redis |
| 归档处理 | MySQL 提交、确认相同或确认旧版本无需写入 |
| 业务写入 | 实际 INSERT / UPDATE / DELETE 数量；相同内容可以为零 |

整轮全部消息成功处理后才显示完成。采集各批入队后继续下载，不逐批等待归档；队列背压、隔离和频控仍可能等待。

“已结束（来源缺口）”表示本轮已检查至末尾，有效报告已确认归档，但存在已隔离且可定位的来源缺陷。任务与运行记录可单独筛选此状态，详情显示缺口证券/报告数、限制和补采位置。完整覆盖仍未成立，数据准备中的缺口继续保留；解析损坏、网络或归档失败仍显示失败，历史失败不改写。

## 统一运行详情

在“采集管理 → 采集任务”展开来源并选择具体任务，打开“运行详情”。运行中展示本轮状态、记录和当前位置；结束、失败或暂停后保留最近一轮已提供的统计。旧运行记录缺少统计时不会倒推补齐。记录数缺少统计时显示“暂无数量统计”，不能据此判断为零或没有采集。已保存计划、下次执行、最近开始与结束分别显示；自动计划在本轮结束后安排，仅手动或停用任务显示“未启用自动执行”。

业务进度按任务登记区分股票、指数、行业、股票日和月份，不统一写成证券。处理页数或批次数单列，不能与业务对象数相除：例如573个指数可能产生4,754个年度数据及确认批次；业务完成比例只使用插件明确提供的已处理指数数。停复牌的归档批次也不代表完成月份。只提供范围时显示“完成数未提供”，不伪造零分母或超过100%的业务进度。

详情顶部按钮分两行：立即/继续采集与暂停任务在第一行，重新采集与归档任务在第二行。归档任务是将任务移出日常列表并停止执行，保留配置、断点和业务数据，不是手动写入业务数据库。保存执行计划与撤销修改仍固定在任务配置页底部，切换任务保留未保存草稿。

进度条只表示已处理/入队比例；没有可信总数时使用等待动画，不虚构百分比。“归档确认”独立显示，达到 100% 不代表全部已经入库。完整错误按纯文本展示，可选中复制；数据质量与用途限制仍在“数据准备”查看。来源特有的连续进度、失败证券和暂无详情字段只在实际提供时出现。

## 增发送配进度

任务显示成功入队记录、核验证券、失败证券、连续进度及当前证券。前面失败但后面仍在入队时，连续进度可能为零；不能据此判断完全没采集。最早缺口保留，有缺口不能显示整轮完成。

## 记录如何查看

“采集管理 → 运行记录”按任务选择采集、归档或错误标签，支持后台分页。选择错误后才加载正文详情。采集、归档每项目各保留最近 100 条，错误 300 条，均只存 Redis，服务重启会丢失。

## 处理错误

先登记项目和错误 ID，修复并验证后只清除已解决的确切 ID，保留新错误及未解决项。查看记录或后来采集成功不表示旧错误已经修复。

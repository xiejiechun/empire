# 下载资源与生效时间

**入口：采集管理 → 下载资源。**

## 保存步骤

1. 查看“当前生效”和“已保存”的区别。
2. 仅调整同时下载数和下载缓冲上限。
3. 点击保存设置；单响应、文件和磁盘保护值保持原样。
4. 正常退出并重开 Empire，确认新值成为当前生效值。

配置保存于 MySQL app_setting，电脑重启保留；未保存草稿不保证跨重启恢复。当前请求和资源对象保持旧值直至正常关闭。

## 运行状态

页面显示当前正在下载数、共享缓冲预留额度及等待下载资源的数量，不再提供设备规划和容量推荐。无资源排队不代表没有网站频控或出口等待；任务运行详情继续展示这些原因。提高上限不保证加速。

下游归档积压、临时内存紧张或事件循环延迟偏高时，程序会暂时降低有效下载窗口；连续低水位后逐步恢复，已保存的上限不变。持续积压时根据最近成功归档速度估算处理能力，恢复窗口时预留约 25% 的处理余量；这是运行反馈估计，实际可持续速度仍以对应业务验收为准。未收齐的完整批继续保留补齐机会，正常重启后重新建立临时估计。

## 限制与校验

股票、新闻、日历及通用HTTP响应不再按分类设置固定大小上限。每个请求先预留256KiB工作区，随后按实际正文三倍加工作区增加额度；解压后的数据同样计入。预算不是Redis占用或整个程序内存上限。

新请求可等待初始额度；已持有正文的请求扩容时若共享额度不足，会释放本次资源并明确报错，不无限互等、不保存半份数据。可降低同时下载数或提高缓冲预算后按原进度恢复。文件仍须满足“单文件上限 ≤ 目录配额”，来源自身的结构和完整性规则继续执行。

文件下载默认单文件 256 MiB、并发 4、目录配额 2 GiB、磁盘余量 128 MiB；当前不因此新增公告或 PDF 业务。详细参数见 [连接与容量参数](help:连接与容量参数)。

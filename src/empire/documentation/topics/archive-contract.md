# 存储与归档规则

## 字段与规则

**MySQL 保存每项目一条 collection_state 已归档状态和业务表：`stock` 保留一份当前股票列表，`finance_news` 保留去重后的历史财经新闻，`trade_calendar` 保存交易和休市日期，`suspension_event` 保存沪深 A 股历史停复牌。另有 `dividend_plan`、`additional_issue`、`rights_issue` 保存增发送配，`income_statement`、`balance_statement`、`cashflow_statement` 保存三大财报，`industry`、`industry_member` 保存当前行业，`yuanhang_index` 保存远航当前指数目录，`ths_index_member_state`、`ths_index_member` 保存同花顺网页当前成分及暂无状态，`yuanhang_index_daily_price`、`yuanhang_index_price_year` 保存原生日K及年度证明，`stock_market_day` 保存七项独立证券日业务头，另有四种分钟事实、竞价序列、分笔类型化块、日摘要及盘口档位表。成功 HTTP 请求原文不持久保存。**

有效响应解析、校验和规范化后，业务消息先进入 Redis 并立即唤醒归档器；归档器每 60 秒恢复扫描可归档批次。新数据提交 MySQL 后、确认 MySQL 已有相同内容后（含可信摘要命中）、或确认消息过时后，均确认并删除对应 Redis 消息。SQL 或后续 Redis 操作失败时保留消息重试；不完整批次继续留在 Redis，旧股票列表仍可查询。

仍只有一个统一归档协调器。不同项目仅在显式审阅的完整业务表组、项目状态和摘要范围互不冲突时并行；未声明或声明与正式登记不符时独占执行，同项目按原顺序处理。新闻、交易月历、财报证券和资本运作证券的独立完整单元可有界合批，最多 16 条、4 MiB 规范内容或 10000 行，先到者分批；一个超出批目标的合法完整单元单独处理。批内重复业务身份另起一批，最终范围证明单独处理。批内 SQL 任一成员失败则整体回滚，所有未确认消息保留；事务成功后才更新摘要、记录、进度并合并精确 ACK。可信摘要热命中包含 collection_state 在内完全免 SQL。

已声明的财报、资本运作纯计算可由有界进程执行，仍使用相同的校验和摘要规则，按原顺序消费结果；归档复用已读消息原文并核对计算返回的消息身份，大单元在索引阶段只读取通过外层字段及正文对象形状校验的元数据，原文进入计算进程后继续完成全部 Envelope、内容身份和业务校验。完整规范行以本机进程产生的无损二进制块返回，仅需 SQL 核对时在父进程展开，热命中仍完成全部业务校验与完整行传输。二进制块不从网络或 Redis 直接反序列化。执行中及等待发布/归档的输入与结果计入共享预算。资源不足或进程崩溃不推进断点、不丢待归档消息；取消等待真实计算结束后才释放额度。

归档统一使用 SHA-256 业务内容摘要：股票比较整份列表，新闻比较每个新闻 ID，日历比较整月，停复牌比较每个事件及连续日期覆盖段。缓存命中免业务查库；缺失、过期或不同则查询 MySQL，不存在才插入，相同不更新，有效修订才更新，旧版本不覆盖。缓存仅保留摘要与版本，不能在入库前写入。手工修改/删除 SQL 数据前，须停止归档并清除对应来源的摘要及到期索引；重新采集使用新批次。摘要不会保留整份业务数据。

归档协调最多保留四个可并行阶段，SQL 事务使用独立的一线程、一连接通道；查询和配置通道独立。规范化的一波结果会全部保留再按批量目标拆分，超出批目标的尾部不丢弃、不在下轮重复计算。资本运作页面的纯解析也使用同一计算通道和预算，独立证券可并行解析，按原顺序消费，取消等待真实计算结束。

三类记录分开，只留 Redis，不进入业务队列，不写入 MySQL：

| 记录 | 保留规则 |
| --- | --- |
| 采集记录 | 每个采集项目独立保留最近 100 条 |
| 归档记录 | 每个采集项目独立保留最近 100 条，独立于采集记录 |
| 错误记录 | 每个项目最近 300 条；每条脱敏样本最多 64 KiB；完整读取才提供原文完整长度/摘要，提前终止显示未知 |

任务设置、网站频控与下载资源设置保存于 MySQL app_setting；必要断点、执行时间和频控运行状态留在 Redis 内存中。只重启应用可续跑；Redis 服务或电脑重启会丢失未归档数据、断点、下次执行时间和记录，但不会丢失已保存配置。Redis 已关闭 AOF 和自动快照，没有关系型“表”，这里使用 String、Hash、Stream 和 LIST；键前缀由 `redis.namespace` 指定，通常为 `empire:dev`。

应用升级不自动迁移、重建或搬运数据库。结构调整需要显式执行针对性 SQL，保留当前业务数据并记录实际变更。不要清空共享 Redis 或删除其他项目数据。

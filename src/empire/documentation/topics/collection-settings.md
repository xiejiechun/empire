# 归档与采集参数

## archive

| 参数 | 用途 |
| --- | --- |
| interval_seconds | 归档器恢复扫描周期 60 秒；正常入队会即时唤醒，只处理规范化业务数据，不处理三类运行和错误记录。 |
| batch_size | 单次 Redis 扫描读取条数，默认 100，不是股票总数；完整列表的 SQL 事务不能按此值拆开。 |
| scan_max_messages | 每轮最多发现 500 条消息，达到后续轮从原位置继续，不从队首反复扫描。 |
| scan_max_bytes | 每轮 Redis 返回的消息数据最多 8388608 字节（8 MiB）；超出单条预算的消息保留并报错，不跳过或裁剪。 |
| scan_time_ms | 每轮扫描时间预算默认 50 毫秒，在 Redis 读取窗口之间检查，不是网络超时。 |
| work_max_units | 每轮最多处理 32 个业务单元；新闻一页、日历一月或股票一个完整列表各算一个，按项目轮转。 |
| work_time_ms | 每轮处理时间预算默认 50 毫秒，在业务单元之间检查；不会中断正在执行的 SQL 事务。 |
| index_max_entries | 内存调度索引最多保存 100000 个 Stream ID，不保存全队列正文；应与入队容量配套。达到上限先处理可归档页，无可释放项目则报错留队。 |
| fingerprint_ttl_seconds | 摘要最后成功确认后有效期，默认 604800 秒（7 天），范围 1～31536000；过期回 MySQL 核对。 |
| fingerprint_max_entries | 每数据集/来源摘要业务键上限，默认 10000，范围 1～100000；超限淘汰摘要，不丢待归档数据。 |

启动恢复积压；不完整批次等待后续页面。事务提交前失败保留队列，并写 Redis 归档失败记录，不把有效业务数据复制为错误样本；提交后确认失败允许重放，当前发布身份阻止旧数据覆盖新列表。旧参数 claim_idle_ms、max_batch_bytes 已不再使用。

入队立即唤醒；一轮预算用完会继续下一轮，不等待 60 秒扫描。未完成股票仅保留有界 ID 索引，不在每次唤醒时重读全批次；完成标记、新批次或恢复检查触发重核。扫描完整边界通过后才判断股票缺页，不能把“下一轮才读取的页”误当成缺页。未知 schema 按已登记的数据集与任务归属隔离项目，消息原位保留；归属不明仍全局暂停。单项目归档失败保留消息，后台延后约 5 秒重试，其他已发现的项目仍可处理。

“立即归档”执行一轮并唤醒后续处理，不代表整个队列已清空；以待归档数量和项目归档记录确认结果。以上时间/字节预算不等于整个进程内存上限，也不承诺把一个完整股票事务拆成 50 毫秒。

明确从头重新采集后，可在游标证明新批次已替代旧批次时释放旧不完整临时页，留下 superseded 归档记录；完整有效但尚未成功写入 MySQL 的数据不会被此规则清除。

## sina_universe

`page_size` 为股票接口每页数量，1～80，默认 80。修改后重启；如果与未完成断点不一致，需要明确从头重新采集。

## sina_news

每页固定 50 条，首次只加载第一页；之后接上上轮 ID 就停止翻页。旧 `refresh_pages` 参数已取消。执行频率在采集任务统一设置，最短 1 秒，共享 HTTP 请求间隔仍由站点访问规则管理。

本机直连、代理、代理回退、重试与重定向使用同一个 HTTP routing 入口和站点冷却，不因当前没有可用代理而切换到另一套限流实现。采集任务读取全部匹配任务及每任务一条最近记录，站点和历史页面读取有界分页工作区；网站规则按完整策略保存，不接受旧整数间隔入口。

## rate_groups.<组名>

| 参数 | 用途 |
| --- | --- |
| domains | 域名后缀列表，如 sina.com.cn 包含根域及所有子域名；修改后重启。 |
| min_interval_ms | 同组请求最小间隔，默认 2000 毫秒；界面保存的 MySQL 覆盖值优先。 |
| max_concurrency | 0 跟随当前生效的全局下载窗口，1～1024 为更严格的同组并发安全阀；在站点访问规则保存后作用于后续请求。自动模式还受健康独立出口 IP 数约束。共享许可时间保存在 Redis。 |

分页、重试和重定向都经过共享频控。HTTP 429 触发整组冷却，修改间隔不清除冷却。HTTP 接口默认总时限按重试预算计算：120＋max(0, 重试次数－2)×60秒，单次退避最多30秒；显式时限优先，最多5次重定向。

执行计划和请求重试次数由采集任务页管理。任务执行间隔是“多久采集一次”，网站请求间隔是“一次采集中请求多快”，两者独立。

# 采集出口与频控

## 在线目录与协议

独立 `infra.proxy_pool` 插件提供 `proxy.pool`，共享 HTTP 插件在每次重试或重定向前重新申请出口与许可。原有来源插件无需分别实现代理逻辑。后台每 5 秒刷新目录，代理分配前还会重新核实。

目录来自同一个 Redis 数据库：`router:proxies:by-code` 的 field 是设备编号，value 是包含 `code`、`proxy`、`exit_ip` 的 JSON；`router:proxies:device` 以相同 JSON 原文为 member、过期 Unix 时间为 score。通过 Redis TIME 原子核实两者，仅采用映射存在且租约未过期的设备。Empire 对这两个 key 只读。

连接值支持 `http://`、`https://`、`socks5://` 和 `socks5h://` 前缀，按声明的协议和端口使用。目录必须是包含 code、proxy、exit_ip 的 JSON；其中 proxy 未声明协议时按生产者契约使用 SOCKS5H，原始凭据按字面编码。显式 URL 按声明协议处理。完整 URL 中已编码的凭据不会再次编码；原始凭据只在连接内存中使用，不进入页面、日志、SQL 或运行记录。一个 Hash 字段只能声明一个入口，不根据端口差值猜测其他协议。

## 配置与生效

| 配置 | 作用与默认行为 |
| --- | --- |
| policy.use_proxy | 按任务启用代理，缺省为 true（代理优先）；保留显式保存的选择 |
| policy.proxy_fallback | 代理不可用时允许直连，默认为 true，仅在 use_proxy 开启时使用 |
| min_interval_ms / proxy_interval_ms | 分别限制本机直连和每个出口 IP 对同站点的请求间隔；同出口多个设备共享代理间隔 |
| scaling_mode | auto 按健康出口 IP 数扩展，fixed 执行固定限速；旧配置默认为 fixed |
| total_interval_ms | 仅固定模式使用的全站合计间隔；自动模式不使用此限制 |
| max_rps | 可选全站每秒保护，0 表示不额外限制，1～100 表示启用；不是源站承载量声明 |
| max_concurrency | 0 跟随全局下载窗口，1～1024 为更严格的站点在途请求安全阀；不能放大全局窗口，自动模式也受健康独立出口 IP 数约束 |

任务与网站设置都保存在 MySQL app_setting，无需新增表或自动迁移。任务的代理策略在下一轮生效；网站参数在后续申请许可时生效。下调并发时，已发出的请求正常完成，不再追加超过新上限的请求。

## 频控和故障处理

设备优先按实际请求次数、再按最近分配时间轮换，避免未取得许可的分配消耗公平轮次；各站独立使用出口槽，同网站跨任务按出口 IP 共享一个在途槽及间隔。同一设备可同时访问不同站点，例如7个健康独立出口可分别支持THS和开盘啦各最多7个在途请求；所有站点合计仍受全局下载窗口及缓冲限制。设备正在请求数是跨站合计，可大于1。自动模式只保留每出口许可及显式全站保护，理论容量不作为额外合计间隔。固定模式保留网站合计间隔。许可由 Redis 原子检查，直连使用原有网站许可键并保留旧等待和冷却。

传输或代理认证失败时，隔离该设备 10 秒起、指数延长至最多 120 秒；共享下载器立即重新申请其他设备，不消耗来源/直连的普通重试次数。同一请求排除已失败设备，即使其隔离到期或重新上线也不重复尝试；最多尝试 1000 个设备，且等待、切换、重试和重定向共用按重试预算计算的总时限，默认2次重试为120秒，100次为6000秒。没有剩余可用设备时按任务策略回退直连，仅代理模式报错并保留断点；代理忙或频控等待不会触发回退。直连失败、来源服务错误及正文不完整继续按原重试预算处理。回退后不会关闭任务的代理选项，后续请求发现设备恢复会再次优先使用代理。移除或凭据变化时，旧连接不再分配，已在途请求结束后关闭旧客户端。

收到 429 后冷却整个网站组，包含所有代理和本机直连，遵守 Retry-After。403 不触发自动换 IP 重试。一次请求包含等待、重试和重定向的总期限默认为120＋max(0, 重试次数－2)×60秒，显式时限优先；不允许回退且代理长期不可用时，本次请求超时，任务保留已有断点，等待下一轮计划或手动继续。

目录的 `exit_ip` 是公网出口身份。多个设备声明相同 `exit_ip` 时，Empire 自动归并其同站点频控；设备编号仅用于连接选择和故障隔离。

新浪股票在代理模式下可同时下载多页，受当前健康独立出口 IP、全局/站点窗口、字节预算和剩余页数共同限制，全局默认 128、最多 1024。按页号校验并提交断点，后页先返回也不能越过失败页。同花顺财报与上市资料按证券、行业按成员响应、通达信分红按报告期（未证实历史的证券另做日期发现）、停复牌与上市状态按日期、巨潮按月份、增发详情按需要的方案 ID 使用相同共享预取。业务校验、入队及断点仍按原顺序，失败不跳过。新浪新闻下一页依赖前页 ID，配股及更名一次完整响应，保留单页/单响应窗口，不人为多读。任务取消会回收全部预取请求和缓冲额度；预取但未提交的结果在继续采集时重新下载。股票完成记录分别显示下载校验与归档确认耗时，不能把归档确认算作网络耗时；原有完整性校验和归档成功清理规则保持生效。

最近 10 秒请求/秒是该站点实际发起请求数除以 10，包含重试，不表示成功入库率。任务网络区以证券、日、月、行业或方案显示预取窗口及待处理结果；可用并发只是站点上限，不代表每个任务正在使用同样多的请求。已保存计划、代理选择和限速优先，更新程序后正常重启生效，无需重置配置或清理断点。

## 运行数据与保密

`<namespace>:rate:<网站组>:total` 保存总许可时间，`<namespace>:rate:<网站组>:proxy:<出口身份摘要>` 保存该出口的网站许可并在一天不使用后到期；出口身份统一采用 exit_ip。网站键保存直连许可和全组冷却。连接池及故障隔离只在本次进程内保存，页面只展示无凭据入口地址。

节点在线由 RouterProxy 维护，Empire 不另外主动探测。等待分配时合并目录刷新，实际分配前仍核实映射及租约。页面“目录在线”只表示生产者目录中的在线记录；“请求失败冷却”表示 Empire 正在暂缓该连接的重试。

采集历史的 network 字段仅保存 proxy_requests、direct_requests、fallback_requests 计数。网站统计为本次 HTTP 插件运行期间的尝试数；包含成功、失败、重试和重定向。错误样本仍按每项目 300 条处理，不将代理密码保存为错误原因。

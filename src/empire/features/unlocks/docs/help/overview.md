# 大小非解禁个股与明细

## 如何查看

一个采集任务负责列表发现及对应股东明细，不能把只下载列表当作业务完成。数据目录搜索“大小非解禁”；按证券及解禁日期查询，查看股东名称、解禁原因及数量。

点击列表中的“查看对应共享股东明细”展开该请求组。重新查询或翻页会清除旧列表链接及已选明细，相同筛选刷新后保留列表滚动位置；返回页面后需从当前列表重新选择，空查询不会继续展示上一次股东内容。

在“采集管理 → 采集任务”搜索“大小非解禁”，可立即采集、继续未完成轮次或重新采集。默认推荐每天北京时间18:00；首次历史请求较多，默认停用，可在任务配置中启用。保存到MySQL，重启保留；网络/计划设置下一轮生效，已保存选择优先。默认代理优先且允许不可用时回退直连。


## 数据范围与更新

列表模式0、明细模式1共用`tdxsj_cgbd_dxfgg`接口，生命周期相同，注册一个采集插件。两张业务表分别保存事件汇总和股东原子明细，不能按接口数量机械拆成两个任务。

列表页容量参数10000000已在2020～2025范围实测：返回14836条；10000只返回10000条。该参数不是内存预算，也不是来源总数保证。正式下载仍由共享下载器限制实际字节，按月份完整响应拆分；不采用非唯一日期排序的偏移分页。列表Count必须等于实际返回行数；第三结果集count不是可靠的全月总数，历史月份可返回0或小于正文的正数（1999-11为1而正文14条）。完整性依据整月一次请求、远高于单月10000条准入上限的10000000容量、响应结构及业务键集合；辅助count大于实际行数仍按截断拒绝。不能把较小count解释为无数据或丢弃其余来源记录。

初始化核验1990-01至下一自然年12月，包括有效空月；支持显式指定月份范围。2026-10-14来源核实在1996-05有记录，核查下限不是来源保证的最早历史。将每月列表与每个必要明细均校验、统一入队后，整轮等待归档成功及无消息残留才算完成。失败保留前序已入队进度，不跳过缺明细。

日常每天18:00重新检查历史及声明未来范围的列表；列表变化、缺少现行证明或明细空缺时补采。未变列表不每天重读全部股东正文；每轮轮换回查一个历史月份以发现列表不能反映的明细修订，重新初始化明确回查全部。未轮到的历史明细独立修订有发现延迟，不承诺完整旧版本回放。

仅重启Empire且Redis存活沿已入队断点继续；Redis丢失从SQL业务及现行完整单元证明重建计划，队列丢失不承诺恢复。范围改变须显式重新初始化，已入队旧批次仍由统一归档消费。

## 字段与日期

列表保留每条来源事实；明细请求粒度为证券、解禁日期及来源原因代码。实测该组合可对应多条不同数量的列表事实，不能按组合去重列表，也不能把共享明细复制给每条列表事实。两者通过请求group_key关联，列表事实另有record_key及出现次数；来源没有字段可裁定每条明细属于哪一条并列列表事实。请求关联字段必须保存。解禁日期是来源计划/生效日期，不等于公告可用日期。来源未给公告时间，不能据此证明事件在历史某日已经公开。

汇总和明细jjsl原单位万股，转为股用精确十进制乘10000；总股本T010也是万股，作为来源提供的比例基数保留，不假定是解禁当日总股本。来源百分比按数量/基数计算，不另存重复比例。行业及名称是来源当次返回值，不代表历史名称/行业版本。名称、行业和总股本基数为可选，缺失名称不阻断普通分析；解禁数量未知仍独立报告质量限制。列表身份不包含这些可修订的名称、行业及总股本字段；同组同原因同数量出现多次用出现序号保留。

## 限制与排错

有效空列表、有效空明细、未请求及请求失败分别表示。列表存在但来源明细为空时保留来源空状态及汇总，数据准备不能把缺少股东内容判成齐全；下轮复查。列表与明细通过共享请求组关联，同组并列列表的明细只显示一份，不按列表行数倍乘。来源舍入可能使明细数量合计与汇总有小差异，不用填零或篡改来源量解决。

# 通达信个股龙虎榜

## 如何查看

在“数据浏览”的可搜索目录打开“个股龙虎榜”，输入六位代码、统一代码或前缀，按日期范围查询；每页最多200个证券日期，选择一行查看原因及席位。表格选择与未提交筛选草稿独立保存；刷新不改输入草稿。“管理采集”定位对应任务。

## 数据范围与更新

“采集管理 → 采集任务 → 通达信 → 个股龙虎榜”首次采集当前A股池及本业务已有历史代码的全部来源日期，无人为最早年限。默认每天北京时间19:30，任务不重叠；计划保存到MySQL，软件关闭期间不执行，按公共每日计划处理漏跑。

每轮请求每只证券完整日期目录，立即补新日期（包含旧日期新增）及待采日期。最近7个自然日每天复查；第8～90日分7组、90日外来源缺失日期分30组，每天各查一组。相同证券日期稳定分组，30日为固定周期而非自然月。来源空值及部分缺失标记保持。更早已完整日期的独立修订须重新采集或显式指定范围重查。“重新采集”强制重查全部来源历史，保留旧历史；目录不再列出的历史标记已退出目录。

停机错过的组在恢复后的7/30日周期内轮到；每天运行且来源请求成功时，较旧详情修订最长相应延迟7/30天。跨日续采固定本轮启动日的组；同日重跑仍查同一组。升级遇旧未完成策略断点会明确拒绝，先以旧版本完成或显式重新采集。

失败不推进该日期；Redis仍在时按证券位置及目录摘要续跑。本轮截止日固定，跨日恢复时先按实际请求日验证完整目录的身份、排序、重复及未来日期，再取不晚于本轮截止日的集合；较新公布日期留给下一轮，不触发旧轮目录冲突。截止日以内目录确有修订仍要求重新初始化。Redis重启丢失临时断点和未归档消息，重新目录并按SQL日头补缺；不能恢复已丢失消息。各日期入队后继续下载，仅整轮结束等待全部成功归档才显示完成。

## 字段与日期

金额为万元，价格为元，涨跌幅为百分数。成交量来源仅标“万”，不猜测手或股。汇总准备必需成交量、成交额、收盘价和涨跌幅；席位准备必需对应方向的买入或卖出金额，反方向可空。NULL显示“来源未提供”，不是零；净额保留来源披露值。单日与多日榜按原因分别展示，不跨榜重复相加；原因代码相同的来源并列行仍保留。

买卖方向、排名及同名“机构专用”分别保存。来源允许不同席位并列排名（例如卖出第1名出现两次），按完整规范内容稳定排序分别保留；完整内容重复仍报错，不靠去重掩盖遗漏。合计仅配对消除买卖榜相同披露行的重复展示，同一方向的多条同名席位不合并。成交额为零或缺失时占比未知。辅助标签、近三月活动次数和营业部名称可能是查询时刻口径，不代表历史当天已知值。

同一原因代码可能返回多条成交额精度不同的汇总。席位重复披露的原因、成交量和成交额须精确匹配其中一条完整汇总，所有来源汇总分别保留，不舍入或合并。此类同代码多汇总仍显示“来源部分缺失”，表示关联存在歧义；响应完整归档不等于来源质量通过。

榜单日期不是公布时刻；来源不提供明确三日榜开始日或完整历史版本，不能用于盘中决策或严格历史信号回放。当前存储版本观测时间以北京时间显示；无变化不刷新业务时间。

## 限制与排错

采集完成仅表示声明响应已校验并归档；“来源无席位明细”和“来源部分缺失”不能证明席位数据已准备好。来源本次无席位而SQL已有有效明细时保留旧内容供历史参考并明确警示，不把旧内容当本次完整响应。早期空明细不是解析失败，也不填零。

来源无记录只说明当前目录可得范围，不能证明证券从未上榜。目录/详情字段异常、数量或关联不符则失败留断点，查看运行记录的确切错误。默认共享代理优先，允许按保存策略回退；开发30股验收单独禁止回退，不改日常网络偏好。

数据准备的“龙虎榜上榜汇总”和“龙虎榜席位明细”分别核验各自字段、日期集合及正文摘要，共享一次响应，不互代通过。SQL浏览不依赖Redis；详细审计最多2000日期，超限请缩小范围。

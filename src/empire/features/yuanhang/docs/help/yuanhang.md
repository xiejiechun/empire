# 远航版历史行情

## 如何查看

采集入口：在“同花顺远航版”平台分组选择“权息与股本历史”。

采集入口：在“同花顺远航版”平台分组选择“股票完整历史日K”。

在采集管理→身份管理选择同花顺远航版，确认在线设备code对应身份已就绪。再到采集管理→任务，分别运行“股票完整历史日K”和“权息与股本历史”。使用原生PC协议，节点只作代理出口，每节点复用自己的固定游客身份。

## 数据范围与更新

在数据浏览→数据目录搜索“远航历史行情”，输入统一证券代码，如000001.SZ、600519.SH、920000.BJ；选择日线、分红送转配股、总股本、普通流通股或自由流通股，填写日期范围后查询。表格每页200条，权息按日期和事件身份共同翻页，同日多条也不会漏掉；查询只显示已归档内容。日期支持1900至2100，实际历史以来源可得范围为准。

任务默认每日北京时间18:00；修改任务策略并保存后按公共调度生效。身份保存在MySQL配置并由本机Windows用户保护，节点IP变更仍复用同一身份。认证拒绝不会触发重新注册。需要程序目录config.toml中的数据库连接；计划和网站策略仍存MySQL。

## 字段与日期

日线初始化按每证券一次完整响应取得，日常先核验最近10个正式交易日，再独立归档一个最多64只证券的历史初始化/补缺批次；停牌证券包含已知最后成交日作非空身份锚点。核对完整帧的声明行数和字节边界、证券、日期集合、开高低收、成交量和成交额，再拆成独立年度消息。规范5只合并完整日线字段表中相邻且所有值完全相同的重复日期；同日冲突、部分字段重复及倒序仍失败，不通过换节点重读直到偶然通过。年度source_count表示独立交易日数，必要的完整或区间响应正常各请求一次，不固化开发对照双读。源没有成交量或成交额时分别保留NULL，界面显示“未知”，依赖量额的分析需检查缺值；不把缺成交量当无成交，纯价格复权仍可使用有效OHLC。来源最高价小于收盘等关系矛盾保留原值，质量列显示“OHLC异常”，正式查询quality_flags=1；正常为0。包含异常的区间停止复权计算，不能把已完整入库等同于适合回测。量为股、价和额为元。停牌日不补假K线，当前池移除证券仍保留历史。

权息和三种股本使用一次联合响应。字段454已包含转增，送缩股为454减460；不把两者重复相加。负值表示净缩股，目前只支持其他分量全0的纯缩股事件。比例为每原股，现金为每原股现金，配股价为元/新增股。同日不同事件分别保留，不相加或任选；本协议不能裁定合成口径时，该区间复权明确报出日期，原始K线仍可查看。事件日期是生效日，不能作为提前已知的公告日期。

股本三种口径独立日期，上市前和未来生效点原样保存；截至日查询只取不晚于该日的已生效点。首个股本点之前未知。普通流通股的明确源NULL保留为“未知”，截至日命中该点时仍未知，不用更早余额填充；总股本和自由流通股仍须有效正数，缺字段仍失败。纯价格复权不依赖流通股余额，市值、换手率等用途须先检查所需口径。

## 限制与排错

近期检查直接核对最近十个交易日所在的覆盖区间；历史完整性比较区间首尾，不逐日展开多年记录。历史补缺分组检查，找到本轮64只待办后停止继续规划，其余证券在后续轮次继续检查。长期停牌仍保留真实成交锚点，新年度仍按覆盖要求补齐前缀；这些优化不缩短采集范围。

本轮网络成本保存在运行结果的network_costs中：HTTP实际尝试、原生连接交换尝试、行情查询、HTTP认证尝试、原生认证交换、重试、已观察接收字节、HTTP解码正文字节和原生解码字节分别累计，失败和暂停也保留已经发生的成本。HTTP认证是HTTP尝试的子集，原生认证与行情查询可能共用一次连接交换，不应把各项相加当作同一种请求数。字节不包含网络协议头；中途失败只表示已经观察到的部分。原有逻辑请求/成功响应统计仍用于业务完成量，不能代替实际网络成本。

数据库执行队列满表示本机SQL通道暂时繁忙。身份配置由运行服务统一复用并定期核验，不再逐证券重复读取；日线规划每组最多64只批量读取年度证明和覆盖字段，同轮只读取并校验一次正式日历，不扫描历史日线正文。控制通道满载时最多等待30秒取得执行位置，超时仍保留断点和待归档数据；可稍后普通采集续跑，不需要从头采集。持续满载须检查具体通道、慢查询或数据库连接，增加源站请求重试次数不能解决本机SQL拥堵。

原生数值解析失败会保留证券、数据种类、字段及日期诊断；非有限数继续报错且不推进该证券断点，不转成零或自动跳过。旧错误缺少字段信息时不能仅凭后来一次成功判定根因已修复。

`Yuanhang excessive idle control frames` 表示复用的行情连接连续收到过多空闲心跳，不代表权息股本内容损坏。每次最多跳过8个精确控制帧，第9个触发旧连接退役，按任务“单次请求失败重试”的原预算在同节点重连，继续使用已有认证；日线与权息股本共同适用。重连仍受频控、缓冲和超时限制，不额外申请账号。预算耗尽则保留断点并报告失败，可稍后普通“立即采集”续跑。无须因此执行“从头采集”。其他坏帧、认证拒绝及业务校验失败继续按各自规则处理。


任务进入等待归档后，全部本轮消息被成功处理才显示完成。下载与归档独立推进，逐年入队期间继续下载，不逐年等待SQL。正常重启保留Redis时继续未入队位置；Redis服务重启后丢失待归档数据和断点，从SQL日期覆盖恢复，补未确认范围；纯缓存核验的较新时间可能丢失，允许保守重核，不因缓存丢失重采全池。来源响应在续采期间变化时重新发布该证券完整年度集合，较早观察版本不能覆盖新确认。

断点仅保留股票池摘要、固定截止日、完整股票池内位置和当前证券的请求计划；整池名单及其他证券计划只在内存中生成。重启后根据正式SQL覆盖重建未开始的后续计划，当前证券已部分入队时继续原请求范围，不因部分年度已归档而缩窄；“从头采集”的完整核验选择在续采时保留。公共断点上限仍为16 KiB。旧版整池计划断点若在中断状态，维护人员先正常关闭程序、确认待归档为0，再用`scripts/migrate_yuanhang_checkpoint.py --apply --backup <新备份路径>`转换位置；原批次和已入队页数保留，启动不自动转换。已完成断点按正常下一轮流程重建。

未完成日线或权息股本提示“股票范围已改变”时，不可直接把旧位置套到新名单。维护人员在正常关闭程序、待归档为空后，使用同一入口`scripts/migrate_yuanhang_checkpoint.py --rebind-scope --previous-scope <旧股票池JSON> --backup <新备份路径>`先核查，加`--apply`执行；权息股本另指定`--job ths-yuanhang-financial-v1`。旧名单必须与断点摘要完全匹配，不能用当前名单冒充。仅支持contract2近期维护、非强制全量且位于完整证券边界的断点；原批次全部已入队页须经正式归档确认。它备份两份名单和原状态、保留批次/页数/截止日，将已处理前缀精确映射到新池，后续仍走原采集规划。移出证券历史保留，旧池跳过统计重置；新增证券插入已处理前缀内部、旧名单无法证明、部分证券或历史补缺则拒绝，不自动漏采或重采整池。恢复后普通“立即采集”，无需“从头采集”。

同截止日已有可信近期核验且没有补缺时，日线不再请求；新增证券在有界初始化批次处理。取消20交易日全历史轮转，近期窗口外的旧修订仅通过已知异常或主动完整核验处理，没有严格历史版本回放。不复权日线不因新增权息事件自动全历史重采。权息和股本仍每天联合核验，同日已完成的计划不重复请求；不依赖日线变动推断事件。代理连接故障和认证请求明确总超时按公共任务request_retries预算重试（默认2，可在任务配置中调整），换节点时必须使用新节点自己的固定账号重新取得会话。传输失败后，有其他健康且身份就绪节点时优先切换，再按失败次数选择；只剩原节点时须等它恢复后才能复用。初始暂无在线节点和采集中目录暂缺均进入同一重试路径。每次选点最多等待125秒，期间只读取共享缓存，遵守节点冷却和有效租约；等待到期消耗一次原任务重试额度，仍有额度则继续等待并重新选点，不提前结束任务。配置重试30次表示首次尝试加30次重试，传输失败、连接重建、缺值确认与选点超时共用这份额度，不各自增加预算；一直没有健康节点时等待可能较长，可随时取消。选点等待不产生网络请求或推进断点。预算用完的错误显示尝试次数、剩余额度、离线或冷却提示及上次传输异常类型，保留原始异常链。没有任何已就绪身份属于配置问题，仍直接提示身份管理。错误详情同时记录证券、最后失败节点和限定节点、最近5次尝试的异常类型链及系统错误码，以及等待开始/结束时目录异常、缓存年龄和身份未就绪、租约过期、目录缺失、冷却、绑定排除的节点数量；节点明细为有界样本，并包含最后失败及限定节点。该信息来自当时共享缓存，不另行探测；不保存代理凭据或任意网络异常原文，旧记录缺少的现场信息不能补回。身份认证拒绝和其他业务校验错误不通过轮换节点重试。权息股本响应结构、身份、日期合法而必需数值明确为NULL时，按任务原重试预算优先切换下一健康在线且身份已就绪的节点，使用该节点自己的固定身份、新建连接，重新取得完整联合响应；仅一个健康节点时可在剩余预算内重连该节点。NULL只影响本证券的节点选择，不使其他证券全局冷却；正常完整响应仍只取一次。传输失败、NULL及选点等待共用同一预算，重试30次最多尝试31次；全部耗尽仍保留原数据和断点。只有一次完整响应通过全部校验才入队，不填零、不跨响应拼值；允许缺值的流通股407仍保留NULL。错误显示证券、字段、日期与实际尝试，详情最多保留最近5次NULL的节点、字段、日期、连接方式、响应字节数和摘要，以及最后一次缺值响应的有界表结构；不保存认证信息或完整正文。代理目录由RouterProxy维护，无健康身份节点时保留断点；源拒绝、坏包与429冷却不会通过轮换身份绕过。

上市前证券：先请求远航原生历史，只有收到完整空帧，或经严格校验的单表一个或多个总股本/流通股本历史点（字段恰好为日期、总股本和流通股，缺自由流通股、无权息列，总股本须正数，流通股可为0或明确NULL），才额外查询一次东方财富上市资料，且仅判断上市状态。明确未上市（状态9且上市日未知）或上市日晚于本轮截止日，并且本类正式库没有既存历史时，列为“deferred_prelisting”延期证券，单列在任务结果和断点的deferred集合；部分股本同时记录首末日期、点数和缺失字段，不生成假日线或空权息股本证明。每轮重新请求；以后上市即转入正常采集。辅助资料的未知状态、缺失身份、请求失败，或已有原生历史与上市状态矛盾时仍失败、不越过证券。正常完整的原生响应不额外查询上市资料，日线、权息和股本事实始终只来自远航PC协议。

已上市证券若仅返回上述严格单点部分股本，且原生日期恰等于精确核实的上市日、正式库没有既存金融历史，则标为“初始股本来源尚未就绪”（deferred_initial_capital），继续处理其他证券。缺少自由流通股本的单元不入库、不生成完整证明；本轮有效数据全部归档后显示“来源缺口”，列出待就绪证券，不能作为初始化完成或股本已齐的依据。同日、同截止日普通重试只复查延期证券；正常重启仍保留该范围，新日按每日完整金融核验规则处理。来源补齐后自动走正式归档并移除该缺口。已上市多点缺自由流通股、上市日不匹配、已有历史矛盾、坏帧和其他缺字段仍失败。缺口证据保留证券、上市日、来源日期、缺失字段和节点编号，便于追查来源延迟；不把东方财富股本当作远航数据填入。

## 技术参考

业务表通过scripts/create_yuanhang_schema.py显式新增，启动不自动建表。规范4的既存金融结构修订用`--financial-history --apply`显式执行，只接受已知旧结构或本入口中断形态，逐批映射旧事件身份并核对完整内容，保留事实及统一状态。规范5不再改表；旧消息先归档清零，再通过显式完整初始化重建全部证明及缓存信任。旧规范证明不能使计算通过。既有其他来源历史保留各自身份；本功能已提供同源复权输入；完整初始化和当前正式部署以实施记录为准。当前部署、随机30股验证和全池实际进度见项目实施记录，任务显示完成不能替代全池内容审计。


全池显式初始化维护可使用`--request-retries 5`，仅影响本次运行，不修改保存的日常策略。中断后`--resume-report <原失败报告>`仅在源码输入、目标库/namespace、股票池和截止日一致、来源摘要匹配原Redis断点时复用已完成证券的审计证据；不保存成功响应正文，不另建采集断点。断点丢失、来源规则改变或证据不完整时须完整重核。恢复只接纳原批次待归档消息，不能处理无关消息；下载仍不逐批等待SQL。

## 增量维护与费用统计

同一证券年的完整与区间消息共用唯一归档路径，局部只替换来源已证明区间，区间外历史保留。版本按日期比较，较早整年响应不能覆盖较新区间；缺口不会因最新日期较新而自动完成。首次切换需要维护人员正常关闭程序、确认待归档0，再执行 scripts/migrate_yuanhang_ranges.py 转换已有覆盖状态；启动不会迁移或重采已有初始化。

若项目覆盖状态行已缺失而年度证明仍在，维护人员核实数据库与证明后，可在同一入口显式增加`--rebuild-missing-state`，先预检、再`--apply --backup <新备份路径>`。恢复只采用各年度证明原有截止日及北京时间版本，不使用全库最新日期扩大单股覆盖，不改行情事实或年度证明；已有状态拒绝此模式，应使用普通转换。状态缺失原因未知时如实保留诊断，不能把恢复说成已查明删除原因。

原生连接的总超时也属于传输重试范围，与认证超时及代理连接异常共用任务重试预算；切换到另一健康节点时使用该节点自己的固定身份。正常响应不增加请求；预算耗尽仍失败留断点，协议或内容错误不借重试跳过。

任务详情分别查看计划请求、完成的逻辑行情响应、跳过证券、成功行情正文/解压字节；正文统计不含认证交换、失败帧及网络包头，不能冒充总线上流量。代理/直连次数由公共网络统计提供，入队条数与归档实际写入单独查看。短区间主要减少字节与入队量，单股请求数并未变为批量；多证券批量尚未确认。

远航身份服务统一管理每个节点的认证会话，日线与权息股本跨任务、跨轮复用；任务结束不会清空会话。行情连接在共享下载器内复用，同一连接连续请求不同证券以及日线、权息股本时不重复登录。普通断网仅重建连接，明确行情认证拒绝时才尝试用原账号更新一次通行证；更新后仍拒绝则停止自动重登并保留错误。节点账号改变或程序退出后不复用旧会话，各节点不借用其他节点账号。无需认证的远航HTTP接口不增加登录。每次业务请求仍遵守原有频控和资源限制，连接复用不代表取消请求间隔或保证固定提速倍数。

## 进度显示

管理端按本轮已规划的完整单元展示百分比：证券、报告期、日期或证券日以本项目实际计划为准。初始化及续采恢复已成功处理数量，失败单元不算成功；准备范围时不猜总量。分红目录发现和报告期核验分别显示当前阶段进度；采集100%仍需等待整轮归档确认。

共享下载临时内存按原生连接实际接收与解压声明大小申请，不再使用股票分类的固定响应上限。Snappy输出在分配前预留，额度不足保留原进度并明确报错；来源条数、业务范围、字段及协议完整性规则不变。

原生double精确空值标记包括符号位单独置位和全部八字节FF；流通股本按现有契约保留NULL，不填零、不丢弃该日期。其他NaN/无穷仍拒绝，其他必需数值的缺失仍按对应业务校验失败。该解析调整不增加正常请求或改变权息股本全响应的维护周期。

新触及且尚无年度覆盖证明的年份，首次区间须包含该年1月1日起的前缀，满足现有年度证明契约；这属于该年初始化，不升级为全部证券全历史重采。完全没有身份/行情锚点的新证券在有界初始化批次取完整响应。

每日任务恢复昨日未完成批次时，先确认原批次全部归档，再在同一次执行中接上当前截止日的近期维护；不会因为先完成昨日批次而把当天更新推迟到下一天。原批次与新增批次请求成本累计展示。

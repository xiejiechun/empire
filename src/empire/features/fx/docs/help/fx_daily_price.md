# MySQL fx_daily_price

## 用途与归属

固定来源ths，数据集fx.price.year，所有者fx业务包；实时任务只有volatile准入归属，不能写本表。每行是品种乘来源日线日期的OHLC事实。

## 结构与身份

| 字段 | SQL 声明 | 含义 |
| --- | --- | --- |
| `unified_code` | `VARCHAR(10) CHARACTER SET ascii COLLATE ascii_bin NOT NULL` | 固定十二品种标识加.FX；与股票身份分离。 |
| `trade_date` | `DATE NOT NULL` | 来源日K线日期标签，仅接收保守截止前日期。 |
| `open` | `DECIMAL(20,10) NOT NULL` | 来源data第2列开盘，按品种报价单位。 |
| `high` | `DECIMAL(20,10) NOT NULL` | 来源data第3列最高，保留来源异常。 |
| `low` | `DECIMAL(20,10) NOT NULL` | 来源data第4列最低，保留来源异常。 |
| `close` | `DECIMAL(20,10) NOT NULL` | 来源data第5列收盘，按品种报价单位。 |

- `PRIMARY KEY (unified_code,trade_date)`
- `KEY ix_fx_date_code (trade_date,unified_code)`
- `CONSTRAINT ck_fx_positive CHECK (open>0 AND high>0 AND low>0 AND close>0)`

所有字段NOT NULL，无隐式业务默认；价格为正DECIMAL(20,10)，不舍入或补零。主键支持品种日期/年份查询；明细另有日期品种索引支持全品种日期范围，不外键到股票名录。

## 读写与关联

日线入队前核对原生当日日线的品种、来源日期及开盘，已结束标签核对完整OHLC；日线不依赖实时报价昨收相等。近期缺少当日行或发生冲突时取至多两个相关年度核验，候选须包含近期全部已结束日期且重叠OHLC一致，否则保留原事实和断点。原生当日行仅证明目录日期槽位，未结束时不入本表；不持久化成功响应或增加实时业务副本。

唯一写入路径为fx.dataset经统一入队/归档；查询fx.daily.query稳定游标每页最多500，完整年度最多366条。日线任务集中读取年度头及每品种SQL最近日期窗口，不在实时任务中回库。完整年验证后替换该年，近30日仅合并已证明集合；无变化不执行本表DML，来源修订仅修改受影响事实/证明。迟到旧版本不能覆盖，SQL提交后Redis失败可安全重放。

观察日历通过同一fx.daily.query.browse读取已选品种收盘，每品种日期范围最多500条，拒绝截断；按来源日期独立于A股日历展示，异常OHLC关系显示缺值，不回写、不补齐、不用实时快照替代。参见[多指标观察日历](help:多指标观察日历)。

日线核对遇到原生当日行身份、日期或价格无效时保留该品种原事实、年度证明和断点，不用昨收或旧实时值补齐核验。实时任务的明确空报价处理独立，不授权写入本表。

跨日目录与历史正文相差一条时，仅当原生当日行证明这一未结束日期、且年度和近期历史尾日对应，才按该日期调整边界：目录提前计入而历史尚未包含，或历史已含而目录尚未计入。该未结束行不进入事实或年度证明，已结束部分仍核对日期集合及内容，其他计数差异拒绝。跨响应失败记录原生当日行、有界计数、尾部和摘要以便诊断。

跨接口来源冲突只阻止对应品种写入，不阻止本轮后续正常品种按同一路径归档；全部有效消息确认后以来源缺口结束。Redis断点保留最早冲突品种及其年份位置，后续正常消息不能越过它宣称全量完成；下一次从该位置重核，内容相同仍零业务DML。来源缺口不授权补造缺失日期或用实时报价替写历史。

## 保留与恢复

MySQL长期保留来源历史，不按分钟保存。Redis丢失依年度证明及近期日期恢复；证明缺失/规范失配/近期日期集合消失触发完整年重取。详细审计需核对全年正文与摘要，不能仅以行数判断完整。较早历史修订经显式重新采集发现。

## 维护与相关说明

新增表仅用显式create_fx_schema维护入口，正常停机、队列清零、独占维护及前后其他业务核对；启动不建表。手工改SQL须停止归档、失效相关摘要和覆盖证明，不直接清Redis队列。用户入口见[同花顺汇率行情](help:同花顺汇率行情)。

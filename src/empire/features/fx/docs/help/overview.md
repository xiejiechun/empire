# 同花顺汇率行情

## 如何查看

采集入口：在“同花顺远航版”平台分组选择“汇率历史日线”。

采集入口：在“同花顺远航版”平台分组选择“汇率实时行情”。

在“采集任务 → 同花顺远航版”选择汇率任务，也可搜索“汇率”。“汇率实时行情”的“数据预览”查看Redis最新值；“汇率历史日线”查看已归档日K线。品种填写USDCNH等代码；日线可筛来源日期、排序和翻页，图表仅概览当前页。市场观察的多指标日历可在今天缺归档时补充已有Redis报价，顶部集中标识Redis及过期状态，默认30秒只刷新已有Redis盘中值，间隔可调、可关闭并保留月历阅读状态，悬停/详情/CSV保留三种时间；不会用实时值补写历史。盘中环比与N期均值为明确标识的估算，来源和边界见[多指标观察日历](help:多指标观察日历)。

## 数据范围与更新

来源为同花顺外汇行情页面，范围固定USDIND、USDCNY、USDCNH、XAUUSD、EURUSD、GBPUSD、USDCAD、USDCHF、USDHKD、AUDUSD、USDJPY、USDSGD，其中包含美元指数和伦敦金。公开行情接口不依赖远航客户端持续打开或账户登录；没有把外汇伪装为股票行情。

实时任务默认每轮结束等待60秒，覆盖每个品种最新值；不保留分钟数据、历史采样或回放。失败保留旧值，超过180秒显示采样过期。完整且身份、时间有效的响应若最新、开、高、低全部明确为空（昨收为空或有效），任务显示“来源暂无报价”和本轮实际更新数量，继续处理其他品种；缺口品种保留上次有效值及采样时间，首次无有效值则不展示报价。所有品种都暂无报价也不会显示全部更新完成，下一轮重新采样。缺字段、部分空值和格式损坏仍报错，不用昨收、零或旧价代填。日线默认每天北京时间09:00集中访问MySQL，首次按来源年份目录补历史，以后补缺年并重核最近30自然日。计划可在任务配置保存，下一轮生效；用户已保存的合法计划优先。

日线直接取来源日K线，不从实时采样合成。09:00后只接收昨天及更早的来源日期标签；09:00前手动运行再延后一日，来源没有明确最终标志，这是一条保守缓冲规则。不开设盘中SQL进度轮询或每半小时收盘检查。周末、节假日与夏令时不套A股交易日历；只保存来源实际日期，不补造缺失日。

每个品种在同一轮获取近期日线及官方图表独立的当日日线，校验品种、日期和开盘；当日接口返回已结束日期时还须匹配完整开高低收。盘中价格会随请求时刻变化，不写入历史。近期缺少当日行或日期/内容不一致时，额外获取相关完整年度核验，最多两年，已核验年份直接复用于补缺。候选年度不能缺少近期已有的已结束日期，重叠日期的开高低收须一致；冲突时不选择某个接口的价格覆盖另一个。实时报价的昨收与日线收盘可能不一致，日线按自身协议核验，不再把两者相等作为必需条件，也不用实时报价填写历史。

来源目录与正文可能在跨日时更新不同步。只有本轮原生当日行能证明、且尚未结束的那一个日期可以解释计数差：目录提前计入而年度尚未包含，或年度已包含而目录还未计入。年度和近期历史尾日必须对应，其他缺失、重复、日期替换或已结束价格冲突仍失败。核验失败的错误详情保留品种、原生当日行、各响应计数、日期边界及摘要，不保存完整成功响应。

例如目录计224条、历史223条，独立当日行明确为当天时，先核验这223条历史及当日日期合并后的目录计数，再排除尚未结束行；已结束年度覆盖为223条，当天不入库。不能直接将所有相差一条的情况都当作正常，也不按工作日推算黄金或外汇应有日期。

日线跨接口的目录数量、日期集合或报价冲突经有界核验仍无法消解时，该品种保留原数据和断点，继续后续正常品种。有效入队数据全部归档确认后，本轮显示“来源缺口”、具体代码及已核验数量，不显示全量完成。下一次按保存计划或手动“立即采集”从最早缺口重核，后续正常品种也会重新检查近期；已有完整年度覆盖不因此全历史重采。网络、响应格式、入队和归档故障仍按原流程失败，不当成可跳过的来源冲突。

暂停/故障不跳过未完成年份；仅重启软件可使用存活Redis断点。Redis或电脑重启丢失实时数据与断点，实时重新获取，日线依据SQL完整年度证明恢复。重新采集会核验全部来源年份，发现30日以外历史修订；普通维护不自动全历史重下。所有品种核验通过且全部已入队消息成功处理并清队后才显示本轮完成。

## 字段与日期

日线为来源日期、开盘、最高、最低、收盘；保留十位小数精度，必需价格缺失或超界失败，不补零。货币对按报价币/基础币，美元指数为指数点，伦敦金为美元/金衡盎司。来源偶有开高低收关系异常，保留原数值并显示“价格关系有效”标记，分析时自行筛除异常。

实时分别展示来源time、来源updateTime和采样时间；前两者可能不同，其准确含义尚无来源最终说明，不以响应time认定价格一定新鲜。“采样已过期”只说明本地超过180秒未成功获取，不推断休市。来源日线日期不是公布时间，不提供过去时点可知版本回放。

## 限制与排错

每品种仅有一份实时值，失败品种可能随其他品种继续更新而保留较久；整键最后成功写入7天后过期。来源晚到或修订由后续日线任务接收；最近30自然日以外等数量的静默修订需要显式重新采集核验。年度数量、起点、排序、日期身份和近期重叠校验失败会保留断点，不能把数量一致当完整证明。来源落后于已经归档日期时暂停该年度更新，不倒退SQL。

近期和年度接口都可能命中不同的来源缓存，不能仅凭接口名称、请求时间或禁止缓存请求头判定哪个值更新。核对可以发现本轮可见的冲突，不能证明来源数据永不再修订，也不提供整个历史每一天的独立终值证明。出现日线日期、数量或已结束内容冲突时，查看错误并在来源恢复后继续采集，无需清空已有数据或调整每日09:00计划。

原生当日日线的品种、日期和交易状态有效，但开、高、低、收四项全部明确为空时，按“当日日线暂无报价”处理，适用于全部十二品种。该品种保留已有历史和最早缺口断点，继续其他正常品种；有效消息归档后本轮显示“来源缺口”、代码及实际核验数量，全部暂无也不会显示完成，不反复生成价格格式错误。下一轮按保存计划或“立即采集”从缺口重核，来源恢复后接着补齐。空报价不触发额外重读或全历史重采。缺字段、部分空值、非法价格、日期/身份损坏及历史正文空值仍报错并保留断点，不用零、旧价或实时报价替代核验。

任务运行记录中的请求和传输成本包含实际尝试；日线入队数量在完整年和近期维护两种路径均随实际发布更新，续采时包含该批次此前入队的记录，不能当成当前待归档数。实时成功仅表示Redis最新值可查，不表示历史全部归档。历史初始化进度以日线任务及真实查询为准。

# 通达信个股融资融券

## 如何查看

采集入口：在“通达信”平台分组选择“个股融资融券”。

在采集管理搜索“个股融资融券”，保存计划后执行。任务数据预览可按证券与日期查询，稳定分页每页最多200条；金额为万元、数量为万股、价格为元，比例为百分数。

## 数据范围与更新

每股固定请求第一页10000条，核对总数、列定义和严格倒序唯一日期；超过上限或缺页失败，不声称只取第一页便已完整。默认每天北京时间19:30；当前名单和已归档历史证券共同构成范围。初始化、日常及从头采集均每股一次全历史核验，属于用户指定全量请求、差异入库，不是来源增量。保存的任务计划和网络策略优先。

证券间共享有界并行预取，按序校验并原子入队；不逐股等待归档，全部入队后确认本轮清队。中断保留失败证券位置；重启软件可继续，Redis服务丢失后SQL保留，下一轮重新核验。已有更早历史修订随每日完整响应发现，不保留来源完整旧版本。

## 字段与日期

日期是来源交易日期，不是公布时刻。原始值包括融资余额、融资买入额、融券余量、卖出量、收盘价及比例分母的成交量和成交额。融资偿还=前一来源记录余额+买入额-当日余额；融券偿还量同理。最早记录按页面公式以前值0计算并标记first_source_row，不能误称独立公布的偿还数值。融券金额=余量×收盘价，差值=融资余额-融券金额；成交量、成交额、收盘价可在停牌历史为NULL；对应金额、差值和比例保持未知。零分母比例显示未知，不能填零。

## 限制与排错

返回范围外的交易日不补零，也不据此判定融资融券资格。明确空响应须带有效页码和总数0；网络失败或坏字段不当空结果。来源服务端报告“cache语句执行超时”（-1009）时，按保存的请求重试次数重试原证券；与网络重试共用预算。仍失败时显示错误码与超时原因，保留失败位置；其他来源错误仍须报错，不能据此当作无融资融券记录。来源没有公布时间与历史版本，普通研究可用，严格历史信号回放单列限制。来源校验失败不推进断点，SQL失败留队，写入成功、相同确认、旧响应确认都由统一归档器清队。

未完成任务遇到股票名单变化时，保留原批次和断点并提示显式维护范围。维护核实原名单、已完成前缀及全部已入队数据归档成功后，可继续未完成证券，不必重下已完成前缀。新增证券插入已完成前缀或原名单无法核实时，不能直接沿用旧索引；从头采集会重新核验，已归档数据保留。

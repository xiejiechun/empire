# 实施ST与撤销ST

## 浏览细节

所选事件显示证券与来源日期，跨页按钮明确区分查看撤销ST和查看实施ST；空选择时入口禁用。返回恢复时间线阅读位置，仍不据来源事件推断当前ST状态。

## 如何查看

分别打开实施ST、撤销ST，按证券候选和来源日期范围查询，默认最新在前。时间线展示旧简称、新简称与原因；更多信息保留来源次数和行业原值，明细标签供核对。可带市场跳公司资料、更名或另一ST栏目。栏目包含类型转换，不推导每日ST区间或当前ST状态。

## 数据范围与更新

采集管理→任务有两个独立插件。默认每天北京时间18:00，代理优先且允许受频控的直连回退。用户可保存计划至MySQL，下一轮生效，重启不丢配置。每轮请求1990-01-01至启动日的来源全部可得历史，每栏目一次完整响应，发现新增、缺口和修订；支持范围不表示每个日期都有事件。立即采集和重新初始化均核验全响应。入队后中断先完成归档，Redis丢失时重新读完整来源与SQL比较。

## 字段与日期

展示证券、实施或撤销日期、前后简称、原因、证监会及通达信行业；NULL及空字符串原因均显示空白，表示来源未给，不猜测补齐。日期是来源事件日期，行业没有历史归属日期，当前简称不重复存储。完整响应内所选证券没有事件是合法空结果，不能推断始终正常。

## 限制与排错

实施栏目还包含ST与*ST转换及撤销退市风险警示但继续ST等事件；依据原因查阅，不自动裁定每日状态。没有公告可用时间，不保证历史选股信号回放。来源计数、字段、重复日期或截断异常均失败且不推进断点；SQL失败保留待归档消息，全部三个市场归档成功且整轮无残留才完成。两个项目独立验收，无需互相等待。

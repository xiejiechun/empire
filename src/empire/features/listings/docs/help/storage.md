# 上市资料存储与维护

## 字段与维护

正式业务表为stock_listing，一证券一条首次上市资料，核心日期和金额为类型列，历史沿革上限256KiB，完整保存，不截断。相同内容不执行业务写入；可信摘要免SQL确认，成功即清理对应待归档消息，失败保留。来源没有修订版本号，按请求开始时间防迟到覆盖，不承诺识别源站语义旧版。新表仅由scripts/create_listing_schema.py显式维护，启动不迁移。

来源缺上市日仅在该项目collection_state现有证券单元保存incomplete、status_code=0及缺字段名称；不保存原响应或部分发行正文。该状态与断点通过公共入队提交、统一归档并成功清队，旧有效资料保持，迟到旧响应不能覆盖新状态。正式业务上市日仍为必需DATE列；本次无需结构迁移。

旧64KiB历史沿革约束使用 `scripts/create_listing_schema.py --upgrade-history-limit --apply` 显式扩容：关闭程序、待归档排空、核对原数据不变，保留断点，升级程序后继续采集失败位置。

[MySQL stock_listing](help:MySQL%20stock_listing) 是唯一逐字段字典，日期冲突、无资料和缺字段状态分别保留，不合并处理。

来源成立日可能晚于上市日（如000032），页面列表及详情提示日期冲突，数据准备也计数警告；两项原值保留，不用成立日修改或推算上市日。成立日是附加字段，该警告不阻止上市日使用。旧契约1数据库通过 `scripts/create_listing_schema.py --upgrade-date-contract --apply` 显式调整约束，关闭软件且队列排空，旧内容保持不变，失效摘要与断点后重新全池采集建立契约2证明；正常启动不维护。

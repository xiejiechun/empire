# 数据预览空间与滚动打磨 · 2026-10-29

用户反例：交易规则目录仅5行，返回目录后只显示约2行，内容区下方大量空间闲置且出现横向滚动条。

## 复现与原因

旧版在1600×1000测试窗口中，列表容器高度687px，首次进入表体185px，进入规则详情再返回后表体缩成90px、max-height为100px。原useStageHeight只监听首次挂载的元素，卸载时测得零高度，重新挂载后没有绑定新容器。另有固定列宽和按钮内边距造成约3px的横向溢出。之前只检查入口与根级横向溢出，未覆盖内部表格高度；本轮增加实际几何断言。

## 修改

- 高度测量改为绑定当前容器，卸载时释放监听，隐藏页面的零尺寸不覆盖有效尺寸；同时测量表头，适配多行表头与密度变化。
- 目录、财报、行情明细按实际剩余高度分配，不再使用100px残留值、窗口高度减固定数值或固定260px上限。
- 目录列宽按比例分配，动作列预留足够宽度，长名称省略；短列表自然呈现全部行，不拉伸行高，不出现多余横向滚动条；仅一页时隐藏分页控件。
- 行情图高度随容器变化，SVG坐标跟随实际宽高，避免大窗口内图形被固定宽高比挤在中间。通用序列图使用同一测量方式。
- 点击当前分类也能从详情返回目录，原筛选仍保留。
- 修正桌面HTML标题仍写V2的问题。

## 验证

npm run build 通过，保留既有大包提示。qa/review-layout.cjs 的18项检查通过，覆盖详情往返3次、重复点击当前分类、页面隐藏/显示、侧栏收起、舒适密度、1000×720/1280×900/1920×1080窗口与125%缩放；断言表格实际可用高度、短列表无裁切、目录无多余横向滚动及页面无根级溢出。qa/review-all-data.cjs 的50项入口回归通过。

修复后同类测试：容器693px，滚动预算665px；5行内容185px全部可见，表体宽度与内容宽度均1374px。大量数据可使用剩余空间，少量数据保持自然行高。

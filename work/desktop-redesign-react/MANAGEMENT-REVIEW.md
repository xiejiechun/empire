# 采集管理设计评审 V3 · 2026-10-29

本轮仅修改独立 Electron 预览，使用有界虚构数据，未连接配置、Redis、MySQL、采集器或身份服务。原客户端不迁移、不发布。

## 六块能力的对应位置

| 原入口 | 新位置 | 本轮可操作设计 |
| --- | --- | --- |
| 采集任务 | 采集任务 | 搜索、来源/状态筛选、批量命令确认、底部运行详情、计划编辑与草稿、资源与身份关联入口 |
| 归档任务 | 任务视图 → 已归档任务 | 任务菜单归档、列表隐藏、搜索、还原；保留原启停语义，不与业务入库混淆 |
| 运行任务/运行记录 | 任务视图的进行中筛选 + 运行记录 | 当前运行在任务表；历史分采集、归档、错误，可筛选、查看诊断、按选中记录清理 |
| 采集出口 | 平台与出口 → 采集出口 | 平台选择、在线/离线、编号/IP搜索、分页、节点详情、站点规则编辑 |
| 下载资源 | 共享资源；任务详情提供入口 | 全部11项资源、逐项当前/保存/草稿比较、规划推荐、预算验证、模拟重启生效 |
| 身份管理 | 平台与出口 → 平台身份；项目详情提供入口 | 平台服务启停演示、节点申请/登录分离、离线保留、只读参数与诊断、不适用来源说明 |

## 关键设计决定

- 仅保留一层顶部模块导航；左侧管理入口稳定，任务筛选只在任务页出现。
- 下载额度是全局共享资源，不能嵌入单项目后让用户误以为独占。项目中提供明确的共享配置入口。
- 身份属于平台与固定节点，多项目共享；不按每个采集器重复创建身份。入口可在项目中，服务控制明确影响整个平台。
- 已归档任务和业务归档记录分别呈现。归档任务保留数据，成功业务归档才清除对应队列消息。
- 正式资源保存后需正常重启；设计稿提供明确标注的模拟按钮，不重启真实程序。
- 运行记录为有界历史；清除记录不等于修复错误，不删除待归档业务。

## 边界

所有动作只操作当前窗口内示例状态，重开不保留演示改动。身份申请、登录、数据采集和归档不执行。来源专项配置、真实运行刷新/并发冲突/权限/后端故障，以及全部64条生产路由尚不属于本轮业务实现验收。任务运行按钮演示确认和反馈，不模拟完整调度时间线。设计预览覆盖上述管理工作流，不代表已经完成正式客户端重构。

## V3.1 使用流程优化

- 侧栏只负责页面导航，状态筛选移到任务表上方；移除重复来源导航，来源和分类在同一筛选栏组合。
- 任务查看历史自动带入项目条件，提供返回任务，保留原选择和筛选。
- 资源及身份从任务中就地打开侧面板，不离开任务；资源当前值、保存值及草稿与全局页面共享同一状态。平台规则与服务状态也共享，避免两套配置。
- 按任务状态显示继续/运行/等待文案；采集中、等待归档时禁用重复启动。来源缺口提供查看来源限制，避免诱导盲目重跑。
- 全局搜索补入运行记录、共享资源、平台和已归档任务。

## V4 · 用户确认的信息架构修订

运行记录取消独立菜单与路由，整合到采集任务底部详情，自动限定所选项目；跨任务排错由任务页“全部任务记录”打开。底部可调整高度。采集、归档、错误记录仍分别展示。

采集出口独立重做：以独立 IP 为主行，展开关联设备，查看各站点占用；站点选择仅为观察视角，不改变全局目录。身份管理为独立菜单，保留平台选择、申请状态、登录结果、服务控制和只读诊断。站点访问规则移至任务“资源与身份”入口。

本轮构建及 qa/review-v4.cjs 验证通过：取消独立记录入口、项目记录条件、全部记录面板、IP分组展开与设备搜索、独立身份诊断。截图 v4-*.png，结果 qa-output/v4-checks.json。窗口 V4，全部仍为样例，不触碰生产服务。

## V4.1 · 运行记录与本轮事件合并

任务详情压缩为“运行与记录 / 资源与身份 / 采集说明”。原运行概览、本轮事件、任务内三级记录表整合为一个按轮次查看的日志：选择本轮/历史轮次，摘要与采集、归档、错误事件一起变化，按发生时间展示。点击阶段按钮过滤，事件详情只读；无错误、暂停未启动分别有明确空状态。切换任务重置轮次，避免把上一项目的历史视角带入新项目。

身份管理增加固定节点/IP搜索、需要检查和离线档案筛选；待首次申请节点不再同时显示登录成功。资源页区分未保存草稿、保存待重启与已生效状态。各页统一表格内边距、标题字重与辅助文字层级。

qa/review-v41.cjs 验证统一日志、错误详情、历史轮次切换、切换任务重置、身份异常及空结果筛选、1280/1920任务页根级溢出；构建通过。截图 v41-*.png，证据 qa-output/v41-checks.json。当前日志为显式示例关联，正式后端的跨记录轮次关联仍需实现，不把设计稿当作生产日志能力。

## V5 · 平台与采集项两级目录

采集任务改为左侧两级目录（平台 → 采集项），平台可折叠，支持平台/采集项名称搜索和运行状态筛选。筛选展开匹配平台，退出搜索保留原展开状态。目录状态点有文字提示，未保存草稿独立标记；平台菜单保留批量命令确认，当前项菜单提供归档。

右侧为单任务完整工作区，替代上下任务表与详情抢占高度。任务标题展示平台、分类、状态及计划；启动、数据和计划操作靠近任务标题。运行与记录使用本轮/上一轮/更早轮次卡片，结果摘要与事件随轮次同步；事件按采集/归档/错误筛选，窄窗口允许摘要与事件文字换行。

本轮验证脚本 qa/review-v5.cjs：目录层级、选项切换与轮次重置、历史结果、平台搜索、无结果、异常筛选、进行中禁用重复启动、1280/1920宽度布局。构建通过；截图 v5-*.png，结果 qa-output/v5-checks.json。预览展示3个有界示例轮次，正式历史分页仍需业务接入，所有操作未连接真实系统。

## V5.1 · 减少页面层级与采集项进度

任务详情收敛为一个工作区，去掉运行/资源/说明页签；站点、资源、身份改成紧凑操作入口，采集说明就地折叠。三张轮次卡片收为单个轮次选择器。事件详情在表格原行下方展开，不再打开抽屉；复杂配置仍使用原有编辑面板。

平台→采集项目录加入每项完整单元计数、进度条、采集中百分比与中断/缺口/待归档/已核验/暂停状态。主工作区也展示同一轮采集进度。待归档示例为360/360、20条消息未完成，进度满格仍明确标待归档，并禁用重复启动；暂停显示未启动，不渲染虚假完成率。

构建及 qa/review-v51.cjs 通过：目录进度、事件行内展开无抽屉、满格待归档、暂停状态、1280/1920布局。截图 v51-*.png，证据 qa-output/v51-checks.json。全部为静态样例，不声称真实实时采集接入完成。
